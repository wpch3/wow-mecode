## 一、【最大问题】没有回归测试，改 A 坏 B

### 现象

| 时间 | 事件 |
|---|---|
| F27 | 交易被取消 —— 查三轮，真因是代码粘贴3次 |
| F30 | 三个问题一起爆 |
| F31 | 队长转让，**第2次返工** |
| F32 | ElvUI 刷屏，**F29 改错地方，这次才找对** |

**共同点：都是"以为改好了，实际没验证到"。**

### 根因

我们的验证方式是**你进游戏手动点**。这有三个致命缺陷：

```
1. 覆盖不全 —— 你只会测刚做的那个功能
2. 不可重复 —— 同样的操作下次未必想得起来
3. 反馈太慢 —— 编译 20 分钟 + 进游戏 5 分钟才知道错了
```

### 建议：建「验收清单」制度

**每个补丁交付时必须带一份可勾选的清单**，例如 F31：

```
[ ] 上线，队长是 bot
[ ] 等 5 秒，看到「把队长交给了你」
[ ] 队伍框皇冠在我头上
[ ] 下线再上线，队长还是我        <- 最容易漏的
[ ] 全是 bot 的队伍，队长不乱转
[ ] 真人当队长时，bot 不抢
```

**成本**：每个补丁多花 5 分钟写清单。
**收益**：F31 这种返工能提前发现。

我已经在 F31/F32/F33 里加了「验证」章节，**以后每份都会有**。

## 二、【第二大问题】上游合并会炸

### 现在改了多少上游文件

```
GroupHandler.cpp      F29 F32
Group.cpp             F32
PetitionsHandler.cpp  A40

MiscHandler.cpp       F30
bot_ai.cpp            A36 A37 A38
SpellInfo.cpp         G17（计划）
Player.cpp            G17（计划）
```

**8 个上游核心文件被改。** 一旦你想更新 TrinityCore，
`git merge` 会在这些地方全部冲突。

### 建议

**所有上游改动统一加标记注释**，格式：

```cpp
// >>> TCMOD F32 begin
    ... 我们的代码 ...
// <<< TCMOD F32 end
```

好处：
1. 合并冲突时一眼看出哪些是我们的
2. 可以写脚本自动提取「我们改了哪些地方」
3. 将来做成真 patch 文件

**我从下一个补丁开始用这个格式。** 已有的等有空回头补。

## 三、【第三大问题】数据库改动没有版本管理

### 现状

```
sql/ 目录下 12 个 SQL
补丁库各处还散落着 SQL
```

**没有任何记录说明「哪些 SQL 已经在你的库里跑过了」。**

风险：
- 重装服务器时不知道该按什么顺序跑
- 同一个 SQL 跑两遍可能出错
- 忘了跑某个 SQL，功能莫名其妙不工作

### 建议：建一张 `tcmod_version` 表

```sql
CREATE TABLE IF NOT EXISTS `characters`.`tcmod_version` (
    `patch_id`   VARCHAR(32) NOT NULL COMMENT '补丁编号，如 A37 / F31',
    `applied_at` TIMESTAMP   NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `note`       VARCHAR(255) DEFAULT NULL,
    PRIMARY KEY (`patch_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

每个 SQL 补丁最后加一行：

```sql
INSERT IGNORE INTO `characters`.`tcmod_version` (`patch_id`, `note`)
VALUES ('A37', '羁绊与关怀双向重做');
```

**收益**：随时 `SELECT * FROM tcmod_version` 就知道装了什么。

## 五、我自己要改的三件事

### 1. 不再给「未经编译验证」的代码

F31 我用 g++ 真编译验证了，F32 我发现了 `GetSource()` vs `getTarget()`
的错误 —— **如果不验证就交付，你又要白编译一次**。

**规则：凡是给 .cpp 代码，必须先在这边用 stub 编译过。**

### 2. 不再假设「上游 API 长什么样」

F32 我一开始写 `itr->GetSource()->GetGUID()`，
以为 `GetSource()` 返回 bot —— 实查发现返回的是 `Group*`。

```
Reference.h:94   TO*   getTarget() const   -> Creature*   【取bot用这个】
Reference.h:96   FROM* GetSource() const   -> Group*
```

**规则：用任何 API 前，先看它的返回类型定义，不靠名字猜。**

### 3. 报「做不到」前先查三遍

ElvUI 那次我说「服务端管不了」，**错的**。
实际是 `GroupHandler.cpp:335` 发的，改两行就根治。

**规则：说"做不到"前，先把完整调用链走一遍。**
