## 二、根因（实查源码，三步锁定）

### 第 1 步：坐骑属于哪个物品分类

```
ItemTemplate.h:311   ITEM_CLASS_MISCELLANEOUS  = 15
ItemTemplate.h:521   ITEM_SUBCLASS_JUNK_MOUNT  = 5
```

坐骑的 class 就是 **MISCELLANEOUS（杂项）**，subclass 是 JUNK_MOUNT。

也就是说——**`AuctionHouseBot.Class.Misc` 这一个数字直接决定坐骑的配额。**

### 第 2 步：我上一版把它从 5 改成了 2

我在上一版 `ahbot.conf` 里写了：

```ini
# 杂项：降低但不归零（你的白名单坐骑属于 MISCELLANEOUS 类，
# 归零会让坐骑配额变 0，所以保留 2）
AuctionHouseBot.Class.Misc = 2
```

**我当时知道坐骑在这一类（注释里都写了），却还是为了"去杂乱"把它调低了。这是判断失误。**
你的原值是 5，我改成 2。

### 第 3 步：算清楚这一改砍掉了多少

权重是按占比分配配额的（`AuctionHouseBotSeller.cpp:473`）：

```cpp
uint32 weightedAmount = std::lroundf(classPrio / float(totalPrioPerQuality[j]) * qualityAmount);
```

| 项 | 你的原值 | 我改后 |
|---|---|---|
| 所有 Class 权重总和 | 63 | 58 |
| Class.Misc | 5 | **2** |
| 单行 Misc 配额 | 3151 件 | **1369 件** |
| 三行合计 | 9452 件 | **4107 件** |
| **净损失** | — | **-5345 件（降幅 57%）** |

## 三、为什么"种类"也变少了（不只是数量）

这是关键，也是你观察得最准的一点。

看取样代码（`AuctionHouseBotSeller.cpp`，在 `AddNewAuctions` 里）：

```cpp
// Set itemId with random item ID for selected categories and color, from _itemPool table
uint32 itemId = Trinity::Containers::SelectRandomContainerElement(_itemPool[sellItem.Color][sellItem.Itemclass]);
```

**它是从池子里【随机抽样】，抽的次数 = 配额。**

- 配额 3151 → 抽 3151 次 → 大部分坐骑款式都能被抽到至少一次
- 配额 1369 → 只抽 1369 次 → **大量款式一次都没被抽中**

所以配额一降，**数量和种类是同时掉的**。你说的"种类少"和"数量少"其实是同一个原因。

---

## 四、修正：改 1 个数字（零编译）

工作区的 `conf/worldserver.conf.d/ahbot.conf` **我已经改好了**，你重新复制一次即可：

```ini
AuctionHouseBot.Class.Misc = 8
```

（原来是 2，现在是 8）

### 为什么是 8 而不是改回 5

| 设成 | 单行 Misc 配额 | 三行合计 | 说明 |
|---|---|---|---|
| 2（我上一版，错） | 1369 | 4107 | 现状 |
| 5（你的原值） | 3254 | 9762 | 只是回到改动前 |
| **8（推荐）** | **4962** | **14888** | **比你改动前还多 57%** |
| 10（上限） | 6015 | 18045 | 会挤占材料份额 |

选 8 的理由：你明确说了坐骑"还是少"，说明**原来的 5 就已经不够**。
不选 10 是因为权重是相对的——Misc 拉到 10 会和 TradeGood(10，材料) 平起平坐，
而材料是拍卖行的主力商品，不该被杂项压过去。**8 是坐骑和材料的平衡点。**

## 六、如果改完还是觉得坐骑少，跑这条 SQL 给我

这条能直接告诉我们**是配额问题还是池子问题**，一次定位：

```sql
-- 拍卖行里实际有多少种、多少件坐骑
SELECT
    COUNT(DISTINCT ii.`itemEntry`) AS `坐骑种类数`,
    COUNT(*)                       AS `坐骑挂单数`
FROM `characters`.`auctionhouse` a
JOIN `characters`.`item_instance` ii ON ii.`guid` = a.`itemguid`
JOIN `world`.`item_template` it      ON it.`entry` = ii.`itemEntry`
WHERE it.`class` = 15 AND it.`subclass` = 5;
```

```sql
-- 服务器上【总共存在】多少种坐骑（池子上限，作为分母对照）
SELECT COUNT(*) AS `全服坐骑种类总数`
FROM `world`.`item_template`
WHERE `class` = 15 AND `subclass` = 5
  AND `Quality` < 7;
```

**怎么看结果**：

| 情况 | 含义 | 下一步 |
|---|---|---|
| 种类数 / 总数 已经很高（比如 >70%） | 配额够了，池子也够 | 说明已到位 |
| 种类数低但挂单数高 | 配额够，但**重复抽同几款** | 我再调取样逻辑 |
| 两个都低 | 配额还不够 | 把 Class.Misc 提到 10 |
| 全服坐骑种类总数本身就很少 | **池子里就没那么多坐骑** | 需要检查过滤链，我另给方案 |

## 七、顺带确认：两个可能锁住坐骑的开关（你的现值都是安全的）

我查了你 conf 里坐骑专属的过滤，**四个全是 0 = 不过滤，没问题**：

```ini
AuctionHouseBot.Class.Misc.Mount.ReqLevel.Min = 0    # 安全
AuctionHouseBot.Class.Misc.Mount.ReqLevel.Max = 0    # 安全
AuctionHouseBot.Class.Misc.Mount.ReqSkill.Min = 0    # 安全
AuctionHouseBot.Class.Misc.Mount.ReqSkill.Max = 0    # 安全
```

对应源码 `AuctionHouseBotSeller.cpp:279-289`，`if (uint32 value = ...)` 写法，0 表示跳过过滤。

另外一个**不影响坐骑但值得知道**的：

```ini
AuctionHouseBot.LockBox.Enabled = 0
```

它管的是"可开启的箱子类物品"（`ITEM_FLAG_HAS_LOOT`，`AuctionHouseBotSeller.cpp:293-300`），
和坐骑无关，保持 0 即可。

## 八、我的教训（已记入坑表）

> **调"降低杂乱"的权重前，必须先查清这个 class 里装的是什么。**

我在注释里明明写了"坐骑属于 MISCELLANEOUS 类"，却还是把它从 5 调到 2。
知道事实 ≠ 用上事实。**降低任何一类的权重之前，要先列出这一类里有哪些是用户想要的东西。**

`Class.Misc` 这一类里除了坐骑，还有：宠物、节日物品、任务道具残留、
以及你白名单里那 233 项 WLK 坐骑段（38766-39006）。
**把它调低 = 同时打击了坐骑和宠物。**
