# G16 · 坐骑「只有三种」的真因与修法

> 2026-08-18
> 用户纠正：「物品数量不是问题，而是**只有三种坐骑物品**」
>
> **我上一版（07号文档）的诊断是错的。** 我当时以为是配额不够（数量问题），
> 你这句话说明是**池子问题**（种类问题）——能上架的坐骑压根就只有三个。
> 配额再高，池子里只有 3 种，也还是只能反复挂那 3 种。

---

## 一、真因：我关掉 `Bind.Pickup` 时，把坐骑一起关掉了

### 证据链（实查源码）

物品要进拍卖池，只有两条路（`AuctionHouseBotSeller.cpp`）：

```
路径A  :123-129   白名单 forceIncludeItems -> push_back + continue
                  【直接入池，无视后面所有过滤】

路径B  :132-156   绑定过滤
       :138-140       case BIND_WHEN_PICKED_UP:
                          if (!GetConfig(CONFIG_AHBOT_BIND_PICKUP))
                              continue;      <- 丢弃
```

绑定类型枚举（`ItemTemplate.h:98-102`）：

```cpp
NO_BIND               = 0,
BIND_WHEN_PICKED_UP   = 1,     // 绝大多数坐骑是这个
BIND_WHEN_EQUIPED     = 2,
BIND_WHEN_USE         = 3,     // 部分坐骑是这个
BIND_QUEST_ITEM       = 4,
```

**我为了干掉"金色战刃"，把 `Bind.Pickup` 从 1 改成了 0。**

后果：所有 `BIND_WHEN_PICKED_UP` 的物品全部走 `:139` 的 `continue` 被丢弃。
而**绝大多数坐骑（军马、科多兽、狮鹫、机械陆行鸟……）正是拾取绑定**。

**结果**：能上架的坐骑只剩下
① 你白名单里真实存在的那几个 ② 极少数 `NO_BIND` 的坐骑
→ 就是你看到的「只有三种」。

### 为什么白名单那 233 项没救回来

你的 `forceIncludeItems` 里 38766-39006 段有 233 个 ID，
但那是一个**连续区间**，不等于 233 个真实坐骑——
`item_template` 里这一段有大量空洞和非坐骑条目。
真正命中的可能只有个位数。

## 二、先拿数据，不要急着改（这一步别跳过）

我上一版就是靠推演下结论才出错的。**先跑这 3 条 SQL，把真相拿到手。**

### 查询1：服务器上到底有多少种坐骑，按绑定类型分组

```sql
SELECT
    `bonding` AS `绑定类型`,
    CASE `bonding`
        WHEN 0 THEN '0=不绑定'
        WHEN 1 THEN '1=拾取绑定(我关掉的就是这个)'
        WHEN 2 THEN '2=装备绑定'
        WHEN 3 THEN '3=使用后绑定'
        WHEN 4 THEN '4=任务物品'
        ELSE '其他'
    END AS `说明`,
    COUNT(*) AS `坐骑种类数`
FROM `world`.`item_template`
WHERE `class` = 15 AND `subclass` = 5 AND `Quality` < 7
GROUP BY `bonding`
ORDER BY `bonding`;
```

**这条最关键。** 如果 `bonding=1` 那一行数字很大（比如几百），
就100%证实是我关 `Bind.Pickup` 造成的。

### 查询2：拍卖行里现在实际有几种坐骑

```sql
SELECT
    COUNT(DISTINCT ii.`itemEntry`) AS `坐骑种类数`,
    COUNT(*)                       AS `坐骑挂单数`
FROM `characters`.`auctionhouse` a
JOIN `characters`.`item_instance` ii ON ii.`guid` = a.`itemguid`
JOIN `world`.`item_template` it      ON it.`entry` = ii.`itemEntry`
WHERE it.`class` = 15 AND it.`subclass` = 5;
```

预期：种类数 = 3（和你肉眼看到的一致）

### 查询3：这 3 种到底是什么（看看是不是白名单里的）

```sql
SELECT DISTINCT
    it.`entry`, it.`name`, it.`bonding`, it.`Quality`, it.`RequiredLevel`
FROM `characters`.`auctionhouse` a
JOIN `characters`.`item_instance` ii ON ii.`guid` = a.`itemguid`
JOIN `world`.`item_template` it      ON it.`entry` = ii.`itemEntry`
WHERE it.`class` = 15 AND it.`subclass` = 5
ORDER BY it.`entry`;
```

## 三、两种修法，看查询1的结果二选一

### 修法A（推荐）：开回 Bind.Pickup，改用白名单精确排除金色战刃

**适用**：查询1 显示 `bonding=1` 的坐骑很多（大概率是这种）

这样做能一次解决两件事：**坐骑全回来，金色战刃仍然不出现。**

**第1步**：把 `ahbot.conf` 里这行改回 1

```ini
AuctionHouseBot.Bind.Pickup = 1
```

**第2步**：先查出金色战刃的 entry（就是你之前看到的那个）

```sql
SELECT `entry`, `name`, `class`, `subclass`, `bonding`, `Quality`, `ItemLevel`
FROM `world`.`item_template`
WHERE `name` LIKE '%战刃%'
  AND `Quality` >= 4
ORDER BY `ItemLevel` DESC
LIMIT 20;
```

**第3步**：把查到的 entry 加进 `forceExcludeItems`

在你的**主 conf**（`worldserver.conf`）里找到这一行：

```ini
AuctionHouseBot.forceExcludeItems = "……你现有的9项……"
```

在末尾追加逗号和新 entry。**黑名单在 `:120` 生效，优先级最高**：

```
AuctionHouseBotSeller.cpp:120   if (excludeItems.count(itemId)) continue;
```

它在白名单(`:123`)和绑定过滤(`:132`)【之前】，所以一定拦得住。

> **为什么这样更好**：`Bind.Pickup` 是个"一刀切"开关，
> 关掉它 = 干掉所有拾取绑定物品（包括几百种坐骑）。
> 而黑名单是"外科手术"，只干掉你不想要的那一件。

---

### 修法B（临时）：保持 Bind.Pickup=0，把坐骑塞进白名单

**适用**：你暂时不想动主 conf，或者查询1显示坐骑大多不是 bonding=1

**原理**：白名单在 `:123-129` 直接 push_back + continue，**无视绑定过滤**。

**第1步**：生成所有坐骑的 entry 列表

```sql
SELECT GROUP_CONCAT(`entry` ORDER BY `entry` SEPARATOR ',') AS `坐骑entry列表`
FROM `world`.`item_template`
WHERE `class` = 15 AND `subclass` = 5
  AND `Quality` < 7
  AND `RequiredLevel` <= 80;
```

**第2步**：把输出的一长串加进主 conf 的 `forceIncludeItems` 末尾。

> **缺点**：这串可能很长（几百个 ID），而且只解决坐骑，
> 其他被 `Bind.Pickup=0` 误伤的物品（大量装备）还是回不来。
> **所以我推荐修法A。**

## 四、顺带说明：07号文档的 Class.Misc 改动仍然有效，保留

我上一版把 `Class.Misc` 从 2 改成 8，那个改动**方向是对的，继续保留**：

- 它解决的是「坐骑**配额**」（能挂多少件）
- 本文解决的是「坐骑**池子**」（有多少种可挑）

**两个是不同层面的问题，都要修。**
池子修好后，配额高才有意义——否则 8 的配额反复挂那 3 种，反而更重复。

## 六、我的教训（第二条，已记坑表）

> **用"一刀切开关"解决单个物品的问题，一定会误伤一大片。**

金色战刃是**一个物品**的问题，我却用了 `Bind.Pickup`（**一整个绑定类别**的开关）去解决。
正确做法是用 `forceExcludeItems` 黑名单精确打击。

**判断依据**：如果一个配置项的名字是"某一类的开关"（Bind.X / Class.X / Items.X），
而你要解决的是"某一件东西"，那八成用错工具了。

另外——**我上一版根据"坐骑少"就断定是配额问题，没让你先查种类数**。
如果我一开始就要查询2的数据，就不会浪费你一轮部署。
**用户说"少"的时候，必须先分清是"数量少"还是"种类少"。**
