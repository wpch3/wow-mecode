## 零、先说三个最重要的实证结论

这三条是本次实查最有价值的部分，**推翻了我之前规划里的乐观假设**。

### 结论1：你的服「拍卖行机器人」其实【已经在跑了】

核心自带 AHBot，而且你的 conf 里**是开着的**：

```
worldserver.conf.dist:3411   AuctionHouseBot.Account = 2
worldserver.conf.dist:3419   AuctionHouseBot.Update.Interval = 1600
worldserver.conf.dist:3427   AuctionHouseBot.Seller.Enabled = 1     <- 卖家：开
worldserver.conf.dist:3823   AuctionHouseBot.Buyer.Enabled  = 0     <- 买家：关
```

也就是说：**挂单功能是开的，收购功能是关的**。

所以「拍卖行用机器人运行」这件事，你已经有了一半。
剩下的问题是三个，全部要现场确认（见第四章「开工前必须先查的3件事」）：

| 疑点 | 为什么关键 |
|---|---|
| 账号 ID 2 下面**有没有角色** | 没角色 -> 卖家名是空的 |
| Update.Interval 被改成 **1600 秒** | 默认 20 秒。1600 秒 = 26 分钟才补一次货 |
| Buyer 关着 | 所以你卖东西**没人买**，经济是单向的 |

### 结论2：卖家名字从哪来 —— 这条决定了整个方案的形状

拍卖行发给客户端的包里，卖家就是一个**裸的角色 guid**：

```
AuctionHouseMgr.h:88        ObjectGuid::LowType owner;              // 卖家
AuctionHouseMgr.cpp:865     data << uint64(owner);                  // Auction->owner
```

客户端拿到这个 guid，再发 NameQuery 回来问名字。而服务端的应答函数
**有一个 npcbot 专用分支**：

```
QueryHandler.cpp:42   void WorldSession::SendNameQueryOpcode(ObjectGuid guid)
QueryHandler.cpp:48       if (guid.IsCreature())            <- NPCBot 走这条
QueryHandler.cpp:52           if (creatureTemplate->IsNPCBot())
QueryHandler.cpp:68               bdata.Name = creatureName;
QueryHandler.cpp:81       if (CharacterCacheEntry const* characterInfo =
                              sCharacterCache->GetCharacterCacheByGuid(guid))   <- 玩家走这条
```

**关键推论（这是本次最重要的发现）**：

`owner` 的类型是 `ObjectGuid::LowType`，**只有低位计数器，没有类型高位**。
拍卖行 `data << uint64(owner)` 发出去的是个裸数字，
客户端会把它当 **Player guid** 去查，也就是走 `QueryHandler.cpp:81` 那条。

所以：

```
PlayerBot  -> characters 表里有真实行 -> CharacterCache 查得到 -> 卖家名正常显示  [可行]
NPCBot     -> 只有 creature_template  -> CharacterCache 查不到 -> 卖家名显示不出  [不可行]
```

**NPCBot 不能直接当拍卖行卖家。** 这不是"难"，是 guid 类型对不上。
绕过它需要什么？-> **给 NPCBot 配一个 characters 表里的"影子角色"**。
这正好把总蓝图里搁置的「批次D 影子角色」激活了（`规划-NPCBot增强总蓝图.md`）。

### 结论3：发现上游一个真 bug —— AddAuction 被调了两次

```
AuctionHouseBotSeller.cpp:935        auctionHouse->AddAuction(auctionEntry);
AuctionHouseBotSeller.cpp:936        auctionEntry->SaveToDB(trans);
AuctionHouseBotSeller.cpp:937
AuctionHouseBotSeller.cpp:938        auctionHouse->AddAuction(auctionEntry);   <- 又来一次
```

看 `AddAuction` 的实现：

```
AuctionHouseMgr.cpp:597   void AuctionHouseObject::AddAuction(AuctionEntry* auction)
AuctionHouseMgr.cpp:601       AuctionsMap[auction->Id] = auction;
AuctionHouseMgr.cpp:602       sScriptMgr->OnAuctionAdd(this, auction);        <- 钩子被触发两次
```

`AuctionsMap[Id] = auction` 是按 key 覆盖，同一个指针写两遍**不会内存泄漏**，
所以现在看不出毛病。**但 `OnAuctionAdd` 这个脚本钩子会被触发两次。**

**为什么这条必须现在记下来**：G16 第3步要挂的就是 `OnAuctionAdd` 钩子。
如果不知道这个 bug，将来 bot 的账目会**莫名其妙翻倍**，
而且会像 F27 那样查半天找不到原因。

> 这和 F27「`// OK start trade` 被粘贴3次」是**同一类问题**：
> 重复调用不报错，只是行为翻倍。已加进坑表。

## 二、三条通道 —— 拍卖行到底怎么让 bot 跑

这是本规划的核心。**按可行性排序，我只推第1条作为起手。**

| 通道 | 做法 | 卖家名 | 要不要编译 | 风险 |
|---|---|---|---|---|
| **通道1 影子账号** | 把 bot 角色建在 AHBot 账号下 | **正常显示** | **不用** | 极低 |
| 通道2 pbot 真挂单 | pbot 走 `HandleAuctionSellItem` | 正常显示 | 要 | 中 |
| 通道3 NPCBot 挂单 | 直接填 creature entry | **显示不出** | 要 | 高，且名字不对 |

### 通道1（推荐起手）：影子账号 —— 零编译，纯配置

核心已经替我们写好了：

```
AuctionHouseBot.cpp:71    if (uint32 ahBotAccId = GetConfig(CONFIG_AHBOT_ACCOUNT_ID))
AuctionHouseBot.cpp:78        CHAR_SEL_CHARS_BY_ACCOUNT_ID
AuctionHouseBot.cpp:85            _AHBotCharacters.push_back(fields[0].GetUInt32());
AuctionHouseBot.cpp:318   uint32 AuctionBotConfig::GetRandChar() const
AuctionHouseBot.cpp:323       return Trinity::Containers::SelectRandomContainerElement(_AHBotCharacters);
```

那条 SQL 是：

```
CharacterDatabase.cpp:409   "SELECT guid FROM characters WHERE account = ?"
```

挂单时随机挑一个：

```
AuctionHouseBotSeller.cpp:920   auctionEntry->owner = sAuctionBotConfig->GetRandChar();
```

**翻译成人话**：
只要在 `AuctionHouseBot.Account`（你的是 **2**）这个账号下面建几个角色，
拍卖行的卖家栏就会**随机显示这些角色的名字**。

不用改一行 C++。名字想叫什么就叫什么。

**这一步做完，"拍卖行用机器人运行"就已经成立了**，而且看起来像一群真人在卖东西。

### 通道2（第二步）：PlayerBot 真的去拍卖行挂单

pbot 是**真 Player + 真 WorldSession**（A25 已实现），所以能走正规下单路径：

```
WorldSession.h:937          void HandleAuctionSellItem(WorldPacket& recvData);   public(706段)
AuctionHouseHandler.cpp:145 void WorldSession::HandleAuctionSellItem(WorldPacket& recvData)
```

**但有一道门**，必须站在拍卖师旁边：

```
AuctionHouseHandler.cpp:189  Creature* creature =
        GetPlayer()->GetNPCIfCanInteractWith(auctioneer, UNIT_NPC_FLAG_AUCTIONEER);
AuctionHouseHandler.cpp:190  if (!creature) return;
```

那道门的实现：

```
Player.cpp:2152   Creature* Player::GetNPCIfCanInteractWith(ObjectGuid const& guid, NPCFlags npcFlags) const
Player.cpp:2178       if (npcFlags && !creature->HasNpcFlag(npcFlags)) return nullptr;
Player.cpp:2195       if (!creature->IsWithinDistInMap(this, creature->GetCombatReach() + 4.0f))
                          return nullptr;
```

`ObjectDefines.h:24   #define INTERACTION_DISTANCE  5.0f`

**所以通道2 需要先把 pbot 传送到拍卖师身边**（`.pbot goto` 已有，A25/step40b）。
好消息是 pbot 没有 socket，`WorldSession.cpp:211 SendPacket: if (!m_Socket) return;`
所以**不会有客户端副作用**。

### 通道3（不推荐）：NPCBot 直挂 —— 卡在 guid 类型

已在「结论2」证明：`QueryHandler.cpp:48` 的 Creature 分支和
`:81` 的 CharacterCache 分支是两条路，`owner` 字段走不到 Creature 那条。

**要做也不是做不到**，路径是：给 NPCBot 建影子角色，用影子角色的 guid 当 owner。
但那样本质就变成通道1了，所以**没必要单独做**。

> 附带发现：`Player.cpp:2185-2188` 有个 npcbot 专用分支，
> NPCBot 只要在 5 码内就能交互，**而且这个分支在 npcFlags 检查之后**。
> 意味着「会走路的拍卖师 bot」是可行的 —— 给 NPCBot 挂
> `UNIT_NPC_FLAG_AUCTIONEER`（`UnitDefines.h:258 = 0x00200000`）
> 就能随身开拍卖行。这条**存档，不在本次五步内**。

**原则和 G11 一样：一步一验证，不跳步。**

### 第1步 · 拍卖行体检 + 影子账号（零编译）

**这一步不用重新编译，改完重启就生效。**

要做的：

1. 查账号 2 下面有没有角色（见第四章）
2. 建一批「商人」角色，名字要像真人
3. `Update.Interval` 从 1600 调回合理值
4. 验证：进游戏开拍卖行，看卖家名是不是我们建的名字

**产出**：一份体检 SQL + 一份 conf 改动说明。

### 第2步 · 打开 Buyer（零编译）

```
worldserver.conf.dist:3823   AuctionHouseBot.Buyer.Enabled = 0   -> 1
```

打开后 bot 会**收购玩家挂的东西**，你卖装备终于有人接盘。
配套要调的是这一组（`AuctionHouseBot.h:120-133`）：

```
CONFIG_AHBOT_BUYER_BASEPRICE_GRAY .. YELLOW           出价基准
CONFIG_AHBOT_BUYER_CHANCEMULTIPLIER_GRAY .. YELLOW    出价概率
CONFIG_AHBOT_BUYER_RECHECK_INTERVAL                   多久看一次
```

**风险**：出价基准配太高 = 无限刷钱（卖垃圾给 bot 赚钱）。第2步要给一份稳妥数值。

## 四、开工前必须先查的 3 件事（要你在 DBeaver 跑）

**不查清楚就动手 = 又要返工。** 这三条查完，第1步才能精确落地。

```sql
-- 查1：AHBot 账号 2 下面有没有角色（决定卖家名显示什么）
SELECT guid, name, level, money
FROM characters
WHERE account = 2;

-- 查2：现在拍卖行里有多少货，卖家分别是谁
SELECT COUNT(*) AS 挂单总数 FROM auctionhouse;

SELECT a.itemowner AS 卖家guid,
       IFNULL(c.name, '【查不到名字】') AS 卖家名,
       COUNT(*) AS 挂单数
FROM auctionhouse a
LEFT JOIN characters c ON c.guid = a.itemowner
GROUP BY a.itemowner
ORDER BY 挂单数 DESC;

-- 查3：确认你的 pbot 角色在哪个账号（决定要不要挪进 AHBot 账号）
SELECT guid, account, name, level
FROM characters
WHERE name IN ('鲤鱼', '卡特莉娜');
```

**「查2」如果卖家名一片"查不到名字"** -> 说明账号 2 是空的，
`GetRandChar()` 返回 0，`owner = 0`。这正是第1步要修的。
