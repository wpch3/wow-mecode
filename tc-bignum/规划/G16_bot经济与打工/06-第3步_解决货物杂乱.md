# G16 第3步 · 解决"货物不齐全 + 很杂乱"

> 2026-08-09
> 用户：「拍卖行的物品还是不齐全，还有而且很杂乱」

---

## 一、先分清两个问题

| 症状 | 原因 | 解法 |
|---|---|---|
| **不齐全** | 补货速度跟不上目标数量 | 调 `ItemsPerCycle` + `.ahbot rebuild` |
| **很杂乱** | **没有等级过滤，1级破布和80级紫装混在一起** | 加 4 个过滤参数 |

**"杂乱"是主要问题，而且有明确解法。**

---

## 二、杂乱的根因（实查）

`AuctionHouseBotSeller.cpp:238-271` 有一组过滤器：

```cpp
:238   if (uint32 value = GetConfig(CONFIG_AHBOT_ITEM_MIN_ITEM_LEVEL))
:241   if (uint32 value = GetConfig(CONFIG_AHBOT_ITEM_MAX_ITEM_LEVEL))
:244   if (uint32 value = GetConfig(CONFIG_AHBOT_ITEM_MIN_REQ_LEVEL))
:247   if (uint32 value = GetConfig(CONFIG_AHBOT_ITEM_MAX_REQ_LEVEL))
:250   if (uint32 value = GetConfig(CONFIG_AHBOT_ITEM_MIN_SKILL_RANK))
:253   if (uint32 value = GetConfig(CONFIG_AHBOT_ITEM_MAX_SKILL_RANK))
```

**注意 `if (uint32 value = ...)` 这个写法** —— 值为 **0 时整个判断跳过**，
也就是「0 = 不过滤」。

你的 conf 现值（我从你上传的文件里查的）：

```ini
AuctionHouseBot.Items.ItemLevel.Min = 0     <- 不限
AuctionHouseBot.Items.ItemLevel.Max = 0     <- 不限
AuctionHouseBot.Items.ReqLevel.Min  = 0     <- 不限
AuctionHouseBot.Items.ReqLevel.Max  = 0     <- 不限
```

**四个全是 0 = 完全不过滤。**

所以 AHBot 会把游戏里**所有物品**都往上挂：
1 级的破布、测试物品、任务道具、80 级的顶级紫装……全混在一起。
这就是"杂乱"。

---

## 三、修法：加等级过滤

### 3.1 推荐配置（80 级服务器）

```ini
# 只挂"有实用价值"的物品
AuctionHouseBot.Items.ItemLevel.Min = 15
AuctionHouseBot.Items.ItemLevel.Max = 284
AuctionHouseBot.Items.ReqLevel.Min = 0
AuctionHouseBot.Items.ReqLevel.Max = 80
```

**为什么是这几个数**：

| 参数 | 值 | 理由 |
|---|---|---|
| `ItemLevel.Min = 15` | 15 | 装等15以下基本是1-10级的垃圾装备 |
| `ItemLevel.Max = 284` | 284 | ICC 25H 的顶级装等，再高就是测试物品 |
| `ReqLevel.Max = 80` | 80 | 需求等级超过80的都是异常数据 |
| `ReqLevel.Min = 0` | 0 | 保留 0，否则材料/药水会被过滤掉（它们 ReqLevel=0） |

> **`ReqLevel.Min` 千万别设非 0** —— 布料、矿石、药水这些
> `RequiredLevel` 都是 0，一设就全没了，那才是真的"不齐全"。

### 3.2 如果还嫌杂，再加职业过滤

```ini
# 降低杂项和任务物品的比重
AuctionHouseBot.Class.Quest = 0
AuctionHouseBot.Class.Key = 0
AuctionHouseBot.Class.Misc = 2
AuctionHouseBot.Class.Generic = 0
```

对照你的现值（`worldserver.conf:3682` 附近）：

```
Class.Quest = ?     -> 改 0（任务物品不该上拍卖行）
Class.Key = ?       -> 改 0（钥匙同理）
Class.Misc = ?      -> 改 2（杂项减少，但保留坐骑等）
Class.Generic = ?   -> 改 0
```

> 这几个是**优先级权重**（0-10），不是开关。设 0 表示这一类几乎不生成。

## 四、"不齐全"的解法

### 4.1 先看现状

```
.ahbot status
```

输出会显示每个行、每个品质的 **当前数量 / 目标数量**。

**如果当前远小于目标** -> 是补货速度问题，看 4.2
**如果当前接近目标但种类少** -> 是过滤器问题，看第三章

### 4.2 补货速度

你已经改成：

```ini
AuctionHouseBot.ItemsPerCycle.Boost = 5000
AuctionHouseBot.ItemsPerCycle.Normal = 500
AuctionHouseBot.Update.Interval = 3600
```

**问题**：`Update.Interval = 3600`（1小时）意味着**每小时才补 5000 件**。
目标 12 万条的话，要 24 小时才能铺满。

**如果你想快点填满**，临时改成：

```ini
AuctionHouseBot.Update.Interval = 60        # 临时：1分钟一次
```

铺满之后再改回 3600。

**或者用命令强制**：

```
.ahbot rebuild all
```

> 注意：`rebuild` 是把现有挂单标记为过期，**不是立刻填满**。
> 真正填充还是靠周期性补货。

### 4.3 检查数量目标是不是真的生效

```sql
SELECT COUNT(*) AS `当前挂单总数` FROM `characters`.`auctionhouse`;

-- 按品质分布
SELECT it.`Quality`, COUNT(*) AS `数量`
FROM `characters`.`auctionhouse` a
JOIN `characters`.`item_instance` ii ON ii.`guid` = a.`itemguid`
JOIN `world`.`item_template` it ON it.`entry` = ii.`itemEntry`
GROUP BY it.`Quality`
ORDER BY it.`Quality`;
```

**对照你配的目标**（White 12000 / Green 12000 / Blue 8000 / Purple 5000）。

## 五、完整改动（照抄）

```ini
# ===== 解决"杂乱"：等级过滤 =====
AuctionHouseBot.Items.ItemLevel.Min = 15
AuctionHouseBot.Items.ItemLevel.Max = 284
AuctionHouseBot.Items.ReqLevel.Min = 0
AuctionHouseBot.Items.ReqLevel.Max = 80

# ===== 减少无意义品类 =====
AuctionHouseBot.Class.Quest = 0
AuctionHouseBot.Class.Key = 0
AuctionHouseBot.Class.Generic = 0
AuctionHouseBot.Class.Misc = 2

# ===== 临时加速铺货（铺满后改回 3600）=====
AuctionHouseBot.Update.Interval = 60
```

改完 **重启 + `.ahbot rebuild all`**，
等 1-2 小时看 `.ahbot status`，铺满后把 `Update.Interval` 改回 `3600`。

## 六、我需要你给的数据

如果改完还是觉得不对，跑这两条贴给我：

```sql
-- 1. 总量
SELECT COUNT(*) AS `挂单总数` FROM `characters`.`auctionhouse`;

-- 2. 装等分布（看"杂乱"到什么程度）
SELECT
    CASE
        WHEN it.`ItemLevel` < 20  THEN 'A: 0-19（垃圾）'
        WHEN it.`ItemLevel` < 60  THEN 'B: 20-59'
        WHEN it.`ItemLevel` < 120 THEN 'C: 60-119'
        WHEN it.`ItemLevel` < 200 THEN 'D: 120-199'
        ELSE 'E: 200+（顶级）'
    END AS `装等区间`,
    COUNT(*) AS `数量`
FROM `characters`.`auctionhouse` a
JOIN `characters`.`item_instance` ii ON ii.`guid` = a.`itemguid`
JOIN `world`.`item_template` it ON it.`entry` = ii.`itemEntry`
GROUP BY `装等区间`
ORDER BY `装等区间`;
```

**如果 A 区间（0-19）占比很大，就证实了"杂乱"是等级过滤缺失造成的。**
