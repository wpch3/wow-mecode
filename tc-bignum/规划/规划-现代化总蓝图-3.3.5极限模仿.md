## 一、先划清"能做"与"不能做"的真实边界

在规划之前，必须知道哪些是物理不可能的。**这几条是硬墙**（全部源码实证）：

| 想要的现代功能 | 3.3.5 能否实现 | 卡在哪 |
|---|---|---|
| 更多种族/职业 | **能，上限 32** | `racemask` 是 uint32（1<<31 是极限）|
| 独立相位（专属营地）| **能，但只有 32 个位** | `Object.h:663 uint32 m_phaseMask` |
| 幻化 | **能** | NPCBot 已自带一套（见下）|
| 飞行坐骑任意地图 | **能** | 服务端控制 |
| 战斗中动态难度 | **能** | Eluna 钩子够 |
| 21.47亿以上血量 | **不能** | 客户端 UpdateFields 是 INT32 |
| 真·跨服 | **不能** | 协议不支持 |
| DX11/12 渲染 | **不能** | exe 是 DX9 |
| 现代 UI 框架（如新版任务追踪）| **部分能** | Lua 可改，但 API 少很多 |

### 【关键约束】相位只有 32 个位

这条直接决定"7.x 专属营地"怎么做，必须先讲清楚：

```cpp
// Object.h:663
uint32 m_phaseMask;
// Object.h:385
bool InSamePhase(uint32 phasemask) const { return (GetPhaseMask() & phasemask) != 0; }
```

**判定是"位与"，不是"相等"。** 所以：

- 总共只有 **32 个独立相位位**
- **不可能**给每个玩家一个专属相位（1000 个玩家就要 1000 位）

**这意味着"每人一个专属营地"不能用相位硬做。** 解法见第四章。

## 四、【重点】玩家专属营地/家园 —— 怎么绕过 32 相位限制

用户点名要 7.x 专属营地，而 12.x 的玩家住房是同类需求。
**这是本文档技术含量最高的一节。**

### 问题重述

```
想要：每个玩家有自己的营地，别人看不见/可邀请
限制：phaseMask 只有 32 位（Object.h:663）
      不可能一人一位
```

### 三个可行方案（按推荐度）

#### 方案 A：副本实例化（推荐，最稳）

**原理**：每个玩家的营地是一个**独立副本实例**，不是相位。

```
做法：
  1. 做一张小地图（或复用现有小副本，如"深岩之洲某洞窟"）
  2. 玩家点 NPC/物品 -> 传送进【自己的实例】
  3. 副本天然隔离，人数无上限
  4. 家具 = gameobject，位置存数据库，进副本时动态生成
  5. 邀请好友 = 组队后一起进
```

**优点**：
- **完全没有数量限制**（副本实例是动态创建的）
- 隔离干净，不会互相干扰
- 家具摆放自由（gameobject 可任意坐标）

**缺点**：
- 要单独进副本，不能"在世界里"
- 需要一张地图（可复用现有的）

**这是 12.x 玩家住房的实际做法，也是最工程正确的方案。**

#### 方案 B：相位分配给"职业/阵营/盟约"而非个人

**原理**：不给每个人分相位，给**类别**分。

```
10 个职业大厅   = 10 位
4 个盟约        = 4 位
剧情阶段（真龙六卷）= 6 位
预留            = 12 位
                 ------
                 32 位刚好够
```

**这正是 7.x 职业大厅的做法** —— 大厅是全职业共享的，不是私人的。

**优点**：零额外工程，`SetPhaseMask` 直接用
**缺点**：不是"专属"，是"同职业共享"

#### 方案 C：相位轮转（进阶，有坑）

**原理**：相位位动态复用 —— 玩家进营地时临时分配一个空闲位，出来就回收。

```
同时最多 32 个玩家在营地里
超过就排队或复用
```

**优点**：能在主世界里做
**缺点**：**并发一高就崩**，且实现复杂。**不推荐。**

### 我的建议

```
职业大厅（7.x 风格）  -> 方案 B（相位），10 个位，简单可靠
玩家私人住房（12.x）  -> 方案 A（副本实例），无上限
```

**两者可以并存，且都不会耗尽 32 位。**

## 八、必须先做的一件事：相位分配表

**32 个相位位是稀缺资源，一旦用乱就很难回收。**
建议在动工前**先定死分配方案**：

| 位 | 十进制 | 用途 | 状态 |
|---|---|---|---|
| bit 0 | 1 | 默认世界（所有人）| **保留，不可动** |
| bit 1-10 | 2..1024 | 10 个职业大厅 | 预留 |
| bit 11-14 | 2048..16384 | 4 个盟约/阵营 | 预留 |
| bit 15-20 | ... | 真龙剧情 6 卷阶段 | 预留 |
| bit 21-28 | ... | 种族专属区域 | 预留 |
| bit 29-31 | ... | 机动/调试 | 预留 |

> 玩家住房**不占相位**（走副本实例，方案A）。
> 这就是为什么方案A重要 —— 它把最大的消耗项移出了相位系统。

## 十、一句话总结

**3.3.5 模仿现代化，瓶颈不在"能不能"，在"工具链"和"32个相位"。**

- 内容资源：**已经有了**（9.2.5 全量包）
- 生产工具：**差 DBC 注册 + 流水线**（第1期解决）
- 系统底座：**相位要精打细算**，住房走副本绕开
- 真正做不到的：DX11渲染、龙翼物理、跨服、21亿血量墙

**其余的，都是工作量问题，不是可行性问题。**
