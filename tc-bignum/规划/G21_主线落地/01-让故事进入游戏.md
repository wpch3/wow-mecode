# G21 · 主线落地：让真龙史诗从 txt 进入游戏

> 2026-08-09
> 这是整个项目**最大的真空**：
> `剧情/故事集-真龙纪元.txt` 有 2866 行 / 4.3 万字，
> **但游戏里一个字都看不到。**

---

## 一、现状：故事已经写得很完整了

实查 `故事集-真龙纪元.txt`，结构非常清楚：

```
┌──────┬───────────────┬────────────┬───────────┐
│ 卷次 │ 标题          │ 主轴       │ 建议等级  │
├──────┼───────────────┼────────────┼───────────┤
│ 序卷 │ 消失的渔村    │ 丙         │  1 - 15  │
│ 一卷 │ 七百年的守候  │ 甲         │ 15 - 30  │
│ 二卷 │ 旧账          │ 乙【重】   │ 30 - 50  │
│ 三卷 │ 同一口井      │ 乙【重】   │ 50 - 65  │
│ 四卷 │ 秩序的重量    │ 甲 + 丙    │ 65 - 78  │
│ 五卷 │ 土底下的味道  │ 三线汇流   │ 78 - 90  │
│ 六卷 │ 携手          │ 乙【重】   │ 90 - 100 │
│ 终卷 │ 她说了什么    │ 三线收束   │ 100+     │
└──────┴───────────────┴────────────┴───────────┘
甲=天意线(真龙) 乙=尘世线(部落联盟) 丙=噩梦线(世界)
```

**关键发现：每卷都有明确的等级区间。**
这意味着**它天生就能挂进游戏的成长曲线** —— 不用重新设计。

## 三、方案A · `.story` 指令（1天，先做这个）

### 3.1 效果

```
.story                查看主线进度和卷次列表
.story 1              阅读第一卷
.story 1 3            阅读第一卷第三章
.story where          提示"你这个等级该看哪一卷"
.story next           接着上次看的继续
```

### 3.2 数据表

```sql
CREATE TABLE IF NOT EXISTS `world`.`story_chapter` (
  `id`          INT UNSIGNED     NOT NULL AUTO_INCREMENT,
  `volume`      TINYINT UNSIGNED NOT NULL COMMENT '0=序卷 1-6=正卷 7=终卷',
  `chapter`     TINYINT UNSIGNED NOT NULL COMMENT '卷内章号',
  `title`       VARCHAR(128)     NOT NULL,
  `min_level`   TINYINT UNSIGNED NOT NULL DEFAULT 1,
  `line_type`   TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '1=天意 2=尘世 3=噩梦',
  `body`        TEXT             NOT NULL COMMENT '章节正文',
  PRIMARY KEY (`id`),
  KEY `idx_vol` (`volume`, `chapter`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='G21 主线章节';

CREATE TABLE IF NOT EXISTS `characters`.`story_progress` (
  `guid`        INT UNSIGNED     NOT NULL COMMENT '玩家guid',
  `volume`      TINYINT UNSIGNED NOT NULL,
  `chapter`     TINYINT UNSIGNED NOT NULL,
  `read_at`     TIMESTAMP        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`guid`, `volume`, `chapter`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='G21 阅读进度';
```

### 3.3 导入工具

**不要手工把 2866 行贴进 SQL** —— 我写个脚本自动切分：

```
tools/story_import.py
  输入：剧情/故事集-真龙纪元.txt
  输出：填充 story_chapter 的 SQL
  切分依据：文件里的「第 X 卷」和章节标记
```

**这个我下一轮交付**（需要先确认章节的确切分隔符）。

### 3.4 指令实现要点

## 四、方案B · 世界文本NPC（1周，效果最好）

### 4.1 设计

在**故事发生地**放讲述者 NPC，玩家对话读到片段。

| 卷次 | 地点 | NPC | 讲什么 |
|---|---|---|---|
| 序卷 | 艾尔文森林·闪金镇码头 | 老渔夫 | 消失的渔村 |
| 一卷 | 龙骨荒野·龙眠神殿外 | 守候者 | 七百年的守候 |
| 二卷 | 阿拉希高地·激流堡废墟 | 老兵 | 旧账 |
| 三卷 | 荒芜之地·奥达曼入口 | 中立商人 | 同一口井 |
| 四卷 | 风暴峭壁·奥杜尔外 | 泰坦造物 | 秩序的重量 |
| 五卷 | 索拉查盆地 | 德鲁伊 | 土底下的味道 |
| 六卷 | 达拉然 | 双阵营使者 | 携手 |
| 终卷 | 龙眠神殿内 | 阿莱克丝塔萨 | 她说了什么 |

**每个 NPC 用 gossip 菜单分章节**，玩家等级不够时说
「你还太年轻，有些事听了也不会懂。」

### 4.2 技术：纯 SQL，零编译

```
creature_template     造 8 个 NPC（entry 段 970001-970008）
creature              放到对应坐标
gossip_menu           对话菜单
gossip_menu_option    章节选项
npc_text              正文
```

**全部是数据配置**，不用改代码。

> **注意**：`npc_text` 单条有长度限制，长章节要拆成多个 gossip 层级。

### 4.3 和 bot 的联动（这是我们的特色）

```
玩家和讲述者NPC对话后，队伍里的bot会有反应：
  人类bot（在激流堡）："我祖父在这儿打过仗。"
  兽人bot（在激流堡）："……我们该走了。"
  暗夜bot（在龙眠）："七百年？对我们来说不算太久。"
```

**实现**：A42 台词表加 `event_id` 字段，
玩家读完某章 -> 触发对应 event_id 的台词。

## 六、和 G20 世界玩法的关系

```
G21 主线落地  ->  玩家【知道】发生了什么
G20 世界重塑  ->  玩家【参与】改变什么

两者结合：
  读完二卷《旧账》     -> 理解洛丹伦为什么是废墟
  参与 B3 洛丹伦重建   -> 亲手改变它
  读完六卷《携手》     -> 理解为什么部落联盟要合作
```

**这就是"故事"变成"你的故事"的路径。**

## 八、需要你确认

```
1. .story 指令要不要做？（1天，随时能读）
2. 讲述者NPC放哪些地点？（我上面列了8个，你可以改）
3. 章节正文要不要精简？
   —— 4.3万字全塞进游戏可能太长，
      建议每章提炼 300-500 字的"游戏版"，完整版留txt
```

**第 3 条最重要** —— 游戏里读长文很痛苦。
我建议做**双版本**：游戏内精简版 + txt 完整版（给愿意深挖的人）。
