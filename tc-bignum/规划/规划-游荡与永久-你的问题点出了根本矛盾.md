# 游荡 vs 永久 —— 你这个问题点出了根本矛盾

> 用户问：「bot批量永久化的退出游荡池会影响他继续当游荡bot吗，
> 我的规划是游荡bot也可以自己找到冒险伙伴」

**答：会，而且是彻底互斥的。A35 做完那些 bot 就【永远站桩】了。**

**你问得非常及时 —— 差一点就把 812 个游荡bot 变成木头人。**

---

## 一、决定 bot 身份的只有一行代码

实查 `bot_ai.cpp:246-250`：

```cpp
void bot_ai::InitializeAI()
{
    if (!me->GetSpawnId() && !IsTempBot() && !me->IsSummon())
        SetWanderer();

    Reset();
}
```

**`GetSpawnId() == 0` 是成为游荡bot的唯一条件。**

| | spawnId | 身份 | 行为 |
|---|---|---|---|
| 游荡bot | **0** | wanderer | 走路点、自己找伙伴、会打架、重启洗牌 |
| 固定bot | **非0** | 普通NPC | **站在原地不动** |

### 而 spawnId 从哪来

```cpp
// 游荡bot（botdatamgr.cpp:210）
bot->LoadBotCreatureFromDB(0, map, true, true, bot_id, &spawnPos);
//                         ^ spawnId 硬编码 0

// 固定bot（botdatamgr.cpp:1125）
bot->LoadBotCreatureFromDB(tableGuid, map, false, false, entry, &spawnPos);
//                         ^^^^^^^^^ 从 creature 表读来的 guid
```

**A35 往 `creature` 表写记录 = 给了它 spawnId = 它再也不是游荡bot。**

## 二、所以 A35 的真实效果是

```
执行 A35 之前：
  812 个游荡bot 在世界里跑，会自己找伙伴冒险

执行 A35（固定10个）之后：
  802 个游荡bot 继续跑
   10 个变成【站桩NPC】，钉在路点坐标上一动不动
```

**那 10 个不是"永久的游荡bot"，是"永久的木桩"。**

这和你的规划（游荡bot自己找冒险伙伴）**完全背道而驰**。

## 四、游荡bot 现在能不能自己组队（先摸底）

我查了代码，**已经有一些基础**：

`bot_ai.cpp:1632`：

```cpp
if (IAmFree() && (!IsWanderer() || !pGroup || me->IsInCombat()))
```

`bot_ai.cpp:18057`：


**说明**：核心里 **wanderer 是可以有 Group 的**（`GetGroup()` 返回非空）。

> 但要我们自己写配对逻辑。

## 五、三条路，你选

### 路线1：放弃 A35，专心做「游荡bot社交」

```
不碰 creature 表，所有bot保持 spawnId=0
写一个 WorldScript：
  定期扫描附近的游荡bot
  等级相近 + 阵营相同 + 都不在战斗 -> 自动组队
  组队后一起走路点、一起打怪
  队伍维持一段时间后解散，各奔东西
```

**优点**：完全符合你的规划，世界是活的
**缺点**：重启后全部洗牌（bot 和队伍都不保留）
**工作量**：中等，一个新 .cpp

### 路线2：混合 —— 少量固定 + 大量游荡

```
固定 20-50 个当「据点NPC」（旅店老板旁边、城门口）
  -> 这些用 A35，站桩，但你随时能找到
其余 760+ 保持游荡
  -> 做社交系统，让它们自己组队冒险
```

**优点**：两种体验都有
**缺点**：固定的那批确实是木桩
**工作量**：A35 已完成 + 路线1的工作量

### 路线3：改核心，让"有 spawnId 的 bot 也能游荡"

```
改 bot_ai.cpp:247 的判断，加一个新标志：
  if ((!me->GetSpawnId() || IsPersistentWanderer()) && ...)
      SetWanderer();

用 creature.ScriptName 或一张新表标记「这个bot是持久化游荡bot」
```

**优点**：真正做到「重启不消失 + 继续游荡」
**缺点**：
- 要改上游 `bot_ai.cpp`
- **游荡bot会走动，但 creature 表里记着固定坐标**
  -> 重启后它会回到原点，中途的位置不保留
- 可能触发别的地方对 spawnId 的假设（要排查）

**工作量**：大，且有未知风险

## 六、我的建议：路线1

**理由**：

1. **你的核心诉求是「世界是活的」** —— bot 自己冒险、自己组队、
   有羁绊有故事。站桩NPC给不了这个。

2. **"重启消失"其实不是问题** —— 游荡bot本来就是背景板，
   重启后换一批新面孔反而更自然（像真实世界的路人）。
   你真正在意的那几个bot，可以用 `.npcbot spawn` 招募成永久伙伴。

3. **A35 的价值在别处** —— 它适合做「据点NPC」：
   比如在新手村放 5 个固定的训练伙伴，在主城放几个可招募的。
   **少量、有明确用途**，而不是批量固定 800 个。
