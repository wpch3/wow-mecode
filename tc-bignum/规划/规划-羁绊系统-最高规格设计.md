# 羁绊系统 · 最高规格设计

> 2026-08-04
> 用户要求：「羁绊系统和关怀系统让玩家有**更多参与感**，
> 比如我也能给他食物或者各种东西，**他也会索要**，
> 还有就是有**更多的互动选项和体验**，羁绊系统也要按照**最高规格**来做」

---

## 一、核心理念：从「单向投喂」到「双向关系」

### step34 现状（已实测生效）

```
bot -> 你     饿了给面包、渴了给水、穷了给钱
你  -> bot    【什么都做不了】
```

**这是单向的。** 你只是个被照顾的对象，没有参与感。

### 本系统要做的

```
bot -> 你     继续关怀（保留 step34）
你  -> bot    【新】给食物/水/钱/礼物，bot 会记住、会道谢、会回礼
bot -> 你     【新】主动【索要】："我的绷带用完了，你还有吗？"
双向          【新】共同经历累积成"羁绊"，解锁更深的对话
```

**关键差别**：bot 会**开口要东西**。
一个只会给予、从不索取的伙伴是"仆人"；
**会向你求助的才是"战友"**。

## 二、羁绊等级：不是进度条，是共同经历

### 2.1 为什么不做进度条

刷满进度条给奖励 = 又一个日常任务。

**我们做的**：bot 记住**具体发生过什么**，然后在合适的时候提起。

```
"还记得吗，上次在辛特兰，你把最后一块面包给了我。"
"我们一起死在那个洞里三次了……第四次总该过了吧。"
```

**这些话之所以动人，是因为它真的发生过。**

### 2.2 数据表（characters 库）

```sql
CREATE TABLE `characters`.`npcbot_bond` (
  `bot_id`          INT UNSIGNED NOT NULL,   -- bot 的 creature entry
  `owner_guid`      INT UNSIGNED NOT NULL,   -- 玩家 guid

  -- 羁绊等级（0-5），由下面的经历【算出来】，不是刷出来的
  `bond_level`      TINYINT UNSIGNED DEFAULT 0,
  `bond_points`     INT UNSIGNED     DEFAULT 0,

  -- === 共同经历（这才是灵魂）===
  `time_together`   INT UNSIGNED DEFAULT 0,  -- 一起在线的秒数
  `battles_won`     INT UNSIGNED DEFAULT 0,  -- 一起打赢的战斗
  `times_saved_me`  INT UNSIGNED DEFAULT 0,  -- bot 救过你（你残血时它治疗/拉怪）
  `times_i_saved`   INT UNSIGNED DEFAULT 0,  -- 你救过 bot
  `deaths_together` INT UNSIGNED DEFAULT 0,  -- 一起团灭
  `gifts_from_bot`  INT UNSIGNED DEFAULT 0,  -- bot 给过你多少东西
  `gifts_to_bot`    INT UNSIGNED DEFAULT 0,  -- 【新】你给过 bot 多少东西
  `requests_met`    INT UNSIGNED DEFAULT 0,  -- 【新】你满足过它几次请求
  `requests_ignored`INT UNSIGNED DEFAULT 0,  -- 【新】你无视过它几次请求

  -- === 情境记忆（用于"还记得吗"）===
  `last_zone_id`    INT UNSIGNED DEFAULT 0,  -- 最近一起去过的地方
  `memorable_zone`  INT UNSIGNED DEFAULT 0,  -- 最难忘的地方（团灭最多的）
  `first_met`       INT UNSIGNED DEFAULT 0,  -- 初遇时间戳
  `last_gift_time`  INT UNSIGNED DEFAULT 0,  -- 防刷：上次收礼时间

  PRIMARY KEY (`bot_id`, `owner_guid`)
);
```

### 2.3 等级与解锁

| 级 | 称呼 | 需要 | 解锁 |
|---|---|---|---|
| 0 | 雇佣关系 | — | 只说必要的话 |
| 1 | 认识了 | 一起 30 分钟 | 开始闲聊见闻 |
| 2 | 熟人 | 一起打赢 20 场 | **开始向你索要东西** |
| 3 | 朋友 | 互相救过 3 次 | 主动送东西、提起共同经历 |
| 4 | 战友 | 一起团灭过 / 长期同行 | 危险时挡在你前面、说重话 |
| 5 | 生死之交 | 综合 | 专属台词、说很私人的事 |

**注意 2 级才解锁"索要"** —— 刚认识就管你要东西，那叫乞丐不叫伙伴。

## 三、【核心新增】双向互动

### 3.1 你给 bot 东西

**上游已经有现成通道**（实查确认）：

```cpp
// bot_ai.cpp:7833
AddGossipItemFor(player, GOSSIP_ICON_TALK,
    LocalizedNpcText(player, BOT_TEXT_GIVE_CONSUMABLE),   // "给予消耗品..."
    GOSSIP_SENDER_USEITEM, GOSSIP_ACTION_INFO_DEF + 1);

// bot_ai.cpp:10274  case GOSSIP_SENDER_USEITEM
//   -> 遍历玩家背包，列出可用消耗品
// bot_ai.cpp:10218  case GOSSIP_SENDER_USEITEM_USE
//   -> _castBotItemUseSpell(item, targets)  让bot使用
```

**我们要做的不是重造，是在这条通道上加"情感反馈"**：

```
你给它面包    -> bot: "谢谢……我确实有点饿了。"        gifts_to_bot++
你给它好酒    -> bot: "这个我可舍不得马上喝。"          bond_points += 5
你给它治疗药  -> bot: "关键时刻能救命，我收好了。"
它正好在索要  -> bot: "你还真带了！我就知道找你没错。"  requests_met++
                                                        bond_points += 15
```

**同一个物品，在"它正好需要"时给，价值高得多。** 这就是参与感。

### 3.2 【最关键】bot 会向你索要

这是让关系变双向的核心。

**触发条件**（都要满足）：
- 羁绊 >= 2 级
- 距上次索要 > 30 分钟（不能烦人）
- 有真实需求（不是随机说话）

**索要什么，取决于它真的缺什么**：

| 情境 | 台词 | 想要 |
|---|---|---|
| 背包没食物且血量<50% | "我的干粮吃完了……你那儿还有吗？" | 食物 |
| 法力<30% 且是法系 | "能给我点水吗？我快没蓝了。" | 饮料 |
| 绷带用完且刚受伤 | "绷带用光了，下次可能就扛不住了。" | 绷带 |
| 装备耐久<20% | "我的武器快断了，有多余的吗？" | 装备/修理 |
| 连续死亡 3 次 | "……我是不是拖后腿了。" | **只是想听你说句话** |

**最后一条不要任何物品** —— 它只是需要你回应。
这种"索要"比要东西更打动人。

### 3.3 你可以主动关心它

新增对话选项（羁绊 >= 1 解锁）：

```
[你还好吗？]        -> 它会说实话：血量/法力/装备/心情
[你需要什么吗？]    -> 它会说出当前最缺的东西
[聊聊天吧]          -> 按羁绊等级说不同深度的话
[给你这个]          -> 走上游 GIVE_CONSUMABLE 通道
[我们一起走过哪些地方] -> 【羁绊3+】回忆共同经历
```

**「你还好吗」这一句，玩家会反复点。** 因为它有回应。

## 四、互动选项设计（更多体验）

### 4.1 情境化闲聊（不是随机废话）

**坏的做法**：随机抽一句台词说出来 -> 玩家两天就腻。

**我们的做法**：台词表带**触发条件**，只在合适的时候说。

```sql
CREATE TABLE `world`.`npcbot_bond_text` (
  `id`           INT UNSIGNED AUTO_INCREMENT,
  `min_bond`     TINYINT UNSIGNED DEFAULT 0,   -- 需要几级羁绊
  `situation`    VARCHAR(32) NOT NULL,          -- 触发情境
  `zone_id`      INT UNSIGNED DEFAULT 0,        -- 0=任意地图
  `text_zh`      VARCHAR(255) NOT NULL,
  `weight`       TINYINT UNSIGNED DEFAULT 10,
  PRIMARY KEY (`id`)
);
```

**situation 取值**：

| 情境 | 什么时候说 |
|---|---|
| `after_hard_win` | 刚打赢一场险仗（残血获胜） |
| `after_wipe` | 刚一起团灭 |
| `player_low_hp` | 你快死了 |
| `bot_saved_you` | 它刚救了你 |
| `you_saved_bot` | 你刚救了它 |
| `idle_night` | 夜晚闲着（游戏内时间） |
| `enter_zone` | 进入新地图 |
| `revisit_zone` | 回到"难忘的地方" |
| `gift_received` | 收到你的礼物 |
| `long_time_no_see` | 很久没上线 |
| `level_up` | 你升级了 |

**举例**（羁绊 4 级，`after_wipe`）：

```
"……又倒下了。"
"但你还在，那就还没输。"
"起来，再来一次。"
```

**同样是团灭，羁绊 1 级只会说**：`"重整旗鼓。"`

### 4.2 情感记忆（羁绊 3+）

```
"还记得吗，我们第一次见面是在{first_met_zone}。"
"我们在{memorable_zone}死过{deaths_together}次……
  那地方我这辈子都忘不了。"
"你救过我{times_i_saved}次。这笔账我记着。"
```

**数字是真的**，不是编的。玩家会认出来"这确实是我们的经历"。

## 七、为什么这个设计是"最高规格"

| 常见做法 | 我们的做法 |
|---|---|
| 好感度进度条 | **共同经历计数**，台词引用真实数字 |
| 随机台词池 | **11 种情境触发**，只在合适时说 |
| 单向送礼 | **双向**：它会索要，你能回应 |
| 送礼只加点数 | **"正好需要时给"** 价值翻倍 |
| 满级给奖励 | 满级解锁**更私人的话**，没有物质奖励 |

**最后一条是刻意的**：如果羁绊满级给一件神装，
那玩家刷的是装备不是感情。**羁绊的奖励只能是羁绊本身。**
