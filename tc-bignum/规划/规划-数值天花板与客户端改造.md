## 一点五、float→int32 截断的真实行为（用户实测「攻强变负数」）

```
StatSystem.cpp   SetAttackPower(int32(base_attPower));
                                ^^^^^ float -> int32
```

x86-64 的 `cvttss2si` 指令：float 超出 int32 范围时返回
**"integer indefinite value" = 0x80000000 = INT_MIN**。

实测：

```
float 40亿    -> int32 = -2147483648
float 22亿    -> int32 = -2147483648
float 21.47亿 -> int32 = -2147483648   <- 连恰好等于 INT32_MAX 的也翻（float 舍入）
```

**圣骑力量精确临界点**（二分法）：

| 力量 | 攻强 | 状态 |
|---|---|---|
| 1,073,741,632 | 2,147,483,520 | 最后一个安全值 |
| **1,073,741,696** | **-2,147,483,648** | **翻负** |
| 400,000,000（用户当前） | 800,000,256 | 正常 |
| 2,000,000,000（用户实测） | -2,147,483,648 | 翻负，与用户反馈一致 |

**临界 ≈ 力量 10.737 亿**（再多 64 点就翻）。

**负攻强的双重后果**：

```
Unit.cpp:9754   int32 ap = GetInt32Value(UNIT_FIELD_ATTACK_POWER) + ...;
                if (ap < 0) return 0.0f;        // 服务端：当 0 算 -> 伤害掉回白板
```

- **服务端**：攻强按 0 处理，伤害变白板
- **客户端**：角色面板直接显示原值 `-2147483648`
- 字段 flag `UF_FLAG_PRIVATE | UF_FLAG_OWNER`（UpdateFieldFlags.cpp:287）-> 只有自己看得到

两件事**同时发生**：面板巨大负数 + 实际伤害归零。

## 二、攻强有【两条独立的路】——这是关键

```
StatSystem.cpp  Player::UpdateAttackPowerAndDamage()

  路 A（装备属性走这条）
    val2 = level*3 + GetStat(STAT_STRENGTH)*2 - 20      // 圣骑/战士/DK
    SetStatFlatModifier(unitMod, BASE_VALUE, val2);
    base_attPower = GetFlatModifierValue(BASE_VALUE) * GetPctModifierValue(BASE_PCT);
    SetAttackPower(int32(base_attPower));               -> UNIT_FIELD_ATTACK_POWER  [int32]

  路 B（只有光环加成走这条）
    attPowerMod = GetFlatModifierValue(unitMod, TOTAL_VALUE);
    SetAttackPowerModPos(int32(attPowerMod));           -> UNIT_FIELD_ATTACK_POWER_MODS [int16!]
```

```
Unit.h:1554  void SetAttackPowerModPos(int32 m) { SetInt16Value(UNIT_FIELD_ATTACK_POWER_MODS, 0, m); }
Unit.cpp:9754  int32 ap = GetInt32Value(UNIT_FIELD_ATTACK_POWER)          // int32
                        + int16(GetUInt16Value(...MODS, 0))               // int16
                        + int16(GetUInt16Value(...MODS, 1));              // int16
```

| 来源 | 落到 | 上限 |
|---|---|---|
| **装备属性（力量/敏捷）** | `UNIT_FIELD_ATTACK_POWER` | **int32 = 21 亿** |
| 光环临时加成 | `UNIT_FIELD_ATTACK_POWER_MODS` | int16 = 32767 |

**结论**：堆装备属性**不会**碰 int16。要踩那个坑，得自己写一个 +5 万 AP 的光环。

| 属性 | 转换公式 | 最终字段 | 倍率 | **客户端墙** | **服务端墙** |
|---|---|---|---|---|---|
| **耐力** | `base + (stam-20)*10` | `SetMaxHealth(uint32)` | **×10** | **2.147 亿** | 4.29 亿 |

**耐力有【两道墙】（2026-07-31 用户实测修正）**：

> 「耐力不能超过两亿一千万，不然血量就会超过21亿归零」
> 「耐力最多4亿就无法往上堆叠」

- **2.147 亿**（客户端墙）：血量 = 耐力x10 = 21.47 亿 = INT32_MAX。
  服务端 `SetMaxHealth` 是 uint32 装得下，但**客户端血量字段按 int32 显示** -> 归零。
- **4.29 亿**（服务端墙）：血量 42.9 亿 = UINT32_MAX，真正回绕。

我上轮只算了服务端墙，**漏了客户端墙** —— 又一次印证「以客户端实际为准」。

**属性本身还有第三道墙**：

```
StatSystem.cpp UpdateStats():111   SetStat(stat, int32(value));
Object.cpp:728  SetStatInt32Value(){ if (value < 0) value = 0; ... }
```

任何属性超 INT32_MAX(21.47亿) 都会先 int32 翻负、再被**钳成 0**。

**源码原文**：

// StatSystem.cpp  Player::UpdateMaxHealth()

// StatSystem.cpp  Player::UpdateArmor()

SetArmor(int32(value));                         // <- int32 上限 21.4 亿
```

```

## 四、为什么 float 让"加到 20 亿也不翻负"

```
Unit.h:904   float GetStat(Stats stat) const { return float(GetUInt32Value(...)); }
```

`GetStat` 返回 **float**（能表示到 3.4e38），所以 `str*2 = 40 亿` 在中间计算里毫无压力，
不会像整数那样翻成负数。只有最后 `int32(base_attPower)` 那一下才截断。

**副作用**：float 只有 24 位有效精度，超过 **16,777,216（1677 万）** 后整数不再精确。
也就是说你堆到 4 亿时，实际生效值可能和填的数差几十上百——但不影响可用性。

**另注**：float 比较有坑。`float(2147483647)` 会被舍入成 `2147483648.0f`，
所以判断是否超 int32 上限**必须用 double 比**，我在测试里踩过这个（第 13 项一度 FAIL）。
