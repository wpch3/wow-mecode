## 零、先回答你的问题：哪些该并进羁绊系统

| 需求 | 归属 | 理由 |
|---|---|---|
| 1 已组队bot自动上线 | **独立做**（前置） | 纯技术功能，没有情感成分。**而且它是其它三个的前提** —— bot 不在线，跟随/传送/对话全是空谈 |
| 2 跟着我走 | **独立做**（前置） | 同上，是基础设施 |
| 3 传送到身前 | **独立做**（小功能） | `.pbot come` 已经有了，这次是补「精确落点」 |
| 4 **对话系统** | **【并进羁绊系统】** | **这个必须并**，理由见下 |

### 为什么对话必须并进羁绊系统

你要的是「**主动找我聊话题 + 根据我的回复自动编译回复**」。

如果对话是独立模块，它只能做到「随机说一句话」——
那就是个复读机，聊三次你就腻了。

**对话的灵魂是「它记得什么」**：

```
没有羁绊数据的对话（复读机）：
  bot: "今天天气不错。"
  你:  "是啊。"
  bot: "嗯。"
  -> 三次之后你再也不想点它

有羁绊数据的对话（有记忆）：
  bot: "还记得上次在辛特兰吗？你把最后一块面包给了我。"
  你:  "记得"
  bot: "那时候我以为你会自己吃掉。……后来我就一直跟着你了。"
  -> 这句话之所以成立，是因为 gifts_to_bot 表里真的有那条记录
```

**羁绊系统的数据表（time_together / times_saved_me / gifts_to_bot / deaths_together）
就是对话系统的「素材库」。** 两者是同一个东西的两面：

- 羁绊系统 = **记录**发生了什么
- 对话系统 = 把记录**说出来**

所以：**对话系统作为羁绊系统的第 3 步实现**，不单独开线。

## 一、【前置1】已组队 PlayerBot 自动上线

### 1.1 你要的效果

```
你登录  ->  队伍里的"鲤鱼"自动跟着上线，还在队里
你下线  ->  鲤鱼自动下线（不留幽灵会话）
```

### 1.2 技术路径（已实查）

**挂钩点**：`PlayerScript::OnLogin`

```cpp
// ScriptMgr.h:692  public 段
virtual void OnLogin(Player* player, bool firstLogin);
// 调用点 CharacterHandler.cpp:996  sScriptMgr->OnPlayerLogin(pCurrChar, firstLogin);
```

**关键问题：登录那一刻，队伍信息加载了没有？**

实查 `Player.cpp:17317`：

```cpp
_LoadGroup(holder.GetPreparedResult(PLAYER_LOGIN_QUERY_LOAD_GROUP));
```

在 `Player::LoadFromDB` 里，**早于** `CharacterHandler.cpp:996` 的 `OnPlayerLogin`。

-> **OnLogin 时 `player->GetGroup()` 已经可用**（Player.h:2155 public 904段）。这条路通。

**队伍成员从哪读**：

```cpp
// Group.h:256   MemberSlotList const& GetMemberSlots() const   public(185段)
// Group.h:167   struct MemberSlot { ObjectGuid guid; std::string name; uint8 group/flags/roles; }
```

**离线成员的判断**：`ObjectAccessor::FindPlayer(guid)` 返回 nullptr = 不在线。

**怎么知道这个成员是 PlayerBot 而不是真人**：
查 `characters` 表里它的账号，比对一个「bot 账号白名单」。
最稳的做法是新建一张表：

```sql
CREATE TABLE `characters`.`playerbot_roster` (
  `char_guid`   INT UNSIGNED NOT NULL,
  `account_id`  INT UNSIGNED NOT NULL,
  `char_name`   VARCHAR(12)  NOT NULL,
  `auto_login`  TINYINT      DEFAULT 1,   -- 主人上线时是否跟着上线
  `owner_guid`  INT UNSIGNED DEFAULT 0,   -- 属于哪个玩家
  PRIMARY KEY (`char_guid`)
);
```

这张表**同时解决了 g_pbots 重启丢失的问题**（现在 g_pbots 是纯内存的）。

### 1.3 要注意的坑（提前记下）

| 坑 | 说明 |
|---|---|
| **不能在 OnLogin 里直接 SpawnBot** | OnLogin 还在登录流程里，此时 `sWorld->AddSession` 可能有竞态。**应该塞进一个延迟队列，下一个 world tick 再处理** |
| **World::AddSession 是异步的** | `World.cpp:334  addSessQueue.add(s)` —— 加进去不等于立刻生效 |
| **玩家可能秒退** | 延迟执行时要重新确认玩家还在线 |
| **bot 上线后不在队里** | 队伍关系存在 `group_member` 表，bot 登录时 `_LoadGroup` 会自动恢复。**但要确认 bot 下线时没被移出队伍** |
| **递归登录** | bot 自己也会触发 OnLogin -> 要判断「这个登录的是不是 bot」，是就直接 return |

## 二、【前置2】跟着我走（Follow）

### 2.1 你的实际痛点

> 「不然无法走出出生点（这里无法决斗）」

所以**当务之急不是完美的跟随 AI，是让 bot 能挪窝**。

### 2.2 分两级做

**Level 1（先做，简单可靠）：定时瞬移跟随**

```
每 2 秒检查一次：
  bot 离你 > 15 码  ->  直接传送到你身后 3 码
  bot 离你 <= 15 码 ->  不动
```

- 优点：**绝对不会走丢、不会卡地形、不会掉进水里**
- 缺点：看起来是"闪现"不是"走路"
- **对"走出出生点"这个需求，这就够了**

**Level 2（后做，好看）：真实寻路移动**

```cpp
// MotionMaster.h  MoveFollow(Unit* target, float dist, float angle)
bot->GetMotionMaster()->MoveFollow(player, 3.0f, float(M_PI));
```

- 优点：真的在走路，有动画
- 缺点：**PlayerBot 是 Player 不是 Creature**，Player 的移动要靠客户端发包驱动。
  服务端主动推 Player 走路需要伪造 `MSG_MOVE_*` 包，**这是个大工程**
- **风险点**：Player 的 `MotionMaster` 在 3.3.5 里对无客户端的会话行为未验证，
  需要实测

> **决策：先做 Level 1**。它解决你的实际问题（走出出生点去决斗），
> 而且零风险。Level 2 等 Level 1 用起来了再说。

### 2.3 指令设计

```
.pbot follow <角色名|all>     开始跟随
.pbot stay   <角色名|all>     原地待命
.pbot 跟随 / .pbot 待命        中文别名
```

## 四、【并入羁绊系统】对话系统

> **这是你最想要的那个，也是最难的。我把它拆成能落地的三层。**

### 4.1 你的原话拆解

> 「最好可以**主动找我聊话题**，再**根据我的回复自动编译回复的话语**，
> 或者**我找他谈话**也可以自动编译回复话语，**一定要自动**」

拆成四个能力：

| # | 能力 | 难度 |
|---|---|---|
| A | bot **主动**开口找你聊 | 低 |
| B | 你能**找它**聊（点它就有对话选项） | 低 |
| C | 根据你的回复**生成**下一句 | **高** |
| D | 全程**自动**，不用你敲指令 | 中 |

### 4.2 「自动编译回复」怎么做 —— 三条路，我的建议

**这是整个设计里最关键的技术选择，我把三条路都摆出来。**

#### 路线 1：状态机 + 语料库（纯本地，无外部依赖）

```
bot 说: "你觉得我们下一步该去哪？"
        [选项1] "去北边"    -> bot: "北边啊……那边的狼群不好惹，不过跟着你我不怕。"
        [选项2] "先休息"    -> bot: "好，正好我也想歇歇。你要不要吃点东西？"
        [选项3] "你决定吧"  -> bot: "我？……那我们去南边看看，我听说那里有个老矿洞。"
```

- **实现**：数据表存「话题 -> 选项 -> 回复」，用羁绊数据填空
- **优点**：零依赖、零延迟、绝对稳定、GBK 兼容无压力
- **缺点**：**不是真的"编译"**，是预写的。写 200 条就能撑很久，但终究有限
- **工作量**：数据表 + 台词库，2-3 天

#### 路线 2：模板 + 变量拼装（半动态）

```
模板: "{称呼}，{时间感慨}。{基于经历的引用}{提问}"

运行时填:
  称呼      = 羁绊等级决定（"喂" -> "老大" -> "老伙计"）
  时间感慨  = 游戏内时间 + 天气
  经历引用  = 从 npcbot_bond 表随机取一条真事
  提问      = 从当前情境（战斗后/城里/野外/夜里）取

产出: "老伙计，天快黑了。我们一起趟过37次战斗了……
       你说，这次的活儿能顺利吗？"
```

- **优点**：**同样的模板能生成上千种组合**，且每句都引用真实数据
- **缺点**：仔细看还是有套路感
- **工作量**：模板引擎 + 变量池，3-4 天
- **这是性价比最高的路线**

#### 路线 3：接外部 AI（真·自动编译）

```
Eluna Lua -> HTTP -> 本地部署的小模型 / 云端 API -> 返回回复
```

- **优点**：**这才是你说的"真正的自动编译"**，能聊任何话题
- **缺点**：
  - 需要 Eluna 有 HTTP 能力（**待实查，3.3.5 Eluna 默认没有**）
  - 有延迟（本地小模型 1-3 秒，云端 0.5-2 秒）
  - 需要处理超时、失败降级
  - **中文编码是大坑**（服务端 GBK <-> API 的 UTF-8）
  - 要么本地跑模型（吃显存），要么联网（有成本）
- **工作量**：不好估，至少 1 周，且有踩空风险

### 4.3 我的建议：路线 2 打底 + 路线 3 做增强

```
第1步  路线2 落地            <- 保证"一定能用"，不依赖任何外部东西
第2步  留好【接口】           <- 对话生成函数做成可替换的
第3步  实验路线3              <- 成了就切过去，不成也不影响已有功能
```

**理由**：你说「一定要实现」，那就**不能把整个功能压在一个有风险的技术上**。
路线 2 先让你玩上，路线 3 慢慢试。

**关键设计**：把「生成回复」这一步抽成一个函数

```cpp
// 伪代码
std::string GenerateReply(uint32 botId, uint32 ownerGuid,
                          std::string const& playerSaid,
                          BondData const& bond);
```

路线 2 是它的第一个实现；将来路线 3 成了，**换掉函数体就行**，
上层的对话触发、UI、羁绊记录全都不用动。

### 4.4 触发时机（怎么做到「主动」和「自动」）

| 时机 | 触发条件 | 例句方向 |
|---|---|---|
| 久别重逢 | 你上线，且距上次 > 8 小时 | "你可算来了。" |
| 战斗后 | 一场硬仗结束，双方都活着 | "刚才那下够险的。" |
| 你救了它 | times_i_saved +1 | "……谢了。我记着。" |
| 一起团灭 | deaths_together +1 | "第几次了？我数不清了。" |
| 深夜同行 | 游戏内 22:00-05:00 且在野外 | "夜里赶路，你不怕？" |
| 长时间沉默 | 30 分钟没互动 | 随机开个话题 |
| 到新地图 | 第一次进某个区域 | "这地方我以前来过。" |
| **它有需求** | 背包空/血少/装备坏 | **索要**（羁绊系统已设计） |

**「自动」的实现**：`WorldScript::OnUpdate` 里节流轮询（照抄
`pbot_autoaccept.cpp` 的 1 秒节流模式），命中条件就 `BotWhisper` 一句。

### 4.5 NPCBot 和 PlayerBot 的差异

| | NPCBot | PlayerBot |
|---|---|---|
| 对话通道 | gossip 菜单（已有完整框架） | **没有 gossip** |
| 说话方式 | `BotWhisper()`（bot_ai.cpp:262） | `ChatHandler::PSendSysMessage` 或世界聊天包 |
| 你怎么回它 | 点 gossip 选项 | **需要新设计** |

**PlayerBot 的对话入口方案**（三选一，待定）：

1. `.pbot talk 鲤鱼 <你想说的话>` —— 最简单，但要打字
2. **对着它说话自动识别** —— 你在 `/say` 或 `/w 鲤鱼` 时钩住，最自然
3. 借用 gossip —— 给 PlayerBot 挂个假 NPC，技术上绕

**倾向方案 2**（钩 `/w` 密语）：最接近「和真人聊天」的体验。
挂钩点待实查：`ChatHandler::HandleChatMessage` 的密语分支。

> **一个重要的坑（提前记）**：
> `bot_ai.cpp:264  if (!target && master->IsPlayer())` —— step48 崩溃点。
> BotWhisper 不传 target 会崩。**对话系统大量用 BotWhisper，
> 必须确认 step48 的修复（比指针地址）已经生效**。
