### D. 物品属性热改免重启 ⭐

```
.reload item_template               重载物品表，不用重启服务端
```

> 这个特别有用：你改造大数值装备时要反复调数值，
> **原版这个核心没有 `.reload item_template`**（我确认过 `cs_reload.cpp`），
> 每改一次数值就得重启一次服务端。加上之后改完 SQL 直接热重载。
>
> 技术上安全：`Item::GetTemplate()` 是每次实时查表（`sObjectMgr->GetItemTemplate(GetEntry())`），
> 不缓存指针，所以重载不会产生野指针。只需重新生成 QueryData 缓存即可。

### E. 属性查看面板

```
.pinfo stats                     显示当前选中目标的全部属性明细
```

## 关于 RBAC 权限（第 6 步会用到，先了解）

新指令要有权限 ID。我核对了 `RBAC.h`，本仓库的约定是：

```cpp
// 官方权限用到 885，注释写明 "custom permissions 1000+"
// NPCBot 作者选择从 70001 开始（RBAC_PERM_COMMAND_NPCBOT = 70001 ... 70037）
```

所以我会把新指令放在 **71001+**，避开官方 885 以下和 NPCBot 的 70001-70037，
将来官方或 NPCBot 更新都不会撞号。

## 重要提醒：执行顺序不能乱

第 1、2 步（改源码 + 编译）**必须早于**第 3 步（执行 SQL）。

原因上一轮已实测验证：只改数据库不改源码，服务端读到大数值会
触发 `ASSERT(false)` 直接崩溃，而不是静默截断。
