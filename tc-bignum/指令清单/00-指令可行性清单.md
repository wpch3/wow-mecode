## 🟡 第三类：能做但要打折（4 条）

### 1. `.gear transmog [装备ID]` —— 只能做「临时外观」，不是真幻化

**问题**：3.3.5 **没有原生幻化系统**。我查了全仓库，`Transmog` 相关代码只存在于
NPCBot 模块里（`botgossip.h`、`botdatamgr.h`），而且**只对 bot 生效，玩家用不了**。

**能做的**：用 `Player::SetVisibleItemSlot()`（`Player.cpp:12170`）改
`PLAYER_VISIBLE_ITEM_1_ENTRYID` 字段，强制显示成另一件装备的外观。

**打折的地方**：
- ❌ **不持久**。重新登录 / 换装 / 跨地图重载后外观会变回去，因为这个字段每次都由实际装备重算
- ❌ 别人看到的外观**可能不同步**（取决于对方何时收到你的更新包）
- ✅ 你要的「无视职业与限制」这点没问题，因为是直接写字段，不走装备校验

**要做成真幻化**需要：加一张 `custom_transmog` 表存映射 + 在 `SetVisibleItemSlot` 里挂钩子 + 登录时重挂。
这是个**独立的中型模块**（约 300-500 行），我可以做，但建议放到全部做完之后再单独开一轮。

### 2. `.learn class_spells` —— 「仅学本职业」需要额外过滤

现有 `.learn all blizzard` 会学**所有职业**的技能（会污染）。
你要的「且仅学全当前职业」可以做，用 `SkillLineAbility.dbc` 按 `classmask` 过滤。
⚠️ 但天赋部分建议直接用现有的 `.learn all talents`，自己实现容易漏天赋树分支。

### 3. `.instance skip_rp` —— 只能做通用版，不保证每个副本都灵

**问题**：副本的 RP 剧情走场**没有统一接口**，每个副本脚本自己实现（有的用
`Events` 定时器，有的用 `SmartAI`，有的硬编码在 boss AI 里）。

**能做的**：通用做法 = 遍历当前副本内所有 Creature，对处于
`MOTION_TYPE_WAYPOINT`/`SPLINE` 状态的强制 `StopMoving()` + 清事件队列。

**打折**：对**大部分**副本有效（比如 ICC 开场、太阳井），但**用 SmartAI 时间轴驱动的
剧情可能跳不掉**。做不到 100%。

### 4. `.bot spawn_raid` —— 强烈建议改成调用现有指令

NPCBot **已经有完整的召唤+组队指令**（`botcommands.cpp`）：
`.npcbot add`、`.npcbot spawn`、`.npcbot debug raid`。

我可以写一个 `.bot spawn_raid` 帮你**批量循环调用**这些现有逻辑，
但⚠️ **一次召唤 24 个 bot 会有明显卡顿**，而且 bot 的职业搭配需要你预先配好 entry 列表。
建议做成 `.bot spawn_raid [配置名]`，配置写在一张自定义表里。

## 🔴 第四类：不建议做（1 条）

### `.instance set_boss_hp [BOSS名] [百分比]` —— 建议改用「选中目标」方式

**「按 BOSS 名字找」这个设计有问题**：
- 中文名匹配要处理多语言 `creature_template_locale`，容易匹配到错误目标
- 同一副本可能有同名小怪
- BOSS 没刷出来时无法定位

**替代方案（我会这样实现）**：
```
.set bosshp 50        把【当前选中】的目标血量设为 50%
```
选中目标最直接、零歧义。如果你确实要按名字找，我也能加个
`.instance findboss [名字]` 先列出候选再选中。

> 顺便：`.instance setbossstate` **已经存在**（`cs_instance.cpp`），
> 那是改 BOSS 的**战斗状态机**（未开始/进行中/已完成），和改血量是两回事，别混淆。

## 建议的实施顺序（重要）

你的原始需求（大数值改造）和新指令是**两个独立工程**。我建议：

```
阶段一：大数值改造（第 0-5 步）   ← 先完成，能立刻用上
   ↓
阶段二：自定义指令（第 6-9 步）   ← 再做，避免一次改太多难排错
```

**理由**：如果两个一起上，编译出错时你无法判断是补丁的问题还是新指令的问题。
分开做，每次编译只引入一类改动，出问题好定位。
