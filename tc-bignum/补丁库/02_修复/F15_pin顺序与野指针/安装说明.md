## 一、先说清楚：`.pin` 从 step49 起【从来没成功过】

你看到的「固定失败：SaveToDB 没能生成 spawnId」不是偶发，**是必然**。

`Creature.cpp:1427-1432`：

```cpp
void Creature::SaveToDB(uint32 mapid, uint8 spawnMask, uint32 phaseMask)
{
    //npcbot: disallow saving generated bots
    if (IsNPCBot() && GetBotAI() && (GetBotAI()->IsWanderer() || IsSummon()))
        return;                    // <-- 【第一行就 return】
```

**只要 bot 还是游荡状态，`SaveToDB` 什么都不做。**

而我 step49 的顺序是：

```
364行  bot->SaveToDB(...)      <- 被拦，spawnId 永远是 0
402行  ai->UnsetWanderer();    <- 太晚了
```

**顺序反了。** 所以：
- `characters_npcbot` 写进去了
- `world.creature` 是空的
- → 就是你遇到的"半永久"死锁

> step60 我只治了"两个指令判断不一致"这个**表象**，
> 没追问"为什么会产生半永久状态"。**这是我的失职。**

## 二、`.pin fix` 导致闪退的根因

`bot_ai.cpp:164`（构造函数初始化列表）：

```cpp
_botData(const_cast<NpcBotData*>(BotDataMgr::SelectNpcBotData(...))),
```

**每个 bot 创建时就把 `NpcBotData*` 缓存进成员变量。**

而我的 `CleanupBroken` 调了：

```cpp
BotDataMgr::UpdateNpcBotData(entry, NPCBOT_UPDATE_ERASE, nullptr);
```

它内部（`botdatamgr.cpp:3118`）：

```cpp
_botsData.erase(bitr);      // unordered_map<uint32, NpcBotData> 存的是【值】
```

**erase 后对象被析构，`bot_ai::_botData` 变野指针。**

```bash
grep -c "_botData->" bot_ai.cpp
# 73
```

**73 处解引用，几乎没有判空** → 招募时一碰就崩。

## 三、「重启后找不到 bot」—— 这个是正常的

`botdatamgr.cpp:210`：

```cpp
bot->LoadBotCreatureFromDB(0, map, true, true, bot_id, &spawnPos);
//                         ^ spawnId=0    ^ generated=true
```

`botdatamgr.cpp:460` 官方注释：

```cpp
//We do not create CreatureData for generated bots
```

**游荡bot是纯内存对象**，每次重启：
1. 上次的全消失
2. 按配置**重新随机生成一批**
3. **entry 可能完全不同**

所以 `Llane (80129)` 重启后不在了，**是游荡bot的正常行为**。

**`.pin` 的意义就是打破这个循环** —— 成功后 bot 写进 `world.creature`，
变成固定生物。但因为错误1，**你从没见过这个效果**。

## 五、改了什么

### 5.1 `.pin` 顺序修正（关键）

```
旧: AddNpcBotData -> SaveToDB(被拦) -> ... -> UnsetWanderer
新: UnsetWanderer -> AddNpcBotData -> SaveToDB(成功) -> ...
```

自检确认：`UnsetWanderer@423行` → `SaveToDB@434行`。

### 5.2 回滚要恢复游荡状态

第1步已经 `UnsetWanderer` 了，如果后续失败必须恢复，
否则 bot 会变成"不游荡也没落库"的孤儿，站着不动直到重启。

```cpp
botAI->SetWanderer();      // bot_ai.cpp:20414，无主bot 的 IAmFree() 为真，能恢复
```

### 5.3 全面禁用 `NPCBOT_UPDATE_ERASE`

**三处**（CleanupBroken / DoUnpin / 回滚）全部改成直接发 SQL：

```cpp
CharacterDatabase.PExecute("DELETE FROM `characters_npcbot` WHERE `entry` = {}", entry);
```

**只删数据库，不动内存** → `_botData` 指针保持有效 → 不崩。

**代价**：要重启才完全生效。**但这比崩服强得多。**

### 5.4 提示语说清楚

`.pin fix` 现在会明确告诉你：

```
已清理数据库里的孤儿记录
内存缓存【故意】不动 —— 动了会让bot_ai的
_botData变野指针，招募时崩服（step62实证）
所以：现在【不要招募这个bot】，先重启服务端
另外：游荡bot本来每次重启就重新洗牌，
这个entry重启后可能就不存在了，属正常现象
```

`.pin status` 对游荡bot也会补一句：

```
提示: 游荡bot每次重启都会重新洗牌，
entry和位置都会变。.pin 成功后才固定。
```

## 七、我的三个错误（已记入坑表）

### 错误1：照抄代码没查调用前提

我 step49 抄 `botcommands.cpp:3860` 的四步，
但**官方那个 `.npcbot spawn` 是对新建bot用的，那种bot不是 wanderer**。

**我换了场景，却没检查 `SaveToDB` 有没有前置条件。**

> **规则：照抄一段代码时，必须查清它的【调用前提】，
> 不能假设换个场景还成立。**

### 错误2：治标不治本

step60 看到"两个指令判断不一致"就去统一判断，
**没追问"谁造成的不一致"**。

> **规则：遇到"状态损坏"，先问【谁造成的】。
> 只做清理工具 = 让用户反复踩。**

### 错误3：删共享数据前没查谁在引用

`_botsData.erase()` 看着无害，
但 `bot_ai.cpp:164` 构造时就缓存了指针。

> **规则：erase/delete 共享容器里的对象之前，
> 必须 grep 谁持有它的指针/引用。**
