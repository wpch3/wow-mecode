## 一、交易：根因 100% 确定

### 你的现象

```text
你对鲤鱼发出交易请求
与[鲤鱼]交易取消: 对方取消了交易。
发送给[鲤鱼]： 与[鲤鱼]交易取消: 对方取消了交易。
（窗口马上关闭）
```

**「对方取消了交易」这句话是决定性证据。**

这不是"被拒绝"（那会显示 BUSY / TARGET_TO_FAR 之类），
而是 **bot 侧主动调用了 `Player::TradeCancel()`**。

### 谁调的 —— 就是我们自己写的代码

我把全仓库 `TradeCancel` 的调用点全查了一遍：

| 位置 | 是不是元凶 |
|---|---|
| `TradeHandler.cpp:69` `HandleIgnoreTradeOpcode` | 否，要客户端点"忽略" |
| `TradeHandler.cpp:74` `HandleBusyTradeOpcode` | 否，要客户端点"正忙" |
| `TradeHandler.cpp:603` `HandleCancelTradeOpcode` | 否，要客户端发包 |
| `Player.cpp:395` `CleanupsBeforeDelete` | 否，`sendback=false` 不发提示 |
| `Player.cpp:21372` `ActivateTaxiPathTo` | 否，坐飞行点才触发 |
| **`pbot_autoaccept.cpp:410-411`（我们的代码）** | **就是它** |

### 元凶原文

`补丁库/02_修复/F11_交易钩子_已解决/源文件/pbot_autoaccept.cpp:410-411`

```cpp
    if (!bot->IsWithinDistInMap(trader, TRADE_DISTANCE, false))
        bot->TradeCancel(true);
```

这是当初为「距离自愈」写的：官方只在发起交易时查一次距离
（`TradeHandler.cpp:704`），之后不查；bot 没客户端不会主动发取消包，
所以你走远了 `m_trade` 会一直挂着，导致下次交易被 `:611` 拦住。

**这个逻辑本身是对的，但它每秒跑一次，一旦条件命中就立刻取消。**

### 为什么你站在旁边也被取消 —— 两个可能，都要排

`IsWithinDistInMap` 的实现（`Object.cpp:1205-1208`）：

```cpp
bool WorldObject::IsWithinDistInMap(WorldObject const* obj, float dist2compare, bool is3D, bool incOwnRadius, bool incTargetRadius) const
{
    return obj && IsInMap(obj) && InSamePhase(obj) && _IsWithinDist(obj, dist2compare, is3D, incOwnRadius, incTargetRadius);
}
```

它查三件事，**任何一件不满足都返回 false**：

| 检查 | 说明 |
|---|---|
| `IsInMap(obj)` | 同一张地图 |
| **`InSamePhase(obj)`** | **相位相同** `(GetPhaseMask() & other) != 0`（`Object.h:385`） |
| `_IsWithinDist` | 距离 < 11.11 码（`ObjectDefines.h:27`） |

**最可能是相位问题。** 实查 `cs_playerbot.cpp`：

```text
:569  come 分支   p->SetPhaseMask(player->GetPhaseMask(), true);   <- 有同步
:636  goto 分支   player->SetPhaseMask(p->GetPhaseMask(), true);   <- 有同步
      spawn 分支  【没有任何相位处理】                              <- 问题在这
```

`.pbot spawn` 走的是官方登录流程（伪造 `CMSG_PLAYER_LOGIN`），
bot 从**它自己上次下线的位置和相位**进世界。
如果它的 `phaseMask` 和你不同（比如你用过 `.phase` 命令，
或它上次下线时在某个任务相位里），`InSamePhase` 永远 false
-> **站一起也会被每秒取消一次**。

## 改动一：距离自愈加宽 + 相位兜底（推荐）

文件：`D:\TrinityCore\src\server\scripts\Custom\pbot_autoaccept.cpp`
（或你实际放的位置）

### 搜索原文

```cpp
    if (!bot->IsWithinDistInMap(trader, TRADE_DISTANCE, false))
        bot->TradeCancel(true);
```

### 替换为

```cpp
    // 只按【纯距离】判断，不掺相位/地图检查。
    // IsWithinDistInMap 内部还查 InSamePhase(Object.cpp:1207)，
    // pbot 用 .pbot spawn 上线时不会同步相位 -> 站一起也判定"太远" -> 秒取消。
    if (bot->GetMapId() != trader->GetMapId())
    {
        bot->TradeCancel(true);
        return;
    }

    float const cancelDist = TRADE_DISTANCE * 3.0f;
    if (bot->GetExactDist2d(trader) > cancelDist)
        bot->TradeCancel(true);
```

### 为什么这样改

| 改动 | 理由 |
|---|---|
| 换成 `GetExactDist2d` | 绕开 `InSamePhase`，只看真实距离 |
| 单独判 `GetMapId()` | 跨地图仍然要取消（原意保留） |
| 阈值放宽到 3 倍（33 码） | 官方 11.11 码是**发起时**的标准；建立后留余量，走两步不至于断 |

需要的 API（已实查）：

```text

Object.h:xxx     uint32 GetMapId() const                                    public
ObjectDefines.h:27  TRADE_DISTANCE = 11.11f
Player.h:1191    void TradeCancel(bool sendback, TradeStatus status = TRADE_STATUS_TRADE_CANCELED)  public(904段)
```

## 改动二：spawn 时同步相位（治本）

文件：`cs_playerbot.cpp`

pbot 上线后相位可能和你不一致，除了交易，还会导致
**互相看不见、buff 加不上、组队功能异常**。

### 在 `come` 分支找到这行（约 569 行）

```cpp
                p->SetPhaseMask(player->GetPhaseMask(), true);         // Object.h:383 public
```

**这行是对的，保留。**

### 问题在 spawn —— 它是异步登录，当场设不了

`.pbot spawn` 只是把登录包塞进队列（`cs_playerbot.cpp:297`），
bot 要 1-3 秒后才真正进世界，那时候命令函数早就返回了。

**所以要在 `pbot_autoaccept.cpp` 的每秒循环里补一次。**

搜索原文（OnUpdate 里的循环体）：

```cpp
            if (e.AutoFlags & PBOT_AUTO_GROUP)      TryAcceptGroup(bot);
```

在它**前面**插入：

```cpp
            // pbot 用官方登录流程上线，会沿用上次下线时的相位。
            // 相位不一致会导致：互相看不见 / 交易被判定"太远" / buff加不上。
            // 有队伍时以队长相位为准，没队伍时不动（尊重 GM 手动设的相位）。
            if (Group* pgrp = bot->GetGroup())
            {
                if (Player* leader = ObjectAccessor::FindPlayer(pgrp->GetLeaderGUID()))
                {
                    if (leader != bot && bot->GetPhaseMask() != leader->GetPhaseMask())
                        bot->SetPhaseMask(leader->GetPhaseMask(), true);
                }
            }
```

需要的 API（已实查）：

```text
Group.h:228   ObjectGuid GetLeaderGUID() const     public(185段)
Object.h:383  void SetPhaseMask(uint32, bool)      public
Object.h:382  uint32 GetPhaseMask() const          public
```

## 二、组队UI移除 —— 钩子没断，是业务逻辑拦的

### 你的疑问是对的方向，但结论相反

我查了 opcode 注册表（`Opcodes.cpp:248-249`）：

```text
/*0x075*/ CMSG_GROUP_UNINVITE       -> WorldSession::HandleGroupUninviteOpcode
/*0x076*/ CMSG_GROUP_UNINVITE_GUID  -> WorldSession::HandleGroupUninviteGuidOpcode
```

**两个都正常注册着，钩子完全没断。** 客户端点「移出小队」，
包能收到、handler 能进、代码能跑到。

### 真正拦住的是这一行

`Player.cpp:24268-24269`，在 `CanUninviteFromGroup()` 里：

```cpp
if (grp->IsLeader(guidMember))
    return ERR_NOT_LEADER;
```

调用链：

```text
客户端点「移出小队」
  -> CMSG_GROUP_UNINVITE_GUID
  -> HandleGroupUninviteGuidOpcode        (GroupHandler.cpp:295)
  -> CanUninviteFromGroup(guid)           (GroupHandler.cpp:312)
  -> Player.cpp:24268 目标是队长 -> ERR_NOT_LEADER
  -> SendPartyResult(...)                 (GroupHandler.cpp:315)  提示很不显眼
  -> return，不执行踢出
```

**所以"UI 不能完美复现"的原因不是钩子缺失，
而是上游规定「队长不能被踢」，而你的 pbot 恰好是队长。**

这跟真人玩家完全一致 —— 你也踢不掉一个真人队长。

### 验证方法

看队伍面板里 bot 名字旁边**有没有王冠图标**。有王冠 = 它是队长 = 踢不掉。

### 三种解法

**A. 手动（现在就能用）**

```text
右键 bot 头像 -> 「提升为队长」把队长要回来 -> 再右键 bot -> 移出小队
```

但 bot 是队长时你没有「提升为队长」的权限，所以实际要：

```text
右键【你自己】头像 -> 退出小队    （队伍解散，bot 自然脱离）
```

**B. 加 `.pbot kick` 指令**（F25 文档里已给，先转队长再踢）

**C. 治本：不让 bot 当队长**

在 `TryAcceptGroup` 接受邀请后，主动把队长让回邀请人：

```cpp
            // bot 不该当队长：会导致踢不掉、改不了副本难度、转不了团队
            if (Group* g = bot->GetGroup())
                if (g->IsLeader(bot->GetGUID()))
                    if (Player* inviter = ObjectAccessor::FindPlayer(_pbotInviter[bot->GetGUID()]))
                        g->ChangeLeader(inviter->GetGUID());
```

> C 需要知道"是谁邀请的"，你的 `TryAcceptGroup` 里应该有这个信息。

## 五、这次的教训

**「对方取消了交易」和「对方拒绝交易」是两回事。**

我前一轮把整个 `HandleInitiateTradeOpcode` 的 14 个拒绝点都列了出来，
方向全错 —— 因为那些是**拒绝**（不建立交易），
而你的现象是**先建立、再被取消**。

一个字的差别，指向完全不同的代码路径。
下次拿到日志原文我会先分辨"拒绝/取消/超时"这三类词。
