## 三、改 `bot_ai.cpp`（加 1 个函数）

**Ctrl+F 搜**（`bot_ai.cpp:19054`）：

```cpp
void bot_ai::GetHomePosition(uint16& mapid, Position* pos) const
```

这个函数完整长这样：

```cpp
void bot_ai::GetHomePosition(uint16& mapid, Position* pos) const
{
    if (IsWanderer())
    {
        mapid = _travel_node_cur->GetMapId();
        pos->Relocate(homepos);
    }
    else
    {
        CreatureData const* data = me->GetCreatureData();
        mapid = data->mapId;
        pos->Relocate(data->spawnPoint);
    }
}
```

**在这个函数的结尾 `}` 后面，粘贴下面整段**：

```cpp

// step37: 把游荡bot的"家"重设到当前位置
//
// 背景：游荡bot的"家"是 _travel_node_cur（当前目标路点），不是出生点。
//       用 GM 指令把它传送过来后，它会发现自己离目标路点极远
//       （bot_ai.cpp:18632 的 MAX_WANDER_NODE_DISTANCE 判定），
//       于是念炉石 WANDERER_HEARTHSTONE（10秒读条）传回去。
//       读条期间 IsCasting()==true，被 bot_ai.cpp:7704 拦截，无法对话。
//
// 返回：true = 成功重设；false = 不是游荡bot（无需处理）
bool bot_ai::ResetWanderHomeToCurrent()
{
    if (!IsWanderer())
        return false;

    // 找离当前位置最近的路点。
    // 找不到就保持原样，绝不置空 —— GetHomePosition 会直接解引用它，置空会崩。
    if (WanderNode const* node = GetClosestWanderNode())
        _travel_node_cur = node;

    // 把"家"挪到脚下。GetHomePosition 对游荡bot返回的就是 homepos
    homepos.Relocate(me);

    // 清掉 evade 状态，否则 _evadeCount >= 50 那条依然会触发炉石
    _evadeCount = 0;
    evadeDelayTimer = 0;

    // 正在念炉石就打断
    if (me->HasUnitState(UNIT_STATE_CASTING))
        me->InterruptNonMeleeSpells(true);

    return true;
}
```

### 为什么必须写在 bot_ai.cpp 里

这个函数用到 4 个 **private** 成员，只有类的成员函数能访问：

```
bot_ai.h:765   _travel_node_cur   private(590)
bot_ai.h:697   homepos            private(590)
bot_ai.h:738   _evadeCount        private(590)
bot_ai.h:723   evadeDelayTimer    private(590)
```

**在 scripts 里绕不过去，这就是解法A必须改上游的原因。**

## 五、新指令 `.tome`

```
.tome            传送【自己】到最近的游荡bot身边
.tome <entry>    传送到指定entry的bot（全服范围找）
```

### 和 `.bf come` 的区别

| 指令 | 谁移动 | 风险 |
|---|---|---|
| `.bf come` | **bot 移动** | 会改变bot状态，需要 step37 的修复配合 |
| `.tome` | **你移动** | **完全不碰bot**，最安全 |

**教训**：测试工具不该改变被测对象的状态。
`.tome` 是"移动观察者"，比"移动被观察者"干净。
