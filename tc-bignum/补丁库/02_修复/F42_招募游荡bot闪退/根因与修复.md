## 二、完整因果链

```
你招募游荡bot
  -> bot_ai.cpp:281 SetBotOwner() 执行
  -> :303 AddBot() 成功，:318 master = newowner
  -> 【但全程没有清 _wanderer 标记】

  -> 但招募时路点已经被清空/失效 -> nullptr
```

### 改动2【兜底】· GetHomePosition 判空

搜索原文（`:19054-19067`，全文件唯一）：

```cpp
void bot_ai::GetHomePosition(uint16& mapid, Position* pos) const
{
    if (IsWanderer())
    {
        mapid = _travel_node_cur->GetMapId();
        pos->Relocate(homepos);
    }
    else
    {
        CreatureData const* data = me->GetCreatureData();
        mapid = data->mapId;
        pos->Relocate(data->spawnPoint);
    }
}
```

替换为：

```cpp
void bot_ai::GetHomePosition(uint16& mapid, Position* pos) const
{
    // F42: _travel_node_cur 是裸指针且无判空（bot_ai.h:765）。
    //   招募/解散/路点重置等时机它可能为空，
    //   原版直接解引用 -> 崩。这里加兜底。
    if (IsWanderer() && _travel_node_cur)
    {
        mapid = _travel_node_cur->GetMapId();
        pos->Relocate(homepos);
        return;
    }

    if (CreatureData const* data = me->GetCreatureData())
    {
        mapid = data->mapId;
        pos->Relocate(data->spawnPoint);
        return;
    }

    // 两者都没有：用当前位置兜底，绝不解引用空指针
    mapid = uint16(me->GetMapId());
    pos->Relocate(me);
}
```

> **为什么 `GetCreatureData()` 也要判空**：
> 游荡bot **没有 creature 表记录**（`botdatamgr.cpp:452` 官方注释
> "We do not create CreatureData for generated bots"），
> 所以原版 else 分支对游荡bot 同样会空指针。
> 改动1 生效后 bot 不再是 wanderer，就会走进这个 else —— **必须一起防**。

## 四、为什么两处都要做

| 只做改动1 | 只做改动2 | 两个都做 |
|---|---|---|
| 招募路径修好 | 不崩了，但 bot 保持 wanderer 混合态 | **推荐** |
| 但别的路径（解散/传送）仍可能空指针 | 行为可能仍不正常 | 治本+兜底 |

`GetHomePosition` 有 **4 个调用点**（`:5977 / :18627 / :18922 / :18944`），
改动2 一次保护全部。
