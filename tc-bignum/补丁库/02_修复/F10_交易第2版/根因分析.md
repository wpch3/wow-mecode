## 一、交易窗口：我删掉的正是弹窗那行

### 1.1 先看官方源码：交易建立时，包发给【谁】

`TradeHandler.cpp:723-729`（`HandleInitiateTradeOpcode` 结尾）：

```cpp
    // OK start trade
    _player->m_trade = new TradeData(_player, pOther);
    pOther->m_trade = new TradeData(pOther, _player);

    info.Status = TRADE_STATUS_BEGIN_TRADE;
    info.TraderGuid = _player->GetGUID();
    pOther->GetSession()->SendTradeStatus(info);      // <-- 【看这里】
}
```

**注意最后一行：`pOther->GetSession()`。**

- `_player` = **发起交易的人** = **你**
- `pOther`  = **被交易的人** = **bot**

**`BEGIN_TRADE` 这个包是发给 `pOther`（bot）的，不是发给你的！**

### 1.2 我 step53 的错误推理

我当时写：

> 「你这边的窗口是 `HandleInitiateTradeOpcode` 直接发给你的，
> 和 bot 一点关系都没有」

**这句话是错的。** 我看到 `HandleInitiateTradeOpcode` 里有 `BEGIN_TRADE`，
就想当然认为是发给发起人的，**没看清收包的是 `pOther`**。

这正是坑表里那条「只看函数名就用，没追包的流向」——
**我第三次踩同一个坑，这次是没看清收包对象。**

### 1.3 所以真实流程是这样的

```
你右键 bot -> 交易
  |
  v
HandleInitiateTradeOpcode (TradeHandler.cpp:606)
  |
  +-- :724  _player->m_trade = new TradeData(...)    你的交易数据建立
  +-- :725  pOther->m_trade  = new TradeData(...)    bot的交易数据建立
  |
  +-- :729  给【bot】发 BEGIN_TRADE                   bot没客户端，包被丢弃
  |         (WorldSession.cpp:211  if (!m_Socket) return;)
  |
  v
【你这边什么包都没收到】-> 没有窗口
【但双方 m_trade 已经建立了】-> 再点交易时被 :611 拦下
```

`TradeHandler.cpp:611`：

```cpp
    if (GetPlayer()->m_trade)
        return;                    // <- 你第二次点交易，卡在这里
```

**这就是你说的「再次点击交易也只是说我已经在交易了」** ——
你的 `m_trade` 还挂着，但窗口从来没出现过。

### 1.4 那 `HandleBeginTradeOpcode` 到底干嘛的

`TradeHandler.cpp:577`：

```cpp
void WorldSession::HandleBeginTradeOpcode(WorldPacket& /*recvPacket*/)
{
    TradeData* my_trade = _player->m_trade;
    if (!my_trade)
        return;

    TradeStatusInfo info;
    info.Status = TRADE_STATUS_OPEN_WINDOW;
    my_trade->GetTrader()->GetSession()->SendTradeStatus(info);   // 给对方发
    SendTradeStatus(info);                                        // 给自己发
}
```

**真人流程是这样的**：

```
玩家A 发起交易
  -> 核心给 玩家B 发 BEGIN_TRADE
  -> 玩家B 的客户端【弹出"XXX想和你交易"提示】
  -> 玩家B 点【接受】
  -> 玩家B 的客户端发 CMSG_BEGIN_TRADE
  -> HandleBeginTradeOpcode 给【双方】发 OPEN_WINDOW
  -> 【两边的交易窗口这才真正打开】
```

**关键**：`OPEN_WINDOW` 才是真正打开窗口的包，而且是**发给双方的**。

我 step53 说「OPEN_WINDOW 只有个0，客户端不知道弹什么」—— **也是错的**。
`uint32(0)` 是 `m_tradeID`（见 `TradeHandler.cpp:49` 的注释
`// CGTradeInfo::m_tradeID`），客户端此时已经知道交易对象是谁了
（`BEGIN_TRADE` 里给过 `TraderGuid`），不需要再给一遍。

### 1.5 所以 step42 原来的做法【是对的】

原来的 `TryAcceptTrade` 做的事：

```cpp
WorldPacket dummy(CMSG_BEGIN_TRADE, 0);
bot->GetSession()->HandleBeginTradeOpcode(dummy);
```

**这相当于替 bot 点了那个「接受交易」按钮**，
让核心给双方发 `OPEN_WINDOW`，**你的窗口就会打开**。

**我 step53 把它注释掉 = 把 bot 的"接受"按钮拆了。**

> 那为什么你 step53 之前也说过窗口不显示？
> 因为 `PBOT_AUTO_TRADE` **默认是关的**（`pbot_autoaccept.h:42`
> `PBOT_AUTO_DEFAULT` 里没有它）。你当时没开这个开关，
> 所以 `TryAcceptTrade` 根本没被调用过。
> **我却把"没开开关"误判成"实现错误"，然后把对的代码删了。**

### 1.6 修复方案

**两步**：

1. **把 `TryAcceptTrade` 的调用恢复回来**（撤销 step53 的注释）
2. **把交易加进默认开关**，省得你还要手动开

另外补两个 step42 原版没有的保护：

- **卡死自愈**：如果 bot 的 `m_trade` 存在但超过 60 秒没进展，
  自动 `TradeCancel` 清理，避免"你的 m_trade 挂着但窗口没出来"的死锁
- **距离检查**：`TRADE_DISTANCE` 之外自动取消（防止你走远了交易还挂着）

## 二、party1 刷屏：客户端在替你踢 bot，但按名字找不到

### 2.1 那句话是什么

「party1 不在你的队伍中」= `ERR_TARGET_NOT_IN_GROUP_S`

全服只有**两处**会发它（实查）：

```
GroupHandler.cpp:335   HandleGroupUninviteGuidOpcode 结尾
GroupHandler.cpp:381   HandleGroupUninviteOpcode 结尾
```

**两个都是"踢人"的处理函数。**

### 2.2 关键：`party1` 不是名字，是客户端的【单位ID】

`party1` / `party2` / `party3` / `party4` 是魔兽客户端的
**UnitID（单位标识符）**，代表"队伍中的第1/2/3/4个成员"。

你的客户端（或某个插件）在调用类似
`UninviteUnit("party1")` 的 API，
它会发 `CMSG_GROUP_UNINVITE` 包，**包里带的字符串就是 `party1`**。

### 2.3 服务端拿这个字符串去按名字找人 -> 找不到

`GroupHandler.cpp:340` `HandleGroupUninviteOpcode`：

```cpp
    std::string membername;
    recvData >> membername;              // <- 收到 "party1"

    if (!normalizePlayerName(membername))
        return;

    ...

    ObjectGuid guid = grp->GetMemberGUID(membername);   // <- 按【名字】找
    if (!guid.IsEmpty())
    {
        Player::RemoveFromGroup(...);
        return;
    }

    if (Player* player = grp->GetInvited(guid))
    {
        player->UninviteFromGroup();
        return;
    }

    SendPartyResult(PARTY_OP_UNINVITE, membername, ERR_TARGET_NOT_IN_GROUP_S);
    //                                 ^^^^^^^^^^ 把 "party1" 原样回给你
}
```

`Group.cpp:2854 GetMemberGUID`：

```cpp
ObjectGuid Group::GetMemberGUID(const std::string& name)
{
    for (member_citerator itr = m_memberSlots.begin(); itr != m_memberSlots.end(); ++itr)
        if (itr->name == name)          // <- 拿 "party1" 和真实名字比
            return itr->guid;
    return ObjectGuid::Empty;           // <- 当然找不到
}
```

队伍里存的是 `鲤鱼` / `Bot战士` 这种真名，
拿 `party1` 去比对**永远不匹配** -> 走到最后一行 -> 报「party1不在你的队伍中」。

### 2.4 为什么"每个ID刷两次"、"连续刷几次"

你说的现象：

```
party1不在你的队伍中
party1不在你的队伍中      <- 同一个ID两次
party2不在你的队伍中
party2不在你的队伍中
...
```

**两次**的原因：客户端有**两个** uninvite 相关的 opcode
（`CMSG_GROUP_UNINVITE` 按名字 / `CMSG_GROUP_UNINVITE_GUID` 按GUID），
某些插件会两个都发一遍。

**连续刷 party1~party4**：说明有东西在**遍历整个队伍**做批量踢人，
一次循环 4 个位置。

### 2.5 这是谁干的？三个可能，需要你确认

| 可能来源 | 判断方法 |
|---|---|
| **A. 客户端插件**（最可能） | 关掉所有插件（`Interface\AddOns` 改名），看还刷不刷 |
| **B. 某个 npcbot 指令** | 刷屏前你做了什么操作？是不是刚用过 `.npcbot` 相关指令 |
| **C. 服务端 npcbot 模块自己发的** | 我已实查：npcbot 模块**不调用** `SendPartyResult`，排除 |

**C 已经排除了**（grep 全仓库，`SendPartyResult` 只在 `GroupHandler.cpp` 里被调用）。

所以是 **A 或 B**，需要你配合定位。

### 2.6 不管是谁干的，服务端都可以【止血】

即使找不到源头，我们也能让这个提示不再刷屏。**两个方案**：

**方案1（推荐）：识别 UnitID，静默忽略**

在 `HandleGroupUninviteOpcode` 开头加一个判断：
如果名字是 `party1`~`party4` / `raid1`~`raid40` / `target` / `focus`
这类客户端保留字，**直接 return，不回包**。

- 优点：治本，一劳永逸
- 缺点：要改上游文件 `GroupHandler.cpp`
- 风险：**极低**，只是多一个 early return

**方案2：把 UnitID 翻译成真实成员**

`party1` -> 队伍里第1个非自己的成员，然后正常踢。

- 优点：让这个操作**真的能用**
- 缺点：**危险** —— 万一是插件误发，会真的把 bot 踢出队
- **不推荐**

> **我的建议：方案1。** 那个操作本来就是无效的（客户端发错了），
> 静默忽略是最安全的。
