## 二、真因

```cpp
// botmgr.cpp:805
if (_owner->GetSession()->PlayerLogout() && bot->IsInGrid() && bot->FindMap() && bot->FindMap()->GetEntry()->Instanceable())
    bot->FindMap()->RemoveFromMap(bot, false);
//                    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//                    判了 FindMap() 非空，却没判 GetEntry() 非空
```

### 三个问题叠在一起

**问题1：`GetEntry()` 可能返回 nullptr，没判空**

```cpp
// Map.h
MapEntry const* GetEntry() const { return i_mapEntry; }
```

`i_mapEntry` 来自 DBC 查询，**地图正在销毁或 DBC 里没这条记录时会是空**。
空指针上调 `->Instanceable()` -> 访问违例。

**问题2：`FindMap()` 被调了 3 次**

```cpp
bot->FindMap() && bot->FindMap()->GetEntry()->Instanceable()
bot->FindMap()->RemoveFromMap(bot, false);
```

第一次判空为真，**但第二、三次调用之间 bot 的 map 可能已经变了**
（登出流程里对象状态在快速变化）。

**问题3：这行只在 `PlayerLogout()` 时执行**

```
你退出到选角色  -> 触发 RemoveBot -> 走到 :805
                -> 此时 bot 的 map 正在销毁
                -> GetEntry() 返回空 -> 崩
```

**这完美解释了你的现象**：
- 退出到选角色界面「没问题」 —— 崩溃发生在服务端，客户端还没感知
- 进另一个角色才闪退 —— 服务端已经崩了，客户端连不上就被踢

**跟"另一个账户有没有 npcbot"无关。**

---

## 三、修复

**文件**：`D:\TrinityCore\src\server\game\AI\NpcBots\botmgr.cpp`

搜索原文（`:805-806`，全文件唯一）：

```cpp
    if (_owner->GetSession()->PlayerLogout() && bot->IsInGrid() && bot->FindMap() && bot->FindMap()->GetEntry()->Instanceable())
        bot->FindMap()->RemoveFromMap(bot, false);
```

替换为：

```cpp
    // F38: 原版有三个隐患，都在玩家登出这条路径上：
    //   1. GetEntry() 可能返回 nullptr（地图正在销毁时），没判空 -> 崩
    //   2. FindMap() 被调用 3 次，期间 bot 的 map 可能变化
    //   3. 这行只在 PlayerLogout() 时走，所以平时测不出来，
    //      表现为"退出到选角色没事，进另一个角色就闪退"
    //   修法：只取一次 map，逐层判空。
    if (_owner->GetSession()->PlayerLogout() && bot->IsInGrid())
    {
        if (Map* botMap = bot->FindMap())
        {
            MapEntry const* mapEntry = botMap->GetEntry();
            if (mapEntry && mapEntry->Instanceable())
                botMap->RemoveFromMap(bot, false);
        }
    }
```

**改动要点**：
- `FindMap()` 只调一次，存进 `botMap`
- `GetEntry()` 的结果判空后再用
- 逻辑语义和原版完全一致，只是加了防护
