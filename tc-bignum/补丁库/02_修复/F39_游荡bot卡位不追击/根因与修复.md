# F39 · 游荡bot 索敌卡位、不向怪物移动

> 2026-08-09
> 用户：「同步修复游荡bot索敌卡位置无法移动的问题，
> 让他们可以察觉并调整位置到怪物身前」

---

## 一、真因：游荡bot 走到了一条"没有移动指令"的分支

```cpp
// bot_ai.cpp:18342  —— 这个 if 游荡bot 一定进得来
if ((IsWanderer() || ...) && !HasBotCommandState(BOT_COMMAND_STAY) && ...)
{
    Unit const* mover = me->GetVehicle() ? me->GetVehicleBase() : me;

    if (!master->IsAlive())          // :18348  <- 见下方【严重隐患】
    { ... 跟随主人尸体 ... }
    else if (!IsCasting(mover) && ...)
    {
        Unit const* mmover = !IAmFree() ? master : nullptr;   // :18367
        //                   ^^^^^^^^^^ 游荡bot 是自由身 -> mmover = nullptr

        if (!mmover && me->GetMap()->IsBattleground() && GetBG())
        {
            ... 战场专用逻辑：抢旗、跟旗手 ...
        }

        // 【关键】非战场时 mmover 一直是 nullptr，
        //         下面的移动逻辑全都不执行 -> bot 站着不动
    }
}
```

**翻译**：这一整块是给"有主人的bot"和"战场bot"写的。
野外的游荡bot 两个条件都不满足，**拿不到任何移动目标**。

### 为什么它还能打怪

它能自动攻击、能放技能（那是另一套逻辑），
**但不会为了打怪而移动位置** —— 所以怪在远处它就干站着，
或者被地形卡住后再也调整不过来。

---

## 二、【顺带发现】一个崩溃隐患

```cpp
// bot_ai.cpp:18348
if (!master->IsAlive())
```

游荡bot 的 master 指向它自己：

```cpp
// bot_ai.cpp:460
master = reinterpret_cast<Player*>(me);      // 把 Creature 强转成 Player*
```

**在这个指针上调 `IsAlive()` 是未定义行为** —— 读的是错位的 vtable。

F05 补丁曾经加过一个 `HasRealMaster()` 来防这个，
但我实查你的 `bot_ai.h`，**这个函数不存在** —— 说明那个补丁没装上，
或者被后来的文件覆盖了。

**这条一起修。**

---

## 三、修复（两处）

**文件**：`D:\TrinityCore\src\server\game\AI\NpcBots\bot_ai.cpp`

### 改动1 · 防止假 master 解引用

搜索原文（`:18346-18348`）：

```cpp
        Unit const* mover = me->GetVehicle() ? me->GetVehicleBase() : me;

        if (!master->IsAlive())
```

替换为：

```cpp
        Unit const* mover = me->GetVehicle() ? me->GetVehicleBase() : me;

        // F39: 游荡bot 的 master 指向它自己（bot_ai.cpp:460 强转），
        //   在上面调 IsAlive() 是未定义行为（读错位 vtable）。
        //   先确认是真人主人再解引用。
        bool const hasRealMaster =
            reinterpret_cast<void const*>(master) != reinterpret_cast<void const*>(me) &&
            master->IsPlayer();

        if (hasRealMaster && !master->IsAlive())
```

### 改动2 · 让游荡bot 追击目标

搜索原文（`:18367`）：

```cpp
            Unit const* mmover = !IAmFree() ? master : nullptr;
```

替换为：

```cpp
            Unit const* mmover = !IAmFree() ? master : nullptr;

            // F39: 游荡bot 是自由身，mmover 恒为 nullptr，
            //   导致非战场情况下拿不到任何移动目标 -> 看见怪也不上前。
            //   这里给它一个目标：正在打的那个敌人。
            if (!mmover && IsWanderer() && me->IsInCombat())
            {
                if (Unit* victim = me->GetVictim())
                {
                    // 近战：贴到 1.5 码内；远程：保持在 25 码内
                    float const wantDist = HasRole(BOT_ROLE_RANGED) ? 25.0f : 1.5f;
                    if (me->GetDistance(victim) > wantDist)
                        GetInPosition(true, victim);
                }
            }
```

---

## 四、为什么这样改是安全的

| 顾虑 | 说明 |
|---|---|
| 会不会影响有主人的bot | 不会。`!mmover && IsWanderer()` 双重条件，有主人的走不到 |
| 会不会影响战场bot | 不会。战场那块在上面先执行，会给 mmover 赋值 |
| 会不会和路点游走打架 | 不会。加了 `me->IsInCombat()`，只在战斗中生效 |
| `GetInPosition` 安全吗 | 安全。`:18304` 上游自己就这么调 |

**`GetInPosition(true, victim)` 是上游现成的函数**，
`bot_ai.cpp:18304` 在非游荡bot 分支里用的就是它。

## 六、如果还是不动

可能是被 `BOT_COMMAND_STAY` 或 evade 状态卡住。插探针：

```cpp
// 在改动2 的 if 里面加
TC_LOG_ERROR("scripts", "F39: {} inCombat={} victim={} dist={}",
    me->GetName(), me->IsInCombat(),
    me->GetVictim() ? me->GetVictim()->GetName() : "NONE",
    me->GetVictim() ? me->GetDistance(me->GetVictim()) : -1.f);
```

`victim=NONE` -> 说明它根本没锁定目标，问题在索敌不在移动。
