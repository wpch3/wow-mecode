## 二、公会「要求签名」灰色 —— 【我没做这功能，不是坏了】

### 2.1 「公会邀请」和「请愿书签名」是两条完全不同的路

你点的是**请愿书（Petition）签名**，不是公会邀请。

| | 公会邀请 | 请愿书签名 |
|---|---|---|
| 怎么触发 | `.guild invite` / 公会面板 | 买请愿书 -> 右键 -> 点目标 |
| 服务端留状态吗 | **留**：`SetGuildIdInvited(m_id)` | **不留** |
| 能轮询吗 | **能**（step42 做的就是这个） | **不能** |
| step42 做了吗 | 做了 | **没做** |

### 2.2 为什么「不留状态」就没法轮询

实查 `src/server/game/Handlers/PetitionsHandler.cpp`：

```cpp
// :513  玩家把请愿书递给目标
void WorldSession::HandleOfferPetitionOpcode(WorldPacket& recvData)
{
    ...
    Player* player = ObjectAccessor::FindConnectedPlayer(offererGuid);
    if (!player)
        return;
    // 一堆检查后，【给目标发个包】，然后函数就结束了
    // 服务端【没有任何字段】记下"这个人正被要求签名"
}
```

```cpp
// :383  目标点"签名"时才走这里
void WorldSession::HandleSignPetition(WorldPacket& recvData)
{
    recvData >> petitionGuid;    // <- 这个 GUID 只存在于【发给客户端的包】里
    recvData >> unk;
}
```

**关键**：那个 `petitionGuid` **只在包里**，服务端不存。

bot 没有客户端，包在这里被丢掉：

```cpp
// WorldSession.cpp:211
void WorldSession::SendPacket(WorldPacket const* packet, bool forced)
{
    if (!m_Socket)
        return;              // <- bot 无 socket，包直接扔了
}
```

-> **bot 永远不知道有人要它签名** -> 永远不回 `SMSG_PETITION_SIGN_RESULTS`
-> **你的按钮就一直灰着**。

**灰色不是 bug，是客户端在等一个永远不会来的回复。**

### 2.3 能做，但必须用【钩子】，要改上游文件

轮询这条路是死的（没状态可轮）。
唯一的路是：**在核心给 bot 发包之前截住它，直接让 bot 签**。

插入点已实查确认：`PetitionsHandler.cpp:513`，在 `if (!player) return;` 下面。

**这个我下一步做**，但按你定的规矩「一次只让一条线处于未验证状态」，
先等交易那条验完。

## 三、NPCBot 改名只生效一半 —— 【这是真 bug，我 step43 漏了 2 层】

这个是我的实现问题，我把三个地方的名字来源全查清楚了。

### 3.1 一个 NPCBot 的名字，客户端有【三个】来源

| 显示位置 | 名字从哪来 | 我 step43 处理了吗 |
|---|---|---|
| **聊天栏** | `Creature::GetName()` -> 内存 `m_name` | **处理了**（`sel->SetName()`）|
| **头顶名字** | `CreatureTemplate::QueryData[locale]` **缓存包** | **漏了** |
| **队伍窗口** | `Group::MemberSlot::name` **快照** | **漏了** |

这就是为什么「只有聊天栏对」。

### 3.2 头顶名字：卡在 QueryData 预生成缓存

实查 `game/Handlers/QueryHandler.cpp:119`：

```cpp
void WorldSession::HandleCreatureQueryOpcode(WorldPackets::Query::QueryCreature& query)
{
    if (CreatureTemplate const* ci = sObjectMgr->GetCreatureTemplate(query.CreatureID))
    {
        if (sWorld->getBoolConfig(CONFIG_CACHE_DATA_QUERIES))
            SendPacket(&ci->QueryData[static_cast<uint32>(GetSessionDbLocaleIndex())]);
            //          ^^^^^^^^^^^^ 【发的是预生成的缓存包，不是实时查的】
        else
        {
            WorldPacket response = ci->BuildQueryData(GetSessionDbLocaleIndex());
            SendPacket(&response);
        }
    }
}
```

而 `CacheDataQueries` **默认是开的**：

```cpp
// World.cpp:1586
m_bool_configs[CONFIG_CACHE_DATA_QUERIES] = sConfigMgr->GetBoolDefault("CacheDataQueries", true);
//                                                                                          ^^^^
```

`QueryData` 里存的名字是 **服务器启动时** 生成的（Creature.cpp:190 `BuildQueryData`）：

```cpp
std::string locName = Name, locTitle = Title;
if (CreatureLocale const* cl = sObjectMgr->GetCreatureLocale(Entry))
{
    ObjectMgr::GetLocaleString(cl->Name, loc, locName);   // 中文名在这里被烤进缓存
    ...
}
queryTemp.Stats.Name = locName;
```

**我 step43 只调了 `sObjectMgr->LoadCreatureLocales()`**（cs_botrename.cpp:337）
—— 它只更新了 `CreatureLocale` 这张表在内存里的副本，
**没有重新烤 QueryData 缓存包**。

于是客户端拿到的还是启动时烤好的旧名字。

### 3.3 实证：官方两条 reload 指令的差别

```cpp
// cs_reload.cpp:453  .reload creature_template <entry>
            sObjectMgr->LoadCreatureTemplate(fields);
            sObjectMgr->CheckCreatureTemplate(cInfo);
        }
        sObjectMgr->InitializeQueriesData(QUERY_DATA_CREATURES);   // <- 【重烤缓存】
```

```cpp
// cs_reload.cpp:1005  .reload creature_template_locale
        sObjectMgr->LoadCreatureLocales();
        handler->SendGlobalGMSysMessage("DB table `creature_template_locale` reloaded.");
        return true;                                               // <- 【不重烤！】
```

**官方自己的 `.reload creature_template_locale` 也有这个问题** ——
改完 locale 不重启就是不生效。这不是你的错，是核心的设计。

修法就是在改完中文名后**手动调一次** `InitializeQueriesData(QUERY_DATA_CREATURES)`。

已核实签名（`ObjectMgr.h:1241`）：

```cpp
void InitializeQueriesData(QueryDataGroup mask);
```

枚举（`ObjectMgr.h:925-934`）：

```cpp
enum QueryDataGroup
{
    QUERY_DATA_CREATURES        = 0x01,
    ...
};
```

### 3.4 队伍窗口：名字是【加入队伍那一刻的快照】

实查 `game/Groups/Group.cpp`，队伍成员名有两个来源：

```cpp
// :491  bot 现场加入队伍时
MemberSlot member;
member.guid      = creature->GetGUID();
member.name      = creature->GetName();      // <- 【拷贝一份，存下来】
```

```cpp
// :347  服务器重启后从库里恢复队伍时
CreatureTemplate const* ct = sObjectMgr->GetCreatureTemplate(entry);
member.name = ct->Name;                      // <- 用的是【英文默认名】，不是中文locale名
```

发包时直接用这个快照，**不会实时去查**：

```cpp
// :2049
data << citr->name;      // <- 用的是存下来的那份
```

**两个后果**：

1. bot 已经在队里时改名 -> `MemberSlot::name` 不变 -> 队伍窗口还是旧名
2. `Group.cpp:347` 用的是 `ct->Name`（英文名），**根本不看中文 locale**
   -> 重启后从库恢复的队伍，bot 名字会变回英文

> 第 2 条是上游 NPCBot 模块自己的设计。要彻底解决得改 `Group.cpp:347`，
> 让它走 `GetNameForLocaleIdx`。这个我列进修复方案备选，但**风险更高**
> （动上游队伍代码），先用「踢出重加」的低风险办法。
