## 问题1：`Logger.spells.aura.effect.nospell=0` 没生效

### 根因：我给的配置**格式不完整**，被静默丢弃

实证 `src/common/Logging/Log.cpp:137-143`：

```cpp
std::vector<std::string_view> tokens = Trinity::Tokenize(options, ',', true);

if (tokens.size() != 2)
{
    fprintf(stderr, "Log::CreateLoggerFromConfig: Wrong config option Logger.%s=%s\n", ...);
    return;                    // <-- 【直接丢弃这个logger配置】
}
```

**`Logger.xxx=` 后面必须是【两段】，用逗号分隔**：

```
Logger.名字 = 级别 , appender列表
```

我给你的是：

```ini
Logger.spells.aura.effect.nospell=0        <- 只有1段，被丢弃
```

**正确写法**：

```ini
Logger.spells.aura.effect.nospell=0,Console
```

> 级别填 0（DISABLED）时 appender 其实用不上，
> 但解析器**强制要求两段**，必须写。

### 那条日志是什么

`SpellAuraEffects.cpp:5050-5056`：

```cpp
void AuraEffect::HandlePeriodicTriggerSpellAuraTick(Unit* target, Unit* caster) const
{
    uint32 triggerSpellId = GetSpellEffectInfo().TriggerSpell;
    if (triggerSpellId == 0)
    {
        TC_LOG_WARN("spells.aura.effect.nospell", "... Spell {} [EffectIndex: {}] does not have triggered spell.", ...);
        return;
    }
```

**Spell 768 是德鲁伊「猎豹形态」**。它的 EffectIndex 2 在 DBC 里
没有配 TriggerSpell，核心每次周期触发都报一次 WARN。

**这是数据问题不是bug**，关掉日志即可，不影响功能。

### 改法

先确认你现在写的那行长什么样：

```bash
grep -n "spells.aura.effect.nospell" worldserver.conf
```

- 如果输出 `Logger.spells.aura.effect.nospell=0` -> **把那行改成下面这样**
- 如果没输出 -> 直接加

```ini
Logger.spells.aura.effect.nospell=0,Console
```

**是改不是加**（重复键会闪退）。

## 问题2：A36 的 SQL 生效 0 个

### 根因：`world.creature` 表里**根本没有 70001/70002**

A36 的 SQL 是：

```sql
UPDATE `world`.`creature` SET `ScriptName` = 'wanderer' WHERE `id` BETWEEN ...
       ^^^^^^^^^^^^^^^^^^
       只能改【已经存在于 creature 表】的行
```

而 70001/70002 是**游荡bot**：

```cpp
// botdatamgr.cpp:210
bot->LoadBotCreatureFromDB(0, map, true, true, bot_id, &spawnPos);
//                         ^ spawnId=0

// botdatamgr.cpp:460  官方注释
//We do not create CreatureData for generated bots
```

**游荡bot是纯内存对象，`creature` 表里没有它们的行。**

-> `UPDATE` 匹配 0 行 -> "生效0个"。

### 这是我的文档错误

A36 依赖 A35（先让 bot 进 `creature` 表变永久），
**但我把这个依赖写在了说明的第七章末尾**，
你按顺序执行时根本走不到那里。

**依赖必须写在文档最前面。**

## 但是：先想清楚你要什么

**A35 会把 bot 从游荡池里拿走**（写进 `characters_npcbot` 就退出游荡池），
**A36 再让它重新游荡**。

所以 A35+A36 的净效果是：

```
bot 永久存在（重启不消失） + 会游荡 + 死了回 creature 表记录的坐标
```

**代价**：
- 游荡池少了对应数量（要同步调低 `NpcBot.WanderingBots.Continents.Count`）
- 位置固定（死亡后回原点，不像纯游荡bot那样随机刷新）

**如果你只是想让游荡bot"重启后还在"** —— 说实话，
**纯游荡bot每次重启换一批新面孔，反而更像活的世界**。
A35+A36 更适合做「固定据点bot」（新手村教官、主城守卫这类）。

**要不要做，你定。**
