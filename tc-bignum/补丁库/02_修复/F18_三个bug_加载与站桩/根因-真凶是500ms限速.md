## 五、修复方案（正好也是你要的"启动时全部加载完"）

### 5.1 改动点

`bot_ai.cpp` 不用动，只改 `botdatamgr.cpp` 那一段。

**文件**：`D:\TrinityCore\src\server\game\AI\NpcBots\botdatamgr.cpp`

**Ctrl+F 搜**（约 875 行）：

```cpp

    {
        static const uint32 WANDERING_BOT_SPAWN_DELAY = 500;
```

**改成**：

```cpp
    if (!_botsWanderCreaturesToSpawn.empty())
    {
        // F18: 原值 500ms/个 —— 500个bot要4.2分钟才能全部出场，
        //   用户以为"只加载了160个"，其实是还没出完。
        //
        //   改成可配置 + 批量出场：
        //     NpcBot.WanderingBots.SpawnDelayMs   每批间隔(ms)，默认50
        //     NpcBot.WanderingBots.SpawnBatch     每批几个，默认10
        //   默认值 = 50ms出10个 = 200个/秒 -> 500个只要2.5秒
        //
        //   【为什么原来要限速】每个 SpawnWandererBot 都要建Creature、
        //   AIM_Initialize（初始化技能/装备/天赋）、加入网格，
        //   一次性全出会造成启动卡顿。批量是折中：既快又平滑。
        static uint32 const WANDERING_BOT_SPAWN_DELAY =
            std::max<uint32>(1, sConfigMgr->GetIntDefault("NpcBot.WanderingBots.SpawnDelayMs", 50));
        static uint32 const WANDERING_BOT_SPAWN_BATCH =
            std::max<uint32>(1, sConfigMgr->GetIntDefault("NpcBot.WanderingBots.SpawnBatch", 10));

        next_wandering_bot_spawn_delay += diff;

        while (next_wandering_bot_spawn_delay >= WANDERING_BOT_SPAWN_DELAY &&
               !_botsWanderCreaturesToSpawn.empty())
        {
            next_wandering_bot_spawn_delay -= WANDERING_BOT_SPAWN_DELAY;

            for (uint32 n = 0; n < WANDERING_BOT_SPAWN_BATCH && !_botsWanderCreaturesToSpawn.empty(); ++n)
            {
                auto const& p = _botsWanderCreaturesToSpawn.front();
                uint32 bot_id = p.first;
                WanderNode const* spawnLoc = p.second;
                _botsWanderCreaturesToSpawn.pop_front();
                SpawnWandererBot(bot_id, spawnLoc, nullptr);
            }
        }

        return;
    }
```

### 5.2 【必须】加 include

我实查过：`botdatamgr.cpp` 里 **`sConfigMgr` 出现 0 次，没有 include `Config.h`**。

**所以必须加。** 在文件顶部的 include 区（`botdatamgr.cpp:13` `#include "CharacterCache.h"` 那一片，按字母序）加一行：

```cpp
#include "CharacterCache.h"
#include "Config.h"                 // <-- F18新增：读 SpawnDelayMs / SpawnBatch
#include "Containers.h"
```

**不加会报 `sConfigMgr 未声明的标识符`。**

> 代码本身我已用 g++ 真编译验证：0 错误 0 警告。

### 5.3 配置项

加到 worldserver.conf：

```ini
# 每批出场间隔（毫秒），越小越快。默认 50
NpcBot.WanderingBots.SpawnDelayMs = 50

# 每批出场几个，越大越快。默认 10
NpcBot.WanderingBots.SpawnBatch = 10
```

**效果对照**：

| 配置 | 出场速率 | 500个耗时 |
|---|---|---|
| 500ms / 1个（原版） | 2个/秒 | 250 秒 |
| 50ms / 10个（新默认） | 200个/秒 | **2.5 秒** |
| 20ms / 25个（激进） | 1250个/秒 | 0.4 秒 |

**如果启动卡顿，把 Batch 调小或 DelayMs 调大。**

## 六、关于「启动完成前全部加载完」

你要的效果，用上面的配置**基本达到了**（2.5秒）。

**但严格来说做不到"100%在启动完成前"** —— 因为：

```
World.cpp:2226  sMapMgr->Initialize()  -> BotMgr::Initialize() -> GenerateWanderingBots()
                                          ^^^^ 这里只是【排队】
World::Update() 开始跑                 -> 才开始消费队列
```

**队列消费必须在 Update 里**，而 Update 要等世界启动完才开始。

**要真正做到"启动时同步全部生成"**，得把 `immediate` 改成 `true`：

```cpp
// botdatamgr.cpp:1889
sBotGen->GenerateWanderingBotsToSpawn(wandering_bots_desired, -1, -1, true, ...);
//                                                                 ^^^^ false -> true
```

**代价**：启动时会卡住直到全部生成完（500个可能卡 10-30 秒），
而且**这段时间没有任何进度提示**。

**我的建议**：先用批量方案（2.5秒出完），如果你坚持要"启动时同步"，
我再给 `immediate=true` 的版本 + 进度日志。
