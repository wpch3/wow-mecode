# step24 治疗致死修复 —— 安装说明

## 一、修的是什么

你实测发现：**血量堆高后，用治疗技能就会死**。这是目前唯一一个
**会让角色直接暴毙、且卡住无法复活**的问题，优先级最高。

### 你遇到的三种状态，全部复现并定位

| 你的描述 | 源码原因 |
|---|---|
| ① 血量没超上限，用治疗后溢出死亡，**真死可复活** | `val = dVal + curHealth` 算出 25亿 → `(int32)` 强转成负 → `SetHealth(0)`。死亡流程完整，所以复活正常 |
| ② 血量已溢出，**释放灵魂也是死亡态，NPC 不能复活**，只有把血量降回上限才恢复 | 复活后 `maxHealth` 仍是 42亿，`(int32)` 仍为负 → 一治疗又死 |
| ③ 打着打着或恢复时死亡，**然后突然又站起来，残血** | `Unit.cpp:9808` `else if (DEAD) val = 1;` —— DEAD 状态下任何回血被强制设成 1 点 |

### 我另外穷举出你没遇到的三种

| 状况 | 表现 |
|---|---|
| ④ 卡尸体 | `JUST_DIED`/`CORPSE` 时任何治疗被吃成 0，怎么治都是 0 血 |
| ⑤ **小额治疗把血瞬间顶满 42.9亿** | `maxHealth` 强转为负 → `val < maxHealth` 判断失效 → 走 `SetHealth(maxHealth)`。**下一次治疗必死** ← 很可能就是"打着打着突然死"的真正来源 |
| ⑥ 溢出状态下**掉血也会死** | `ModifyHealth(-100)` 同样触发 `val <= 0`。不只治疗危险，任何血量变动都危险 |

---

## 二、根因

```cpp
// Unit.cpp  int32 Unit::ModifyHealth(int32 dVal)
int32 curHealth = (int32)GetHealth();      // GetHealth() 返回 uint32（上限42.9亿）
int32 val = dVal + curHealth;
if (val <= 0) { SetHealth(0); return -curHealth; }    // ← 强转成负数就走这里 = 死
int32 maxHealth = (int32)GetMaxHealth();   // ← 同样强转，判断全乱
if (val < maxHealth) { ... }
```

实测：

```
(int32)4100000000 = -194967296
```

血量是 `uint32`（上限 42.9 亿），但函数内部全用 `int32`（上限 21.47 亿）。
**超过 21.47 亿就必然出事**。

`Unit::GetHealthGain` 有**一模一样的 bug**，影响生命偷取
（`SpellEffects.cpp:1536` 吸血效果），一并修了。

---

## 三、修法：签名不动，只提升内部计算

```cpp
int64 curHealth = (int64)GetHealth();
int64 val = (int64)dVal + curHealth;
int64 maxHealth = (int64)GetMaxHealth();
SetHealth((uint32)val);
```

**为什么不改签名**：`DealHeal` 里有

```cpp
sScriptMgr->OnHeal(healer, victim, (uint32&)gain);
```

改返回类型会让这个引用强转出错。内部用 `int64` 已经足够解决问题，
而且对**全部 28 个调用点零影响**（传参隐式提升）。

## 四、安装

在 `D:\TrinityCore` 根目录开 **Git Bash**：

```bash
bash apply_step24.sh
```

期望输出：

```
[1/2] 修改 Unit.cpp（两个函数）...
  [OK] Unit::ModifyHealth 已修复（CRLF）
  [OK] Unit::GetHealthGain 已修复（CRLF）
  修改 2 处，跳过 0 处

[2/2] 验证...
  [OK] curHealth 已是 int64
  [OK] val 已是 int64
  [OK] maxHealth 已是 int64
  [OK] SetHealth 转换正确
  [OK] 无残留的 int32 强转

 修复完成！
   血量安全线  21.47亿 -> 42.9亿
   耐力安全线  2.147亿 -> 4.29亿
```

然后 **VS2022 重新编译**（只改了 `Unit.cpp`，不用重跑 CMake）。

脚本特性：**幂等**（重复跑显示"跳过"）、**保留 CRLF**（实测 14930 行 CRLF 零裸 LF）。

## 五、效果

| | 修复前 | 修复后 |
|---|---|---|
| 血量安全线 | 21.47 亿 | **42.9 亿** |
| 耐力安全线 | 2.147 亿 | **4.29 亿** |

**42.9 亿是 `UNIT_FIELD_HEALTH`（uint32 字段）的物理极限**，
再往上要改客户端字段布局 —— 那个留到你改客户端时一起做。
