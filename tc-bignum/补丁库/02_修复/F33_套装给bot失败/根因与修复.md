## 一、为什么会失败 —— 三个独立原因

我实查了 `.gearset bot` 的全流程，**失败不是一个原因，是三个**。

### 原因1：`.gearset bot` 压根没给 bot 装备（设计如此）

```cpp
// step10_cs_gearset.cpp:1783  HandleBot
        handler->PSendSysMessage("|cff888888装备将发到你的背包，"
                                 "用 NPCBot 自带的装备界面给它装上|r");

        std::vector<std::string> sub;
        sub.push_back(tok[1]);
        if (ilvl) sub.push_back(std::to_string(ilvl));
        return HandlePieces(handler, player, sub);      // <- 只是发到玩家背包
```

**`.gearset bot` 只是 `.gearset pieces` 的别名**，它把装备发给你，
指望你手动一件件给 bot 装。所以"给 bot 配装"这个功能**从来就没实现过**。

### 原因2：等级门槛（最常见的失败点）

真正装备时走 `bot_ai::_canEquip`：

```cpp
// bot_ai.cpp:12212
    //level requirements
    if (me->GetLevel() < newProto->RequiredLevel)
        return false;
```

**bot 等级 < 装备需求等级 -> 直接拒绝。**

你的 bot 如果是低等级，发一套 264 装等的装备，**一件都装不上**。

### 原因3：装备评分倒退保护

```cpp
// bot_ai.cpp:12201
        //prevent equipping worse items (only standard or not)
        if (!ignoreItemLevel)
            if (slot > BOT_SLOT_RANGED || einfo->ItemEntry[slot] != oldProto->ItemId)
                if (IAmFree() || !master->IsGameMaster())
                    if (_getItemGearStatScore(oldProto, slot, oldItem) > _getItemGearStatScore(newProto, slot, newItem))
                        return false;
```

**新装备评分低于旧装备 -> 拒绝。**
注意 `!master->IsGameMaster()` —— **GM 模式下这条会被跳过**。

### 还有一道：物品所有权校验

```cpp
// bot_ai.cpp:13207
        //cheating
        if ((!newItem->GetOwnerGUID().IsEmpty() && newItem->GetOwnerGUID() != master->GetGUID()) ||
            (from_bank ? !BotDataMgr::WithdrawBotBankItem(receiver, itemGuid.GetCounter()) : !master->HasItemCount(newItemId, 1)))
        {
            BOT_LOG_ERROR("entities.player",
                "bot_ai::_equip(): player {} ({}) is trying to make bot {} (id: {}) equip item: ... but either does not have this item or does not own it");
            return BotEquipResult::BOT_EQUIP_RESULT_FAIL_NO_ITEM;
        }
```

**物品必须真在你背包里且属于你。**
这条决定了：**不能凭空给 bot 变装备，必须先发到玩家背包再转移。**

## 二、先给你一个立刻能用的办法（不用改代码）

在我做出 `.gearset botequip` 之前，**现在就能用的正确流程**：

```
1. .gm on                                <- 关键！绕过评分倒退保护
2. .gearset bot 战士 200                 <- 装备发到你背包
3. 右键 bot -> 管理装备 -> 自动装备(AUTOEQUIP)
4. .gm off
```

**第 1 步是关键**。`bot_ai.cpp:12204 !master->IsGameMaster()` ——
GM 模式下评分倒退保护会被跳过，成功率大幅提升。

**装等要匹配 bot 等级**：80 级 bot 用 200-264，60 级 bot 用 90-120。
发超过 bot 等级能穿的装备，`:12213` 一定拒绝。

## 三、传家宝问题 —— 你的判断完全正确

### 根因

```cpp
// step10_cs_gearset.cpp:937
            if (p->Quality < ITEM_QUALITY_UNCOMMON)
                continue;
```

**只有品质【下限】，没有【上限】，也没有品质精确匹配。**

传家宝的特征：
- `Quality = ITEM_QUALITY_HEIRLOOM (7)` —— 比史诗还高
- `ItemLevel` 很低（通常 1-80）
- `RequiredLevel = 1`

而评分函数 `ScoreForRole` 是按属性算的，传家宝属性随等级成长，
在模板里存的是**高成长系数**，所以经常评分最高 -> 被选中。

**你说的「按装备等级加品质颜色来搜索」完全正确，这是标准解法。**

### 修法：给 `PickBestItem` 加三道过滤

**文件**：`step10_cs_gearset.cpp`（你装到 TrinityCore 的那份）

搜索原文（`:937`，**两处都要改** —— `PickBestItem` 和 `PickBestWeapon` 各一处）：

```cpp
            if (p->Quality < ITEM_QUALITY_UNCOMMON)
                continue;
```

替换为：

```cpp
            if (p->Quality < ITEM_QUALITY_UNCOMMON)
                continue;
            /*
             * F33: 三道精度过滤
             *  1) 传家宝(7)/代币(ITEM_QUALITY_ARTIFACT=6) 一律排除
             *     —— 传家宝装等低但评分虚高，会挤掉正常装备
             *  2) 品质上限：不要超过调用者要求的档次
             *  3) 装等下限：ilvlCap 的 60%，避免选到装等过低的"高品质垃圾"
             */
            if (p->Quality >= ITEM_QUALITY_ARTIFACT)     // 6=神器 7=传家宝
                continue;
            if (qualityWant && p->Quality != qualityWant)
                continue;
            if (ilvlCap && p->ItemLevel < ilvlCap * 6 / 10)
                continue;
```

同时**函数签名加一个参数**。搜索：

```cpp
    inline uint32 PickBestItem(uint8 cls, GearRole role, uint32 ilvlCap,
                               uint32 invType, uint32 armorSub,
                               std::unordered_set<uint32> const& exclude,
                               uint32 playerLevel = 0)
```

改成：

```cpp
    inline uint32 PickBestItem(uint8 cls, GearRole role, uint32 ilvlCap,
                               uint32 invType, uint32 armorSub,
                               std::unordered_set<uint32> const& exclude,
                               uint32 playerLevel = 0,
                               uint32 qualityWant = 0)     // F33: 0=不限, 3=蓝, 4=紫
```

`PickBestWeapon` 同样改（签名 + 过滤块）。

### 品质对照（`SharedDefines.h:377-384`）

```
ITEM_QUALITY_POOR      = 0   灰
ITEM_QUALITY_NORMAL    = 1   白
ITEM_QUALITY_UNCOMMON  = 2   绿
ITEM_QUALITY_RARE      = 3   蓝
ITEM_QUALITY_EPIC      = 4   紫
ITEM_QUALITY_LEGENDARY = 5   橙
ITEM_QUALITY_ARTIFACT  = 6   神器（红）
ITEM_QUALITY_HEIRLOOM  = 7   传家宝
```

### 用法（改完之后）

```
.gearset pieces 战士 264 紫        只出紫装
.gearset pieces 战士 200 蓝        只出蓝装
.gearset pieces 战士 264           不限品质（但仍排除传家宝/神器）
```

> **注意**：这需要在命令解析处（`:1611` 和 `:1764` 调用点）把品质参数传进去。

## 四、真正的解决方案：`.gearset botequip`（下一步交付）

要做一个**真给 bot 装备**的命令，技术路径已探明：

```
1. 用 PickBestItem 挑装备（带品质过滤）
2. player->StoreNewItem(...)      发到玩家背包（满足 bot_ai.cpp:13208 所有权校验）
3. 找到 bot 的 bot_ai
4. 调用装备接口
```

**卡点**：`bot_ai.h:654 _equip()` 是 **private**：

```cpp
// bot_ai.h:650-654（private 段）
    bool _canEquip(ItemTemplate const* newProto, uint8 slot, bool ignoreItemLevel, Item const* newItem = nullptr, bool ignore_combine = false) const;
    [[nodiscard]] BotEquipResult _equip(uint8 slot, Item* newItem, ObjectGuid receiver, bool store_to_bank, bool from_bank = false);
```

**按最高铁律，我给出三条绕过路径**：

| 路径 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 在 `bot_ai.h:296` public 段加一个 `EquipItemForMaster(uint8 slot, Item*)` 转发到 `_equip` | 改上游 1 行声明 + 1 个小函数 |
| B | 模拟 gossip 包，走 `GOSSIP_SENDER_EQUIP`（`bot_ai.cpp:9493`） | 要构造 gossip 上下文，繁琐 |
| C | 直接调 AUTOEQUIP 路径（`bot_ai.cpp:9298`） | 无法指定具体装备 |

**已确认 public 段可用锚点**：

```
bot_ai.h:293   Item* GetEquips(uint8 slot) const { return _equips[slot]; }     public
bot_ai.h:296   [[nodiscard]] BotEquipResult UnEquipAll(ObjectGuid receiver, bool store_to_bank);
bot_ai.h:298   bool HasRealEquipment() const
```

`UnEquipAll` 是 public 且能改装备 —— 说明**上游本来就允许外部改 bot 装备**，
加一个 `EquipItemForMaster` 完全符合上游设计意图，不是拆安全气囊。
