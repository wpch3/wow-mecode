## 二、实证：游荡bot的 `_botsData` 是【运行时凭空生成】的

### 2.1 生成流程（`botdatamgr.cpp:452`）

```cpp
uint8 bot_spec = BotDataMgr::SelectSpecForClass(bot_class);
_botsData.emplace(std::piecewise_construct,
    std::forward_as_tuple(next_bot_id),
    std::forward_as_tuple(BotDataMgr::DefaultRolesForClass(bot_class, bot_spec),
                          bot_faction, bot_spec));
_botsExtras.emplace(next_bot_id, NpcBotExtras{...});
...
//We do not create CreatureData for generated bots      <-- :460 官方注释
```

**每生成一个游荡bot，就往内存 `_botsData` 里塞一条**，
**但【故意】不创建 CreatureData（也就是不写 world.creature）。**

### 2.2 而且它是【必须】有的（`botdatamgr.cpp:195-200`）

```cpp
NpcBotData const* bot_data = BotDataMgr::SelectNpcBotData(bot_id);
NpcBotExtras const* bot_extras = BotDataMgr::SelectNpcBotExtras(bot_id);
...
ASSERT(bot_data);          // <-- 【没有就直接崩服】
ASSERT(bot_extras);
```

**游荡bot没有 `_botsData` 会 ASSERT 崩服。**

所以「characters_npcbot 有、world.creature 无」
**恰恰是游荡bot应该有的样子**。

### 2.3 我 step60 的判断表是错的

我当时写：

```
PIN_STATE_FREE               两张表都没有  -> 纯游荡bot
PIN_STATE_BROKEN_DATA_ONLY   只有 characters_npcbot -> 损坏
```

**完全反了。** 正确的应该是：

```
游荡bot（未固定） = _botsData 有  +  world.creature 无   <- 这才是正常
已固定           = _botsData 有  +  world.creature 有
```

## 三、`.pin fix` 为什么"修了等于没修"

### 3.1 死锁链条

```
GetPinState()
  -> BotDataMgr::SelectNpcBotData(entry)
  -> botdatamgr.cpp:2929  _botsData.find(entry)     【读内存】
                                                          |
CleanupBroken()                                           |
  -> CharacterDatabase.PExecute("DELETE FROM characters_npcbot ...")
                                                    【只删数据库】
                                                          |
                                                          v
                            内存 _botsData 纹丝不动 -> hasData 永远 true
                                                          |
                                                          v
                                            永远判定"损坏"，无限循环
```

**step62 我为了避开野指针崩服，改成"只删库不动内存"——
这个决定本身是对的（确实不能 erase），
但它让基于内存的判断永远看不到变化。**

### 3.2 更糟的是：那条 DELETE 是有害的

游荡bot的 entry（比如 80770）**本来就不在 `characters_npcbot` 表里**
（它是运行时生成的，只在内存）。

所以那条 `DELETE FROM characters_npcbot WHERE entry = 80770`
**删了个空气**，什么也没发生。

**但如果 entry 恰好撞上一个真实的已招募bot，就会误删别人的数据。**

## 四、正确的判断模型

### 4.1 三个状态的正确定义

| 状态 | `_botsData`(内存) | `world.creature` | `IsWandererBot()` | 能做什么 |
|---|---|---|---|---|
| **游荡bot** | 有 | **无** | **是** | `.pin` |
| **已固定** | 有 | **有** | **否** | `.pin off` |
| **已招募** | 有（owner≠0） | 有 | 否 | 用 `.npcbot remove` |

**关键判据不是"两张表都有"，而是 `IsWandererBot()`。**

`Creature.cpp:3617`：

```cpp
bool Creature::IsWandererBot() const { return bot_AI && bot_AI->IsWanderer(); }
```

这个才是权威 —— 它直接反映 bot 的真实身份。

### 4.2 真正的"损坏"只有一种

```
world.creature 有记录  +  _botsData 没有
```

这种会让 `botdatamgr.cpp:1174` 启动时 **ABORT_MSG 崩服**。

**只有这一种需要修。** 而它的修法是**删 creature 表**（不是删内存）。

## 五、修复方案

### 5.1 重写 `GetPinState()`

```cpp
enum PinState
{
    PIN_STATE_WANDERING,   // 游荡bot：IsWandererBot()==true 且 creature表无
    PIN_STATE_PINNED,      // 已固定：IsWandererBot()==false 且 creature表有
    PIN_STATE_RECRUITED,   // 已招募：owner != 0
    PIN_STATE_BROKEN       // 真损坏：creature表有 但 _botsData无（会崩服）
};
```

**判断顺序**：
1. 先看 `owner != 0` → 已招募
2. 再看 `IsWandererBot()` → 游荡中
3. 再看 creature 表 → 已固定 / 损坏

### 5.2 `.pin` 的前置检查改成

```cpp
if (st == PIN_STATE_WANDERING)   -> 放行，执行固定
if (st == PIN_STATE_PINNED)      -> "已经是永久的了"
if (st == PIN_STATE_RECRUITED)   -> "这个bot已被招募"
if (st == PIN_STATE_BROKEN)      -> "数据损坏，用 .pin fix"
```

### 5.3 `.pin fix` 只处理真损坏

只删 `world.creature`（那个可以安全删，没人缓存它的指针），
**永远不碰 `_botsData`**。

### 5.4 `.pin status` 显示真实身份

加上 `owner` 和 `IsWandererBot()`，让你一眼看清。
