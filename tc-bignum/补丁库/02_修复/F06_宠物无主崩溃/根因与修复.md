# step52 `botpet:GlobalUpdate(): no owner!` 刷屏 + 闪退

> 用户反馈：「后台一直弹出 botpet:GlobalUpdate(): no owner! 而且不会停，然后闪退了」
>
> **上一轮我说"不崩服"是错的。** 刷屏那条确实不崩，但**同一个空指针在别处会崩**。

---

## 一、先纠正我上一轮的判断

我上一轮只看了这一处：

```cpp
// bpet_ai.cpp:2277  GlobalUpdate
if (!petOwner)
{
    BOT_LOG_ERROR("entities.unit", "botpet:GlobalUpdate(): no owner!");
    return false;        // <- 这里确实安全
}
```

然后就下结论"不崩服"。**这个排查是不完整的** ——
我只查了打日志那一处，没查 `petOwner` 在**别的入口**会不会被解引用。

**和 step38 那次犯的是同一个错**：只看了一条路径就下全局结论。

## 二、真正的崩溃点

### 2.1 全量扫描结果

`petOwner->` 解引用共 **196 处**，其中 **22 个函数没有前置判空**：

```
   428  SetPetStats                70 处
   102  _calculatePos              15 处
  1465  _getTarget                 10 处
  1371  IsInBotParty                6 处
   247  CureGroup                   5 处
   152  SetBotCommandState          4 处   <- 【真凶】
  1550  CalculateAttackPos          4 处
  1587  GetInPosition               4 处
  ...
```

### 2.2 崩溃在这一行

```cpp
// bpet_ai.cpp:169   SetBotCommandState()
if ((st & BOT_COMMAND_FOLLOW) && !IsChanneling() &&
    ((!me->isMoving() && !IsCasting() && petOwner->GetBotOwner()->IsAlive()) || force))
                                        ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                                        双重解引用，petOwner 为空直接崩
```

### 2.3 为什么 `GlobalUpdate` 的判空挡不住它

因为 `SetBotCommandState` **是从外部直接调用的**，根本不经过 `GlobalUpdate`：

```cpp
// bot_ai.cpp:1026   主人执行 .npcbot sendto 之类的指令时
if (botPet && !CCed(botPet, true))
{
    botPet->GetBotPetAI()->SetBotCommandState(BOT_COMMAND_STAY);
    //                     ^^^^^^^^^^^^^^^^^ 绕过了 GlobalUpdate 那道门
```

**所以流程是**：

```
无主宠物存在
  -> 每帧 UpdateAI -> GlobalUpdate 判空 -> return false -> 只刷日志（不崩）
  -> 某一刻主人下指令 / 触发别的回调
  -> SetBotCommandState 被直接调用 -> petOwner->GetBotOwner() -> 【崩】
```

**这解释了为什么"刷屏很久之后才闪退"** —— 刷屏是慢性症状，
崩溃要等某个外部调用发生。

## 三、修复：两层

### 3.1 第一层【必做】：清掉数据源

**根本原因是"存在无主宠物"**，把它清掉，后面都不会发生。

执行 `patches/step46_突破人数上限_第1阶段/sql/修复-宠物模板刷屏.sql`

那个 SQL 会把混进 `creature_template_npcbot_extras` 的**宠物模板**踢出去
（宠物 `flags_extra = 0x8A000000`，比 bot 少一位）。

**光做这一步，刷屏和崩溃都会消失。**

### 3.2 第二层【建议做】：给代码加防线

数据修好了，但**代码本身仍然脆弱** —— 以后任何原因导致无主宠物，
还会崩在同一个地方。加一道保险：

**Ctrl+F 搜**（`bpet_ai.cpp:152`）：

```cpp
void bot_pet_ai::SetBotCommandState(uint32 st, bool force, Position* newpos)
{
    if (!(st & (BOT_COMMAND_INACTION)))
    {
        if (!me->IsAlive() || JumpingOrFalling())
            return;
    }
```

**在函数最开头插入**（`if (!(st &` 那行【之前】）：

```cpp
void bot_pet_ai::SetBotCommandState(uint32 st, bool force, Position* newpos)
{
    //step52: 无主宠物防崩。
    //  petOwner 只在 IsSummonedBy()(bpet_ai.cpp:2208) 赋值一次，
    //  非正常生成的宠物它永远是 nullptr。
    //  本函数第169行 petOwner->GetBotOwner()->IsAlive() 是双重解引用，
    //  而它被 bot_ai.cpp:1026 从外部直接调用，绕过了 GlobalUpdate 的判空。
    if (!petOwner || !petOwner->GetBotOwner())
        return;

    if (!(st & (BOT_COMMAND_INACTION)))
    {
        if (!me->IsAlive() || JumpingOrFalling())
            return;
    }
```

> **为什么连 `GetBotOwner()` 也判**：169 行是
> `petOwner->GetBotOwner()->IsAlive()`，两层都可能为空。

### 3.3 第三层【可选】：把刷屏压成一次

刷屏本身也该治 —— 每帧一条日志会淹没真正的错误。

**Ctrl+F 搜**（`bpet_ai.cpp:2279`）：

```cpp
    if (!petOwner)
    {
        BOT_LOG_ERROR("entities.unit", "botpet:GlobalUpdate(): no owner!");
        return false;
    }
```

**改成**：

```cpp
    if (!petOwner)
    {
        //step52: 原来每帧刷一条，几分钟就能把日志刷爆，
        //  真正的错误全被淹没。改成【只报一次】，并把自己标记为待删除。
        if (!_reportedNoOwner)
        {
            _reportedNoOwner = true;
            BOT_LOG_ERROR("entities.unit",
                "botpet:GlobalUpdate(): no owner! pet entry {} guid {} —— 将被移除",
                me->GetEntry(), me->GetGUID().GetCounter());
            me->AddObjectToRemoveList();   // 无主宠物没有存在意义，直接清掉
        }
        return false;
    }
```

**在 bpet_ai.h 加成员**，Ctrl+F 搜（`bpet_ai.h:150`）：

```cpp
    Creature* petOwner{};
```

**在它下面加**：

```cpp
    bool _reportedNoOwner{};       // step52: 防止 no owner 日志刷屏
```

> **访问段确认**：150 行在 protected/private 段里，
> 新成员放同一段，只在 bpet_ai 内部用，没问题。

| 层 | 效果 | 代价 |
