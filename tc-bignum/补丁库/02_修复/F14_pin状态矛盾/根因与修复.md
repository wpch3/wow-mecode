# step60  `.pin` 状态自相矛盾：说它是永久的，取消又说它本来不是

> 用户反馈：
> 「我第一次用这个功能就告诉我是永久的，但是我取消他又告诉我本来就不是永久的」
>
> ```
> .pin      -> 这个bot已经有持久化数据了
> .pin off  -> 这个bot本来就不是永久的
> ```

---

## 一、结论：我用了【两个不同的判断依据】，它们本来就会打架

这是我 step49 的设计缺陷，**不是你操作错了，也不是数据坏了**。

### 两条消息各自查的是什么

| 指令 | 代码位置 | 判断依据 | 查的是哪张表 |
|---|---|---|---|
| `.pin` | `cs_botpersist.cpp:231` | `BotDataMgr::SelectNpcBotData(entry)` | **characters_npcbot** |
| `.pin off` | `cs_botpersist.cpp:351` | `bot->GetSpawnId()` | **world.creature**（内存里的 m_spawnId） |

**两个不是一回事。**

### 你这个 bot 的真实状态

```
characters_npcbot  里【有】记录     -> .pin  说"已经有持久化数据了"
creature 表        里【没有】记录   -> spawnId = 0
                                    -> .pin off 说"本来就不是永久的"
```

**两句话都是"对"的，因为它们在说两件不同的事。**
而对你来说，这就是自相矛盾。

---

## 二、为什么会变成这个"半永久"状态

### 2.1 永久化必须两张表【同时】写

实查官方 `.npcbot spawn` 的落库四步（`botcommands.cpp:3859-3873`）：

```cpp
BotDataMgr::AddNpcBotData(id, ...);                    // 1. 写 characters_npcbot
creature->SaveToDB(map->GetId(), ...);                 // 2. 写 world.creature
uint32 db_guid = creature->GetSpawnId();               //    拿到 spawnId
creature->LoadBotCreatureFromDB(db_guid, map);         // 3. 按 spawnId 重载
sObjectMgr->AddCreatureToGrid(db_guid, ...);           // 4. 挂进网格
```

**四步缺一不可。** 我 step49 照抄了这四步，但**没有做失败回滚**。

### 2.2 你这次很可能是这样断掉的

```
.pin 执行
  |
  +-- AddNpcBotData 成功        -> characters_npcbot 有了记录
  |
  +-- 中间某一步失败/异常       <- 比如 UnsetWanderer 那时候还没编译进去
  |
  +-- SaveToDB 没执行成功       -> creature 表【空的】，spawnId 还是 0
  |
  v
半永久状态：一张表有，一张表没有
  |
  v
.pin      看 characters_npcbot -> "已经有持久化数据了"，拒绝
.pin off  看 spawnId(=0)       -> "本来就不是永久的"，拒绝
  |
  v
【死锁】：两个指令都进不去，这个 bot 卡住了
```

> **注意**：你之前 `UnsetWanderer` 编译报错（step59），
> 说明在那之前 `.pin` 走的路径是不完整的。
> **这很可能就是造成半永久状态的那次。**

### 2.3 这个状态还有个隐患：启动崩服

实查 `botdatamgr.cpp:1168-1176`，服务器启动时会做**交叉校验**：

```
creature 表有 bot，但 characters_npcbot 没有  ->  ABORT_MSG 直接崩服
```

**你现在是反过来的**（characters_npcbot 有、creature 没有），
这个方向**不会崩服**，但会留下一条孤儿记录。

所以不紧急，但要清掉。

## 四、第一部分：解开当前卡住的 bot

### 4.1 先看清楚它到底什么状态

在 DBeaver 里执行（**`Alt+X` 执行全部**）：

```sql
-- 把 70001 换成你那个 bot 的 entry
-- 不知道 entry 的话：选中 bot 后用 .npcbot info 看，或者用下面第2条查
SET @entry := 70001;

-- 1) characters 库：有没有持久化记录
SELECT '=== characters_npcbot ===' AS step;
SELECT * FROM `characters`.`characters_npcbot` WHERE `entry` = @entry;

-- 2) world 库：creature 表里有没有实体
SELECT '=== world.creature ===' AS step;
SELECT `guid`, `id`, `map`, `ScriptName`
FROM `world`.`creature` WHERE `id` = @entry;

-- 3) 这个 entry 是不是游荡bot池的
SELECT '=== creature_template_npcbot_extras ===' AS step;
SELECT * FROM `world`.`creature_template_npcbot_extras` WHERE `entry` = @entry;
```

**预期结果**（如果是我说的半永久状态）：

```
characters_npcbot  -> 1 行
world.creature     -> 0 行     <- 就是这里断的
creature_template_npcbot_extras      -> 1 行
```

### 4.2 清掉孤儿记录

```sql
SET @entry := 70001;

-- 删掉 characters_npcbot 里的孤儿记录，让它变回纯游荡bot
DELETE FROM `characters`.`characters_npcbot` WHERE `entry` = @entry;

-- 顺便清干净可能的残留（正常情况下这两条都删0行）
DELETE FROM `characters`.`characters_npcbot_group_member` WHERE `entry` = @entry;
DELETE FROM `world`.`creature` WHERE `id` = @entry;

-- 验证：三张表都应该查不到
SELECT '=== 验证：以下三个都应该是空 ===' AS step;
SELECT * FROM `characters`.`characters_npcbot` WHERE `entry` = @entry;
SELECT * FROM `world`.`creature` WHERE `id` = @entry;
SELECT * FROM `characters`.`characters_npcbot_group_member` WHERE `entry` = @entry;
```

### 4.3 重启服务器

`characters_npcbot` 的内容在内存里有缓存（`BotDataMgr::_botsData`），
**光删数据库不够，必须重启**才能让内存也清掉。

重启后这个 bot 会重新变回普通游荡 bot。

## 五、第二部分：改代码（三处）

我把 `cs_botpersist.cpp` 改好了，**直接覆盖文件**即可。

改动内容如下（供你了解，不用手动改）：

### 5.1 判断依据统一

**问题**：`.pin` 看 `characters_npcbot`，`.pin off` 看 `spawnId`。

**改法**：两边都改成**同时看两张表**，并把三种状态分开处理：

```
状态A  两张表都没有       -> 纯游荡bot，可以 .pin
状态B  两张表都有         -> 已固定，可以 .pin off
状态C  只有一张表有       -> 【损坏状态】，给出明确提示 + 提供修复
```

### 5.2 `.pin` 加失败回滚

四步里任何一步失败，**把前面已经做的撤销掉**，
不留半永久状态。

### 5.3 新增 `.pin fix` —— 自助修复损坏状态

选中 bot，`.pin fix` 会：

- 检测出是哪张表缺了
- 把另一张表的孤儿记录清掉
- 让它回到"纯游荡bot"状态

这样以后再遇到就不用手动跑 SQL 了。

### 5.4 `.pin status` —— 看真实状态

```
.pin status
```

输出：

```
entry: 70001
  characters_npcbot : 有
  world.creature    : 无        <- 一眼看出问题
  spawnId(内存)     : 0
  判定: 【损坏】只有持久化数据，没有实体。用 .pin fix 修复
```

## 七、我的错误记录

**教训：一个功能的"开"和"关"，必须用【同一个判断依据】。**

我 step49 写 `.pin` 时用 `SelectNpcBotData`（因为那时在想"官方怎么判重复"），
写 `.pin off` 时用 `GetSpawnId()`（因为那时在想"怎么拿到要删的 guid"）。

**两个函数分开写、分开想，就用了两套标准，必然打架。**

正确做法：**先定义"什么叫已固定"（两张表都有），
然后开关两边都用这一个定义。**

已记入坑表。
