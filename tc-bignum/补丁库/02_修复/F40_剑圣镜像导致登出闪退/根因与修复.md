## 一、这次的日志直接锁定了真凶

**F38 我改的 `botmgr.cpp:805` 不是这次的原因。** 真正的问题是三个：

### 证据1：`Entry: 70552` 是剑圣的镜像分身

```cpp
// botcommon.h:44
BOT_ENTRY_MIRROR_IMAGE_BM = 70552,
```

日志里 **master 的 Entry 是 70552** —— 意思是：
「一个镜像分身的主人，是另一个镜像分身」。**这本身就不正常。**

### 证据2：`master map id 0 "Unknown"`

```cpp
// Map.cpp:1072
(owner && owner->IsInWorld()) ? owner->GetMap()->GetId() : 0u,
(owner && owner->IsInWorld()) ? std::string(...) : std::string{"Unknown"}
```

`0` 和 `"Unknown"` 是 `owner->IsInWorld() == false` 时的**兜底值**。
说明**主人已经不在世界里了，镜像还活着**。

### 证据3：上游自己标了 "tempfix"

```cpp
// Map.cpp:1052
//npcbot: tempfix for bots out of grid during remove from map
```

**上游知道这里有问题，只是临时糊了一下。**

## 二、完整因果链

```
你退出到选角色
  -> 剑圣bot 被移除
  -> 它的【镜像分身】还留在世界里（分身的 owner 指向已销毁的剑圣）
  -> Map::RemoveFromMap 走到 :1065  obj->IsInGrid() == false
  -> 走 else 分支，只打日志，【不做任何清理】
  -> 分身对象被析构，但 Eluna 那边还持有它的引用
  -> Eluna 触发 event 31（对象删除）
  -> ObjectVariables.ext:43 调 GetGUIDLow() -> 对象已失效 -> 崩
```

**为什么"不用进角色就闪退"**：崩溃发生在登出清理阶段，
你还没点进新角色，服务端已经死了。

## 三、修复（三处，按重要性排序）

### 改动1【必做】· 移除 bot 时先清掉它的宠物/分身

**文件**：`D:\TrinityCore\src\server\game\AI\NpcBots\botmgr.cpp`

搜索原文（`:803` 附近，`CleanupsBeforeBotDelete` 那行）：

```cpp
    CleanupsBeforeBotDelete(guid, removetype);
```

在它**上面**插入：

```cpp
    // F40: 先切断 bot 的宠物/镜像分身与主人的关联，再清理 bot 本体。
    //   否则分身的 creator 变野指针，Eluna 的 ObjectVariables 扩展
    //   在对象删除事件(31)里访问它 -> "invalidated object" -> 崩服。
    //   典型案例：剑圣(BOT_CLASS_BM)的 Mirror Image (entry 70552)。
    //   写法照抄上游 botmgr.cpp:795（注意 GetBotsPet() 返回 Unit* 不是 Creature*）
    if (Unit* bpet = bot->GetBotsPet())
        bpet->SetCreator(nullptr);

    CleanupsBeforeBotDelete(guid, removetype);
```

> **注意**：`botmgr.cpp:795-796` 已经有一处 `SetCreator(nullptr)`，
> 但那是在**另一个分支**（DungeonBot），走不到普通登出这条路。

### 改动2【必做】· 补上 `:1065` else 分支的清理

**文件**：`D:\TrinityCore\src\server\game\Maps\Map.cpp`

搜索原文（`:1065-1073`）：

```cpp
            if (obj->IsInGrid())
                obj->RemoveFromGrid();
            else
            {
                Player const* owner = obj->ToCreature()->GetBotOwner();
                BOT_LOG_ERROR("npcbots", "Map::Remove<Bot>FromMap() bot {} id {} is in map id {} \"{}\" instanceId {} but not in grid!\nmaster: {}\nmaster map id {} \"{}\"",
                    obj->GetName(), obj->GetEntry(), GetId(), GetMapName(), i_InstanceId, owner ? owner->GetGUID().ToString() : std::string{ "Unknown" },
                    (owner && owner->IsInWorld()) ? owner->GetMap()->GetId() : 0u, (owner && owner->IsInWorld()) ? std::string(owner->GetMap()->GetMapName()) : std::string{"Unknown"});
            }
```

替换为：

```cpp
            if (obj->IsInGrid())
                obj->RemoveFromGrid();
            else
            {
                // F40: 原版这里【只打日志不清理】，对象带着失效状态被析构，
                //   Eluna 的对象删除事件(31)再去访问它就崩。
                //   这里补上必要的清理：切断与主人的关联。
                Player const* owner = obj->ToCreature()->GetBotOwner();
                BOT_LOG_ERROR("npcbots", "Map::Remove<Bot>FromMap() bot {} id {} is in map id {} \"{}\" instanceId {} but not in grid!\nmaster: {}\nmaster map id {} \"{}\"",
                    obj->GetName(), obj->GetEntry(), GetId(), GetMapName(), i_InstanceId, owner ? owner->GetGUID().ToString() : std::string{ "Unknown" },
                    (owner && owner->IsInWorld()) ? owner->GetMap()->GetId() : 0u, (owner && owner->IsInWorld()) ? std::string(owner->GetMap()->GetMapName()) : std::string{"Unknown"});

                if (Creature* botCre = obj->ToCreature())
                {
                    botCre->SetCreator(nullptr);
                    botCre->SetOwnerGUID(ObjectGuid::Empty);
                }
            }
```

> **为什么要 `ToCreature()`**：这段在模板函数 `Map::RemoveFromMap<T>` 里，
> `obj` 的静态类型是 `T*`。`SetCreator`/`SetOwnerGUID` 定义在
> `Unit.h:1261 / :1242`，必须先转成具体类型才能调。
> 外层 `if constexpr (std::is_base_of_v<Creature, T>)` 已保证它是 Creature。

### 改动3【推荐】· 让 Eluna 扩展别崩

**文件**：`D:\TC-Build\bin\RelWithDebInfo\lua_scripts\extensions\ObjectVariables.ext`

跳到 **43 行**，它长这样（大致）：

```lua
local function DestroyObjData(event, obj)
    local guid = obj:GetGUIDLow()      -- 43行，崩在这
    ...
end
```

改成：

```lua
local function DestroyObjData(event, obj)
    -- F40: 对象可能已失效（NPCBot 的镜像分身在删除时会出现这种情况），
    --      用 pcall 保护，取不到就直接返回，不影响服务器运行。
    local ok, guid = pcall(function() return obj:GetGUIDLow() end)
    if not ok or not guid then
        return
    end
    ...
end
```

> **这一步是兜底**。改动1+2 治本，改动3 保证即使还有漏网之鱼也不会崩服。
> **如果你不想动 Lua，可以先只做 1+2。**
