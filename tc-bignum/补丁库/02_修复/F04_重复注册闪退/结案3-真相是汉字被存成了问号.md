## 二、`??` 不是显示问题，是文件里真的存着问号

我上一轮说「`??` 是控制台显示不了中文」—— **那个判断错了**。

真相是：**保存时字符就被替换了**。

### 为什么会这样

VS2022 在你选「另存为 -> UTF-8 带签名」之前，
文件可能已经被某一步操作**转成了无法表示中文的编码**（比如 ASCII / Windows-1252）。

转换时遇到汉字，编码器无法表示 -> **静默替换成 `?`**。

这是**不可逆**的：一旦存成 `?`，原来的汉字信息就永久丢了。
之后你再存成 UTF-8 BOM，保存的也只是那两个问号。

> 这也解释了为什么你「改成 UTF-8 BOM 后还是崩」——
> 编码格式确实改对了，但**内容已经在更早的某一步被破坏了**。

## 四、如果贴完还是变成 `??`

说明 VS2022 那个文件的编码设置有问题。**换个编辑器贴**：

### 方案 A：用 Notepad++（推荐）

1. 用 Notepad++ 打开 `botcommands.cpp`
2. 菜单 **编码** -> 确认是 **UTF-8-BOM**（不是"转为"，是先看当前是什么）
3. 如果不是，选 **编码 -> 转为 UTF-8-BOM**
4. 贴入那 21 行
5. 保存

### 方案 B：用 Git Bash 直接写（最稳）

把上面那 21 行存成 `alias.txt`（用任何能保证 UTF-8 的方式），
然后：

```bash
cd /d/TrinityCore/src/server/game/AI/NpcBots
# 备份
cp botcommands.cpp botcommands.cpp.bak
# 在 npcbotCommandTable 的 { 后面插入
python3 - <<'EOF'
import io
p='botcommands.cpp'
s=io.open(p,encoding='utf-8-sig').read()
alias=io.open('alias.txt',encoding='utf-8').read()
key='static ChatCommandTable npcbotCommandTable =\n        {\n'
assert key in s, "找不到插入点"
s=s.replace(key, key+alias, 1)
io.open(p,'w',encoding='utf-8-sig').write(s)
print("插入完成")
EOF
```

`encoding='utf-8-sig'` 会自动带 BOM，**保证不会被转成问号**。

### 方案 C：先不要中文别名

中文别名是**锦上添花**，不是必需品。

**直接删掉那 21 行**，服务端就能启动，
`.npcbot add` / `.npcbot info` 这些英文命令完全正常。

等主线功能都验证完，再回头处理中文别名。
