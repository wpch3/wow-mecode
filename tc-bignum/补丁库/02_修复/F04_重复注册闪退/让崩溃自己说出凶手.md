# 还在崩？让 ASSERT 自己把凶手名字打出来

> 2026-08-04
> 前提：`wp` 那个重复你已经修了，编码也换成 UTF-8 BOM 了，**但还是崩在同一处**。

---

## 一、先回答你的问题：其它 patch 要不要改编码？

**不用。**

而且要先纠正一点 —— **这次崩溃和编码没有任何关系**。

| 问题 | 影响 |
|---|---|
| 编码（BOM） | 中文**显示**乱码、中文**别名匹配**失败 |
| 本次崩溃 | 命令**注册**阶段的重复检测 |

两者是独立的。你把三个文件改成 UTF-8 BOM 是对的（解决中文别名），
但它**治不了这个崩溃**，所以还崩是正常的，不是你改错了。

**判断标准很简单**：

- 文件里**没有中文** -> 完全不用管编码
- 中文只在**注释**里 -> 不用管（顶多注释乱码，不影响功能）
- 中文在**字符串字面量**里（玩家能看到的文字、参与比较的命令别名）-> 才需要 UTF-8 BOM

你已经改的这三个正好是有中文字面量的，**改对了，不用再改别的**。

## 二、为什么查不下去了

```cpp
// ChatCommand.cpp:39
ASSERT(!_invoker, "Duplicate blank sub-command.");
```

**它只说"有重复"，不说"是谁重复"。**

我们靠 grep 猜了三轮（botrename -> 全量扫描 -> wp），
现在 wp 修了还崩，说明**还有第二个重复**，继续猜下去效率太低。

**直接让它自己说。**

## 三、改一行，让崩溃报出命令名

### 3.1 打开文件

```
D:\TrinityCore\src\server\game\Chat\ChatCommands\ChatCommand.cpp
```

### 3.2 Ctrl+F 搜（第 39 行）

```cpp
        ASSERT(!_invoker, "Duplicate blank sub-command.");
```

### 3.3 替换成

```cpp
        ASSERT(!_invoker, "Duplicate blank sub-command. name='" STRING_VIEW_FMT "'", STRING_VIEW_FMT_ARG(builder._name));
```

**就这一行，其它什么都不动。**

### 3.4 为什么这样写是安全的

- `builder._name` 就是当前正在注册的命令名，**函数参数里现成的**
- `STRING_VIEW_FMT` / `STRING_VIEW_FMT_ARG` 定义在 `Define.h:125-126`，
  **同一个文件的第 62 行已经在用了**（`ASSERT(!tokens.empty(), "Invalid command name '" STRING_VIEW_FMT "'." ...)`），
  照抄官方写法，不用额外 include
- 我实际编译运行验证过输出格式：

```
ASSERTION FAILED: Duplicate blank sub-command. name='wp'
ASSERTION FAILED: Duplicate blank sub-command. name='npcbot'
```

### 3.5 重新编译

只改了一行内容，**不用重跑 CMake**。

## 四、拿到名字之后怎么做

启动服务端，崩溃信息会变成类似：

```
Duplicate blank sub-command. name='xxxx'
```

**把那个 `xxxx` 告诉我**，或者你自己直接查：

```bash
grep -rn '"xxxx"' /d/TrinityCore/src/server/scripts/ /d/TrinityCore/src/server/game/AI/NpcBots/ | grep -P '\{\s*"xxxx"'
```

### 三种可能的结果

| 查到的情况 | 说明 | 修法 |
|---|---|---|
| **同一个 .cpp 里出现两次** | 那个文件的命令表写重复了 | 删掉一条 |
| **两个不同 .cpp 各一次，且都是顶层命令** | 两个脚本抢同一个名字 | 改掉其中一个的名字 |
| **只找到一处** | 说明是 `AddSC_xxx` 又被调了两次 | 回去 grep `cs_script_loader.cpp` |

## 六、如果你想跳过排查，直接定位

还有个更狠的办法：**把 ASSERT 改成打印警告但不崩**，
让它一次性把**所有**重复的命令都列出来。

```cpp
        // 临时诊断版：不崩，只记录
        if (_invoker)
        {
            TC_LOG_ERROR("server.loading", "[重复命令] name='{}'", builder._name);
        }
        else
        {
```

然后把原来的赋值那几行包进 `else` 里：

```cpp
        if (_invoker)
        {
            TC_LOG_ERROR("server.loading", "[重复命令] name='{}'", builder._name);
        }
        else
        {
            TrinityStrings help;
            std::tie(_invoker, help, _permission) = *(std::get<ChatCommandBuilder::InvokerEntry>(builder._data));
            if (help)
                _help.emplace<TrinityStrings>(help);
        }
```

**服务端能正常启动**，然后去看日志里所有 `[重复命令]` 行 ——
一次性拿到完整清单。

> **排查完记得改回原样**（恢复 `ASSERT`），
> 这个版本会让重复的命令静默失效，不适合长期使用。

**建议**：先用第三章那个一行改动（快、信息够用）。
如果重复不止一个，再上这个"列全部"的版本。
