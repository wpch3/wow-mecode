# `name='??'` —— 凶手是一个【中文命令名】

> 2026-08-04
> 这个输出信息量很大，基本可以锁定范围了。

---

## 一、`??` 说明了什么

Windows 控制台（GBK 代码页）显示不了 UTF-8 中文，会打成 `?`。

```
name='??'
     ^^
     2 个问号 = 2 个字节组 = 【一个两字中文词】
```

我逐个核查了所有可能有中文命令名的地方：

| 文件 | 命令表里有中文吗 | 结论 |
|---|---|---|
| `cs_botrename.cpp` | **无**（中文都在函数内比较） | 安全 |
| `cs_playerbot.cpp` | **无**（同上） | 安全 |
| `pbot_autoaccept.cpp` | 无（它没有命令表） | 安全 |
| `botcommands.cpp` | **有** —— step41 那 21 个中文别名 | **凶手在这** |

> `.pbot 过来` 那种中文是 `tok[0] == "过来"` 的**函数内字符串比较**，
> 不经过命令表，所以不会触发这个 ASSERT。
> 只有 `botcommands.cpp` 里的中文是真正注册成**命令名**的。

**我也核对了自己给的清单**：21 个中文别名（招募/解雇/释放/生成/移动/
查找/复活/信息/隐藏/显示/杀死/修复/传送/装等/召回/列表/删除/设置/命令/
距离/指令）**内部没有重复**，上游原有 30 个英文命令也没有重复。

**所以是插入的时候产生了重复** —— 多半是那段别名贴了两次，
或者插入位置和已有条目重叠了。

## 二、一条命令定位（Git Bash）

```bash
bash 查中文命令重复.sh /d/TrinityCore/src
```

我用"故意贴两次"的场景验证过，它会直接输出：

```
  [!! 找到凶手 !!] 以下中文命令名【重复】了：

    "招募"  出现 2 次：
        第 656 行: { "招募",       HandleNpcBotAddCommand, ...
        第 660 行: { "招募",       HandleNpcBotAddCommand, ...
```

**精确到行号**，删掉重复的那几行即可。

### 脚本查三件事

1. `botcommands.cpp` 里所有中文命令名及出现次数（**核心**）
2. 中文别名段是否被整段贴了两次
3. `npcbotCommandTable` 全表重复检查（含英文，上游原本 30 条）

## 三、如果不想跑脚本，手动查也行

```bash
grep -n '"招募"\|"解雇"\|"信息"\|"列表"\|"设置"' \
  /d/TrinityCore/src/server/game/AI/NpcBots/botcommands.cpp
```

**每个词应该只出现 1 次。** 出现 2 次的就是凶手。

或者直接看条目总数：

```bash
sed -n '/static ChatCommandTable npcbotCommandTable/,/^        };/p' \
  /d/TrinityCore/src/server/game/AI/NpcBots/botcommands.cpp | grep -c '^\s*{\s*"'
```

- **上游原本 30 条**
- 加了 21 个中文别名 -> 应该是 **51 条**
- 如果是 **72 条**（30 + 21×2），说明别名段贴了两遍

## 四、最可能的两种情况

### 情况 A：别名段贴了两次

安装说明里我写了「在这个 `{` 下面插入下面整段」，
如果你试了两次（比如第一次没保存成功又贴了一遍），就会重复。

**修法**：删掉其中一整段。

### 情况 B：插入位置压到了已有条目

比如插在了 `{ "set", npcbotSetCommandTable }` 这行上面/中间，
导致某个条目被复制。

**修法**：脚本第 3 节会把英文命令的重复也列出来，看那里。

## 五、顺便说明：这和编码无关

你把三个文件改成 UTF-8 BOM 是**对的**，但那治的是
「中文别名**匹配不上**」，不是这个崩溃。

两件事的关系是：

```
编码错   -> 中文别名注册进去了，但玩家打 .npcbot 信息 匹配不上（不崩）
名字重复 -> 注册阶段就 ASSERT（崩服，就是现在这个）
```

**现在编码修好了，中文别名能被正确读取了，
反而让"重复"这个问题暴露出来** ——
之前 GBK 编码时，两次插入的字节可能不完全一致，未必判定为重复。

所以这其实是**进展**，不是倒退。
