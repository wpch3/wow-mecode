## 一、真凶：`GroupHandler.cpp:335`

### 1.1 完整链路（全部实查）

```
ElvUI 的队伍框刷新
  -> 对队伍里每个单位发 CMSG_GROUP_UNINVITE_GUID（按GUID踢人/查询）
  -> GroupHandler.cpp:295  HandleGroupUninviteGuidOpcode
  -> GroupHandler.cpp:312  CanUninviteFromGroup(guid)
  -> GroupHandler.cpp:323  if (grp->IsMember(guid))     <- 【NPCBot 在这里返回 false】
  -> GroupHandler.cpp:329  if (grp->GetInvited(guid))   <- 也是 false
  -> GroupHandler.cpp:335  SendPartyResult(PARTY_OP_UNINVITE, "", ERR_TARGET_NOT_IN_GROUP_S);
                           ^^^^^^^^^^ 就是这一句，弹出「XXX不在你的队伍中」
```

### 1.2 为什么 NPCBot 会走到这里 —— 这是本次最关键的发现

**NPCBot 根本不在 `m_memberSlots` 里，它在一个独立容器。**

```cpp
// Group.cpp:2844
bool Group::IsMember(ObjectGuid guid) const
{
    return _getMemberCSlot(guid) != m_memberSlots.end();    // 只查真人容器
}
```

而 NPCBot 存在这里：

```cpp
// Group.h:195-204
        //npcbot
        bool Create(Creature* leader);
        bool AddMember(Creature* creature);
        void LoadCreatureMemberFromDB(uint32 entry, uint8 memberFlags, uint8 subgroup, uint8 roles);
        void UpdateBotOutOfRange(Creature* creature);
        void LinkBotMember(GroupBotReference* bRef);
        void DelinkBotMember(ObjectGuid guid);
        GroupBotReference* GetFirstBotMember() { return m_botMemberMgr.getFirst(); }
        GroupBotReference const* GetFirstBotMember() const { return m_botMemberMgr.getFirst(); }
        //end npcbot

// Group.h:371-373
        //npcbot
        GroupBotRefManager  m_botMemberMgr;      <- bot 在这个独立容器
        //end npcbot
```

**结论**：`IsMember(bot_guid)` 对 NPCBot **永远返回 false**，
所以每次 ElvUI 刷新队伍框，服务端都会回一条「不在你的队伍中」。

**这不是 ElvUI 的 bug，是上游 NPCBot 模块没给 `IsMember` 打补丁。**

### 1.3 为什么 F29 没拦住

F29 我改的是 `:381`（`HandleGroupUninviteOpcode`，**按名字**版），
但 ElvUI 走的是 `:295`（`HandleGroupUninviteGuidOpcode`，**按GUID**版）。

两个是不同的 opcode，改错地方了。

## 二、修法：两处改动（推荐做法）

### 改动一【治本】：让 `IsMember` 认识 bot

**文件**：`D:\TrinityCore\src\server\game\Groups\Group.cpp`

搜索原文（`:2844`，**全文件只有一处**）：

```cpp
bool Group::IsMember(ObjectGuid guid) const
{
    return _getMemberCSlot(guid) != m_memberSlots.end();
}
```

替换为：

```cpp
bool Group::IsMember(ObjectGuid guid) const
{
    if (_getMemberCSlot(guid) != m_memberSlots.end())
        return true;

    //npcbot: NPCBot 不在 m_memberSlots，在 m_botMemberMgr 独立容器里。
    //  不认它会导致 GroupHandler.cpp:335 对每个 bot 回一条
    //  「XXX不在你的队伍中」，被 ElvUI 的队伍框刷新触发成刷屏。
    //  【注意】GroupBotReference : Reference<Group, Creature>
    //    Reference.h:94  TO*   getTarget() const  -> Creature*  用这个
    //    Reference.h:96  FROM* GetSource() const  -> Group*     不是bot！
    if (guid.IsCreature())
    {
        for (GroupBotReference const* bitr = GetFirstBotMember(); bitr != nullptr; bitr = bitr->next())
            if (bitr->getTarget() && bitr->getTarget()->GetGUID() == guid)
                return true;
    }
    //end npcbot

    return false;
}
```

> **为什么加 `guid.IsCreature()` 判断**：
> 避免对真人玩家多跑一次链表遍历。真人永远不会在 bot 容器里。

### 改动二【止血】：踢不到人时不发错误

**文件**：`D:\TrinityCore\src\server\game\Handlers\GroupHandler.cpp`

搜索原文（`:335`）：

```cpp
    SendPartyResult(PARTY_OP_UNINVITE, "", ERR_TARGET_NOT_IN_GROUP_S);
}

void WorldSession::HandleGroupUninviteOpcode(WorldPacket& recvData)
```

把那一句改成：

```cpp
    // F32: 按GUID踢人找不到目标时保持静默。
    //   ElvUI 等插件会对队伍成员批量发 CMSG_GROUP_UNINVITE_GUID，
    //   NPCBot 命中不了就会刷屏。真人玩家走 :381 按名字版，那边照常提示。
    // SendPartyResult(PARTY_OP_UNINVITE, "", ERR_TARGET_NOT_IN_GROUP_S);
}

void WorldSession::HandleGroupUninviteOpcode(WorldPacket& recvData)
```

> **注意**：注释掉的是 `:335`（按GUID版，参数是 `""` 空名字）。
> **不要动 `:381`**（按名字版，参数是 `membername`）——
> 那个是真人踢人失败时的正常提示，注释了会让你不知道踢人为什么失败。

## 三、只做一处行不行？

| 方案 | 效果 | 副作用 |
|---|---|---|
| **只做改动二** | 刷屏消失 | bot 仍然"不算队员"，右键菜单踢 bot 无效 |
| **只做改动一** | 刷屏消失 **且** 右键能踢 bot | 需确认 `GroupBotReference` 的接口 |
| **两个都做** | **最稳** | 无 |

**建议两个都做。** 改动一治本，改动二兜底
（万一还有别的插件走别的路径，也不会刷屏）。

**如果改动一编译报错**（`GroupBotReference` 接口对不上），
**先只装改动二**，刷屏一样会消失，回头再修改动一。
