# 合并安装：step25 + step26 + step28

三个东西一次装完、**只编译一次**。分开装的话要跑三遍 CMake，太浪费时间。

| step | 内容 | 类型 |
|---|---|---|
| 25 | 血量参数扩容（治疗致死修复的下半场）| 改已有文件 |
| 26 | `.nst` NPC 状态调度器 | **新文件** |
| 28 | `.scene` 场景快照 | **新文件** + SQL |

---

## 第 1 步：跑 step25 脚本（改已有文件）

在 `D:\TrinityCore` 根目录开 **Git Bash**：

```bash
python patches/step25_血量参数扩容/fix_health_param.py .
```

> 末尾那个 `.` 是参数，别漏。

期望最后一行：`修改 11 处，跳过 0 处`

**前提**：必须已装 step24。如果没装，先跑：

```bash
bash patches/step24_治疗致死修复/apply_step24.sh
```

---

```
patches/step26_NPC状态调度/源文件/cs_npcstate.cpp   (572 行)
   -> D:\TrinityCore\src\server\scripts\Commands\cs_npcstate.cpp

patches/step28_场景快照/源文件/cs_scene.cpp          (582 行)
```

## 第 3 步：注册（改 1 个文件，加 4 行）

`src/server/scripts/Commands/cs_script_loader.cpp`

**声明区**（跟着现有的 `void AddSC_xxx_commandscript();` 排）：

```cpp
void AddSC_npcstate_commandscript();
void AddSC_scene_commandscript();
```

**调用区**（跟着现有的 `AddSC_xxx_commandscript();` 排）：

```cpp
    AddSC_npcstate_commandscript();
    AddSC_scene_commandscript();
```

## 第 4 步：重跑 CMake + 编译

新增了文件，**必须重跑 CMake**。

step25 改了 `Unit.h`，会连带重编不少文件，等的时间比平时长。

```
sql/41_scene_tables.sql
```

## 第 6 步：验证

### step25 血量

```
（把耐力堆到 4 亿，血上限 40 亿）
用治疗技能    -> 应该能一次回大量血，不再卡在 21 亿
```

### step26 .nst

```
选中任意 NPC
.nst              -> 看当前状态
.nst invuln       -> 变无敌，打不了但能选中
.nst story        -> 连选都选不中
.nst normal       -> 变回普通怪
.nst list         -> 看六档说明
```

### step28 .scene

```
找个 NPC 多的地方
.scene save 测试 30
（用 .nst 改几个 NPC 的状态，或者挪走位置）
.scene load 测试        -> 应该全部回到原样
.scene info 测试        -> 看里面有什么
.scene list             -> 所有快照
```

**重点验证两者联动**：用 `.nst story` 设的状态，
存快照再还原后应该**自动恢复**。

---

## 出错怎么办

- **编译错误** → 只发**第一条** error
- **SQL 报错** → 发错误号（1064/1264 这种）
- **指令没反应** → 检查 `cs_script_loader.cpp` 四行加了没
