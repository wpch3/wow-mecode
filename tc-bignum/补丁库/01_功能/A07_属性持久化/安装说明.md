## 一、属性持久化

### 根因

```cpp
.modify stat  →  SetStatFlatModifier()   // Unit.h:1521，只改内存
.set crit     →  ApplyRatingMod()        // Player.h:1649，只改内存
```

`characters` 表里**没有存这些修正值的字段**，所以 `SaveToDB` 不会保存，
重登时内存重建 = 归零。

装备属性为什么不丢？因为它每次登录从 `character_inventory` 重新算。
GM 手动加的是凭空来的，无处可存。

### 方案：复用幻化模块的架构

| 部件 | 做法 |
|---|---|
| 存储 | `characters.custom_playerstat`（新表，不碰官方表） |
| 缓存 | 服务器启动时全量载入内存 |
| 应用 | `PlayerScript::OnLogin`（`ScriptMgr.h:692`）重新 apply |
| 保存 | 改的时候直接写库 |

**和幻化的差异**：幻化必须插进 `SetVisibleItemSlot` 底层（有时序陷阱），
属性只需要 `OnLogin` —— 登录后才最终结算属性，不存在抢跑。

### 和 Solocraft 不冲突

| 系统 | 用哪个槽 |
|---|---|
| Solocraft | `SetStatPctModifier`（**百分比槽 PCT**） |
| 本模块 | `SetStatFlatModifier`（**固定值槽 TOTAL_VALUE**） |

不同槽位，互不覆盖。

## 二、套装等级匹配

### 根因

`cs_gearset.cpp` 的 `PickBestItem()` 原来只筛：

```cpp
if (ilvlCap && p->ItemLevel > ilvlCap)   // 只看装等
    continue;
```

**完全没有 `RequiredLevel` 检查** —— 整个文件搜不到这个词。

`ItemLevel`（装等）和 `RequiredLevel`（需求等级）是两回事，
只筛前者会发出一堆穿不上的装备。

### 修法

`PickBestItem` 和 `PickBestWeapon` 都加一个 `playerLevel` 参数：

```cpp
if (playerLevel && p->RequiredLevel > playerLevel)
    continue;
```

三个调用点传入 `GearSet::LevelCapFor(player)`，由 conf 控制开关。

### 3. World.cpp 挂载点

在 `LoadSpellInfoImmunities()` 那一段附近（或任意 `sObjectMgr->Load...` 之后）加：

```cpp
    TC_LOG_INFO("server.loading", "Loading GM stat persistence...");
    sCustomStatPersist->LoadFromDB();
```

```cpp
#include "CustomStatPersist.h"
```

### 4. 注册钩子

`cs_script_loader.cpp` 或 `ScriptLoader.cpp` 里加：

```cpp
void AddSC_statpersist_hook();      // 声明区
    AddSC_statpersist_hook();       // 调用区
```

### 5. 给 `.modify` / `.set` 加记录调用

**`cs_modify.cpp`** 的 `ModifyOneStat()` 里，`SetStatFlatModifier` 之后加：

```cpp
        // 持久化
        sCustomStatPersist->Record(target->GetGUID().GetCounter(),
            CustomStatPersistMgr::TYPE_UNITMOD, uint8(unitMod), float(amount));
```

**`cs_combathelper.cpp`** 的 `SetRating()` 里，`ApplyRatingMod` 之后加：

```cpp
            sCustomStatPersist->Record(player->GetGUID().GetCounter(),
                CustomStatPersistMgr::TYPE_RATING, uint8(cr), float(want));
```

两个文件都要 `#include "CustomStatPersist.h"`。


```
conf/worldserver.conf.d/playerstat.conf
```

新增两项：
- `PlayerStat.Persist = 1` —— 属性持久化开关
- `GearSet.MatchLevel = 1` —— 套装按等级推荐（加到任意 conf 都行）

## 六、注意事项

**① 用 Set 不是 Handle**

```cpp
player->SetStatFlatModifier(...)     // 直接赋值，重复登录不累加  ← 用这个
player->HandleStatFlatModifier(...)  // 增量修改，会越登越高      ← 不能用
```

**② 全服清空**

```sql
TRUNCATE TABLE characters.custom_playerstat;
```
然后重启服务器。

**③ 数值上限**

`amount` 是 FLOAT，理论上很大，但**建议不要超过 int32（21亿）** ——
下游的属性计算有些地方会转成 int32。
