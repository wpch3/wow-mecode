# step32 `.findmodel` 游戏内模型搜索 —— 安装说明

> 制定：2026-08-02
> 目的：解决「.model 要 displayid，但没地方查」这个卡点。
> 结论先行：**权威模型表就在你自己硬盘里**，本指令把它变成可搜索的。

---

## 零、这个指令解决什么

你问「没有分享模型 id 的网站吗」，答案是：

| 来源 | 有没有 | 对不对得上你的客户端 |
|---|---|---|
| wowhead 页面源码里的 `displayId` | 有 | **不一定**。是暴雪原版号 |
| dMorph 之类的现成列表 | 有 | **不一定**。同上 |
| **你自己的 `CreatureDisplayInfo.dbc`** | 有 | **100% 对得上** |

第三行才是真答案。你打了 HD 补丁，客户端里 `Creature\Wolf\Wolf.m2` 这个文件
被换成了 WoD 的高模，**但 displayid 到模型文件的映射关系没变**。
所以只要从你自己的 DBC 里读，读出来的号一定能用。

step31 v1 硬编码 32 个 displayid 全错，根因就是那些号是从网上抄的原版号。

---

## 一、原理（一句话）

```
displayid  --CreatureDisplayInfo.dbc-->  ModelID  --CreatureModelData.dbc-->  模型文件路径
   26232                                   2775                    Creature\Nerubian\Nerubian.mdx
```

`ModelName` 是人能读懂的路径字符串，所以**可以按关键字搜**。
服务端启动时已经把这两张表全读进内存了（`DBCStores.cpp:298/301`），
运行时零 IO，搜索就是遍历内存数组。

## 二、装文件

### 2.1 拷源文件

把 `源文件/cs_modelfind.cpp` 拷到：

```
D:\TrinityCore\src\server\scripts\Commands\cs_modelfind.cpp
```

### 2.2 加声明（`ScriptLoader.h`）

打开 `D:\TrinityCore\src\server\game\Scripting\ScriptLoader.h`，
找到其它 `_commandscript` 声明那一片，加一行：

```cpp
void AddSC_modelfind_commandscript();
```

### 2.3 加进函数体（`ScriptLoader.cpp`）—— 【最容易漏的一步】

打开 `D:\TrinityCore\src\server\game\Scripting\ScriptLoader.cpp`，
找到 **`AddCommandsScripts()` 函数体**，在里面加：

```cpp
AddSC_modelfind_commandscript();
```

> **铁律 4**：只加 2.2 的声明不加这里，编译能过，
> 但游戏里会提示「命令不存在」。这个坑踩过一次了。

### 2.4 重跑 CMake

新增了源文件，**必须重跑 CMake**（`CMakeLists.txt:154` 是自动扫描目录的，
但扫描发生在 configure 阶段）。

CMake GUI -> Configure -> Generate，然后 VS 里编译 `scripts` 项目。

## 三、用法

### 3.1 搜（主力用法）

```
.fm wolf
```

输出长这样：

```
[搜到 47 个含 "wolf" 的模型]
247   Wolf       (model 119)
843   Wolf       (model 119)
26233 DireWolf   (model 2871)
...
选中一个ID -> .model id <该ID>
```

拿到号直接：

```
.model id 26233
```

### 3.2 反查

```
.fm id 26232      看这个号是什么模型
.fm npc 24191     看这个生物用什么模型
.fm sel           看选中目标的模型
.fm me            看自己现在的模型
```

`.fm sel` 特别有用：**在世界里看到喜欢的怪，选中它，直接读出号**。

### 3.3 常用英文关键字

模型文件名是英文的，中文搜不到。常用词：

```
生物   wolf bear cat spider dragon murloc gnoll kobold naga
       demon felguard infernal succubus voidwalker
       scourge skeleton ghoul abomination lich
       elemental golem treant
种族   human orc dwarf nightelf scourge tauren gnome troll
       bloodelf draenei
坐骑   horse ram tiger raptor kodo wolf mechastrider
```

## 四、离线导出全表（可选，但很好用）

游戏里一次只回显 30 条。想要完整表格：

```bash
python 工具库/tools/dump_models.py "D:\TC-Build\bin\RelWithDebInfo\dbc"
```

生成 `模型总表.csv`，**双击用 Excel 打开**，列是：

```
displayid | modelid | 模型短名 | 模型完整路径 | 缩放 | 玩家型
```

Excel 里筛选排序随便玩，比聊天框舒服得多。

也可以直接命令行搜：

```bash
python 工具库/tools/dump_models.py "D:\TC-Build\bin\RelWithDebInfo\dbc" -k wolf
```

> 脚本已用构造的真 DBC 二进制实测通过：
> 正确解析头部、字符串池、缩放浮点数，正确跳过坏行。

## 五、已知行为（不是 bug）

| 现象 | 原因 |
|---|---|
| 搜中文搜不到 | 模型文件名是英文的，这是暴雪定的 |
| 同一个模型出现多次 | 多个 displayid 共用一个 ModelID，只是贴图不同。**都能用** |
| 标了「玩家型模型」的 | `ExtendedDisplayInfoID != 0`，外观靠装备决定，变过去可能是裸模 |
| `.model` 变完性别变了 | `Unit.cpp:10938` `SetDisplayId` 里带 `SetGender`，官方逻辑 |
| 搜到的号 `.model` 后隐形 | 该模型文件你的客户端里没有（补丁没装全） |
