## 二、为什么零补丁

**核心底牌**（已逐行核实）：

```cpp
SpellMgr.h:669   SpellInfo const* GetSpellInfo(uint32) const   // public，用这个
SpellInfo.h:387  std::array<SpellEffectInfo, 3> _effects       // public 区
SpellInfo.h:215  int32  BasePoints                             // 伤害/治疗数值
SpellInfo.h:226  uint32 ChainTargets                           // 链式跳跃
SpellInfo.h:342  uint32 RecoveryTime                           // 冷却
```

> **踩过的坑**：`SpellMgr.h:671` 的 `_GetSpellInfo()` 虽然是非 const，
> 但它在 **`SpellMgr.h:670` 的 private 区**，外部调用报 `C2248`。
> 官方自己的做法是 `const_cast`，见 `SpellMgr.cpp:4970`：
> ```cpp
> if (SpellInfo* spellInfoTrigger = const_cast<SpellInfo*>(GetSpellInfo(...)))
> ```
> 本模块沿用这个写法。

服务器启动时可以**运行时改写任何现有法术**。而客户端只负责画图标、播动画，
**实际结算全在服务端** —— 所以改数值、改冷却、改目标数，玩家完全不用下补丁。

这跟「加全新技能」是两回事，那个才必须改 `Spell.dbc`。

---

## 三、设计原则

按《老职业魔改-十职业扩充方案.txt》第一部：

1. **不做数值膨胀** —— 补功能位，不是单纯加伤害
2. **每个职业补它缺的**，不是它已经强的
3. **和新职业错位**，不抢饭碗

### 特别考虑了你的环境叠加

| 已有系统 | 影响 |
|---|---|
| Solocraft | 5-40 倍属性 |
| speed.conf | CD 压缩到 85%/80%/90% |
| 大数值改造 | 装备属性上限 21 亿 |

所以这里用的是**温和倍率**（多数 1.3-1.5 倍），而不是文档里写的理论值。
觉得不够爽调 `CustomSpell.GlobalScale` 就行。

**所有数值都有 int32 溢出保护**（21 亿封顶，不会回绕成负数）。

## 四、安装

### 1. 放源文件

```
源文件/CustomSpellTweak.h    →  D:\TrinityCore\src\server\game\Spells\CustomSpellTweak.h
源文件/CustomSpellTweak.cpp  →  D:\TrinityCore\src\server\game\Spells\CustomSpellTweak.cpp
```

> 放 `Spells` 目录（已存在），跟 `CustomSpeed.*` 一个地方。

### 2. 打补丁

```bash
cd /d/TrinityCore
bash step18_老职业技能/apply.sh
```

改动极小：**World.cpp +7 行 0 删除**。

挂载点选在 `LoadSpellInfoImmunities()` 之后 —— 此时所有 SpellInfo 已加载完毕，
改动不会被后续流程覆盖。

### 2b.（可选）召唤数量补丁

**只有想让「亡者大军 10 只」生效才需要这步。**

```bash
bash step18_老职业技能/apply_summon.sh
```

**为什么单独一个补丁**：`SpellEffects.cpp:2281` 有个硬编码白名单

```cpp
switch (properties->ID) {
    case 64: case 61: ... case 713:
        numSummons = (damage > 0) ? damage : 1;   // 白名单里才读 BasePoints
        break;
    default:
        numSummons = 1;                            // 亡者大军走这里，写死 1
}
```

亡者大军的 `SummonProperties ID` 不在白名单里，所以**光改 BasePoints 无效**。

本补丁把 `default` 改成 `numSummons = (damage > 1) ? damage : 1;`
—— 只在 `BasePoints > 1` 时生效，**不影响其他任何召唤法术的原有行为**。

只改 1 行，不用重跑 CMake。

### 3. 重跑 CMake + 编译

**必须重跑**（新增源文件）。

### 4. 放 conf

```
conf/worldserver.conf.d/customspell.conf  →  D:\TC-Build\bin\RelWithDebInfo\worldserver.conf.d\
```

### 5. 重启

⚠️ **法术数据在启动时加载，`.reload config` 对本模块无效，必须重启。**

## 五、conf 配置

| 项 | 默认 | 说明 |
|---|---|---|
| `CustomSpell.Enable` | 1 | 总开关，0 = 全部恢复原版 |
| `CustomSpell.GlobalScale` | 1.0 | 全局倍率，范围 0.1-10.0 |
| `CustomSpell.Warrior` ~ `Druid` | 1 | **分职业开关**，某个职业过强就单独关 |

**觉得整体太强**：`GlobalScale = 0.5`
**觉得某职业过强**：`CustomSpell.Mage = 0`

## 十、以后加新改动

`CustomSpellTweak.cpp` 里对应职业的函数加一行：

```cpp
ScaleEffect(法术ID, 1.5f, C, "中文描述");      // 放大数值
ScaleCooldown(法术ID, 0.7f, C, "中文描述");    // 缩短冷却
AddChainTargets(法术ID, 2, C, "中文描述");     // 链式跳跃 +2
SetSummonCount(法术ID, 10, C, "中文描述");     // 召唤数量
SetMaxTargets(法术ID, 5, C, "中文描述");       // 最大目标数
```

**每条都会自动记日志**，失败会说明原因（法术不存在/没有冷却/不是链式法术）。
