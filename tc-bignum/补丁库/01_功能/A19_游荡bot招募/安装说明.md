# step33 游荡 bot 招募开关 —— 安装说明

> 制定：2026-08-02
> 需求（用户原话）：「我发现野外游荡的机器人我无法招募甚至无法对话」
> 用户要求：「这种需要做开关的就做开关吧」

---

## 零、先说清楚这个改动的性质

这是**本项目第一次改上游 NPCBot 的源码**（之前 32 个 step 都是新增文件）。
所以要格外小心，下面每一处都给了**原文 + 精确行号**。

### 为什么游荡 bot 默认不能对话 —— 这是设计，不是 bug

```cpp
// bot_ai.cpp:7703-7711  OnGossipHello
if (... ||
    (!player->IsGameMaster() && (IsWanderer() || me->IsSummon())))
{
    player->PlayerTalkClass->SendCloseGossip();   // <- 直接关掉对话框
    return true;
}
```

游荡 bot 是**世界背景**，作者故意不让玩家招募。
GM 可以对话（`IsGameMaster()` 例外），普通玩家不行。

---

## 一、【重要】只改一处是不够的 —— 有两道关卡

这是我实查源码时发现的关键点，**如果只改第一处，你会遇到
「对话框能打开了，但里面没有招募按钮」**。

### 关卡 1：`bot_ai.cpp:7707` —— 决定能不能【打开对话框】

```cpp
(!player->IsGameMaster() && (IsWanderer() || me->IsSummon())))
```

### 关卡 2：`bot_ai.cpp:7761` —— 决定【招募按钮显不显示】

```cpp
if (player_guidlow != _botData->owner && IAmFree() && !IsWanderer())
{
    uint32 cost = BotCfg::GetNpcBotCostHire(player->GetLevel(), _botclass);
    ...
    AddGossipItemFor(player, GOSSIP_ICON_TAXI, ... GOSSIP_SENDER_HIRE ...);
}
```

`!IsWanderer()` 在这里，所以游荡 bot **永远不会被加上招募选项**。

**两处都要改，缺一不可。**

---

## 二、【必读】一个必须知道的副作用

我查了 `_wanderer` 这个标记的全部生命周期：

```
bot_ai.cpp:20412  void bot_ai::SetWanderer() { if (IAmFree()) { _wanderer = true; ... } }
bot_ai.cpp:247    InitializeAI(): if (!me->GetSpawnId() && !IsTempBot() && !me->IsSummon()) SetWanderer();
```

**全仓库搜索结果：`_wanderer` 只有置为 true 的地方，没有任何地方置回 false。**

### 这意味着什么

招募一个游荡 bot 之后，它**仍然带着 `_wanderer = true` 标记**。
而源码里有 **30 多处**在判断 `IsWanderer()`，包括：

| 行号 | 行为差异 |
|---|---|
| 1223 | 骑乘逻辑不同 |
| 4323 | 跟随距离 `followdist + 10`（跟得更远）|
| 5970 | `CanSit() && !IsWanderer()` —— **不会坐下** |
| 14888 | `SetPvP(master->IsPvP() \|\| IsWanderer())` —— **强制开PvP** |
| 15732 | `_chaseTimer = 5000`（不是普通bot的20000）|
| 15876 | 复活计时不同 |

**所以招募来的游荡 bot 行为会和正常 bot 有细微差异。**

### 更重要的：持久化问题

```cpp
bot_ai.cpp:247   if (!me->GetSpawnId() && ...)  SetWanderer();
```

游荡 bot 是**动态生成的，没有 SpawnId**（不在 `creature` 表里）。
这意味着：

> **服务器重启后，这个 bot 不会以同样的身份回来。**

它可能：
- 消失（因为动态生成的实体不落库）
- 或者变成一个新的游荡 bot

**这不是本补丁引入的问题，是游荡 bot 的固有性质。**

### 结论：这个功能适合谁

| 场景 | 适不适合 |
|---|---|
| 想临时拉个野外 bot 打一场 | **适合** |
| 想收集/长期培养某个游荡 bot | **不适合**，重启会丢 |
| 单机自己玩，图个方便 | **适合** |

**所以默认关闭，想用再开。**

### 改动 4：`botconfig.cpp` 第 739-742 行附近

**找到这一段**（botconfig.cpp:739）：
```cpp

{
    return _enableNpcBots;
}
```

**在它下面加一个函数**：
```cpp
bool BotCfg::IsWanderingBotHireEnabled()
{
    return _enableWanderingBotHire;
}
```

---

### 改动 5-A：`bot_ai.cpp` 第 7707 行（开对话框）

**找到这一行**（bot_ai.cpp:7707，在 `OnGossipHello` 里）：
```cpp
        (!player->IsGameMaster() && (IsWanderer() || me->IsSummon())))
```

**整行替换为**：
```cpp
        (!player->IsGameMaster() && ((IsWanderer() && !BotCfg::IsWanderingBotHireEnabled()) || me->IsSummon())))
```

**改动含义**：
- 开关关闭时：`IsWanderer() && true` = 原逻辑，游荡bot照样关对话框
- 开关打开时：`IsWanderer() && false` = false，游荡bot可以对话
- `me->IsSummon()` 那部分**没动** —— 召唤物永远不能对话

---

### 改动 5-B：`bot_ai.cpp` 第 7761 行（显示招募按钮）

**找到这一行**（bot_ai.cpp:7761）：
```cpp
    if (player_guidlow != _botData->owner && IAmFree() && !IsWanderer())
```

**整行替换为**：
```cpp
    if (player_guidlow != _botData->owner && IAmFree() && (!IsWanderer() || BotCfg::IsWanderingBotHireEnabled()))
```

**改动含义**：
- 开关关闭：`!IsWanderer()` 原逻辑
- 开关打开：游荡 bot 也会被加上招募按钮

> **注意**：`bot_ai.cpp` 需要能访问 `BotCfg`。
> 第 7703 行已经在用 `BotCfg::IsNpcBotModEnabled()`，
> **说明头文件已经引入，不用额外 include。**

## 四、配置文件

在 `worldserver.conf.d\` 目录下新建一个文件（或加到已有的 npcbot conf 里）：

```ini
[worldserver]

#
#    NpcBot.WanderingBot.AllowHire
#        允许玩家招募野外游荡的 NPCBot
#        Default: 0 (关闭，维持上游原版行为)
#                 1 (开启，玩家可以和游荡bot对话并招募)
#
#    注意：招募来的游荡bot仍带 wanderer 标记，行为与普通bot有差异
#          （不会坐下、强制PvP、跟随距离更远），且服务器重启后不保留。
#

NpcBot.WanderingBot.AllowHire = 0
```

> 铁律：conf 文件**必须有 `[worldserver]` 段头**，
> 注释**必须独立成行**（不能行尾 `#`）。

## 八、这次没做什么（避免误解）

| 没做 | 原因 |
|---|---|
| 让游荡 bot 招募后变成普通 bot | 要清 `_wanderer` 标记，涉及 30+ 处判断，风险太大 |
| 游荡 bot 持久化 | 要给它们分配 SpawnId 写进 creature 表，是另一个大工程 |
| `.bots` 批量指令 | 排在下一批，本 step 只做开关 |

**先把最小可用的做通，验证没问题再往上叠。**
