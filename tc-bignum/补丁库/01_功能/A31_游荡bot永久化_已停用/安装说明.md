# step49 游荡 bot 永久化开关 `.pin` —— 安装说明

> 需求：「给游荡bot做个是否永久存在的开关，可以让npcbot重启就消失或者永久存在。
> 这个功能不用做gm专用，只不过除去gm2-3其他的都最多只能留4个」

---

## 零、先说清楚原理（这决定了它为什么可靠）

### 游荡 bot 为什么重启就没了

```cpp
// botdatamgr.cpp:210
bot->LoadBotCreatureFromDB(0, map, true, true, bot_id, &spawnPos);
//                         ^          ^^^^
//                         spawnId=0  generated=true

// Creature.cpp:3531
CreatureData const* data = generated ? nullptr : sObjectMgr->GetCreatureData(spawnId);
// generated=true -> 【完全不读 creature 表】，纯内存对象
```

上游注释写得很直白（`botdatamgr.cpp:460`）：

```cpp
//We do not create CreatureData for generated bots
```

**游荡 bot 从来没进过数据库。**

### 怎么让它永久 —— 照抄官方 `.npcbot spawn`

`botcommands.cpp:3860-3873` 的落库四步：

```
1. BotDataMgr::AddNpcBotData(...)        -> 写 characters_npcbot
2. creature->SaveToDB(...)                -> 写 world.creature
3. LoadBotCreatureFromDB(db_guid, map)    -> 用真 spawnId 重载
4. sObjectMgr->AddCreatureToGrid(...)     -> 挂进网格
```

**不是我发明的流程，是官方自己的做法。**

### 一个致命约束（我实查发现的）

```cpp
// botdatamgr.cpp:1168-1176  服务端启动时会交叉校验
for (auto const& [_, cdata] : sObjectMgr->GetAllCreatureData())
    if (cdata.id >= BOT_ENTRY_BEGIN && ...IsNPCBot() && 不在 characters_npcbot 里)
        invalid_ids.push_back(cdata.id);
...
ABORT_MSG("Invalid NPCBot spawns found in `creature` table
           having no data in `characters_npcbot` table!");
```

**只写 `creature` 不写 `characters_npcbot` = 下次启动直接崩服。**

所以本补丁**两张表同时写**，顺序严格照抄官方。

## 一、依赖：必须先装 step44

代码里用了 `UnsetWanderer()`，那是 **step44 新增的方法**。

```cpp
// 第5步
if (bot_ai* ai = bot->GetBotAI())
    ai->UnsetWanderer();
```

**为什么必须有这一步**：

```cpp
// Creature.cpp:3617
bool Creature::IsWandererBot() const { return bot_AI ? bot_AI->IsWanderer() : ...; }
```

1. 它会**继续按路点游走**，"固定"就没意义了

**如果你还没装 step44**，先去装（`patches/step44_两个bug修复/bug1-招募游荡bot闪退.md`），
否则这里编译不过。

## 四、用法

```
.pin                 把【选中的】游荡bot设为永久
.pin off             取消永久（重启后消失）
.pin list            列出你固定的bot
.pin count           看还能固定几个
```

中文别名：`.pin 固定` / `取消` / `列表` / `数量`

### 权限分级（按你的要求）

| 账号等级 | 上限 |
|---|---|
| `SEC_GAMEMASTER`(2) / `SEC_ADMINISTRATOR`(3) | **不限** |
| `SEC_PLAYER`(0) / `SEC_MODERATOR`(1) | **4 个** |

非 GM 还有一条限制：**只能取消自己固定的 bot**。

### "谁固定的"存在哪

用 `world.creature.ScriptName` 存 tag，格式 `pin:<玩家guid低位>`。

**为什么用这个字段**：它对 NPCBot 完全无副作用
（bot 走 `bot_ai` 不走 ScriptName），且不占用任何业务字段。

## 五、验证清单

```
[ ] 编译通过，服务端能启动
[ ] .pin count                看到 "0 / 4"（非GM）或 "GM不限量"
[ ] 找一个游荡bot，选中
[ ] .pin                      提示"已固定"，给出 entry 和 spawnId
[ ] 观察它                    【重点】应该【停止游荡】，站在原地
[ ] .pin list                 能看到它
[ ] 【关键】重启服务端
[ ] 它还在原地                <- 这就是"永久存在"
[ ] .pin off（选中它）        提示已取消
[ ] 再重启                    它不见了（变回普通游荡bot池）
[ ] 非GM账号连续固定5个        第5个应被拒绝
```

**最关键的是"重启后还在"那一条** —— 那是这个功能的全部意义。

## 六、如果想让普通玩家也能用

指令挂的是 `rbac::RBAC_PERM_COMMAND_WORLDTOOLS`（step21 自建 = 71012），
**普通玩家默认没有这个权限**。

想开放给所有人：

```sql
-- auth 库
INSERT INTO `auth`.`rbac_default_permissions` (`secId`, `permissionId`, `realmId`)
VALUES (0, 71012, -1)
ON DUPLICATE KEY UPDATE `permissionId` = `permissionId`;
```

`secId=0` 就是 `SEC_PLAYER`。**改完要重启**（RBAC 权限有缓存）。

> **提醒**：开放后所有玩家都能固定 4 个 bot。
> 100 个玩家 = 400 个永久 bot，会实打实占服务器资源。
> 建议先自己用，觉得稳了再开放。

---

## 七、和数量上限的关系（step45/46）

固定的 bot 会**永久占用一个 bot 模板**（从 spare 池里拿走）。

```
可用游荡bot = 模板总数 - characters_npcbot 行数
```

所以固定得多了，游荡的就少了。如果发现游荡 bot 变少：
- 要么 `.pin off` 释放几个
- 要么用 step46 的 SQL **多生成一些模板**
