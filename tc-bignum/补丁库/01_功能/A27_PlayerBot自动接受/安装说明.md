## 三、怎么用

### 默认行为（什么都不用做）

bot 一上线就会**自动接受**：

| 项目 | 默认 | 说明 |
|---|---|---|
| 组队邀请 | **开** | 你邀请它，1秒内自动进队 |
| 公会邀请 | **开** | 自动入会 |
| 复活请求 | **开** | 有人给它放复活术自动接 |
| 召唤确认 | **开** | 术士仪式/会面石自动过去 |
| 死后释放 | **开** | 死了自动变鬼魂去墓地，不然它就一直躺着 |
| 决斗请求 | **关** | 见下方说明 |
| 交易请求 | **关** | **只开窗口，不点确认**，见下方说明 |

**为什么决斗默认关**：

1. 你想切磋一下它就秒接，反而没了「邀战」的仪式感
2. step43 对手系统要用决斗演「棋逢对手」的戏，自动接受会抢戏

想开：`.pbot auto Evirstara duel on`

**交易为什么默认关，而且只做一半**：

交易是**唯一一个能让你真的丢东西**的功能。如果做成"全自动点确认"：

```
你往交易框放了东西 -> bot 秒点确认 -> 东西没了，撤都来不及
```

这不是方便，这是事故。所以这条**只做一半**：

- 自动**打开**交易窗口（相当于 bot 点了"是"）
- **不**自动点最终的"确认交易"

这样你能正常给它东西、从它那儿拿东西，**但最后那一下永远由你决定**。

想开：`.pbot auto Evirstara trade on`（开的时候会再提醒你一次）

### 指令控制（你要的"也要有指令操作"）

```
.pbot auto                              看所有bot的开关状态
.pbot auto <角色名>                     看某个bot的开关
.pbot auto <角色名> <项目> <on|off>     单独开关某一项
.pbot auto all <项目> <on|off>          一次改所有bot
.pbot auto master <on|off>              总开关（应急一键全停）

.pbot accept <角色名|all>               立刻处理挂起的邀请（不等轮询）
```

**项目**：`group` / `guild` / `duel` / `res` / `summon` / `trade` / `release` / `all`

**中文别名**：`自动` / `接受`，项目也能用
`组队`/`公会`/`决斗`/`复活`/`召唤`/`交易`/`释放`/`全部`，开关能用 `开`/`关`

举例：

```
.pbot auto Evirstara duel on          让它接受决斗
.pbot auto all guild off              所有bot都不再自动入会
.pbot auto master off                 全部停掉（应急）
.pbot 自动 Evirstara 组队 关           中文也行
.pbot accept Evirstara                我不想等这1秒，马上接
```

## 七、性能说明

`ScriptMgr.h:256` 的注释明确写着 `don't execute too heavy code here`，
所以做了两层节流：

1. **每 1000ms 才扫一次**（不是每帧）—— 邀请是低频事件，1秒延迟感知不到，
   但比每帧扫（约50ms一次）省 **20 倍**开销
2. **只遍历 `g_pbots`**（通常个位数），真人玩家完全不参与

即使将来 bot 数量涨到 100 个，每秒也只是 100 次指针查找 + 几个布尔判断，
可以忽略不计。
