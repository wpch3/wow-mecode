## 一、无需做的（查完确认不用做）

### 1.1 复活响应包 —— 底层是同一个函数

```cpp
// MiscHandler.cpp  HandleResurrectResponse
if (!GetPlayer()->IsResurrectRequestedBy(packet.Resurrecter))
    return;
GetPlayer()->ResurrectUsingRequestData();     // <- 就是 step42 调的那个
```

step42 的 `TryAcceptResurrect()` 直接调 `ResurrectUsingRequestData()`，
**已经等价于点了"接受"**。重复做没有意义。

### 1.2 好友请求 —— 单向添加

```
SocialHandler.cpp  HandleAddFriendOpcode
```

加好友**不需要对方同意**（魔兽从来如此），没有"待确认"状态。

### 1.3 副本难度 / 团队难度

```
WorldSession.h:1106  HandleSetDungeonDifficultyOpcode
WorldSession.h:1107  HandleSetRaidDifficultyOpcode
```

由**队长**设定，成员自动跟随，没有弹窗。

### 1.4 会面石 / 术士仪式

```
SpellEffects.cpp:3988  unitTarget->ToPlayer()->SendSummonRequestFrom(unitCaster);
Player.cpp:23603       SendSummonRequestFrom -> 设 m_summon_expire
Player.cpp:23598       HasSummonPending() { return m_summon_expire >= now; }
```

走的就是召唤那条路，**step42 的 `TryAcceptSummon()` 已覆盖**。

## 二、做不了的两条 —— 说清楚卡在哪

> 按最高铁律，说"做不到"必须回答三个问题。下面逐条回答。

### 2.1 准备确认（Ready Check）

#### 【问题1】具体挡住了哪一行？

```cpp
// Group.cpp:2121  BroadcastPacket —— 队长发起准备确认时走这里
for (GroupReference* itr = GetFirstMember(); itr; itr = itr->next())
{
    Player* player = itr->GetSource();
    ...
    if (player->GetSession() && (group == -1 || itr->getSubGroup() == group))
        player->SendDirectMessage(packet);      // <- bot 无 socket，包被丢弃
}
```

```cpp
// WorldSession.cpp:211  SendPacket
if (!m_Socket)
    return;                                     // <- 这里丢的
```

**bot 根本不知道有人发起了准备确认。**

#### 【问题2】能不能轮询状态绕过？

不能。查过了：3.3.5 的准备确认是**纯广播，服务端不保存状态**：

```
Group.h:309   void BroadcastReadyCheck(WorldPacket const* packet);
Group.h:310   void OfflineReadyCheck();
```

Group 类里**没有** `m_readyCheckStarted` / `m_readyCheckMembers` 这类字段
（后来的版本才有）。没有状态 = 没法轮询。

#### 【问题3】有没有别的实现路径？

**有，但要改上游一行。**

```cpp
// Group.cpp:2145  OfflineReadyCheck()
for (member_citerator citr = m_memberSlots.begin(); citr != m_memberSlots.end(); ++citr)
{
    Player* player = ObjectAccessor::FindConnectedPlayer(citr->guid);
    if (!player || !player->GetSession())       // <- 只对【没有session的】自动回"未准备"
    {
        WorldPacket data(MSG_RAID_READY_CHECK_CONFIRM, 9);
        data << citr->guid;
        data << uint8(0);                       // 0 = 未准备
        BroadcastReadyCheck(&data);
    }
}
```

**PlayerBot 有 session**，所以不走这个分支 ->
队长那边会一直等它应答 -> **转圈到超时**。

改法（一行）：在这个 if 里加上"或者它是 bot 会话"，并回 `uint8(1)`（已准备）。

#### 为什么这次没做

1. **要改上游文件**（Group.cpp），前面几条都是零上游改动，性质不同
2. **影响面**：`OfflineReadyCheck` 是全服所有队伍都走的路径
3. **收益低**：准备确认主要用于团本开怪前，你现在 bot 数量还是个位数

**已记录，等你说要就做**，改动很小。

### 2.2 LFG 随机副本提议

#### 【问题1】挡在哪？

同样是"服务端有状态但拿不到"：

```
LFGMgr.h:149  struct LfgProposal;              <- 只有前向声明
LFGMgr.h:159  typedef std::map<uint32, LfgProposal> LfgProposalContainer;
```

`LfgProposalContainer` 的实例是 **LFGMgr 的私有成员**，
外部没有 `GetProposalFor(guid)` 这类公开接口。

#### 【问题2】需要什么？

给 LFGMgr 加一个 public 查询方法，或者直接在 LFG 的提议流程里判 bot 会话。

#### 【问题3】别的路？

`WorldSession.h:1124 HandleLfgProposalResultOpcode` 是 public，
**可以直接调**——但前提是知道 `proposalID`，而那个 ID 只在提议包里，
bot 收不到包（同 2.1 的原因）。

#### 为什么没做

**这个我建议真的不要做。** 理由不是技术难度：

随机副本队列会把 bot **和真人玩家匹配到一起**。
bot 现在还没有战斗 AI，进本就是站着不动 —— 这会**影响到别的真实玩家**。

等 bot 有了完整战斗 AI 再考虑，那时候它进本才是帮忙而不是拖累。

## 三、如果你要做准备确认，改法在这

**只改一处，Group.cpp:2145**

需要先给 WorldSession 暴露一个"是不是bot会话"的公开查询
（step40 已经加了 `m_isBotSession` 成员，只需再加个 getter）。

```cpp
// WorldSession.h  加在 public 段（577行 QueuePacket 附近）
bool IsBotSession() const { return m_isBotSession; }
```

```cpp
// Group.cpp:2149  改这个 if
    Player* player = ObjectAccessor::FindConnectedPlayer(citr->guid);
    if (!player || !player->GetSession())
```

改成：

```cpp
    Player* player = ObjectAccessor::FindConnectedPlayer(citr->guid);
    bool isBot = player && player->GetSession() && player->GetSession()->IsBotSession();
    if (!player || !player->GetSession() || isBot)
    {
        WorldPacket data(MSG_RAID_READY_CHECK_CONFIRM, 9);
        data << citr->guid;
        data << uint8(isBot ? 1 : 0);      // bot 回"已准备"，离线的回"未准备"
        BroadcastReadyCheck(&data);
    }
```

**这样 bot 会立刻回"已准备"，队长不用等它。**

要做的话说一声，我把它做成正式补丁（含测试）。
