# A38 让游荡 bot 待在你要的位置

## 问题

`.npcbot move` 对游荡 bot 无效，报 `has data but no live creature`
或者提示成功了但 bot 根本没过来。

## 为什么（一句话）

`bot_ai.cpp:19054-19067`：

```cpp
void bot_ai::GetHomePosition(uint16& mapid, Position* pos) const
{
    if (IsWanderer())
    {
        mapid = _travel_node_cur->GetMapId();    // <- 读【路点】
        pos->Relocate(homepos);                   // <- 读【内存】
    }
    else
    {
        CreatureData const* data = me->GetCreatureData();
        mapid = data->mapId;
        pos->Relocate(data->spawnPoint);          // <- 读【creature 表】
    }
}
```

**游荡 bot 只认路点，不读 `creature` 表。**
`.npcbot move` 改的正是 `creature` 表 -> 改了也没用。

这不是 bug，是两套定位系统。要控制游荡 bot 的位置，得从路点下手。

---

## 三种方案，按需选

| 方案 | 效果 | 改动量 | 可逆 |
|---|---|---|---|
| **方案1** 挪路点 | bot 游荡范围整体搬到你要的区域 | 一条命令 | 可逆 |
| **方案2** 转回固定 bot | bot 彻底站桩在你脚下 | 一条 SQL + 重启 | 可逆 |
| **方案3** 建专属路点圈 | bot 在你指定的几个点之间来回巡逻 | 几条命令 | 可逆 |

---

## 方案1：把路点挪过来（最快，不用重启）

游荡 bot 认路点，那就**把路点搬到你面前**。

### 步骤

1. 站到你想让 bot 待的位置
2. 选中那个游荡 bot
3. 查它当前在哪个路点：

```
.npcbot wp info
```

4. 把那个路点挪到你脚下：

```
.npcbot wp move
```

（选中 bot 时会自动找到它所在的 wp；也可以 `.npcbot wp move #wpId` 指定）

### 原理（实查源码 `botcommands.cpp:1277-1308`）

```cpp
wp->Relocate(player);                                  // :1298  挪到你脚下
if (Creature* creature = wp->GetCreature())
    creature->NearTeleportTo(*player);                 // :1300
WorldDatabase.PExecute(
    "UPDATE creature_template_npcbot_wander_nodes SET x={},y={},z={},o={} WHERE id={}",
    wp->m_positionX, wp->m_positionY, wp->m_positionZ,
    wp->GetOrientation(), wp->GetWPId());              // :1302  落库，重启不丢
```

**限制**（`:1291`）：不能跨地图挪，`wp->GetMapId() != player->GetMapId()` 会被拒绝。

**注意**：这个路点是**公共的**，所有路过的游荡 bot 都会用它。
挪了之后那一片的 bot 都会往这边走。想要专属的用方案3。

## 方案2：把它转回固定据点 bot（彻底站桩）

如果这个 bot 你压根不想让它游荡，直接摘掉游荡身份。

### 步骤

1. 跑 SQL（把 70231 换成你要的 entry）：

```sql
UPDATE `world`.`creature`
SET `ScriptName` = ''
WHERE `id` = 70231;
```

2. **重启服务端**（`ScriptName` 是 `LoadCreatures` 时读进内存的，热改无效）

3. 重启后 bot 会站在 `creature` 表记的坐标上（你的是 map 0, x=-8936.7, y=-129.2 暴风城）

4. 现在 `.npcbot move` **对它生效了** —— 因为它走 `GetHomePosition` 的 else 分支，读 `creature` 表

### 为什么必须重启

`_wanderer` 这个标志位一旦设上就**没有任何代码把它设回 false**：

```
bot_ai.cpp:20416   _wanderer = true;     <- 全仓库唯一的写入点
bot_ai.h:762       bool _wanderer{};     <- private，无 setter
```

所以只能靠重启时重新走 `InitializeAI()` 来决定身份。

用 `补丁库/01_功能/A36_持久化游荡bot/sql/分配三层架构.sql`，
里面有方案 A/B/C/D 四种分配方式。

## 方案3：给它建专属巡逻路线（最灵活）

想让 bot 在你的据点附近来回走，而不是满世界跑。

### 步骤

1. 走到第一个点，建路点：

```
.npcbot wp add 0 我的据点1
```

2. 走到第二个点：

```
.npcbot wp add 0 我的据点2
```

3. 查看新建的 wp 编号：

```
.npcbot wp list
```

4. 把两个点互相连接（假设编号是 5100 和 5101）：

```
.npcbot wp setlinks 5100 5101
.npcbot wp setlinks 5101 5100
```

5. 限制等级段，只让你想要的 bot 用（可选）：

```
.npcbot wp setlevels 5100 1 80
```

6. **重启服务端**让路点图重新加载

### 命令出处（全部实查）

```
botcommands.cpp:504   "add"       HandleNpcBotWPAddCommand
botcommands.cpp:503   "move"      HandleNpcBotWPMoveCommand
botcommands.cpp:505   "del"       HandleNpcBotWPDeleteCommand
botcommands.cpp:506   "list"      HandleNpcBotWPListCommand
botcommands.cpp:508   "go"        HandleNpcBotWPGoCommand
botcommands.cpp:509   "setlevels" HandleNpcBotWPSetLevelsCommand
botcommands.cpp:514   "setlinks"  HandleNpcBotWPSetLinksCommand
botcommands.cpp:516   "info"      HandleNpcBotWPInfoCommand
```

`wp add` 会写库（`botcommands.cpp:1389`）：

```sql
INSERT INTO creature_template_npcbot_wander_nodes
  (id,mapid,x,y,z,o,zoneId,areaId,minlevel,maxlevel,flags,name,links)
```

## 找不到 bot 在哪？

游荡 bot 满世界跑，先定位再操作：

```
.npcbot go 70231          -- 传送到 bot 当前位置
```

出处 `botcommands.cpp:2681-2699`，有 `if (!bot)` 防护，不会崩。

如果提示 `NpcBot 70231 is not found!`，说明它正在**跨地图传送途中**
（`bot_ai.cpp:7395-7402` -> `BotMgr::TeleportBot`，走延迟回调，
中途 `RemoveFromWorld` + `RemoveFromMap`，短暂不在注册表里）。

等几秒再试。

## 推荐

看你到底想要什么：

- **就想让这个 bot 别乱跑，待在据点** -> **方案2**（一条 SQL + 重启，最干净）
- **想让它在据点附近活动但仍是游荡 bot** -> **方案3**
- **只是临时把它叫过来** -> `.npcbot go 70231` 你过去，或**方案1**

你的三层架构里，「固定据点 NPC」这层本来就该用**方案2**。
现在 15 个 bot 全是游荡的，第 1 层是空的。
