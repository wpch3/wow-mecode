## 一、先说清楚现状（彻查结论）

| 系统 | 现状 | 缺什么 |
|---|---|---|
| A20 伙伴关怀 | **只有 bot -> 你**（单向） | 你 -> bot 完全没做 |
| A32 羁绊系统 | **只有 SQL 表，零行代码** | 全部逻辑 |
| 上游「给予物品」按钮 | 是「让bot当场喝掉」不是赠予 | 语义就不对 |

**你点了没反应的原因**：那个按钮的过滤器要求物品必须有
「TargetA==TARGET_UNIT_CASTER」的法术效果，
**普通食物/材料/装备全被挡掉**，列表是空的。

详见同目录 `彻查报告-给予物品为什么没反应.md`。

## 二、重大发现：NPCBot 有现成的「银行」系统

我实查到一套完整的 public API（`botdatamgr.h:282-287`）：

```cpp
static bool CanDepositBotBankItemsCount(ObjectGuid playerGuid, uint32 items_count);  // :282
static BotBankItemContainer const* GetBotBankItems(ObjectGuid playerGuid);           // :283
static uint32 GetBotBankItemsCount(ObjectGuid playerGuid);                           // :284
static Item* WithdrawBotBankItem(ObjectGuid playerGuid, ObjectGuid::LowType itemGuidLow); // :285
static void DepositBotBankItem(ObjectGuid playerGuid, Item* item);                   // :286
```

**全部 public(203段)。**

底层是真实物品存储（`botdatamgr.cpp:4045`）：

```cpp
trans->PAppend("INSERT INTO characters_npcbot_gear_storage (guid, item_guid) VALUES ({}, {})", ...);
```

存的是 `item_guid`，JOIN `item_instance` —— **真物品，不是数字**。

### 但有个限制要注意

**key 是 `playerGuid` 不是 `botGuid`** —— 这是"玩家的bot共用仓库"，
不是"每个bot自己的背包"。

**所以要额外建一张表记录「哪件物品是给哪个bot的」。**

## 三、系统设计（不局限于原想法）

### 3.1 三层结构

```
第1层  赠予/接收        物品真实转移
第2层  情感反馈         bot 说什么、做什么
第3层  羁绊累积         记录、等级、解锁
```

**三层都要 NPCBot 和 PlayerBot 各一套实现。**

### 3.2 第1层：赠予通道

#### NPCBot 版

**新建 gossip 菜单项**（不改上游那个"使用消耗品"）：

```
右键bot -> [赠予物品]
             |
             +-- 列出背包【所有可交易物品】（宽松过滤，只排除任务物品/绑定物品）
             |
             +-- 选中 -> Player::DestroyItem 扣除
             |          -> BotDataMgr::DepositBotBankItem 存入
             |          -> 新表记录归属哪个bot
             |
             +-- 触发第2层情感反馈
```

**要用的 API（已实查）**：
```
Player.h:1161   void DestroyItem(uint8 bag, uint8 slot, bool update)   public(904段)
botdatamgr.h:286  DepositBotBankItem(ObjectGuid, Item*)                public(203段)
botdatamgr.h:282  CanDepositBotBankItemsCount(...)                     public(203段)  <- 先查容量
```

#### PlayerBot 版（更简单）

PlayerBot **是真 Player，有真背包**，直接用交易系统：

```
你发起交易 -> bot 自动接受（step57 已实现，已验证）
   -> 你放东西 -> 你点确认
   -> bot 自动点确认（【新做】）
   -> 物品真进 bot 背包
   -> 触发第2层
```

**只需要新增「自动确认交易」+ 交易完成钩子。**

### 3.3 第2层：情感反馈（这是"更完美"的核心）

**不是简单说句谢谢。** 按四个维度决定反应：

| 维度 | 影响 |
|---|---|
| **物品类型** | 食物/药水/装备/垃圾/珍稀 -> 不同台词 |
| **物品价值** | 相对bot等级，判断"贵重"程度 |
| **当前需求** | bot 正饿着时给食物 vs 不饿时给 -> 反应完全不同 |
| **羁绊等级** | 生疏时客套，熟悉后随意，深交后打趣 |

#### 举例：同样给一块面包

```
羁绊0 + 不饿：  "……谢谢。"（收下，放进包里）
羁绊0 + 饿了：  "正好，我确实有点饿了。"（当场吃掉）
羁绊3 + 饿了：  "你怎么知道我饿了？……算了，我吃了。"
羁绊5 + 不饿：  "又给我带吃的。我又不是小孩子。"（但还是收下了）
```

#### 还要有「拒绝」

**能拒绝的伙伴才像人**：

```
给他不能用的职业装备： "这个我用不了，你自己留着吧。"（不收）
羁绊0 时给超贵重物品： "这太贵重了，我不能收。"（不收）
连续快速塞东西：       "够了够了，我拿不下了。"（防刷）
```

### 3.4 第3层：羁绊累积（重做计分）

**原设计只有 `gifts_to_bot++`，太粗糙。**

新的计分逻辑：

```
基础分 = 物品价值权重（1-10分）
   x 需求系数（正需要时 x3，不需要时 x1）
   x 首次系数（第一次给某类物品 x2）
   - 重复惩罚（同一物品24小时内重复给，第2次起递减）
```

**防刷设计**：
- 同一物品ID，24小时内只有首次全额计分
- 每日赠予上限（超过后只有台词没有分数）
- 垃圾物品（灰色品质）不计分，且bot会吐槽

### 3.5 反向：bot 主动索要（关怀系统的双向补完）

**A20 现在是 bot 单方面给你东西。要加"它也会开口要"。**

```
触发条件（任一）：
  背包空了 + 羁绊>=2       -> "我的绷带用完了，你还有吗？"
  连续死3次                 -> "……我是不是拖后腿了？"（不要东西，只要你回应）
  装备耐久 < 20%            -> "我的剑快断了。"
  长时间没休息              -> "能歇会儿吗？"

你的回应：
  给了 -> requests_met++    -> 羁绊+，且它会记住
  无视 -> requests_ignored++ -> 羁绊-（但不会太重，最多停止索要）
```

## 七、给你的确认点

**开始写代码前，我需要你确认三件事**：

1. **赠予的物品去哪**
   - A) 进 bot 银行（玩家能取回）
   - B) 直接消失（纯情感投入，不可逆）
   - C) bot 当场使用（食物就吃、药水就喝）
   - **建议：A+C 混合** —— 能用的当场用，用不了的存起来

2. **要不要"拒绝"机制**
   - 我倾向要（更像人），但会让你有时给不出去

3. **先做哪个**
   - A) 先 NPCBot（你现在主要用这个）
   - B) 先 PlayerBot（技术上更简单）
   - **建议 A**
