## 二、本版做了什么

### 只改 1 个文件

你的源码里有个上游那年代没有的东西 —— **`GetCreatureListWithOptionsInGrid` + `FindCreatureOptions`**
（`WorldObject.h:549` / `:315`），`GridNotifiers.h:1427` 已内建 `IsAlive` 过滤：

```cpp
if (i_args.IsAlive.has_value() && u->IsAlive() != i_args.IsAlive)
```

**这正是上游要新增的 `GetDeadCreatureListInGrid`** —— 你已经有了。于是：

| 文件 | 上游 | 本版 |
|---|---|---|
| `Object.h` / `Object.cpp` | 加模板函数 | ❌ 不用，已有 |
| `GridNotifiers.h` | 加 `AllDeadCreaturesInRange` | ❌ 不用，已有 |
| `ScriptedCreature.h` | 加包装 | ❌ 不用 |
| `Player.h` / `Player.cpp` | 改 `SendItemRetrievalMail` 签名 | ❌ 不用，邮件在模块内自建 |
| `Group.cpp` | 跟着改调用 | ❌ 不用 |
| **`LootHandler.cpp`** | 主逻辑 | ✅ **只改这个，+13 行** |

### 4 个 bug 全修

| 上游 bug | 本版做法 |
|---|---|
| 无限刷装备 | **全程走原版 `Player::StoreLootItem()`**，状态维护/成就/Eluna 钩子全部交给它 |
| 抢别人的怪 | 每具尸体调用 `Player::isAllowedToLoot()`（`Player.cpp:17886`） |
| 剥皮无限刷 | 用当前 `c` 判断；且 `LOOT_SKINNING` 直接跳过不参与 |
| `clear()` 顺序 | 先 `isLooted()` 判断，再 `clear()` |

### 额外解决 NPCBot 大坑

`botmgr.cpp:997-1006`：

```cpp
gr = new Group;
if (!gr->Create(_owner))     // 召 bot 就自动建真 Group
sGroupMgr->AddGroup(gr);
```

**你只要召一个 bot，`GetGroup()` 就非空。** 上游写的是 `if (!player->GetGroup())` 才启用
—— 意味着你**带 bot 刷材料时群体拾取永远不工作**，恰恰是最需要它的场景。

本版判断的是「组里有没有**真人**」，纯 bot 队视同单人，全量拾取。

## 三、组队为什么不会被抢

`Player::isAllowedToLoot()` 已经把五种分配方式全考虑到了：

| 分配方式 | 行为 |
|---|---|
| **自由拾取 FFA** | `return true` —— 先到先得，**这是暴雪原意，不算抢** |
| **轮抽 ROUND_ROBIN** | 只有轮到你、或有你的专属物品才 true |
| **队长分配 MASTER** | true，但 permission 二次卡 |
| **组队/需求优先** | 轮抽逻辑 + 超阈值物品单独判断 |
| **剥皮** | 只有 lootRecipient 本人 |

再加两道闸：

1. **超阈值物品跳过**（`AoELoot.SkipRollItems = 1`）—— 要 roll 的紫装不碰，留给正常 roll 窗口
2. **`is_blocked` / `rollWinnerGUID` 校验** —— 已锁定或别人赢走的不碰

**结果：队友的 roll 窗口一个不少，你只是把本来就该你的一次性收了。**

## 四、安装步骤

### 第 1 步：备份

```bash
cd /d/TrinityCore
git status
git add -A && git commit -m "before aoe loot"
git branch backup-before-aoeloot
```

### 第 2 步：放源文件

复制到**已存在**的 `Loot` 目录（不用新建目录）：

```
源文件/CustomAoELoot.h    →  D:\TrinityCore\src\server\game\Loot\CustomAoELoot.h
源文件/CustomAoELoot.cpp  →  D:\TrinityCore\src\server\game\Loot\CustomAoELoot.cpp
```

> **为什么放 Loot 而不是新建 Custom 目录**：
> `src/server/game/CMakeLists.txt` 用 `CollectSourceFiles` + `CollectIncludeDirectories`
> 递归扫描。放进**已有目录**最稳妥 —— 跟你上次 `CustomSpeed.*` 放 `Spells\` 一个道理。

### 第 3 步：打补丁

**先把整个 `step15_AoELoot` 文件夹从工作区下载到本地**，比如放 `D:\patches\`，然后：

```bash
cd /d/TrinityCore
bash "/d/patches/step15_AoELoot/apply.sh"
```

> 路径里的 `D:\patches\` 换成你实际存放的位置。
> Git Bash 里 `D:\xxx` 要写成 `/d/xxx`，**路径有空格必须加引号**。
>
> 不确定路径？在 Git Bash 里把 `apply.sh` **拖进窗口**，会自动填入正确路径，
> 前面补个 `bash ` 再回车即可。

脚本特性（已实测）：

- **CRLF 兼容** —— 先转 LF 匹配，写回还原 CRLF
- **幂等** —— 重复跑 3 次只提示"已打过"，不会重复插入
- **失败即停** —— 锚点找不到立即退出，不留半吊子

预期输出：

```
[1/3] √ 已加 #include "CustomAoELoot.h"
[2/3] √ 已插入物品群体拾取
[3/3] √ 已插入金币群体拾取
```

### 第 4 步：确认改动只有 13 行

```bash
git diff --stat
# 应该只有 LootHandler.cpp，13 insertions(+)，0 deletions
```

**如果显示删除了行，或动了别的文件，停下来告诉我。**

### 第 5 步：重跑 CMake（必须）

**新增了源文件，`file(GLOB)` 的列表在生成时固定，不重跑扫不到。**

CMake GUI → Configure → Generate。

### 第 6 步：编译

跟第 5 步那三个指令（`.spell clean` / `.reloaditem` / `.gmhelp`）**攒一起编译一次**。

### 第 7 步：放 conf

```
conf/worldserver.conf.d/aoeloot.conf
    →  D:\TC-Build\bin\RelWithDebInfo\worldserver.conf.d\aoeloot.conf
```

已做 GBK 兼容检查（75 行 / 1572 字符，全部通过）。

## 五、配置项

| 项 | 默认 | 说明 |
|---|---|---|
| `AoELoot.Enable` | 1 | 总开关 |
| **`AoELoot.Range`** | **60** | 半径（码）。上游是 30，你要广点刷材料所以给了 60。范围 5-200 |
