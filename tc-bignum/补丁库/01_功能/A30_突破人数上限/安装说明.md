> 目标：先把**代价最低、风险最小**的三条做掉，实测通过再进第 2 阶段。

| # | 内容 | 改动量 | 要编译吗 |

## 一、副本/团本人数放开

### 1.1 墙在哪

```cpp
// Map.cpp:3961-3967   InstanceMap::CannotEnter
uint32 maxPlayers = GetMaxPlayers();
if (GetPlayersCountExceptGMs() >= maxPlayers)
{
    TC_LOG_WARN("maps", "MAP: Instance '{}' of map '{}' cannot have more than '{}' players. Player '{}' rejected", ...);
    return CANNOT_ENTER_MAX_PLAYERS;
}
```

**全服就这一处拦截**，破掉它副本就没人数限制了。

### 1.2 改动 A：加 conf 枚举

**Ctrl+F 搜**（`World.h:111`）：

```cpp
    CONFIG_INSTANCE_IGNORE_RAID,
```

**在它下面加一行**：

```cpp
    CONFIG_INSTANCE_IGNORE_PLAYER_LIMIT,        // step46: 忽略副本人数上限
```

改完长这样：

```cpp
    CONFIG_INSTANCE_IGNORE_LEVEL,
    CONFIG_INSTANCE_IGNORE_RAID,
    CONFIG_INSTANCE_IGNORE_PLAYER_LIMIT,        // step46: 忽略副本人数上限
    CONFIG_CAST_UNSTUCK,
```

> **为什么加在这**：`CONFIG_*` 是个 enum，
> 加在中间会让后面所有值 +1。这没关系（都是编译期常量），
> 但**必须整个项目一起重编译**，不能只编 game。

### 1.3 改动 B：读取配置

**Ctrl+F 搜**（`World.cpp:1012`）：

```cpp
    m_bool_configs[CONFIG_INSTANCE_IGNORE_RAID]  = sConfigMgr->GetBoolDefault("Instance.IgnoreRaid", false);
```

**在它下面加一行**：

```cpp
    m_bool_configs[CONFIG_INSTANCE_IGNORE_PLAYER_LIMIT] = sConfigMgr->GetBoolDefault("Instance.IgnorePlayerLimit", false);
```

### 1.4 改动 C：跳过判定

**Ctrl+F 搜**（`Map.cpp:3961`）：

```cpp
    // cannot enter if the instance is full (player cap), GMs don't count
    uint32 maxPlayers = GetMaxPlayers();
    if (GetPlayersCountExceptGMs() >= maxPlayers)
    {
```

**整段替换成**：

```cpp
    // cannot enter if the instance is full (player cap), GMs don't count
    //step46: Instance.IgnorePlayerLimit = 1 时完全忽略副本人数上限。
    //  默认 false，行为和原版一致，不影响没开这个开关的服。
    uint32 maxPlayers = GetMaxPlayers();
    if (!sWorld->getBoolConfig(CONFIG_INSTANCE_IGNORE_PLAYER_LIMIT) &&
        GetPlayersCountExceptGMs() >= maxPlayers)
    {
```

**下面那几行不用动**，保持原样：

```cpp
        TC_LOG_WARN("maps", "MAP: Instance '{}' of map '{}' cannot have more than '{}' players. Player '{}' rejected", GetInstanceId(), GetMapName(), maxPlayers, player->GetName());
        return CANNOT_ENTER_MAX_PLAYERS;
    }
```

> **`sWorld->getBoolConfig` 在 Map.cpp 能直接用吗**：能。
> Map.cpp 已经 include 了 World.h（文件里到处在用 sWorld），
> 不用额外加 include。

## 二、自己带的 bot 上限：40 -> 255

### 2.1 墙在哪

```cpp
// botconfig.cpp:485-489
if (uval >= MAX_RAID_SIZE)                  // MAX_RAID_SIZE = 40
{
    BOT_LOG_ERROR("server.loading", "NpcBot.MaxBots value at offset {} is {} > 39, enforcing max value!", uint32(i), uint32(uval));
    uval = uint8(MAX_RAID_SIZE - 1);        // 强制压回 39
}
```

### 2.2 改法：删掉这个夹逼

**Ctrl+F 搜**（`botconfig.cpp:485`）：

```cpp
                if (uval >= MAX_RAID_SIZE)
                {
                    BOT_LOG_ERROR("server.loading", "NpcBot.MaxBots value at offset {} is {} > 39, enforcing max value!", uint32(i), uint32(uval));
                    uval = uint8(MAX_RAID_SIZE - 1);
                }
```

**整段替换成**：

```cpp
                //step46: 放开 40 人硬夹逼。
                //  存储类型是 uint8（botconfig.h:30 LvlBrackets），所以上限 255。
                //  想要 255 以上要把 LvlBrackets 和 GetMaxNpcBots 都改成 uint32，
                //  那是第2阶段的事。
                //
                //【重要】超过 40 之后，第 41 个及以后的 bot
                //  【不会显示在客户端团队框里】——那是 3.3.5 客户端的硬限制，
                //  服务端改不了。bot 本身正常存在、正常战斗。
                if (uval > 250)
                {
                    BOT_LOG_ERROR("server.loading", "NpcBot.MaxBots value at offset {} is {} > 250, enforcing max value!", uint32(i), uint32(uval));
                    uval = 250;
                }
```

> **为什么留 250 不是 255**：给自己留点余量。
> `uint8` 是 255，但代码里可能有 `count + 1` 之类的地方，
> 贴着上限跑容易溢出。250 是安全值。

### 2.3 配置怎么写

```ini
# worldserver.conf.d\npcbot_maxbots.conf
[worldserver]

# 9个值必须齐全（botconfig.cpp:470 ASSERT）
# 现在可以超过 39 了
NpcBot.MaxBots = 5,10,20,30,50,80,120,180,250

NpcBot.MaxBotsPerClass = 50
NpcBot.MaxBotsPerAccount = 0
```

## 三、bot 模板批量生成（解决"服务器总数"的真瓶颈）

### 3.1 为什么这才是真瓶颈

```cpp
// botdatamgr.cpp:1878-1886
uint32 maxbots = sBotGen->GetSpareBotsCount();
if (maxbots < wandering_bots_desired)
{
    BOT_LOG_FATAL("server.loading", "... Desired amount of wandering bots ({}) cannot be created. Aborting!");
    ASSERT(false);                          // 【直接崩服】
}
```

**配置里写 10000，但库里只有 500 个模板 -> 启动就崩。**

模板池来自 `creature_template_npcbot_extras`（botdatamgr.cpp:325）。

### 3.2 好消息：entry 上限已经放开

```cpp
// botcommon.h:39-41
BOT_ENTRY_BEGIN          = 70001,
//BOT_ENTRY_END          = 71000,        <- 【上游自己注释掉了】
BOT_ENTRY_CREATE_BEGIN   = 70800,
```

`next_bot_id` 是 `uint32`，理论到 42 亿。

### 3.3 SQL 见 sql/ 目录

`sql/批量生成bot模板.sql` —— 带存储过程，
可以指定「生成 N 个某职业的 bot 模板」。

**先跑 500 个试试**，确认能启动、能刷出来，再往上加。

## 四、编译与验证

### 4.1 编译

改了 `World.h` 的 enum -> **必须全量重编译**（不能只编 game）。
不用重跑 CMake（没新增文件）。

### 4.2 配置

```ini
# worldserver.conf.d\unlimited.conf
[worldserver]

# 副本忽略人数上限
Instance.IgnorePlayerLimit = 1

# 自己能带的bot（9个值，现在能超39了）
NpcBot.MaxBots = 5,10,20,30,50,80,120,180,250
NpcBot.MaxBotsPerClass = 50
```

### 4.3 验证清单

```
[ ] 服务端能正常启动（日志无 ASSERT）
[ ] 启动日志无 "NpcBot.MaxBots value at offset N is X > 250"
[ ] .npcbot add 连续招募，能超过 39 个
[ ] 招到第 41 个时：bot 存在、能跟随、能战斗
[ ] 【预期】第 41 个之后团队框不显示 —— 这是客户端限制，正常
[ ] 带一堆bot进5人本，不再被"副本人数已满"拦住
[ ] 带 20+ 个bot进副本，能全部进去
[ ] 挂机 10 分钟观察 CPU/内存
```

**重点看最后一条** —— 数量上去之后性能是主要风险。

## 五、这一阶段【不包含】什么

说清楚边界，免得你以为漏了：

| 没做 | 为什么 | 什么时候做 |
|---|---|---|
| 队伍 >40 人 | 要改 MAX_RAID_SIZE + 检查36处引用 | 第2阶段 |
| bot上限 >255 | 要把 uint8 全链路换 uint32 | 第2阶段 |
| 10万 bot 不卡 | 需要休眠/分片机制 | 第3阶段 |
| 团队框显示>40人 | 需要自定义 AddOn | 第4阶段（可选）|
