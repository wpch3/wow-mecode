# step26 NPC 状态调度器 —— 安装说明

## 一、能做什么

一条指令切换 NPC 的"可被攻击性"，做剧情不用再改数据库。

```
.nst invuln     -> 无敌，谁都打不了（像原版小孩）
.nst story      -> 剧情，打不了+不可选中+不参战
.nst pconly     -> 玩家打不了，怪能打（护送目标）
.nst normal     -> 普通怪，可打会还手
.nst neutral    -> 中立黄名，可打不主动
.nst friend     -> 友好绿名
```

档位名可用中文：`无敌` `剧情` `仅怪` `普通` `中立` `友好`

### 三种选目标方式

| 命令 | 作用 |
|---|---|
| `.nst <档位>` | 改选中的（临时，重刷失效）|
| `.nst <档位> save` | 改选中的并**写库**（永久）|
| `.nst <档位> r <半径>` | 改周围所有 NPC |
| `.nst <档位> r <半径> save` | 改周围所有并写库 |
| `.nst <档位> entry <ID>` | 改**全世界**该 entry（自动写库）|
| `.nst` | 看当前目标是什么档位 |
| `.nst list` | 看全部档位说明 |

## 二、六档的实际区别

| 档位 | 玩家能打 | 怪能打 | 能选中 | 阵营 | 典型用途 |
|---|---|---|---|---|---|
| **无敌** | 否 | 否 | **是** | 不改 | 剧情 NPC、要对话的重要角色 |
| **剧情** | 否 | 否 | 否 | 不改 | 纯背景板、装饰性角色 |
| **仅怪** | 否 | **是** | 是 | 不改 | 护送任务的被护送者 |
| **普通** | 是 | 是 | 是 | 14 敌对 | 普通怪 |
| **中立** | 是 | 是 | 是 | 31 黄名 | 中立生物、木桩 |
| **友好** | Ctrl | 是 | 是 | 35 绿名 | 友方 NPC |

**无敌 vs 剧情的区别**：无敌**仍可选中**（能对话、交任务），剧情**连选都选不中**。

**"不改阵营"的意义**：无敌/剧情/仅怪三档**不动 faction**，
所以联盟守卫设成无敌后**仍然是联盟**，不会变成中立而失去阵营归属。

## 四、实现里避开的两个坑

### 坑 1：UNIT_STATE_UNATTACKABLE 不能用

```cpp
// Unit.h:259
UNIT_STATE_UNATTACKABLE = UNIT_STATE_IN_FLIGHT,
```

它是**"飞行中"的别名**！设了会让 NPC 被当成在坐飞行点，
`SpellEffects.cpp` 里十几处 `IsInFlight()` 判断全部误判。

**本实现只用 flag，完全不碰 UnitState。**

### 坑 2：UNIT_FLAG_NON_ATTACKABLE(0x02) 不可靠

```cpp
// UnitDefines.h:136
UNIT_FLAG_NON_ATTACKABLE = 0x00000002,
// not attackable, set when creature starts to cast spells with SPELL_EFFECT_SPAWN
// ... removed when spell hits caster, original name is UNIT_FLAG_SPAWNING
```

它是 **SPAWNING 用的**，法术命中时会被自动清掉，拿它做长期状态会失效。
正确的是 `UNIT_FLAG_NON_ATTACKABLE_2 (0x10000)`。

### 为什么用 SetImmuneToPC 而不是裸设 flag

```cpp
// Unit.cpp:8663  SetImmuneToPC(bool apply, bool keepCombat)
```

它除了设 flag，还会：

- `ValidateAttackersAndOwnTarget()` —— 把正在打它的人踢掉
- 遍历 `CombatRefs` 结束战斗
- **NPCBot 分支已处理**（`pair.second->GetOther(this)->IsNPCBotOrPet()`）

裸设 flag 不会断当前战斗，改了还在挨打。

## 五、攻击判定链（供你理解各档为什么这么配）

`WorldObject::IsValidAttackTarget`（`Object.cpp:2991`），越靠前优先级越高：

```
:3004  HasUnitState(UNIT_STATE_UNATTACKABLE)     <- 不能用（=IN_FLIGHT）
:3033  UNIT_FLAG_UNINTERACTIBLE                  <- 不可选中
:3043  UNIT_FLAG_NON_ATTACKABLE | NON_ATTACKABLE_2
:3071  IsImmuneToNPC() / IsImmuneToPC()          <- 分别屏蔽怪/玩家
```

**注意**：这段在你的库里被 NPCBot **改写过**，
bot 走的是 `IsNPCBotOrPet()` 分支而不是 `UNIT_FLAG_PLAYER_CONTROLLED`。
所以 `pconly` 档对 bot 的效果 = 对玩家的效果（bot 被当玩家侧处理）。

## 六、持久化说明

| 方式 | 写哪张表 | 生效范围 |
|---|---|---|
| `save`（选中/半径） | `creature.unit_flags`（按 guid）| **只有这一只** |
| `entry <ID>` | `creature_template.unit_flags` | 该 entry **全部** |

`ObjectMgr.cpp:2227` 确认服务端会读 `creature.unit_flags`，所以单只持久化可行。

**faction 只能存在 `creature_template`**（没有 per-guid 覆盖），
所以对单只用 `save` 时，如果该档位要改阵营，会连带影响同 entry 的所有 NPC。
—— 这也是无敌/剧情/仅怪三档**故意不改 faction** 的另一个原因。

**临时召唤物（TempSummon）没有 spawnId，存不了**，会在提示里告诉你有几个没存上。
