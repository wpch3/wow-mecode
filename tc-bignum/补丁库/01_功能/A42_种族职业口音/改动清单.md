> 2026-08-09

## 零、好消息：职业已经支持了，只差种族

实查发现 A37 建表时**已经预留了职业字段**：

```text
-- npcbot_gift_text（world库）
`bot_class`    TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '限定职业 0=通用'

-- npcbot_request_text（world库）
`bot_class`    TINYINT UNSIGNED NOT NULL DEFAULT 0
```

而且 C++ 侧的挑选逻辑**已经实现了"职业专属优先、没有就回退通用"**：

```cpp
// bot_companion.cpp:189
std::string BotCompanionMgr::PickText(uint8 careType, uint8 botClass) const
{
    ...
    // 先收集匹配的（职业专属优先，没有就用通用）
    std::vector<CompanionText const*> pool;
    for (CompanionText const& t : itr->second)
        if (t.BotClass == botClass)          // :198  职业专属
            pool.push_back(&t);

    if (pool.empty())
        for (CompanionText const& t : itr->second)
            if (t.BotClass == 0)             // :203  回退通用
                pool.push_back(&t);
    ...
}
```

**所以第1步是纯 SQL —— 往表里插带 `bot_class` 的台词就行，零编译。**

种族需要加一个字段和一段筛选逻辑，放第2步。

## 第2步 · 种族口音（要改代码，下一轮做）

### 2.1 为什么种族要单独做

两张表**都没有 `bot_race` 字段**，C++ 侧 `PickText` 也只接收 `botClass`。

### 2.2 数据来源已实证

**NPCBot**：

```cpp
// botdatamgr.h:128
struct NpcBotExtras
{
    uint8 race;        // <- 种族在这
    uint8 bclass;
};

// botdatamgr.h:222
static NpcBotExtras const* SelectNpcBotExtras(uint32 entry);
```

用法（`QueryHandler.cpp:62` 上游范例）：

```cpp
NpcBotExtras const* extData = BotDataMgr::SelectNpcBotExtras(creatureId);
uint8 race = extData->race;
```

### 2.4 改动预览（下一轮交付完整清单）

```
1. SQL   两张表各加 `bot_race` TINYINT DEFAULT 0
2. C++   CompanionText 结构加 uint8 BotRace
3. C++   LoadCareTexts 读这个字段
4. C++   PickText 签名加 botRace，三级优先：
             种族+职业都匹配 > 只匹配职业 > 只匹配种族 > 通用
5. C++   调用点传入种族
```

**优先级设计是关键** —— 不能简单地"种族优先"，
否则一个亡灵法师会永远说亡灵台词，丢掉法师特色。
