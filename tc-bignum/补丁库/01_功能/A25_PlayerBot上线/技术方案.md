## 一、完整登录链路（实查）

`CharacterHandler.cpp:686-717` 官方登录流程：

```cpp
void WorldSession::HandlePlayerLoginOpcode(WorldPacket& recvData)
{
    m_playerLoading = true;
    ObjectGuid playerGuid;
    recvData >> playerGuid;

    if (!IsLegitCharacterForAccount(playerGuid))      // <- 门 2
        { KickPlayer(...); return; }

    std::shared_ptr<LoginQueryHolder> holder = std::make_shared<LoginQueryHolder>(GetAccountId(), playerGuid);
    if (!holder->Initialize()) { m_playerLoading = false; return; }

    AddQueryHolderCallback(CharacterDatabase.DelayQueryHolder(holder)).AfterComplete([this](SQLQueryHolderBase const& holder)
    {
        HandlePlayerLogin(static_cast<LoginQueryHolder const&>(holder));
    });
}
```

## 二、三道门（全部已定位）

### 门 1：`LoginQueryHolder` 类型不可见

```cpp
// CharacterHandler.cpp:58   定义在 .cpp 里，【不在任何头文件】
class LoginQueryHolder : public CharacterDatabaseQueryHolder
```

**后果**：外部代码无法构造它，也就无法直接调 `HandlePlayerLogin()`
（虽然那个函数是 public，`WorldSession.h:718`）。

### 门 2：`_legitCharacters` 白名单

```cpp
// WorldSession.h:1285
bool IsLegitCharacterForAccount(ObjectGuid lowGUID)
{
    return _legitCharacters.find(lowGUID) != _legitCharacters.end();
}
```

`_legitCharacters` **只在客户端请求角色列表时填充**。
bot 没有客户端，这个集合是空的 -> 登录被拒。

### 门 3：空 socket 导致的定时崩溃

```cpp
// WorldSession.cpp:298
if (IsConnectionIdle() && !HasPermission(rbac::RBAC_PERM_IGNORE_IDLE_CONNECTION))
    m_Socket->CloseSocket();      // <- 没判空，必崩

// WorldSession.cpp:764
bool IsConnectionIdle() const { return m_timeOutTime < GameTime::GetGameTime() && !m_inQueue; }
```

## 三、解法：伪造 CMSG_PLAYER_LOGIN 包（最干净）

**不去碰私有类型，而是走官方原路。**

```cpp
// QueuePacket 是 public（WorldSession.h:577，494行起的public段）
WorldPacket* pkt = new WorldPacket(CMSG_PLAYER_LOGIN, 8);
*pkt << botGuid;
session->QueuePacket(pkt);
```

**优点**：
- 完全走官方登录流程，不绕过任何初始化
- 不需要访问 `LoginQueryHolder`
- 后续维护跟着上游走

**这样门 1 自动解决。**

---

## 四、门 2 和门 3 的解法

### 门 2：让 bot 角色进白名单

`_legitCharacters` 是 private，外部改不了。**两个选择**：

**选择 A（推荐）**：在 `WorldSession` 加一个 public 方法

```cpp
// WorldSession.h  在 IsLegitCharacterForAccount 旁边加
void AddLegitCharacter(ObjectGuid guid) { _legitCharacters.insert(guid); }
```

**一行，风险极低。**

**选择 B**：调用 `HandleCharEnumOpcode` 让它自然填充
—— 但那会触发一堆发包逻辑，反而复杂。

### 门 3：授予免疫超时权限

```cpp
// 创建会话时给 SEC_ADMINISTRATOR，或单独授权
// 让 HasPermission(RBAC_PERM_IGNORE_IDLE_CONNECTION) 为真
// 条件短路 -> 永远走不到 m_Socket->CloseSocket()
```

**验证方法**：bot 挂机 10 分钟不崩，就说明这条生效了。

## 五、完整流程（第1步要写的代码）

```cpp
bool SpawnPlayerBot(uint32 accountId, ObjectGuid charGuid)
{
    // 1. 建无 socket 的会话
    //    WorldSession.h:495  收 shared_ptr<WorldSocket>，传 nullptr
    WorldSession* sess = new WorldSession(
        accountId,
        std::move(accountName),
        nullptr,                       // <- 没有 socket
        SEC_ADMINISTRATOR,             // <- 顺便解决门3
        EXPANSION_WRATH_OF_THE_LICH_KING,
        0, Minutes(0), LOCALE_zhCN, 0, false);

    // 2. 门2：把角色加进白名单
    sess->AddLegitCharacter(charGuid);

    // 3. 注册到世界
    sWorld->AddSession(sess);

    // 4. 伪造登录包
    WorldPacket* pkt = new WorldPacket(CMSG_PLAYER_LOGIN, 8);
    *pkt << charGuid;
    sess->QueuePacket(pkt);

    return true;
}
```

**登录是异步的**（`DelayQueryHolder`），所以要等几百毫秒才会真正进世界。

## 六、准备工作（你要做的）

### 建一个专用账号和角色

```
1. 服务端控制台或游戏内：
   .account create BOTACC1 botpass123

2. 用这个账号登录游戏，创建一个角色（比如叫 "小铁"）
   记下角色名

3. 退出登录（bot 要用这个角色，不能同时在线）
```

**为什么要独立账号**：
- bot 角色会写 `characters` 库
- 用你自己的号会污染存档
- 独立账号方便批量管理和清理

### 查出 accountId 和 charGuid

```sql
-- 在 auth 库
SELECT id, username FROM `auth`.`account` WHERE username = 'BOTACC1';

-- 在 characters 库
SELECT guid, name, account, level, race, class
FROM `characters`.`characters`
WHERE account = <上面查到的id>;
```

## 八、风险与止损

| 风险 | 应对 |
|---|---|
| 崩服 | **先在测试环境跑**，别在你正在玩的存档上试 |
| 存档污染 | 用独立账号，出问题直接删账号 |
| 登录卡死 | 异步登录，如果 5 秒没进世界就是失败，看日志 |

**止损点**：如果第1步搞不定（比如登录流程还有我没发现的门），
**不要硬撑**，我们退回去用 NPCBot + step34 的方案，那条路已经跑通了。
