# 修复：`Evirstara 未进入世界` —— 找到真正的拦截点

> 用户反馈：编译成功，但等了 10 秒以上 `.pbot list` 仍显示"未进入世界"
> 结论：**不是异步延迟，是两处硬拦截。伪造登录包这条路本身走不通。**

---

## 一、真凶：取包循环要求 socket 非空

```cpp
// WorldSession.cpp:312
while (m_Socket && _recvQueue.next(packet, updater))
      ^^^^^^^^^
```

**我们的会话 `m_Socket = nullptr`，所以这个循环一次都不执行。**

`QueuePacket()` 确实把包放进了 `_recvQueue`（`WorldSession.cpp:271`），
**但永远没人来取。** 登录包就那么躺在队列里。

**这是我方案的设计缺陷** —— 我验证了"发包不崩"（`SendPacket` 有判空），
却没验证"收包能不能被处理"。

---

## 二、第二个拦截：无 socket 的会话会被踢出世界

```cpp
// WorldSession.cpp:512
if (!m_Socket)
    return false;         // Will remove this session from the world session map
```

**即使第一处修好，会话也会在下一个 tick 被移除。**

---

## 三、修复方案：给会话加"bot 标记"

不能简单粗暴地删掉 `m_Socket &&`，那会影响所有真实玩家的断线处理。
**要精确地只对 bot 会话放行。**

### 改动 1：`WorldSession.h` 加标记成员

**Ctrl+F 搜**（`WorldSession.h:1299`）：

```cpp
        std::shared_ptr<WorldSocket> m_Socket;
```

**在它上面加一行**：

```cpp
        bool m_isBotSession = false;   // step40: 无网络连接的 PlayerBot 会话
        std::shared_ptr<WorldSocket> m_Socket;
```

### 改动 2：`WorldSession.h` 加 public 读写方法

**加在 577 行 `QueuePacket` 附近**（和上次 `AddLegitCharacter` 放一起）：

```cpp
        // step40: PlayerBot 会话标记
        void SetBotSession(bool val) { m_isBotSession = val; }
        bool IsBotSession() const { return m_isBotSession; }
```

改完这一片应该是：

```cpp
        bool DisallowHyperlinksAndMaybeKick(std::string const& str);

        // step40: PlayerBot 需要手动把角色加进白名单。
        void AddLegitCharacter(ObjectGuid guid) { _legitCharacters.insert(guid); }
        void SetBotSession(bool val) { m_isBotSession = val; }
        bool IsBotSession() const { return m_isBotSession; }

        void QueuePacket(WorldPacket* new_packet);
        bool Update(uint32 diff, PacketFilter& updater);
```

### 改动 3：`WorldSession.cpp:312` 让 bot 会话能取包

**原文**：
```cpp
    while (m_Socket && _recvQueue.next(packet, updater))
```

**改为**：
```cpp
    // step40: bot 会话没有 socket，但仍需处理自己投递的包（如登录包）
    while ((m_Socket || m_isBotSession) && _recvQueue.next(packet, updater))
```

### 改动 4：`WorldSession.cpp:512` 不要移除 bot 会话

**原文**：
```cpp
        if (!m_Socket)
            return false;                                       //Will remove this session from the world session map
```

**改为**：
```cpp
        // step40: bot 会话本来就没有 socket，不能因此被移除
        if (!m_Socket && !m_isBotSession)
            return false;                                       //Will remove this session from the world session map
```

### 改动 5：`cs_playerbot.cpp` 创建会话后打标记

**找到**（在 `sess->AddLegitCharacter(charGuid);` 附近）：

```cpp
        sess->AddLegitCharacter(charGuid);
```

**在它上面加一行**：

```cpp
        // step40: 标记为 bot 会话，让 WorldSession::Update 容忍空 socket
        sess->SetBotSession(true);
        sess->AddLegitCharacter(charGuid);
```

## 四、安全性评估（为什么这样改是安全的）

我逐行检查了 `WorldSession::Update` 里所有用到 `m_Socket` 的地方：

| 行 | 代码 | 对 bot 会话安全吗 |
|---|---|---|
| 298 | `m_Socket->CloseSocket()` | **安全**，被 `SEC_ADMINISTRATOR` 的权限短路 |
| **312** | `while (m_Socket && ...)` | **要改**（改动3）|
| 492 | `if (m_Socket && m_Socket->IsOpen() && _warden)` | 安全，已判空 |
| 499 | `if (m_Socket && !m_Socket->IsOpen())` | 安全，已判空 |
| **512** | `if (!m_Socket) return false;` | **要改**（改动4）|

**循环体内部（312-430）除了 312 那一处，没有再用 `m_Socket`。**
所以放行取包循环不会引入新的空指针风险。

## 六、我的错误

**我验证了"发包安全"，却没验证"收包能不能被处理"。**

```
SendPacket   有 if (!m_Socket) return;   -> 我看到了，判断"安全"
Update 取包  有 while (m_Socket && ...)  -> 我没查，这才是关键
```

**教训：验证一条链路时，要把【双向】都走一遍。**
只查了"出"没查"进"，就是半个验证。
