## 一、【重大发现】一个死锁，可能才是真凶

查源码时发现了这个，**它能完美解释"改什么都没用"**：

```cpp
// bot_ai.cpp:17717   GlobalUpdate 内
    if (IsDuringTeleport())
        return false;              // <- 提前退出

// bot_ai.cpp:18257   同一个 GlobalUpdate，但在 17717 【之后】
    if (!me->HasNpcFlag(UNIT_NPC_FLAG_GOSSIP) && !HasBotCommandState(BOT_COMMAND_NOGOSSIP))
        me->SetNpcFlag(UNIT_NPC_FLAG_GOSSIP);     // <- 恢复对话标记
```

### 死锁链条

```
_duringTeleport 卡住不清
    -> GlobalUpdate 每次都在 17717 提前 return
    -> 18257 永远执行不到
    -> bot 永远拿不回 UNIT_NPC_FLAG_GOSSIP
    -> Player::GetNPCIfCanInteractWith(guid, UNIT_NPC_FLAG_GOSSIP) 返回 nullptr
       （Player.cpp:2178）
    -> 【服务端根本不调用 OnGossipHello】
    -> step33 改的开关再对也没用，因为那段代码压根不执行
```

**症状和"开关没生效"一模一样，但病根完全不同。**

### 为什么 `.bf come` 可能触发它

`.bf come` 调 `BotMgr::TeleportBot()`，它会 `SetIsDuringTeleport(true)`（botmgr.cpp:555）。
清除依赖回调（botmgr.cpp:634）。如果回调因为某些条件走了别的分支，
标记就留在那儿了。

**注意**：这是【假设】，不是结论。`.bd` 就是用来验证它的。

## 三、怎么用（这是重点）

```
1. .bf come            叫一个游荡bot过来
2. 选中它
3. .bd                 诊断
```

### 输出长这样

```
=== Kaelthas (entry 70123) ===
--- 第一关：NPC_FLAG_GOSSIP ---
  [拦截] 没有 GOSSIP 标记！
  服务端【根本不会调用 OnGossipHello】
--- 第二关：OnGossipHello 内部条件 ---
  [通过] !IsNpcBotModEnabled()      = false
  [通过] class disabled             = false (class=1 wanderer=yes)
  [通过] IsTempBot()                = false
  [通过] me->IsInCombat()           = false
  [通过] CCed(me)                   = false
  [通过] IsCasting()                = false
  [拦截] IsDuringTeleport()         = true  <<< 很可能是这个
  [通过] ISSUED_ORDER|NOGOSSIP      = false
--- step33 改的条件 ---
  AllowHire 配置读到的值 = true(1)
  [通过] step33 条件                = false
--- 结论 ---
  病因：缺 GOSSIP 标记，卡在第一关
  根因：IsDuringTeleport 卡住了
  解法：用 .bd fix 强制修复
```

**这一屏就能定位到底是哪个条件。**

### 三种可能的结论

| 输出 | 含义 | 下一步 |
|---|---|---|
| `AllowHire = false(0)` | **配置真的没读到** | 检查 conf 拼写/位置 |
| `没有 GOSSIP 标记` + `IsDuringTeleport = true` | **死锁确认** | `.bd fix` |
| `所有条件都通过` | 服务端没问题 | 客户端/网络层 |

## 四、`.bd fix` 强制修复

```
选中 bot -> .bd fix
```

做三件事：
1. `AbortTeleport()` 取消挂起的传送事件
2. `SetIsDuringTeleport(false)` 清掉卡住的标记
3. **直接补上 GOSSIP 标记**（不等 GlobalUpdate）

**修完立刻右键试。**

### 如果 fix 之后能对话了

**说明死锁假设成立。** 那我就知道该怎么根治了：
在 `.bf come` 传送完成后主动清标记，或者把 17717 那个提前 return 改成
不影响 flag 恢复。

**这才是"从头做"该修的地方** —— 不是重写招募逻辑。
