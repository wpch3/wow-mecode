# 第 11 步：战斗节奏优化 —— 安装说明

## 这一步解决什么

`.cheat cooldown` 是**一刀切归零**，开了就是无限火力。
这一步是**按百分比缩放**，去掉站桩感但保留节奏。

| | GCD | 读条 | 单技能CD |
|---|---|---|---|
| 缩放 | **60%** | **75%** | 分段 85/80/90% |
| 效果 | 1.5s → 0.9s | 火球 3.5s → 2.6s | 冲锋 15s → 12.75s |

---

## 关于你问的「1 级火球术只要 1.5 秒，还需要优化吗」

**需要，你恰好撞上了唯一一个看不出问题的等级。**

火球术的读条随 Rank 递增，这是官方设计：

| 等级 | 火球术 | 读条 | 循环耗时 | 手感 |
|---|---|---|---|---|
| **1 级** | Rank 1 | **1.5 秒** | max(1500, GCD 1500) = 1500 | 读条=GCD，**感觉不出问题** |
| 12 级 | Rank 3 | 2.5 秒 | 2500 | 开始有等待 |
| 24 级 | Rank 5 | **3.5 秒** | **3500** | 读条是 GCD 的 2.3 倍，站桩感明显 |
| 80 级 | Rank 16 | 3.5 秒 | 3500 | 同上 |

优化后全等级段均匀提速 **1.33x**，不需要给法师单独调参数。

---

## 你提问后新增的保护：读条不低于 GCD

复查时发现原方案有个「白压」问题：

```
某个 1 秒读条的技能
  读条 1000ms  ×75%  → 750ms
  GCD  1500ms  ×60%  → 900ms

读条 750ms 比 GCD 900ms 还短
→ 那 150ms 完全白给（反正要等 GCD 转好）
→ 还会让读条条一闪而过，观感变差
```

已加保护 `Speed.CastNotBelowGcd = 1`（默认开）：

| 技能 | 原读条 | 无保护 | 有保护 | 说明 |
|---|---|---|---|---|
| 火球术 Rank16 | 3500 | 2625 | 2625 | 长读条不受影响 |
| 火球术 Rank1 | 1500 | 1125 | 1125 | 正常缩放 |
| 1 秒读条技能 | 1000 | 750 | **900** | ← 保护生效 |
| 0.8 秒读条 | 800 | 600 | 600 | 原读条已低于 GCD，不干预 |

## 安装（5 步）

### 1. 复制两个新源文件

把 `源文件/` 里的两个文件复制到：

```
D:\TrinityCore\src\server\game\Spells\CustomSpeed.h
D:\TrinityCore\src\server\game\Spells\CustomSpeed.cpp
```

### 2. 打补丁（二选一）

#### 方式 A：一键脚本（推荐）

Git Bash 里执行：

```bash
cd /d/TrinityCore
bash "/d/你放脚本的路径/apply.sh"
```

脚本特点：
- 精确字符串替换，不受 CRLF/LF 影响
- 自动备份原文件为 `.bak`
- **幂等** —— 重复执行会跳过已打的，不会重复插入
- 每步校验，锚点找不到立即停止

预期输出：

```
  [完成] Spell.cpp  include
  [完成] Spell.cpp  读条缩放
  [完成] Spell.cpp  GCD缩放+急速修复
  [完成] SpellHistory.cpp  include
  [完成] SpellHistory.cpp  CD缩放

  新打 5 处，跳过 0 处（已存在）
```

#### 方式 B：手工改

见本目录下 `../step11_核心补丁.md`，有精确到行号的原文和改法。

### 3. 放 conf

```
speed.conf  →  D:\TC-Build\bin\RelWithDebInfo\worldserver.conf.d\speed.conf
```

> **不用改后缀**。它和档位文件（epic.conf 等）是不同功能，
> 同时生效互不干扰。切档位时也别把它关掉。

### 4. （可选但建议）让 .reload config 生效

`D:\TrinityCore\src\server\game\World\World.cpp`：

- 顶部加 `#include "CustomSpeed.h"`
- `World::LoadConfigSettings()` 函数**末尾**加一行：

```cpp
    // ===== [CUSTOM SPEED] 让 .reload config 能刷新战斗节奏设置 =====
    sCustomSpeed->LoadConfig();
```

不加也能用，只是改 conf 后要**重启**而不能热重载。调手感时这个很省事。

### 5. 重跑 CMake + 编译

> **这次是新增源文件，必须重跑 CMake。**
> 源文件列表是 `file(GLOB)` 在生成时固定的。

```
CMake GUI → Configure → Generate
VS2022 → 生成解决方案
```

## 顺带修的原版缺陷

```cpp
// Spell.cpp:8650 原版把物理职业排除在急速加成外
if (StartRecoveryCategory == 133 && StartRecoveryTime == 1500 &&
    DmgClass != MELEE && DmgClass != RANGED && !HasAttribute(ABILITY))
    gcd *= UNIT_MOD_CAST_SPEED;
```

**结果**：法师堆急速能把 GCD 压到 1.0s，
战士堆到 100% 急速 GCD 还是死板的 1500ms。

补丁加了个 `else if` 分支接住物理职业。
这不是给近战开挂，是把本来就歪的地方拉直。

由 `Speed.HasteAffectsMelee = 1` 控制，不想要可以关。

## 调参建议

先按默认值（60/75/85-80-90）玩一段时间再调。**数字好看不等于手感好。**

觉得还不够快：
```conf
Speed.Gcd = 50
Speed.Cast = 65
```

觉得太快了：
```conf
Speed.Gcd = 75
Speed.Cast = 85
```

只想调某个职业（8=法师）：
```conf
Speed.Cast.Class8 = 70
```

> GCD 低于 50% 时，客户端的技能冷却转圈动画可能和服务端对不上
> （按钮看着还在转，其实已经能放了）。这是客户端预测问题，
> 不是 bug。60% 以上基本看不出来。

## 出错怎么办

编译报错**只发第一条**，带文件名行号。

最可能的问题：
- `CustomSpeed.h: No such file` → 检查文件是否在 `src\server\game\Spells\`，以及有没有重跑 CMake
- 脚本报「找不到锚点」→ 源码版本不同，改用手工方式（`step11_核心补丁.md`）

**回滚**：脚本备份了 `.bak`，把 `Spell.cpp.bak` 改回 `Spell.cpp` 即可。
