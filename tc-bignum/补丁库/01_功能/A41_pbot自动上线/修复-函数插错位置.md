# A41 修复 · 四个函数插进了类内部

> 2026-08-09
> 报错：
> ```text
> C2352  "playerbot_commandscript::PBotRosterAdd": 调用非静态成员函数需要一个对象   cs_playerbot.cpp 414
> C2352  "playerbot_commandscript::PBotRosterRemove": 调用非静态成员函数需要一个对象  cs_playerbot.cpp 514
> LNK1181 无法打开输入文件 scripts.lib
> ```

---

## 一、这是我的错

我在改动清单里写「在 `SpawnBot` 函数**上面**插入」，
但没说清 `SpawnBot` 本身在**类内部**：

```text
cs_playerbot.cpp:106    std::vector<PBotEntry> g_pbots;              <- 类外（全局）
cs_playerbot.cpp:119    class playerbot_commandscript : public CommandScript
cs_playerbot.cpp:120    {
cs_playerbot.cpp:121    public:
cs_playerbot.cpp:200        static bool SpawnBot(...)                 <- 类内！
cs_playerbot.cpp:843    };                                            <- 类结束
```

你按字面照做，四个函数就成了**类的成员函数**。

于是：
- `PBotRosterAdd(...)` 变成 `playerbot_commandscript::PBotRosterAdd(...)`
- 它们不是 `static`，调用需要对象实例 → **C2352**
- `scripts` 项目编译失败 → 没生成 `scripts.lib` → **LNK1181**

> **LNK1181 是连锁反应，不用单独管。** 只要 C2352 修好，它自动消失。
> 坑表里那条「先看错误列表最下面/最前面的真错误」在这里同样适用 ——
> `scripts.lib` 打不开是因为 scripts 项目**根本没编译成功**。

---

## 二、修法：把四个函数从类里移到类外

### 2.1 先找到它们

在 `cs_playerbot.cpp` 里 Ctrl+F 搜：

```text
A41 · spawn 核心
```

你会看到我给的那一整段（从 `// ====== A41 · spawn 核心 ======` 注释开始，
到 `PBotRosterRemove` 函数的结束大括号为止）。

**这一整段包含 4 个函数**：

```text
bool PBotSpawnCore(...)          { ... }
void PBotLoadRoster(...)         { ... }
void PBotRosterAdd(...)          { ... }
void PBotRosterRemove(...)       { ... }
```

### 2.2 剪切

把这一整段**完整剪切**（Ctrl+X）。

**剪的时候注意**：从 `// ============================================================================`
（`A41 · spawn 核心` 那行的上一行）开始，
到 `PBotRosterRemove` 的收尾 `}` 为止，**包含中间所有内容**。

### 2.3 粘贴到正确位置

搜索原文（`:106`，**全文件唯一**）：

```cpp
std::vector<PBotEntry> g_pbots;
```

在**这一行的下面**粘贴（Ctrl+V）。

粘完后结构应该是这样：

```cpp

// ============================================================================
//  A41 · spawn 核心（不依赖 ChatHandler，供自动上线复用）
// ============================================================================

    ...

    ...
```

## 三、装完自检

### 3.1 位置检查（最重要）

在 VS 里按 **`Ctrl+M, Ctrl+O`**（折叠所有）。

折叠后你应该看到这些**全部左对齐、平级**：

```text
bool PBotSpawnCore(...)              {...}
void PBotLoadRoster(...)             {...}
void PBotRosterAdd(...)              {...}
void PBotRosterRemove(...)           {...}
class playerbot_commandscript ...    {...}
```

**如果四个函数缩进比 `class` 深，说明还在类里面，没移出来。**

### 3.2 搜索计数

| 搜索词 | 应有 | 说明 |
|---|---|---|
| `bool PBotSpawnCore` | 1 | 定义 |
| `void PBotRosterAdd` | 1 | 定义 |
| `PBotRosterAdd(owner->GetGUID()` | 1 | 在 SpawnBot 里的调用 |
| `PBotRosterRemove(owner->GetGUID()` | 1 | 在 despawn 里的调用 |
| `A41 · spawn 核心` | **1** | 只能有一段，多了就是粘重复了 |

**最后一条特别重要** —— 如果你剪切时没剪干净又粘了一次，
会变成两份定义，报 C2084（函数已有主体）。

## 五、为什么放类外是对的

这四个函数需要被 **`pbot_autoaccept.cpp` 跨文件调用**：

```cpp
// pbot_autoaccept.h 里的声明（步骤2）
bool PBotSpawnCore(uint32, ObjectGuid, std::string const&, uint32, std::string*);
void PBotLoadRoster(ObjectGuid, std::vector<PBotEntry>&);
```

声明是**自由函数**（全局作用域），
实现如果放在类里就成了 `playerbot_commandscript::PBotSpawnCore`，
两者**签名不匹配** —— 就算 C2352 侥幸不报，链接时也会 LNK2019。

**声明在哪个作用域，实现就必须在哪个作用域。**
