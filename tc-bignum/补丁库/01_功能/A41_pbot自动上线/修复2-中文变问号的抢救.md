## 七、以后怎么避免（重要）

### 那个弹框千万别点「否」

```text
「此文件中的某些 Unicode 字符未能保存到当前代码页中，
  是否以 Unicode 编码重新保存此文件？」

点【是】  -> 以 UTF-8 保存，中文完好
点【否】  -> 存不下的字符全变 ?，中文报废   <- 你之前点的这个
```

### 根治：复制代码后先清理

```bash
# 1. 清掉 NBSP 等隐形字符（这才是弹框的根源）
python3 tools/fix_nbsp.py --fix 你改的文件.cpp

# 2. 检查有没有已损坏的中文
python3 tools/find_mojibake.py 你改的文件.cpp
```

**清理干净后，VS 永远不会再弹那个框，也就不会再有变问号的机会。**

## 八、工具说明

### `tools/find_mojibake.py`

找出被存成问号的中文，**并自动分类**（这是关键 —— 一个文件可能有
2000+ 个问号，手工分不清哪些要紧）：

```bash
python3 tools/find_mojibake.py 文件.cpp              # 完整报告
python3 tools/find_mojibake.py --code-only 文件.cpp  # 只看致命的
python3 tools/find_mojibake.py --dir D:/TrinityCore/src   # 扫整个目录
```

分类逻辑：

| 类别 | 判断依据 | 严重性 |
|---|---|---|
| **[致命] 代码** | 问号在可执行代码里，且是连续问号 | 必须修 |
| **[重要] 字符串** | 问号在 `"..."` 里 | 玩家看得到 |
| **[可缓] 注释** | 在 `//` 或 `/* */` 里 | 不影响编译 |
| **[正常] 排除** | 三元 `? :`、`#if`、`'?'` | 不是损坏 |

**扫全目录找出所有历史损坏**：

```bash
python3 tools/find_mojibake.py --dir /d/TrinityCore/src/server/scripts
```

结尾会给汇总，标出哪些文件是【致命】哪些只是【文本】。

### `tools/fix_nbsp.py`

清理 12 种隐形危险字符（NBSP / 全角空格 / 零宽 / 弯引号 / 长破折号），
修复后自动写回 UTF-8 with BOM + CRLF，并做 GBK 兼容复查。

## 附：em dash 说明

扫描会报 `U+2014 em dash 16 处`。**这个不用改**：

- 实测 `'\u2014'.encode('gbk')` **可以编码** -> 不会触发 VS 弹框
- 补丁库 A25 原版就有 18 处 -> 是原有书写风格

工具把它列出来只是提示，不是错误。
