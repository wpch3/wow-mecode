## 二·五、你问的「圣骑士扔锤子」

### 先说一个必须知道的真相

这类限制有**两层**，改装备只能解决第一层：

| 层 | 在哪 | 改装备能解决吗 |
|---|---|---|
| **谁能装备** | `item_template.AllowableClass` | ✅ 能 |
| **法术要什么武器** | `Spell.dbc` 的 `EquippedItemClass`（`SpellInfo.h:369-371`） | ❌ **不能** |

`SpellInfo.cpp:1358` 的判定：

```cpp
if (EquippedItemClass == -1) return true;                       // 法术不挑武器
if (item && item->IsFitToSpellRequirements(this)) return true;  // 武器符合要求
return false;                                                    // 否则放不出来
```

**意思是**：如果某法术在 DBC 里写死「必须单手锤」，你把武器改成剑，**法术依然放不出来**——限制在法术那边。

### 所以做了 `.item check`

造装备**之前**先查清楚：

```
.item check 53408

===== 法术 53408 =====
名称：审判之锤
  要求 ItemClass = 2 (武器)
  允许的类型：单手锤 双手锤
  .item type <entry> 类型 单手锤        ← 直接告诉你该怎么设
```

### 完整流程

```
.item check 53408                              1. 先查法术要什么武器
.item clone 40395 -y                           2. 克隆一把武器，得到 800000
.item type 800000 职业 圣骑士 类型 单手锤 部位 主手   3. 设成圣骑专属单手锤
.item stat 800000 力量 5000 暴击 2000 耐力 8000     4. 加属性
.item spell 800000 1 53408 装备                 5. 挂技能
.item combat 800000 伤害 5000 8000 速度 2.6      6. 调伤害
.additem 800000                                7. 拿到手
```

## 二·五·五、改已存库的装备（常见问题）

### 能改吗？能，随时改

```
.item type   800000 职业 圣骑士 类型 单手锤     改类型
.item stat   800000 力量 5000 暴击 2000        改属性
.item spell  800000 1 71903 命中 2.0           改技能
.item combat 800000 伤害 5000 8000             改伤害
```

**改完立刻生效，不用重启，不用重新 clone。**

原理：`Item::GetTemplate()`（`Item.cpp:540`）是**每次实时查表**：

```cpp
ItemTemplate const* Item::GetTemplate() const
{
    return sObjectMgr->GetItemTemplate(GetEntry());   // 不缓存指针
}
```

所以改了模板，**所有已发出去的实例自动跟着变** —— 包括别的玩家背包里的。

### 但有一个坑：穿在身上的要脱了再穿

**症状**：tooltip 显示新属性了，但**角色面板的力量没变**。

**原因**：`Player::_ApplyItemBonuses()`（`Player.h:1925`）是在**装备的那一刻**
把属性算进人物面板的，之后不会重算。改模板不触发重算。

**解法**：脱下来再穿上。

> 程序会**自动检测**：如果你正穿着这件装备，改完会提示
> 「你正穿着这件装备 —— 脱下再穿上才会生效」。
> 没穿的话不提示，避免刷屏。

### 哪些改动需要脱穿

| 改动 | 需要脱穿吗 |
|---|---|
| `.item stat` 属性 | ✅ 需要 |
| `.item combat` 伤害/护甲 | ✅ 需要 |
| `.item spell` 技能 | ✅ 需要（装备触发类） |
| `.item type` 职业/类型 | ✅ 需要 |
| 名字、品质、装等 | ❌ 不用，tooltip 直接变 |

### `.item spell` —— 加技能（**5 槽位，触发独立**）

```
.item spell 800000 1 71903 命中 2.0        槽位1：命中触发，每分钟2次
.item spell 800000 2 20375 装备            槽位2：装备时被动
.item spell 800000 3 33697 使用 0 120000   槽位3：主动使用，CD 2分钟
.item spell 800000 4 clear                 清除槽位4
```

**5 个槽位互不干扰**，可以同时挂 5 个不同触发方式的技能。

| 触发方式 | 说明 |
|---|---|
| `装备` / `被动` | 穿上就生效（光环用这个） |
| `命中` / `触发` / `proc` | 命中时几率触发（**必须配 PPM**） |
| `使用` | 右键点击发动 |
| `使用无cd` | 消耗品用 |

> **贴心保护**：如果设了「命中触发」但 PPM 是 0（永远不会触发），
> 会自动改成 1.0 并提示你——这是 WDE 里最常见的错误。

### `.item combat` —— 改战斗数值


## 四、关键技术决策（都踩过坑）

### 1. 必须写数据库，不能只改内存

只改内存是陷阱：造完发给自己，**重启服务器后背包里变成红色叹号**（模板没了）。

### 2. 不写死列名

`item_template` 有 130+ 列，且**不同整合包列数不同**。

证据：本仓库 `ObjectMgr.cpp:2938` 的 SELECT 注释只标到索引 136，
但 `:3096` 实际读 `fields[137]` —— 说明存在未被注释覆盖的列（如 `VerifiedBuild`）。

**写死列名一旦对不上，INSERT 直接失败。**

解法：先从 `information_schema.COLUMNS` 查出真实列名，在 C++ 里拼出
`INSERT INTO item_template SELECT <新entry>, col2, col3, ... FROM ...`。

### 3. 不用临时表

`DatabaseWorkerPool` 是**连接池**，`DirectExecute` 之间不保证同一条连接，
`TEMPORARY TABLE` 会在下一句丢失。所以改成一条语句完成，零连接依赖。

### 3b. 写库必须用 DirectPExecute（同步）—— 实测踩到的坑

**症状**：`.item clone 40395 -y` 报「写入失败：重载后找不到 entry 800000」，
但前面的克隆预览显示完全正常。

**根因**（`DatabaseWorkerPool.h:76` 的注释写得很清楚）：

```cpp
//! Enqueues a one-way SQL operation ... executed asynchronously.
void PExecute(...)          // ← 异步排队，不等执行完就返回

//! Directly executes ... will block the calling thread until finished.
void DirectPExecute(...)    // ← 同步阻塞，执行完才返回
```

原来用 `PExecute` 写 INSERT，**SQL 还在队列里排队，代码就已经跑到
`LoadItemTemplates()` 了** —— 读的时候数据库里还没有这一行。

**修复**：14 处写操作全部改成 `DirectPExecute`。

### 3c. 什么时候该用哪个

| 场景 | 用哪个 | 原因 |
|---|---|---|
| **写完立刻要回读** | `DirectPExecute` | 异步的话读到的是旧数据 |
| 写完不回读（如幻化） | `PExecute` | 内存缓存是权威源，异步不卡主线程 |
| 查询 | `Query` / `PQuery` | 本来就是同步的 |

> 幻化模块（`CustomTransmog.cpp`）用 `PExecute` 是**正确的** ——
> 它的权威数据在内存缓存里，数据库只是持久化，不需要立刻回读。

### 4. 写完必须重载 + 重建 QueryData

```cpp
sObjectMgr->LoadItemTemplates();                        // 读进内存
const_cast<ItemTemplate*>(created)->InitializeQueryData();  // 重建客户端缓存
```

你 conf 里 `CacheDataQueries = 1`，**不重建的话客户端鼠标悬停看到空白**。
（这个坑 `.reloaditem` 已经踩过，直接复用）

### 5. int32 溢出保护

你做过大数值改造，上限是 int32（21 亿）。所有缩放都钳制在 ±2100000000，
**不会回绕成负数**。

### 6. 删除保护

`.item del` **只允许删 800000-899999 段**，防手滑删掉官方物品。
