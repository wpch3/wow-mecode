# ⚠️ 提交前必读：子模块的坑

你的 `git diff --stat` 输出完全正确，但**先别用 `git add -A && git commit`**，
那样会漏掉 Eluna 的修改。

---

## 你的输出解读

```
$ git diff --stat
 src/server/game/Entities/Item/Item.cpp |  4 ++--     ← ✅ 耐久 2 处
 src/server/game/Globals/ObjectMgr.cpp  | 20 ++++----  ← ✅ 物品读取器 10 处
 src/server/game/LuaEngine              |  0          ← ⚠️ 注意这行
 3 files changed, 12 insertions(+), 12 deletions(-)

$ cd src/server/game/LuaEngine && git diff --stat
 LuaEngine.cpp | 2 +-                                  ← ✅ Eluna 修复在这
```

**12 insertions / 12 deletions 完全正确**（ObjectMgr 10 处 + Item 2 处）。

**但 `LuaEngine | 0` 这行要注意**：`0` 表示"子模块内容有变化，但父仓库不知道改了啥"。
Eluna 的那 1 行改动**不属于**这 12 处，它在独立的子模块仓库里。

---

## 我实测复现了这个坑

我搭了个和你一模一样的父仓库+子模块结构测试：

```
=== 父仓库 git diff --stat (模拟你的情况) ===
 mysub | 0
 1 file changed, 0 insertions(+), 0 deletions(-)
```

然后在父仓库执行 `git add -A && git commit`：

```
On branch master
Changes not staged for commit:
        modified:   mysub (modified content)
no changes added to commit          ← 提交失败！
```

再查子模块实际状态：

```
子模块 f.txt 当前内容:      line1 MODIFIED
子模块 HEAD 提交里的内容:   line1
=> 子模块改动【未被提交】，仅存在于工作区
```

**结论：在父仓库 `git add -A` 不会提交子模块内部的文件改动。**

更危险的是，这时如果你（或将来任何教程）执行了：

```bash
git submodule update --force     # 常见的"同步子模块"命令
```

**Eluna 的修改会被直接冲掉**，而且没有任何提示。到时候编译能过，
但 Lua 里传大数值还是报 `value must be less than or equal to 4294967295`，
你会完全找不到原因。

## ✅ 正确的提交方法：先子后父

### 第 1 步：先提交子模块（Eluna）

```bash
cd /d/TrinityCore/src/server/game/LuaEngine
git add -A
git commit -m "eluna: fix uint64 CHECKVAL truncation"
```

✅ 验证：
```bash
git log --oneline -1
git status
```
应显示刚才的提交，且 `working tree clean`。

### 第 2 步：回父仓库，此时指针变化会显现

```bash
cd /d/TrinityCore
git diff --stat
```

**注意看变化**——`LuaEngine` 那行的 `0` 变成了 `2 +-`：

```
 src/server/game/Entities/Item/Item.cpp |  4 ++--
 src/server/game/Globals/ObjectMgr.cpp  | 20 ++++++++++----------
 src/server/game/LuaEngine              |  2 +-      ← 变成 2 了
```

这说明父仓库现在能记录"子模块指向了新提交"。

### 第 3 步：提交父仓库

```bash
git add -A
git commit -m "bignum: item loader 32bit + durability 32bit + eluna uint64 fix"
```

✅ 最终验证：
```bash
git status
```
应显示 `nothing to commit, working tree clean`。

```bash
git log --oneline -1
cd src/server/game/LuaEngine && git log --oneline -1 && cd /d/TrinityCore
```
两边都应各有一条新提交。

## 📌 这个坑以后还会遇到

只要碰 Eluna 的代码（比如后面第 5 步解除 Eluna 限制），都要按
**"先提交子模块，再提交父仓库"** 的顺序。

另外记住：**永远不要在有未提交改动时执行 `git submodule update --force`**。
