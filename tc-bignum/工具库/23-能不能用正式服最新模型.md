# 能不能用正式服的最新模型直接替换？

> 制定：2026-08-02
> 问题：能不能用正式服（11.x）的最新模型直接替换现在的模型？
> 答案：**"直接替换"不行，但"转换后替换"可行**，而且社区已经这么干十几年了。

---

## 一、先说结论

| 做法 | 可行性 | 代价 |
|---|---|---|
| 把 11.x 的 `.m2` 直接丢进 patch | **不行**，格式不认 | 模型不显示 / 崩客户端 |
| 用工具**转换**后再丢进去 | **可行** | 每个模型 5-15 分钟手工 |
| 下别人**转好的**整包 | **可行，最省事** | 只能用别人做过的 |

**你现在装的 HD 补丁，本质上就是别人帮你做完了第 2 步的成品。**
你之前自己查出来"HD 补丁底子是 WoD(6.x)/Legion(7.x)"——就是这个道理。

---

## 二、为什么不能直接用（三道硬墙）

### 墙 1：M2 版本号

3.3.5 客户端只认 **version 264**。

| 版本号 | 资料片 |
|---|---|
| 256-257 | Classic |
| 260-263 | TBC |
| **264** | **WotLK 3.3.5  <- 只认这个** |
| 265-272 | Cataclysm |
| 272 | MoP / WoD |
| 272-274 | Legion / BfA / Shadowlands |

（来源：wowdev.wiki/M2 版本表）

### 墙 2：文件结构从 Legion 开始整个变了

- **Legion (7.0) 之前**：M2 是一整块，魔数 `MD20`
- **Legion (7.0) 及之后**：M2 变成**分块格式**，魔数不再是 `MD20`，
  老数据被塞进一个叫 `MD21` 的块里

3.3.5 客户端打开文件看到的第一个魔数不是 `MD20`，**直接就不认了**。

### 墙 3：贴图引用方式变了（这是最麻烦的一道）

- **3.3.5**：模型里存**路径字符串**，比如 `Creature\Wolf\WolfSkin.blp`
- **BfA (8.0) 及之后**：模型里存 **FileDataID 数字**（`TXID` 块），
  文件名在客户端里**根本不存在了**

所以 8.0 以后的模型，就算你把版本号改对了，
它也不知道去哪找贴图——因为它记的是一个数字，而 3.3.5 只认路径。

> 这就是你之前查到的 **"8.2 后客户端移除99%文件名，只认 FileDataID"** 那条边界。

## 三、【重点】这条可能和你的宠物蓝贴图是同一个根因

还有第四道墙，专门坑贴图：**BLP 的像素格式**。

```
DXT1 / DXT3 / DXT5     DX9 时代的压缩格式，3.3.5 能读
BC5 (PIXEL_BC5 = 11)   DX10+ 格式，3.3.5 【读不了】
```

3.3.5 是 DX9 客户端。喂给它 BC5 贴图，它解不了，
**渲染出来就是蓝紫色**。

你的宠物贴图问题，症状完全对得上：
- 你已排除加载机制、m2/skin、补丁版本
- 三次测试（只BLP / 去m2skin / 全套）都蓝

**跑一下就知道**：

```bash
python 工具库/tools/patch_scan.py "你的宠物补丁目录"
```

看第 3 段"编码分布"有没有 `BC5`。有的话就是它，
解法是转成 DXT5，或者直接删掉那部分贴图用原版的。

> 这条一直挂在待办里没结，正好这次一起验证。

## 四、能做的三条路（按省事程度排）

### 路 A：下别人转好的整包（推荐，你现在就在这条路上）

社区有大量做好的降版本整合包。你现在装的就是。

**要点**：找 **WoD(6.x) / Legion(7.x)** 时期的包。
你自己已经查出来这一点了——**9.0 之后的 UV 对不上**，
因为暴雪在 8.x-9.x 重做过一批模型的 UV 展开。

### 路 B：自己转（工具链已经在你的文档里）

`工具库/07-模型格式转换.md` 有完整流程，简述：

```
1. wow.export        从正式服客户端提取 m2 + blp
2. TXID              把 FileDataID 引用转回路径字符串（要反复跑约15次）
3. Multi Converter   转 M2 版本号和结构（跑1次）
4. 转 BLP            确保是 DXT 不是 BC5
5. 改 DBC / 打包 MPQ
```

**代价**：每个模型 5-15 分钟，且**不保证成功**。
骨骼数超标、粒子系统新字段、动画块结构变化，
都可能导致转出来的模型崩客户端或动作错乱。

**越新的模型越难转。** 11.x 的模型转 3.3.5 属于地狱难度。

### 路 C：换个更高版本的服务端（不推荐现在做）

想用"最新"模型，最直接的办法是用能跑那个版本的服务端。
但这跟你之前调研的结论一致：

- CypherCore 支持 11.2.5，但**没有 NPCBot**
- 你的整条工具链（40+ 指令、剧情系统、NPCBot 定制）都是 3.3.5 的
- 客户端要走 CASC + FileDataID，工具链完全不同

**这条路等于推倒重来。已归档在 `规划-长期路线-64位与正式服魔改.md`。**

## 五、一个现实的建议

你的目标是"更好看的模型"，不是"必须是 11.x 的模型"。

**WoD/Legion 时期的模型，和 11.x 的差距其实很小** ——
暴雪在 6.x-7.x 做过一次全面的角色模型重制（就是著名的"HD 模型更新"），
那之后主要是加新内容，老模型的精度没有再大幅提升。

所以：
- **想要好看** -> 路 A，找质量高的 WoD/Legion 整合包，**性价比最高**
- **想要某个特定的新模型**（比如某个新坐骑）-> 路 B，单个转，值得
- **想要整套 11.x** -> 不现实，代价远超收益

## 六、动手前先体检

拿到任何模型包，先跑这两个：

```bash
# 看 M2 版本号（不需要 Python）
bash 工具库/tools/m2ver.sh "补丁目录"

# 完整体检：M2版本 + BLP编码(含BC5检测) + DBC列数
python 工具库/tools/patch_scan.py "补丁目录"
```

判定：

| 看到 | 结论 |
|---|---|
| `MD20 + 264` | 能直接用 |
| `MD20 + 其他数字` | 要转版本 |
| `MD21` | Legion+，3.3.5 完全不认 |
| BLP 编码有 `BC5` | 会显示蓝紫色，必须转 DXT |
