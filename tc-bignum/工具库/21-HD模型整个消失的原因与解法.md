# HD 模型装上后整个建模消失 —— 原因与解法

> 日期：2026-08-01
> 现象：用户装 WoD 新模型补丁，**建模整个消失，无报错无闪退**；
> 换成只改皮肤的旧模型补丁则完全正常。

---

## 一、先说结论：这不是 bug，是缺一块拼图

**"无报错、无闪退、只是消失"** —— 这个组合本身就是最重要的线索。

| 现象 | 说明什么 |
|---|---|
| 崩溃 / 闪退 | 文件格式不对（MD21 之类）|
| 白模 / 绿模 | 贴图路径错 |
| 报 Error #132 | 内存或文件损坏 |
| **完全消失，无任何报错** | **客户端成功加载了，但被告知"不要画"** |

最后一种意味着：**客户端读到了模型，但渲染时发现没有可画的几何体。**

---

## 二、根因：HD 模型走的是另一套文件名，DBC 没告诉客户端

WoD/Legion 的人物模型在移植到 3.3.5 后，**文件名带 `_HD` 后缀**：

```
原版：Character\Human\Female\HumanFemale.m2
HD ：Character\Human\Female\HumanFemale_HD.m2
     Character\Human\Female\HumanFemaleSkin00_00_HD.blp
```

**客户端默认去找【不带 _HD】的那套。**

所以会发生这种事：

```
客户端要画人类女性
  -> 查 CharSections.dbc，得到 HumanFemaleSkin00_00.blp（不带 _HD）
  -> 你的补丁里只有 HumanFemaleSkin00_00_HD.blp
  -> 找不到 -> 没有贴图 -> 没有可渲染的批次
  -> 【什么都不画】
```

**结果就是：模型消失，但客户端不认为这是错误**，所以不报错、不崩溃。

### 社区实证

ownedcore 上做 WoD/MoP 人物移植的人给出的原话（2014）：

> You need to go into **charSections.dbc** and put `_HD.blp` for all the missing textures.
> Of course make sure you have the textures that end with `_HD.blp` in your models folder.

以及：

> 把 `Character\Human\Female\HumanFemaleFaceLower03_05.blp`
> 改成 `Character\Human\Female\HumanFemaleFaceLower03_05_HD.blp`

**这正是你缺的那一步。**

---

## 三、还有第二个开关：ChrRaces.dbc

同一个帖子里紧接着的一句：

> oh and you need to edit your **chrraces dbc**.
> open it and look at **column 25 and 26**. for the orc, the number under 25 is 1
> and the number under 26 is 1. **change 25 to 2 and 26 to 0**

wowdev.wiki 的 ChrRaces 页面对这个字段的描述是：

> **"Force to HD model if available"**

**这个字段就是"用不用 HD 模型"的总开关。** 不改它，客户端不会去找 `_HD` 文件。

---

## 四、为什么"只改皮肤的旧模型补丁"就没问题

因为它**覆盖的是原版文件名**：

```
旧模型补丁：Character\Human\Female\HumanFemaleSkin00_00.blp   <- 不带 _HD
                                    ↑ 和 DBC 里写的完全一致
```

客户端按 DBC 里的路径去找，**正好找到你的文件**，直接用。
不需要改任何 DBC。

**这就是为什么它"完全没问题"，而 HD 补丁"整个消失"。**

---

## 五、三个解法（按省事程度排序）

### 方案 A：找自带 DBC 的完整 HD 包（最省事）

**成熟的 HD 移植包会自带改好的 `CharSections.dbc` 和 `ChrRaces.dbc`。**

用 `patch_scan.py` 检查你的补丁：

```bash
python 工具库/tools/patch_scan.py "你的HD补丁目录"
```

看第 1 段的 `.dbc 数据表` 计数：

| 结果 | 说明 |
|---|---|
| **有 DBC** | 作者做全了，你**漏装了 DBC 部分** -> 补上即可 |
| **0 个 DBC** | 包不完整，走方案 B 或换包 |

> **你之前那个 `ralia-nude-patch` 就是 0 个 DBC** ——
> 如果你现在这个 HD 包也是 0，那就是同样的问题。

**社区公认完整的包**（模型 + 贴图 + DBC 全套）：
- **Leeviathan 版**（人物 + NPC，含血精灵，评价最好）
- **Finsternis 版**（人物 + 生物 + 坐骑）

### 方案 B：自己改 DBC（需要 WDBX Editor）

前提：批次 3 的 WDBX Editor。

```
1. 从客户端 MPQ 提出 CharSections.dbc 和 ChrRaces.dbc
2. WDBX Editor 打开，选 WOTLK 3.3.5
3. ChrRaces.dbc：把你要 HD 化的种族，第 25 列改 2、第 26 列改 0
4. CharSections.dbc：把贴图路径批量加上 _HD 后缀
5. 存回，放进补丁的 DBFilesClient\ 目录
6. 删 Cache
```

**第 4 步的批量技巧**（原帖作者推荐）：

```
用 DBC 编辑器导出为文本
Notepad++ 打开
全部替换：.blp  ->  _HD.blp
再导入回去
```

**注意**：不是每一行都要加 `_HD`。原帖有人指出过这个坑 ——
有些行（比如 `HumanFemaleNakedTorsoSkin00_02.blp`）在 HD 包里
可能没有对应的 `_HD` 文件。**加了反而会让那部分也消失。**

**稳妥做法**：先确认补丁里到底有哪些 `_HD` 文件，只改这些行。

### 方案 C：反向重命名（土办法，但有效）

**不改 DBC，改文件名。**

把补丁里所有 `_HD.blp` / `_HD.m2` 的 `_HD` **去掉**，
让它们直接覆盖原版文件名。

```
HumanFemaleSkin00_00_HD.blp  ->  HumanFemaleSkin00_00.blp
HumanFemale_HD.m2            ->  HumanFemale.m2
HumanFemale_HD00.skin        ->  HumanFemale00.skin
```

原帖也提到过这条路：

> maybe it's easier to just replace the texture file names with a batch renamer.
> Remove the "_HD" and overwrite the existing ones with similar names.

**优点**：完全不碰 DBC，用批量改名工具几秒搞定
**缺点**：`.m2` 和 `.skin` 的内部引用可能还指向 `_HD` 名字，
模型可能仍然不显示 —— **对纯贴图包有效，对带模型的包不一定**

**建议**：先拿一个种族试，成了再批量做。

---

## 六、还有一个可能：缺 .skin 文件

如果 DBC 都对了还是消失，检查 `.skin`。

`.skin` 文件存的是**渲染批次和几何体分组**。
`.m2` 只有骨骼和顶点，**`.skin` 才决定"画哪些三角形"**。

```
HumanFemale_HD.m2
HumanFemale_HD00.skin   <- 缺这个，模型加载成功但画不出东西
HumanFemale_HD01.skin
HumanFemale_HD02.skin
HumanFemale_HD03.skin
```

**症状完全一致：无报错、无崩溃、什么都不显示。**

`patch_scan.py` 会统计 skin/m2 比值，正常应该是 **1 个 m2 对 1-4 个 skin**。
比值小于 1 就是缺文件。

---

## 七、诊断流程

```
建模消失（无报错）
      |
      v
跑 patch_scan.py
      |
      +-- .dbc 数量 = 0 ?
      |      是 -> 【方案 A】找带 DBC 的完整包，或【方案 B】自己改
      |      否 -> 你漏装 DBC 了，把 DBC 放进 DBFilesClient\
      |
      +-- skin/m2 比值 < 1 ?
      |      是 -> 缺 .skin 文件，包不完整
      |
      +-- 文件名带 _HD ?
             是 -> 必须改 DBC（方案 B）或去掉后缀（方案 C）
             否 -> 应该能直接覆盖，检查目录层级和 Cache
```

---

## 八、给你的具体建议

你现在手上有两个补丁：

| 补丁 | 状态 | 建议 |
|---|---|---|
| **旧模型（只改皮肤）** | **完全正常** | **先用着**，主线要紧 |
| 新模型（WoD） | 建模消失 | 跑 `patch_scan.py` 看有没有 DBC |

**如果新模型包没带 DBC**，我的建议是**先不折腾** ——
去找 Leeviathan 或 Finsternis 的完整包，那两个是社区验证过
"解压丢 Data 就能用"的，省下改 DBC 的全部工作。

**你现在旧模型补丁已经能用了，视觉需求基本满足。**
HD 模型这件事排到客户端批次里，不影响主线。

---

## 九、一句话

> **消失 = 客户端找不到 DBC 里写的那个文件名。**
>
> **HD 模型走 `_HD` 后缀，DBC 里写的是不带后缀的名字，两边对不上。**
>
> **解法要么改 DBC（正规），要么去掉 `_HD` 后缀（土办法），
> 要么换一个自带 DBC 的完整包（最省事）。**
