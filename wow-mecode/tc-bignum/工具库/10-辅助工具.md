# 辅助工具

## 一、数据库

### HeidiSQL（你已在用）
- 免费，轻量，Windows 原生
- 适合批量 SQL、快速查改

### DBeaver（你已在用）
- 跨平台，功能更全
- **注意**：`Ctrl+Enter` 执行光标处，**`Alt+X` 执行全部**

### WoWDatabaseEditor（推荐加装）
见 `09-一体化框架.md`。WoW 专用 IDE，**官方支持 TC 3.3.5**，
调 NPC / SmartAI 很省事，还有 OpenGL 3D 视图。
https://github.com/BAndysc/WoWDatabaseEditor

### Keira3 —— 不要装
**AzerothCore 专属。** Keira2 才是 TrinityCore 版，2019 年就归档停更了。
详见 `09-一体化框架.md` 的勘误段。

## 二、二进制编辑

### 010 Editor（付费，有试用）

**最强的十六进制编辑器**，卖点是 **Binary Template** —— 
可以用模板文件解析二进制格式，把一堆十六进制变成结构化视图。

**WoW 相关用途**：
- 查看 M2 文件结构（retroport 排错）
- 搜索模型引用了哪些 `.blp`
- 手动修补 DBC / M2 的某个字段
- 分析未知格式

社区有现成的 M2/WMO/ADT/DBC 模板文件可下载。

### HxD（免费替代）

纯十六进制编辑，没有模板功能，但免费够用。
临时查个字节用它就行。

## 三、3D 软件

### Blender（免费，推荐）

**用途**：
- 编辑从 wow.export / WMV 导出的 OBJ
- 做自定义模型
- 渲染宣传图

**关键插件**：
- **io_scene_wowobj** —— wow.export 自带（在 `addons/blender/`），
  导入 OBJ 时自动配材质
- **WoW Blender Studio** —— 更完整的 WoW 工作流插件（社区维护）

**注意**：Blender 导出的模型**不能直接给 3.3.5 用**，
还要走 M2 转换（见 `07-模型格式转换.md`）。

### 3ds Max

老牌，有 M2 导入导出插件（`M2Mod`）。
但要付费，Blender 够用的话没必要。

## 四、客户端调试

### WoW 客户端自带

游戏内命令：
```
/console scriptErrors 1        显示 Lua 错误
/console taintLog 1            插件污染日志
/reload                        重载界面
/dump <表达式>                 打印变量（需要 DevTools 插件）
```

### 删 Cache（改客户端文件后必做）

```
World of Warcraft/Cache/        ← 删掉整个文件夹
```

**改了 DBC 或模型不删 Cache，游戏还会用旧的。**
这是最常见的"改了没效果"原因。

### 有用的调试插件

| 插件 | 用途 |
|---|---|
| **DevTools** | 浏览游戏内 API 和变量 |
| **!BugGrabber** + **BugSack** | 捕获 Lua 错误 |
| **Spell ID 显示类插件** | 鼠标悬停显示法术 ID |
| **idTip** | 显示物品/法术/NPC 的 ID |

**idTip 对你特别有用** —— 你做自定义物品/法术时，
游戏里悬停就能看到 ID，不用回去查数据库。

## 五、服务端调试

### TrinityCore 自带命令

```
.debug <子命令>          各种调试
.gm on                   GM 模式
.server info             服务器状态（延迟、在线数）
.reload <表名>           热重载数据表
.npc info                看选中 NPC 的详细信息
.gobject info            看物件信息
```

**`.server info` 特别重要** —— playerbot wiki 提到用它看延迟，
判断 bot 数量是否超载。你以后调 bot 数量时会用到。

### 日志

```
D:\TC-Build\bin\RelWithDebInfo\logs\
├── Server.log           主日志
├── DBErrors.log         数据库错误（SQL 数据有问题会记这）
└── Crash_*.txt          崩溃转储
```

**DBErrors.log 值得定期看** —— 很多"数据配错了"的问题
服务端只是静默记日志，游戏里表现为"莫名其妙不生效"。

## 六、版本控制

### Git（你已在用）

**建议**：把你的 `tc-bignum` 工作区也纳入 git。
28 个 step 的补丁，出问题能回溯。

```bash
cd /path/to/tc-bignum
git init
git add .
git commit -m "step28 完成"
```

**特别是**：`patches/` 和 `sql/` 目录，这些是你的心血。

## 七、文件对比

### WinMerge / Beyond Compare

**用途**：
- 对比两个版本的 DBC 导出 CSV，看改了什么
- 对比补丁前后的 .cpp 文件
- 合并上游更新时解决冲突

你从上游仓库拉更新时会很有用。
