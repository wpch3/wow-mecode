# 整合客户端体检 / 加密怎么办

> 采集日期：2026-07-31
> 场景：你手上是**别人整合好的 zhCN 3.3.5a 客户端**，Data 里一堆 MPQ 补丁，
> 但不知道作者有没有加密、能不能在上面继续改。

---

## 一、先纠正我上一篇文档里的一句错话

`00-工具总览与前置条件.md` 里我写了这么一句：

> 3.3.5 原版客户端**只从 MPQ 归档读文件**，而且对自定义 MPQ 有校验。
> 你把改好的模型/贴图/DBC 放进去，游戏可能直接忽略。

**这句是错的，前半句错得离谱。**

查证过程：Warmane 的 HD 客户端整合帖里，玩家把一堆 `patch-4.MPQ`
到 `patch-Y.MPQ` 直接丢进 Data 就能用，全程没提改 exe；
另一个高清模型帖用户原话是
"I ran the original .exe client from Warmane's downloads section
and it seems to load all the updated models just fine"。
来源：forum.warmane.com/showthread.php?t=433477 / t=456935

**真相拆成两件事**：

| 能力 | 原版 exe | 需要打补丁 |
|---|---|---|
| 加载 `Data\patch-4.MPQ` 这种**真 MPQ 文件** | **本来就能** | 不需要 |
| 加载 `Data\patch-4.MPQ` 这种**文件夹** | 不能 | **需要** |
| 自定义 Item.dbc 不显示问号图标 | 不能 | 需要（另一种补丁）|
| 改登录界面等 Interface 文件 | 不能 | 需要 |

也就是说：**做补丁包这件事，原版 exe 就够了。**
打补丁的 exe 给你的是**开发便利**（改文件不用重打包）和几个**额外特性**，
不是入场券。

我把 `00` 那篇的措辞已经同步改掉了。这条错误的性质和之前
"flags_extra 130"、"faction 1868" 是一类：**凭印象写结论，没查实证**。

## 二、你的客户端：已经能确定的事

你说"里面很多 MPQ，全是补丁"，这一条本身就是**强证据**：

```
作者塞了 N 个 patch-X.MPQ 进去  →  这些补丁在游戏里是生效的
                              →  否则作者塞它们干嘛
                              →  所以 MPQ 加载链路是通的
                              →  你按同样规则加一个包，一样会被加载
```

**所以"我能不能做客户端补丁"这个问题，答案已经是能了。**
剩下的只是"作者有没有给我留位置"和"我看不看得懂他的包"。

## 三、"加密"到底指什么 —— 三种情况分开谈

你担心的"加密"，实际对应三个完全不同的东西，
影响范围差别极大。

### 情况 A：MPQ 删了 (listfile) —— 最常见，99% 是这个

**现象**：MPQ Editor 打开作者的包，看到一堆 `unknown\File00000001.blp`，
没有正常目录树。

**原理**：MPQ 内部**不存明文路径**，只存路径的哈希值。
`(listfile)` 是包里一个特殊文件，记着"哈希 → 真实路径"的对照表。
作者把它删掉，你就只能看到哈希。

zezula.net 官方原话（MPQ 格式作者本人）：

> Many protected maps today have listfiles removed. Due to the nature of MPQs,
> it is complicated to use the file without the file name,
> because the file name serves as a key.

**这算加密吗**：严格说不算，文件本身没加密，只是**你不知道它叫什么**。

**对你的影响**：

| 你想干的事 | 受影响吗 |
|---|---|
| 做自己的新补丁包 | **完全不受影响** |
| 覆盖某个官方文件（你知道路径） | **完全不受影响** |
| 看作者包里有什么 | 受影响 |
| 在作者的改动上继续改 | 受影响 |

**解法**：外挂一份 listfile。因为**官方文件的路径是公开已知的**，
你不需要作者给，自己下一份 3.3.5 全量 listfile 挂上去，
作者包里凡是覆盖官方文件的部分，路径立刻就显出来了。

只有作者**自己新造的**文件（比如他自制的模型）才会仍然是 unknown。

具体操作见第五节。

### 情况 B：MPQ 头被改坏（真·保护）—— 少见

**现象**：MPQ Editor 直接打不开，或者打开就崩。

**原理**：改 MPQ 头里的"文件数量"字段等，让游戏还能读但工具读不了。
这在 War3 自定义地图圈很常见，WoW 整合包圈**很少见**，
因为整合包作者的目的是分发内容，不是防拆。

**对你的影响**：同情况 A —— 不影响你做自己的包。

**解法**：Ladik 本人在 zezula.net 说，遇到打不开的包可以发给他修。
实践里更划算的做法是：**绕过去，不去动它**。

### 情况 C：exe 加壳 —— 真正会挡路的

**现象**：exe 被 UPX / Themida / VMProtect 之类压过或保护过。

**对你的影响**：**只影响"你想再改 exe"这件事**。
不影响 MPQ，不影响 DBC，不影响你做内容。

**什么时候才会撞上**：你想给 exe 加"自定义物品图标修复"
或"允许文件夹补丁"这类特性的时候。

**解法**：**别在他的 exe 上改**。拿一份干净的 3.3.5.12340 原版 exe
自己打补丁，或直接用现成的打好补丁的 exe。exe 是可替换件。

## 四、三分钟活体测试（最重要的一节）

**静态分析全是猜，这个测试五分钟给你确定答案。**
不用装任何工具，不碰作者的任何文件。

### 准备

先跑体检脚本，拿到"推荐字母"：

```bash
bash 工具库/tools/client_check.sh "/d/你的魔兽目录"
```

假设它告诉你 `patch-Y.MPQ` 空着。下面用 Y 举例。

### 测试 1 —— 真 MPQ 文件能不能加载（判断有无入场券）

1. 用 MPQ Editor：`MPQs → New MPQ`，命名 `patch-Y.MPQ`，一路 Next
2. 从任意官方 MPQ 里提出 `Sound\Music\GlueScreenMusic\WotLK_main_title.mp3`
3. 找个**别的** mp3（随便什么歌），改名成 `WotLK_main_title.mp3`
4. 拖进 `patch-Y.MPQ`，保持目录结构 `Sound\Music\GlueScreenMusic\`
5. 把 `patch-Y.MPQ` 放进 `Data\`
6. **删掉客户端的 `Cache` 文件夹**（不删的话很多改动不生效）
7. 启动游戏，听登录界面音乐

| 结果 | 结论 |
|---|---|
| 听到你的歌 | **通了。** MPQ 加载正常，客户端魔改可以开工 |
| 还是原来的音乐 | 字母被占了/优先级不够，换更靠后的字母重试 |

> 为什么用登录音乐：不用进游戏、不用连服务器、不用改 DBC，
> 最快的闭环。而且 mp3 改名即可，不用转格式。
> 注意：`.wav` / `.ogg` **不能只改扩展名**，必须真转成 mp3。

### 测试 2 —— 文件夹补丁能不能加载（判断 exe 打没打过补丁）

1. 把上一步的 `patch-Y.MPQ` **文件**改名成 `patch-Y.MPQ.bak`
2. 在 `Data\` 下新建**文件夹**，名字就叫 `patch-Y.MPQ`
3. 在里面建目录 `Sound\Music\GlueScreenMusic\`，放同一个 mp3
4. 删 Cache，启动

| 结果 | 结论 |
|---|---|
| 听到你的歌 | **exe 打过补丁**。改文件不用重打包，开发效率起飞 |
| 没听到 | exe 是原版（或没打这个特性）。**不影响做内容**，只是每次要重打包 |

### 测试 3 —— 作者的包看不看得进去（判断加密程度）

1. MPQ Editor 打开作者的某个 `patch-X.MPQ`
2. 看目录树

| 现象 | 对应情况 | 严重度 |
|---|---|---|
| 正常目录树 | 没做任何处理 | 无影响 |
| 一堆 `unknown\` | 情况 A，删了 listfile | 轻，可缓解 |
| 打不开 / 崩溃 | 情况 B，头被改 | 中，绕开即可 |

**关键**：测试 1 通过的话，测试 3 是什么结果都**不影响你开工**。

## 五、情况 A 的缓解：外挂 listfile

作者删了 listfile，你可以用**官方全量 listfile** 把大部分路径找回来。

### 原理

官方文件的路径（`Creature\Murloc\Murloc.m2` 之类）是公开知识，
社区有整理好的全量清单。挂上去后，MPQ Editor 会把哈希和清单逐一比对，
对得上的就显出真实路径。

**能找回的**：作者覆盖官方文件的部分（占绝大多数）
**找不回的**：作者自己新造的文件

### 操作

1. 弄一份 3.3.5 listfile（社区常见名 `listfile.txt`，wowdev / model-changing 有）
2. MPQ Editor → `Tools → Options` → 设置 **ListFile directory**
3. 或者打开包之后：`设置 → 文件列表 → 增加文件到列表`，选你的 txt
4. 刷新，unknown 大量减少

### 中文社区的土办法（CSDN 有实录）

listfile 太大（高版本有 89 万条）会卡死编辑器。做法是**只做你要的那部分**：

- 只想要 DBC → 新建 txt，只写 `DBFilesClient\` 开头的路径
- 只想要生物模型 → 只写 `Creature\` 开头的
- 只想要装备 → 只写 `Item\` 开头的

小清单，秒出结果。

## 六、体检脚本 `client_check.sh`

已放在 `工具库/tools/client_check.sh`，**只读，不改客户端任何文件**。

### 用法

```bash
bash 工具库/tools/client_check.sh "/d/魔兽世界"
```

### 它输出五段

| 段 | 内容 |
|---|---|
| 1 | 所有 exe 的大小 / MD5 / SHA1，跟官方 12340 指纹比对 |
| 2 | 加壳特征扫描 + 明文串可见度（判断能不能 hex 编辑）|
| 3 | Data 里的官方包 / 自定义包 / **文件夹型补丁** 清点 |
| 4 | **patch 字母占用图**，直接告诉你该用哪个空位 |
| 5 | 下一步指引 |

### 第 4 段长这样

```
  Data 目录
  （优先级从左到右递增，越靠右越能覆盖别人）
    [4] 5  6  7  8  9 [A] B  C  D  E  F  G  H  I  J ... X  Y [Z]
    [X]=已占用   X=空闲
    ==> 推荐你用: patch-Y.MPQ
```

### 关于 MD5 比对的一个重要提醒

脚本内置的官方指纹是这个：

```
MD5 : 45892bdedd0ad70aed4ccd22d9fb5984
SHA1: 178f78380affd260cb775d44397ba6b33ac05fdb
```

来源 github.com/anzz1/wow-client-checksums。**注意**：这份表覆盖
deDE / enGB / enUS / esES / esMX / frFR / ruRU 七个语种——
七个语种的 Wow.exe 是**同一个文件**，hash 完全相同。

**但这份表里没有 zhCN / zhTW。** 中文代理版（第九城市/网易）的 exe
和欧美版本来就不是同一个二进制。

所以：**你的中文客户端 hash 对不上，是正常的，不能据此判断被改过。**
这也是为什么第 5 段一直强调"定性只能靠活体测试"。

## 八、一句话总结

> **作者加没加密，跟你能不能做客户端改造，基本无关。**
>
> 加密影响的是"你能不能读懂他做了什么"，
> 不影响"你能不能自己做点什么"。
>
> 你要做的只有一件事：**在没被占用的字母上，建你自己的包。**

| 问题 | 状态 |
|---|---|
