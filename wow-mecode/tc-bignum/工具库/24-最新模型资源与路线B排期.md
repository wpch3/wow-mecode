### 所以结论

| 想要 | 可行性 |
|---|---|
| 用 10.x 的模型**替换**现有种族外观 | **完全可行**，改 DBC 就行 |

**"外观替换"和"新增可玩种族"是两件事，前者没有版本上限。**

# 第三部分：能不能写个"兼容工具/插件"

先说结论：**转换工具能写（但没必要重写），运行时兼容层不能写。**

## 为什么"运行时兼容插件"做不到

你想要的理想形态大概是："装个插件，客户端就能直接读 11.x 的模型"。
这个做不到，原因是**解析器在 exe 里，不在任何可替换的位置**：

```
M2 解析      编译进 Wow.exe 的机器码
渲染管线     DX9，编译进 exe
BLP 解码     编译进 exe，只认 DXT1/3/5，不认 BC5(DX10格式)
Lua/插件层   只能操作 UI，碰不到模型加载
```

**插件（AddOn）跑在 Lua 沙箱里，权限只到 UI。**
它连"加载一个模型文件"这个动作都插不进去，更别说改解析逻辑。

要做真正的运行时兼容，等于：
1. 逆向 exe 里的 M2 解析函数
2. 用 DLL 注入 hook 掉它
3. 自己写一个支持 274 版本 + chunked 格式的解析器
4. 还得把 DX9 渲染管线改成能吃 BC5

**这是"重写客户端渲染层"级别的工程**，不是一个工具。
社区二十年没人做成，不是没想到，是代价太高。

## 为什么"离线转换工具"没必要重写

因为**已经有了，而且很成熟**：

| 工具 | 干什么 | 状态 |
|---|---|---|
| **wow.export** | 从正式服/CDN 提取 m2+blp | 活跃维护 |
| **TXID Fixer** | FileDataID -> 路径字符串 | 成熟 |
| **MultiConverter** | M2 版本号/结构转换 | MaxtorCoder 在维护 |

GrimReapaa 那个 178,479 文件的整包，就是这三个工具跑出来的。

**你要真想写工具，有价值的切入点不是"重写转换器"，
而是"补上转换器没做的那一步"：**

## 【可以做】DBC 自动注册工具

全量包最大的问题是**不含 DBC**——模型在包里，但游戏里调不出来。

这件事可以自动化：

```
输入：模型包目录（一堆 .m2）
处理：
  1. 扫描所有 .m2，拿到路径
  2. 读现有 CreatureModelData.dbc，找空闲 ID
  3. 为每个模型生成 CreatureModelData 行（ID + 路径）
  4. 生成对应的 CreatureDisplayInfo 行（displayid -> modelid）
  5. 输出新 DBC（客户端和服务端各一份）
  6. 顺便生成一份 CSV 清单，说明哪个 displayid 是哪个模型
输出：能直接用的 DBC + 对照表
```

**这个有实际价值**，因为：
- 手工加 178,479 个模型是不可能的
- 加完之后你的 `.fm` 指令立刻就能搜到它们
- 是纯 Python，不涉及逆向，风险低

**代价**：DBC 读写我已经在 `dump_models.py` 里做过了（读的部分已验证），
写的部分要新做，但格式一样，工作量可控。

## 补充：装了9.2.5的包，能兼容12版本的补丁吗？

**不能。而且这两件事根本没有关系。**

### 关键误解：模型包不是"客户端升级"

你可能把它想成了软件版本——"装了新版底子，就能装更新的插件"。
**WoW 不是这样。**

```
你装的 9.2.5 整包 = 一堆【已经转成 264 格式】的文件
你的客户端       = 还是 3.3.5，M2 只认 264，DX9 渲染

装再多包，客户端一个字节都没变。
```

**兼容性 100% 由 Wow.exe 决定，而 exe 你没换过。**
所以装 9.2.5 的包对"能不能吃 12.x 的东西"这件事，**影响为零**。

### 那什么情况下 12.x 的补丁能用？

只有一种：**别人已经把它降版本转成 264 了。**

而如果它已经转好了，那你装不装 9.2.5 的包，它都能用。
**两者不互为前提。**

| 补丁状态 | 能用吗 | 和9.2.5包有关吗 |
|---|---|---|
| 12.x 原始文件（未转换）| 不能 | 无关 |
| 12.x 已降版本到264 | 能 | 无关 |

### 现在有 12.x 的降版本包吗？——查了，没有

社区现状（2026-08 实查）：

| 版本 | 降版本资源 |
|---|---|
| 9.2.5 及以前 | **有全量整包**（GrimReapaa 那个）|
| 10.x Dragonflight | **有零散单项**（坐骑包、龙翼素材等）|
| 11.x The War Within | 零星 |
| **12.x Midnight** | **没找到** |

Midnight (12.0) 2026年1月才上线，3月2日正式发行。
**太新了，社区还没做。**

### 真正需要担心的"兼容"是另一回事：包与包打架

你问的"兼容"，实际会遇到的问题不是版本，而是**同名文件冲突**：

```
9.2.5包   里有 Creature\Wolf\Wolf.m2
某新包    里也有 Creature\Wolf\Wolf.m2
        -> MPQ 优先级高的【整个文件】赢，不合并
        -> 如果两边的 .m2 / .skin / .blp 不配套 -> 模型花掉或消失
```

**这才是装多个模型包的真实风险**，和版本号无关。
`21-HD模型整个消失的原因与解法.md` 讲的就是这个。

### 还有一道工具层的墙：.skel

即使你想自己转 12.x 的模型，MultiConverter 有个硬限制：

> "M2 using **.skel** are not supported"（作者原文）

`.skel`（骨架分离文件）是 Legion 7.3 引入的。
**现代人物模型大量使用 .skel**，这就是为什么：

- **生物/坐骑/物件** 好转（大多不用 .skel）
- **人物角色模型** 难转（普遍用 .skel）

这也解释了为什么社区的人物模型进度看起来慢于生物模型——
不是没人做，是工具卡在这。

### 结论

1. 装 9.2.5 的包 **不会**提升任何兼容性上限
2. 12.x 目前 **没有**降版本资源
3. 想混装多个包，要担心的是**同名文件冲突**，不是版本
4. **9.2.5 那个包已经是社区天花板**，装它就是拿到了目前能拿到的最好的

## 补充2：12.x 的皮肤能不能"只换贴图，保留9.x的m2/skel/anim"？

**不能。这是个很自然的想法，但卡在一个硬约束上。**

### 为什么想法合理

贴图（.blp）确实是三者里最"独立"的：
它不含骨骼、不含动画，理论上就是一张图。
所以"换皮不换骨"听起来应该可行。

**在同一代模型内部，这确实可行** —— 这就是无数"HD贴图包"的原理。

### 为什么跨版本不行：UV 展开变了

模型和贴图之间靠 **UV 坐标**对应：
模型每个顶点记录"我该取贴图上哪个位置的像素"。

```
9.x 的 m2  +  9.x 的 blp   -> 对得上
9.x 的 m2  +  12.x 的 blp  -> UV 对不上 -> 贴图错位/花屏
```

暴雪重做模型时会**重新展 UV**（顶点和贴图的对应关系整个变），
新贴图是照着新 UV 画的，喂给老模型就会错位。

**这正是你自己早就查出来的那条**：
> "HD 补丁底子是 WoD(6.x)/Legion(7.x)，要找 6.x/7.x 的贴图补丁，**9.0 的 UV 对不上**"

同样的道理，12.x 的贴图对 9.x 的模型也对不上。

### 三个文件的真实关系

| 文件 | 能不能单独换 | 原因 |
|---|---|---|
| `.blp` 贴图 | **同代可以，跨代不行** | 受 UV 约束 |
| `.skin` | **不能单独换** | 记录顶点索引，和 m2 严格绑定 |
| `.skel` / `.anim` | **不能单独换** | 记录骨骼层级和动画，和 m2 严格绑定 |

`.m2` + `.skin` + `.skel` + `.anim` 是**一套原子单位**，
拆开混搭只会得到花掉的模型或崩溃。

### 那"能不能做插件/程序/改客户端"？

这个问题拆成三层，难度天差地别：

**第1层：插件（AddOn）—— 做不到**

AddOn 跑在 Lua 沙箱里，权限只到 UI 层。
它连"加载一个模型文件"这个动作都插不进去。
（这条上一篇讲过，结论不变。）

**第2层：外部程序（离线转换）—— 已经有了，就是路线B**

wow.export + TXID + MultiConverter 就是干这个的。
"写个程序自动兼容"= 重写这套工具链，没必要。

**第3层：改客户端 —— 理论可行，代价极高**

要让 3.3.5 的 exe 直接吃 12.x 的模型，需要：

| 要改什么 | 难度 |
|---|---|
| M2 解析器（支持 274 + chunked MD21）| 逆向 + 重写函数 |
| 贴图引用（FileDataID -> 路径）| 要自建映射表 |
| `.skel` 骨架分离加载 | 3.3.5 完全没有这个概念 |
| BLP 解码器（支持 BC5）| DX9 管线不支持，要改渲染 |
| 顶点格式 / 着色器 | 新模型用了新 shader |

这不是"打个补丁"，是**重写客户端渲染层**。
社区二十年没人做成，不是没想到，是投入产出比太差。

**更现实的对比**：
花同样的精力，用 MultiConverter 能转几百个模型；
而改客户端可能一年都出不来一个能跑的版本。

### 唯一真正的例外：MultiConverter 的 .skel 墙

顺便说清楚一个你可能会撞上的限制。MultiConverter 作者原文：

> "M2 using **.skel** are not supported"

`.skel` 是 Legion 7.3 引入的骨架分离格式。
**现代人物模型普遍使用**，生物/坐骑大多不用。

所以：
- **生物 / 坐骑 / 物件 / 武器** -> 好转，成功率高
- **人物角色模型** -> 卡 .skel，这才是"人物模型进度慢"的真正原因

（不是没人做人物模型，是工具在这一步就停了。）

### 结论

1. 12.x 贴图配 9.x 模型 -> **UV 对不上，会花**
2. `.m2/.skin/.skel/.anim` 是**原子单位**，不能拆开混搭
3. 插件层做不到；外部转换工具**已经有了**；改客户端等于重写渲染层
4. **老老实实用整包 + 单项转换，是唯一划算的路**
