## 一、先把数字算清楚 —— 你说对了，而且比你想的还少

我上一篇说"人物模型难转"，容易让人以为工作量是天文数字。**算一下就知道不是。**

### 真实的人物模型数量

WoW 的人物模型不是"每个 NPC 一个模型"，而是 **种族 x 性别** 的组合：

```
基础种族模型 = 种族数 x 2（男女）
```

| 范围 | 种族数 | 模型数 |
|---|---|---|
| 3.3.5 原生（含哥布林等未开放）| 约 12 | **约 24** |
| 加到 BfA 全同盟种族 | 约 25 | **约 50** |
| 加到 Dragonflight（含龙希尔）| 约 27 | **约 55** |

**核心结论：真正要转的"人物模型"，是【50 个左右】，不是几百上千。**

你说的"几百上千"更接近**装备模型**（头肩胸腿等，每个种族一套）的量级，
那个确实上千，但**装备不用 .skel，好转得多**。

### 所以工作量到底多大

假设一个模型手工处理 30 分钟（含试错）：

```
50 个模型 x 30 分钟 = 25 小时
```

**这是一个人一周业余时间能干完的量。** 你的判断是对的 —— 数量不是问题。

**真正的问题不是数量，是"每一个都可能卡住"。** 下面说卡在哪。

## 二、卡点的真相：`.skel` 到底是什么

上一篇我说"MultiConverter 不支持 .skel"就停了，**说得不够透**。查了格式文档之后，情况其实比想象的清楚。

### `.skel` 只是把 M2 里的几块搬了出去

`.skel` 文件的全部内容（wowdev.wiki/M2/.skel 实查）：

| 块 | 内容 | 在 3.3.5 里对应 |
|---|---|---|
| `SKL1` | 名字 + flags | M2 header 的 name |
| `SKA1` | **attachments** + 查找表 | M2 的 attachments 数组 |
| `SKB1` | **bones** + key_bone_lookup | M2 的 bones 数组 |
| `SKS1` | **global_loops + sequences** + 查找表 | M2 的 sequences 数组 |
| `SKPD` | 父 skel 的 FileDataID（去重用）| 无，要展开 |
| `AFID` | .anim 文件 ID 列表 | 3.3.5 按文件名找 |
| `BFID` | .bone 文件 ID 列表 | 3.3.5 无 |

**关键洞察**：

> `.skel` 里的 `SKA1` / `SKB1` / `SKS1`，
> **就是 3.3.5 的 M2 本来就有的那几个数组**，只是被搬到外部文件了。

所以"支持 .skel"在原理上 **不是发明新东西，是把搬出去的搬回来**：

```
读 .skel 的 SKB1  ->  取出 bones 数组     ->  塞回 M2 header 的 bones
读 .skel 的 SKA1  ->  取出 attachments   ->  塞回 M2 header 的 attachments
读 .skel 的 SKS1  ->  取出 sequences     ->  塞回 M2 header 的 sequences
重算所有 M2Array 的 offset
```

**这是一个"数据搬运 + 偏移重算"的活，不是图形学难题。**

### 但有两个真实的坑

**坑1：`SKPD` 父子链**

```
lightforgeddraeneimale.skel  ->  SKPD 指向 draeneimale_hd
                                  自己没有 .anim，用父级的
```

所以转换器**必须递归解析父 skel**，不能只看一个文件。
（这也是为什么随手写的脚本容易在同盟种族上翻车。）

**坑2：M2Array 偏移全是相对的**

M2 里所有数组都是 `{count, offset}`，offset 是**相对 MD21 块起始**的。
把外部数据塞回去，**所有后续数组的 offset 全要重算**。
写错一个字节，客户端直接崩。

## 三、【重要】社区已经趟通了，有现成路径

在自己造轮子之前，先确认一件事：**这条路已经有人走通了。**

### 路径 A：M2Mod + Blender（有完整实战记录）

Hive Workshop 上有人写了完整流程，**核心思路值得注意**：

> "Since 7.3.5 WoW character models uses .skel files, that are unreadable by jM2converter."
> 「7.3.5 之后人物模型用 .skel，jM2converter 读不了」

他的**绕过办法**是：

> "**Why am I using WoD character models?** WoD character models are in better file system
> than later ones and **they haven't changed much until Shadowlands**."
> 「WoD 的人物模型文件结构更好，而且**直到 Shadowlands 都没怎么变**」

**这句话信息量极大**：

> 暴雪从 WoD(6.x) 到 Shadowlands(9.x)，**人物模型本身几乎没变**。
> 变的是文件组织方式（拆出 .skel），不是模型质量。

**所以你用 WoD/Legion 的人物模型，和用 9.x 的，视觉上差别极小。**
这就是为什么社区停在 7.x 不是"做不动了"，而是**再往后收益太低**。

## 四、完整转换流程（人物模型专用）

### 前置：判断你的目标模型用不用 .skel

```bash
# 用 wow.export 导出后，看目录里有没有 .skel 文件
# 有 .skel  -> 走流程 B
# 没 .skel  -> 走流程 A（简单得多）
```

**经验规律**：
- WoD (6.x) / Legion 早期 -> 多数**没有** .skel
- 7.3.5 之后的人物模型 -> **有** .skel

### 流程 A：无 .skel（WoD/Legion 早期人物、绝大多数生物）

```
1. wow.export   选 6.x/7.0 版本，导出 M2 (Raw) + 贴图
                （可以用 CDN 在线模式，不用下客户端）
2. 改魔数        用 010 Editor 或十六进制工具
                文件开头 "MD21xxxxMD20xxxx..." -> 删掉前 8 字节
                -> 变成 "MD20xxxx..."，转换器才认
3. TXID Fixer   反复拖进去点 Fix，约 15 次直到无变化
                （FileDataID -> 路径字符串）
4. MultiConverter  拖进去 Fix 一次（版本号 + 结构转 264）
5. BLP 检查     确认不是 BC5（3.3.5 读不了，会显示蓝紫色）
6. 加 DBC       CreatureModelData + CreatureDisplayInfo
7. 打包 MPQ     + 放服务端 dbc 目录
8. 游戏内验证    .fm <关键字> 搜到 -> .model id <displayid>
```

> 第 2 步"删前 8 字节"是社区实战帖里的关键技巧，
> 原理：Legion 的 M2 是 `MD21` 包着 `MD20`，删掉外层头就退化成 WoD 格式。

### 流程 B：有 .skel（现代人物模型）

```
1. wow.export   导出时【勾选】"export linked .skel/.bone files"
                （CHANGELOG 实查：0.2.x 已支持这个选项）
2. Blender      装 WoW Blender Studio（Blender 3.1）
                导入 M2 -> 它会自动合并 .skel 的骨骼
3. 检查          骨骼数、动画序列、attachment 点位
4. 导出          WBS 导出成 3.3.5 格式的 M2
5. 之后同流程 A 的 5-8 步
```

**注意**：WBS 的 M2 支持在 Discord 测试版里，稳定性不如 WMO 部分。

## 五、如果要自己做工具 —— 现实的切入点

**不建议**从零写 M2 解析器。但有三个**真空地带**值得自己做，
而且都是纯 Python、风险低、立刻见效：

### 工具1：`.skel` 合并器（技术核心，但范围可控）

```
输入：xxx.m2（chunked, 含 SKID 指向 .skel）+ xxx.skel
处理：
  1. 解析 M2 的 chunk 表，定位 MD21
  2. 解析 .skel 的 SKL1/SKA1/SKB1/SKS1
  3. 若有 SKPD，递归加载父 skel（同盟种族必须）
  4. 把 bones / attachments / sequences 塞回 MD20 结构
  5. 重算所有 M2Array offset
  6. 输出扁平的 MD20 文件
输出：能喂给 MultiConverter 的传统 M2
```

**难度**：中高。**但范围明确**，格式文档齐全（wowdev.wiki 有完整结构）。
**价值**：补上工具链唯一的真空。做出来对整个社区都有用。

### 工具2：DBC 批量注册（上一篇提过，最划算）

178,479 个模型手工加 DBC 不可能。这个必须自动化。
**纯数据处理，零风险，我随时能写。**

### 工具3：批量流水线（把现有工具串起来）

```python
# 伪代码
for m2 in 目录:
    if 有skel: 工具1合并
    删前8字节魔数
    调 TXID.exe（命令行）
    调 MultiConverter.exe
    检查 BLP 编码，BC5 的转 DXT5
    记录到 DBC 清单
生成 DBC + MPQ 打包脚本
```

**难度**：低（就是 subprocess 调外部程序 + 文件管理）。
**价值**：把 25 小时的手工活压到几小时无人值守。

## 七、关于"完全兼容"这四个字

要说清楚一件事，避免期待落空：

**"转换"永远是有损的。** jM2converter 作者原话：

> "Beware, when you retroport a model, you always lose some data
> (the newer client features) and you won't be able to get them back."

会丢的东西：
- 新版粒子系统的额外字段
- 新 shader 效果（3.3.5 的 DX9 管线没有）
- 部分动画混合特性
- LOD 分级（3.3.5 只有一套）

**但对"看起来更好"这个目标，这些损失基本无感。**
社区那些 HD 整合包全都是这么转出来的。
