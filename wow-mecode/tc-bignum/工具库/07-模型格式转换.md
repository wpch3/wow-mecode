# 模型格式转换（Retroport）

> **Retroport** = 把新版本 WoW 的模型"倒port"到旧版客户端
> 这是给 3.3.5 加现代模型的标准做法

---

## 一、为什么需要转换

新版 WoW（BFA / SL / DF / TWW）的 M2 模型格式和 3.3.5 **不兼容**：

| 差异 | 说明 |
|---|---|
| M2 版本号 | 3.3.5 是 264，新版更高 |
| 贴图引用方式 | 新版用 **FileDataID**（数字），3.3.5 用**路径字符串** |
| 骨骼/动画结构 | 有变化 |
| 粒子系统 | 新增了字段 |

**直接丢进 3.3.5 会：不显示 / 崩溃 / 无贴图。**

---

## 二、工具链

| 工具 | 作用 | 何时用 |
|---|---|---|
| **wow.export** | 从新版客户端提取 m2 + blp | 第一步 |
| **TXID** | 修复贴图 FileDataID 引用 | 第二步 |
| **Multi Converter** | M2 格式版本转换 | 第三步 |
| **jM2converter** | 另一套转换器（Java）| 替代方案 |
| **010 Editor** | 二进制查看，排查引用 | 排错时 |

---

## 三、完整流程（来自实战帖）

以加一把新版武器到 3.3.5 为例：

### 第 1 步：提取模型

用 **wow.export** 连新版客户端（或在线 CDN 模式）：

1. Models 标签，搜索武器名（如 `ArtifactSoulrend`）
2. 选一个配色
3. 导出为 **RAW (M2)** 格式，**勾选一并导出贴图**

导出后目录结构类似：
```
items/objectcomponents/weapons/
├── artifactsoulrend_d_03_red.m2
├── artifactsoulrend_d_03_red_01.blp
└── ...
```

顺便去 wow.tools 或 wow.export 下载对应**图标**：
```
interface/icons/inv_sword_2h_artifactsoulrend_d_03.blp
```

### 第 2 步：改名（去掉配色后缀）

```
artifactsoulrend_d_03_red.m2  →  artifactsoulrend_d_03.m2
```

### 第 3 步：TXID 修复贴图引用

把 `.m2` 拖进 **TXID**，点 Fix。

> **实战帖说要跑约 15 次** —— 因为每次只修一层引用。
> 反复拖进去点 Fix，直到没有变化为止。

TXID 的作用：把新版的 **FileDataID 数字引用**转换成 3.3.5 认识的**路径字符串**。

### 第 4 步：Multi Converter 转格式

把 `.m2` 拖进 **Multi Converter**，点 Fix。**这次只需要一次**。

它做的是 M2 版本号和结构转换。

### 第 5 步：确认贴图齐全（可选）

用 **010 Editor** 打开 m2，搜索 `.blp`，看引用了哪些贴图文件。
确保这些文件都在你的导出目录里。

漏了贴图 → 游戏里绿色 / 方块 / 绿色粒子。

### 第 6 步：改 DBC

**WDBX Editor** 打开 `ItemDisplayInfo.dbc`（选 WOTLK 定义）：

| 列 | 值 |
|---|---|
| `ID` | 100050（自己定，唯一）|
| `ModelName_1` | `artifactsoulrend_d_03.mdx` ← **写 .mdx** |
| `ModelTexture_1` | `artifactsoulrend_d_03_red` ← 不带扩展名 |
| `InventoryIcon` | `inv_sword_2h_artifactsoulrend_d_03` |

保存到**服务端 dbc 目录**。

### 第 7 步：打包 MPQ

**MPQ Editor** 建 `patch-4.MPQ`：

```
patch-4.MPQ/
├── DBFilesClient/
│   └── ItemDisplayInfo.dbc        ← 从服务端 dbc 目录拖过来
├── Item/
│   └── ObjectComponents/
│       └── Weapon/
│           ├── artifactsoulrend_d_03.m2
│           └── *.blp
└── Interface/
    └── Icons/
        └── inv_sword_2h_artifactsoulrend_d_03.blp
```

### 第 8 步：服务端配置

HeidiSQL 里复制一件**同类型**武器（2H 剑就复制 2H 剑），
把 `displayid` 改成 100050。

### 第 9 步：测试

1. 重启服务端
2. **删客户端 Cache 文件夹**
3. 进游戏，`.additem <你的entry>`

## 四、故障对照表（实战帖原文整理）

| 现象 | 原因 |
|---|---|
| **不可见** | 没跑 TXID，或没跑 Multi Converter，或顺序反了 |
| **贴图错误** | `ModelTexture_1` 名字写错 |
| **无动画** | MPQ 里文件没放全 |
| **崩溃** | `ModelName_1` 写错，或 HeidiSQL 里 displayid 用错 |
| **绿色粒子** | MPQ 里粒子贴图漏了 |
| **绿色模型** | 找不到贴图（路径/名字错）|
| **方格贴图** | 路径错（大小写、少 `.mdx`、反斜杠方向）|

**顺序很重要**：必须**先 TXID，后 Multi Converter**。反了不行。

## 五、生物模型（和武器略有不同）

改 `CreatureDisplayInfo.dbc` + `CreatureModelData.dbc`：

1. `CreatureModelData.dbc` 加一行，`ModelName` 填模型路径
   （如 `Creature\murloc2\murloc2.mdx`）
2. `CreatureDisplayInfo.dbc` 加一行，`ModelID` 指向上面那行的 ID，
   `TextureVariation_1` 填贴图名
3. 服务端 `creature_template.modelid1` 填 `CreatureDisplayInfo` 的 ID

MPQ 路径：
```
patch-4.MPQ/
└── Creature/
    └── murloc2/
        ├── murloc2.m2
        └── murloc2.blp
```

> **注意大小写**：实战帖特别提醒 `Creature` 首字母大写，
> "maybe WoW is case sensitive"。保持和原路径一致最安全。

## 七、给你项目的评估

**这条线值不值得做？**

| 考虑 | 判断 |
|---|---|
| 工作量 | **中高** —— 每个模型都要走 9 步 |
| 效果 | **很好** —— 现代模型质量远超 3.3.5 原版 |
| 风险 | 中 —— 步骤多，容易出错，但不影响服务端 |
| 前置 | 必须有打过补丁的 exe |

**建议**：先不批量做。等你的服务端玩法定型后，
挑**几件核心装备**（比如你的顶级自造装备）做现代模型，
作为"传说品质"的视觉标识。

批量做的话，考虑找现成的 retroport 模型包（社区有人做好了整套）。
