## 【勘误 2026-07-31】原版 exe 到底能不能加载自定义 MPQ

**本篇初版写了"原版客户端只从 MPQ 读文件、对自定义 MPQ 有校验、可能直接忽略"，
这句是错的。已作废，下面是查实后的版本。**

查证依据：Warmane HD 客户端整合帖里玩家把 `patch-4.MPQ` 到 `patch-Y.MPQ`
一堆包直接丢进 Data 就生效，全程没改 exe；另一帖用户原话
"I ran the original .exe client from Warmane's downloads section
and it seems to load all the updated models just fine"。

### 真相：拆成两种能力

| 能力 | 原版 exe | 需要打补丁的 exe |
|---|---|---|
| 加载 `Data\patch-4.MPQ` 这种**真 MPQ 文件** | **本来就能** | 不需要 |
| 加载 `Data\patch-4.MPQ` 这种**文件夹** | 不能 | **需要** |
| 自定义 Item.dbc 不显示问号图标 | 不能 | 需要（另一种补丁）|
| 改登录界面等 Interface 文件 | 不能 | 需要 |

**结论**：做补丁包这件事，**原版 exe 就够了**。
打过补丁的 exe 给的是**开发便利**和几个额外特性，**不是入场券**。

> 拿到别人整合好的客户端不知道能不能改？
> 跑 `工具库/tools/client_check.sh` 体检，再照
> `11-整合客户端体检与加密应对.md` 做三分钟活体测试，五分钟出结论。

### 打过补丁的客户端 exe（可选，但强烈建议）

WotLK Modding Wiki 原文：

> many modders have discovered another feature of the wow client that can be enabled
> by rewriting some of its internal code. This edit makes it possible for the game
> **not only to load files from MPQ archives, but from plain folders** that just have
> the same name as an MPQ archive, such as a folder in the Data directory called `patch-4.MPQ`.

**打过补丁的 exe 真正给你的**：

1. **把"MPQ"做成普通文件夹** —— 改个文件不用重新打包，直接丢进文件夹
2. 自定义物品不再显示问号图标（另一种补丁，见下）
3. 允许改 Interface 文件（登录界面等）

第 1 点对开发效率是质变。你调一个模型贴图，改完存盘、重进游戏就能看，
不用每次重打 MPQ。**但这只是效率问题，不是能不能做的问题。**

**获取方式**：
- 现成的：https://www.mediafire.com/file/kewam47gtdshhln/Wow.exe/file
  （WotLK Modding Wiki 官方给的链接）
- model-changing.net 论坛（需注册）
- 手动打补丁步骤：https://wotlkdev.github.io/wiki/your_first_mod/your_first_client_edit

**另一个值得装的：anzz1 的 WoWPatcher335**
https://github.com/anzz1/WoWPatcher335 （下载在 wowmodding.net）

打完之后**自定义物品不用改 Item.dbc、不用打 MPQ**，
直接往 `item_template` 加数据就行。附带四个开关：

| 开关 | 作用 |
|---|---|
| 4GB RAM | 加 /LAA 标志，32 位客户端能用 4G 内存 |
| Allow Interface Edits | 允许改登录界面等 |
| Cast Bar Fix | 默认姓名板显示施法条 |
| Disable Cache | 不写 WDB 缓存（改数据不用天天删 Cache）|

**它要求输入干净未改的 Wow.exe**，改过的会报 "invalid or corrupt"。
配套用 `DBC.EnforceItemAttributes = 0`（worldserver.conf）。

> **对你的情况**：你的中文客户端 exe 已经被作者动过，
> 大概率喂不进这个 patcher。要用就找一份干净的 12340 原版 exe 单独打。
> exe 是可替换件，不用在作者那份上折腾。

> 另有 **WoWME (WoW Model Editor launcher)** 一类的启动器，
> 作用相同：让客户端接受自定义文件。TBC 时代常用，WotLK 也能用。

### MPQ 加载优先级（3.3.5a）

```
Data\<locale>\  优先于  Data\

Data\enUS 内：  patch-enUS-Z > ... > patch-enUS-A > patch-enUS-9 > ... > patch-enUS-1
                > lichking.MPQ > expansion.MPQ > base.MPQ > locale-enUS.MPQ

Data 内：       patch-Z > ... > patch-A > patch-9 > ... > patch-1
                > lichking.MPQ > expansion.MPQ > common-2.MPQ > common.MPQ
```

**结论**：自定义补丁命名为 `patch-4.MPQ` 及以上（4-9, A-Z）即可覆盖官方文件。
最高优先级是 `Data\enUS\patch-enUS-Z.MPQ`。

**命名规则**（很多人栽在这）：
- 必须 `patch-` 开头
- 后接一个字符（数字 1-9 或字母 A-Z）
- 扩展名 `.MPQ` **必须大写**

## 典型工作流：给服务器加一件自定义武器

这是最常见的需求，串起来看各工具怎么配合：

```
1. wow.export        从新版客户端提取想要的武器模型 (.m2 + .blp)
2. TXID              修复 m2 文件的贴图引用（跑 15 次，见文档）
3. Multi Converter   把新版 m2 转成 3.3.5 格式
4. WDBX Editor       在 ItemDisplayInfo.dbc 加一行，指向新模型
5. MPQ Editor        建 patch-4.MPQ，放进 DBFilesClient/ 和 Item/ObjectComponents/
6. HeidiSQL          在 item_template 复制一件武器，displayid 指向第 4 步的 ID
7. 删客户端 Cache 文件夹，重进游戏
```

**常见故障对照**（来自实战帖）：

| 现象 | 原因 |
|---|---|
| 模型不可见 | 没跑 TXID 或 Multi Converter |
| 贴图是绿的 | DBC 里贴图名写错 |
| 贴图是方块 | 路径写错（大小写、少 `.mdx` 后缀、反斜杠）|
| 没有动画 | MPQ 里文件没放全 |
| 绿色粒子 | 同上，粒子贴图漏了 |
| 直接崩溃 | ModelName 写错，或 HeidiSQL 里 displayid 用错 |

## 对你当前项目的优先级建议

你现在手上有模型类工具，缺的按重要性排：

| 优先级 | 工具 | 为什么 |
|---|---|---|
| **1** | **Ladik's MPQ Editor** | 所有客户端改动的载体，原版 exe 就能用 |
| **2** | WDBX Editor | 你已经在做自定义物品/生物，迟早要改 DBC |
| 3 | 打过补丁的 exe | **不是入场券**，是效率工具 + 额外特性（见上文勘误）|
| 4 | BLP 转换工具 | 做自定义图标 |
| 5 | Multi Converter + TXID | 想用新版模型时才需要 |
| 6 | Noggit | 做自定义地图才需要，学习曲线陡 |

**特别提醒**：你之前做过 `.item clone`、自造装备 entry 800000+、
自定义法术 900000+，这些**服务端侧已经完成**，但如果要给它们
**自定义外观**（新模型/新图标），就必须走客户端这条线。
