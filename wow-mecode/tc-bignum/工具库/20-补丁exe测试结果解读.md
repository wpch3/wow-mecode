## 二、模型生效但音乐不生效 —— 不是优先级问题

### 你的现象

- 文件夹里的**模型** -> 生效
- 文件夹里的**音乐** -> 不生效
- 你知道作者也整合了音乐

**"模型生效"这一条已经证明文件夹补丁功能是好的**，
所以不是"文件夹没被读到"，也基本不是优先级。

### 真正的原因：音频有独立的加载路径

3.3.5 客户端读音频文件**和读模型贴图走的不是同一套逻辑**。
这就是为什么在早期文档（`06-音效与文本.md`）里记过一条：

> 音频例外：可直接放 `Data\Sound\...`，不用打 MPQ。

**音频可以从 Data 下的裸目录直接读**，这是个特例。反过来说，
它对"文件夹伪装成 MPQ"这套机制的支持**和模型不一样**。

### 三个可能原因，按可能性排序

| # | 原因 | 怎么验证 | 怎么解决 |
|---|---|---|---|
| **1** | **音频要真 MPQ，不吃文件夹补丁** | 把音乐打成真 `.MPQ` 试 | **打包成真 MPQ** |
| 2 | 路径或文件名不对 | 用 MPQ Editor 开官方包核对完整路径 | 改成完全一致 |
| 3 | 格式不对 | 确认是真 mp3 不是改名的 wav/ogg | 真转格式 |

### 建议的验证顺序

```
第一步：把【同一批音乐文件】打包成真 patch-<字母>.MPQ
        放进 Data\（或 Data\zhCN\）
        删 Cache，进游戏听
```

| 结果 | 结论 |
|---|---|
| **打包后能听到** | **音频不吃文件夹补丁，以后音乐一律打包** |
| 打包后还是听不到 | 是路径或格式问题，走原因 2、3 |

**这一步能一次性区分"机制问题"和"文件问题"。**

### 关于"作者也整合了音乐"

如果作者的音乐在 `Data\zhCN\` 里，而你的放在 `Data\`，
那确实会被压过（locale 整体优先）。

但**模型能生效说明你的文件夹位置是对的** ——
除非你的模型和音乐放在了不同的地方。**确认一下这两个是不是在同一个补丁目录里。**

## 三、物品还是问号 —— 你的判断是对的，但根因在别处

### 你说的没错

> 「我觉得不是这个修复 exe 的问题，毕竟皮肤和模型补丁确实完全生效了」

**对的。** 而且我在你传的 `worldserver.conf` 里找到了直接证据。

### 第 1298 行

```
DBC.EnforceItemAttributes = 1
```

**这就是问号图标的原因之一。**

TrinityCore 官方对自定义物品的要求是：

> If using TrinityCore make sure to set **`DBC.EnforceItemAttributes = 0`**
> in your worldserver.conf.

`EnforceItemAttributes = 1` 时，服务端会**强制用客户端 `Item.dbc` 里的属性**
覆盖你 `item_template` 里的设置。你的自定义 entry 在 `Item.dbc` 里不存在，
就会出问题。

### 改法

```
worldserver.conf 第 1298 行
DBC.EnforceItemAttributes = 1
                          ↓
DBC.EnforceItemAttributes = 0
```

**改完重启 worldserver。**

### 但这只是第一步

`EnforceItemAttributes = 0` 解决的是**服务端侧的属性强制**。
红问号图标是**客户端侧**的问题，还需要下面之一：

| 方案 | 说明 |
|---|---|
| **A. WDBX Editor 的 WotLK Item Import** | 从你的 `item_template` 批量生成 `Item.dbc` 记录 |
| B. exe 的 Custom Item Fix 补丁 | anzz1 的 patcher 带这项，**你的 exe 可能没有** |
| C. 手动在 `Item.dbc` 加行 | 物品少的时候可行 |

**推荐 A** —— 你有 800000+ 的自定义装备，手动加不现实。

WDBX Editor 的操作路径（社区教程实录）：
```
File -> Open -> Item.dbc（服务端 dbc 目录里的）
选 WOTLK 3.3.5
Tools -> WotLK Item Import
  Database: 你的 world 库名
  Table:    item_template
  Template: Trinity
点 Load
```
生成后把 `Item.dbc` 放进补丁的 `DBFilesClient\` 目录。

### 所以问号的完整解法

```
1. worldserver.conf:1298  改成 0，重启服务端
2. WDBX Editor 跑 WotLK Item Import 生成新 Item.dbc
3. 打包进 patch 的 DBFilesClient\
4. 删 Cache
```

**这也验证了你的判断**：不是 exe 的锅，是**服务端配置 + DBC 缺记录**两层原因。

## 四、模型消失是版本不兼容 —— 已确认

你说：

> 「模型版本不兼容会消失，但是换成皮肤的就没问题了」

**这和 `patch_scan.py` 的判定完全一致**：
MD21 / 非 264 版本的模型，3.3.5 读不了，表现就是**不显示**（不一定崩溃）。

**你的应对是对的**：只用贴图（BLP），不动模型（M2），
让 3.3.5 原版模型或已移植的 HD 模型来承载。

配合你自己发现的**"要找 6.x/7.x 的补丁，不要找 9.0 的"**，
这条路已经走通了。
