# 装机路线图 —— 从第一个工具装到最后一类

> 制定日期：2026-07-31
> 适用：Windows + VS2022 + Git Bash + CMake GUI + DBeaver（你的环境）
> **本文所有下载地址都在 2026-07-31 实际访问验证过**，没有一个是凭印象写的

---

## 零、总原则：分六批，每批装完立刻验收

**不要一口气全装。** 理由有三：

1. 装完不验，出问题时分不清是哪个工具的锅
2. 有些工具**装了当天就能用上**，有些是几个月后才碰
3. 你的主线（`.emote` + `.say`）不依赖任何一个客户端工具 ——
   **批次 0 和 1 装完就可以回主线了**，2 到 5 可以慢慢来

### 批次总表

| 批次 | 内容 | 耗时 | 何时必须装完 |
|---|---|---|---|
| **0** | idTip + 客户端体检 | **10 分钟** | 现在，立刻 |
| **1** | WoWDatabaseEditor | **30 分钟** | 做剧情/SmartAI 之前 |
| **2** | MPQ Editor + listfile + 活体测试 | **40 分钟** | 客户端改造开工前 |
| **3** | WDBX Editor | **20 分钟** | 自定义物品要图标时 |
| **4** | exe 补丁（可选） | 30 分钟 | 嫌重打包麻烦时 |
| **5** | 素材工具（WMV / wow.export / BLP） | 60 分钟 | 要做新模型新贴图时 |
| **6** | 按需（HxD / 010 / Blender / Noggit） | 不定 | 撞上具体需求时 |

**累计到批次 3 = 约 100 分钟**，这就覆盖了 90% 的实际使用场景。

### 关键分界线

```
批次 0-1  ==>  和客户端【无关】，纯服务端提效，装完直接回主线
──────────────────── 分界线 ────────────────────
批次 2-5  ==>  客户端改造线，主线告一段落再碰也不迟
批次 6    ==>  按需，可能永远用不上
```

## 批次 0 —— 十分钟，零成本

### 0.1 idTip（游戏内显示 ID）

**作用**：鼠标悬停在技能/物品/NPC上，tooltip 直接显示数字 ID。
你做 `.nst`、`.scene`、木桩时反复要查 entry / spell id，装了这个省一半时间。

**【重要】不要从 CurseForge 下**。CurseForge 上的 idTip 是 retail 版本
（最新 12.0.8，对应正式服），**3.3.5a 装不上**。

**要用 WotLK 移植版**：
```
https://forum.warmane.com/showthread.php?t=431404
（帖内 mega.nz 链接，标题就叫 "idTip for WotLK"）
```
移植者说明：支持 spells（含技能/天赋/buff/debuff）、glyphs、items、NPCs。

**安装**：
```
解压到  <客户端>\Interface\AddOns\idTip\
进游戏 -> 角色选择界面左下角 "AddOns" -> 确认已勾选
```

**验收**：进游戏，鼠标指向任意技能，tooltip 底部出现 `Spell ID: xxxx`。

> **备选**：如果 mega 链接失效，`locus313/WoW-3.3.5a-Addons`
> （https://github.com/locus313/WoW-3.3.5a-Addons）
> 是一个持续维护的 3.3.5a 插件合集仓库，2026-03 还在更新，可以去里面找。

### 0.2 跑客户端体检

```bash
bash 工具库/tools/client_check.sh "/d/你的魔兽目录"
```

**验收**：拿到两个信息
- 你的 exe 是什么状态（原版 / 改过 / 加壳）
- **patch 字母占用图** —— 记下它推荐给你的字母，批次 2 要用

> 详见 `11-整合客户端体检与加密应对.md`

## 批次 1 —— WoWDatabaseEditor（最该装的那个）

### 1.1 前置：.NET 8 Runtime

```
https://dotnet.microsoft.com/download/dotnet/8.0
```
选 **.NET Desktop Runtime 8.x, Windows x64**（不是 SDK，不是 ASP.NET Core）。

> 你装了 VS2022，可能已经有了。命令行 `dotnet --list-runtimes` 看一眼，
> 有 `Microsoft.WindowsDesktop.App 8.x` 就跳过这步。

### 1.2 下载 WDE

**Windows 直链**（AppVeyor 持续构建的最新版）：
```
https://ci.appveyor.com/api/projects/BAndysc/wowdatabaseeditor/artifacts/WoWDatabaseEditorWindows.zip?branch=master
```
仓库：https://github.com/BAndysc/WoWDatabaseEditor

解压即用，**内置自动更新器**，以后不用再手动下。

### 1.3 连你的数据库

首次启动会让你填数据库连接。填你 DBeaver 里那套：

| 字段 | 值 |
|---|---|
| Host | `127.0.0.1` |
| Port | `3306` |
| World database | 你的 world 库名 |
| Hotfix / Auth | 可留空 |
| **Core version** | **选 `TrinityCore 3.3.5 (WotLK)`** |

> **选错 core version 会导致字段对不上**，这一项务必确认。

### 1.4 【可选但推荐】接 DBC

WDE 能直接读 3.3.5 DBC。指向你服务端的 DBC 目录：
```
D:\TC-Build\bin\RelWithDebInfo\dbc\
```
接上之后，编辑器里的 spell / item 引用会显示**真实名字**而不是裸数字。

### 1.5 验收

三个都要过：

1. 打开 `creature_template`，搜你的木桩 entry，能看到数据
2. 打开一条 SmartAI 脚本，看到的是**下拉菜单**不是裸数字
3. 打开 3D 视图，能看到地图

**验收 2 是重点** —— 这就是它比 DBeaver 强的地方。

### 1.6 和 DBeaver 的分工（别废掉 DBeaver）

| 任务 | 用哪个 |
|---|---|
| 跑你写的 `41_scene_tables.sql` 等批量脚本 | **DBeaver** |
| 你自造的 `custom_scene` / `custom_scene_npc` 表 | **DBeaver**（WDE 不认识）|
| 精调单个 NPC / 物品 | **WDE** |
| 写 SmartAI | **WDE** |
| 3D 里核对 `.scene` 存的坐标 | **WDE** |

> **提醒**：Keira3 不要装，AzerothCore 专属。详见 `09` 篇勘误。

## 批次 2 —— MPQ Editor（客户端改造的地基）

### 2.1 下载（版本已更新，注意）

官方页：http://www.zezula.net/en/mpq/download.html

**最新是 4.0.0.937**（我旧文档写的 3.6.0.844 已过时）：

| 语言 | 直链 |
|---|---|
| 英文 | http://www.zezula.net/download/mpqeditor_en.zip |
| **中文** | **http://www.zezula.net/download/mpqeditor_cn.zip** |

**官方有中文版**，建议直接用中文的。
32+64 位都在同一个包里。Windows 7 以上可用，绿色解压即用。

### 2.2 【必做】同时下 listfile 包

**同一页面下方**：
```
http://www.zezula.net/download/listfiles.zip   (9.83 MB)
```
官方说明原话：
> Listfiles for MPQ archives. They are necessary for opening older MPQ archives.

**这个包就是你上一轮"加密"问题的解药。** 别人整合包里删了 listfile 的 MPQ，
挂上这份就能显出大部分真实路径。

### 2.3 配置（很多人第一次栽在这）

```
Tools -> Options
  Work directory   : D:\wow-work\        (解出来的文件放这)
  ListFile directory: D:\wow-work\listfiles\   (解压 listfiles.zip 到这)
```

### 2.4 【验收 = 三分钟活体测试】

这一步不只是验收工具，**同时是验收你的客户端能不能改**。
完整步骤在 `11-整合客户端体检与加密应对.md` 第四节，这里只列骨架：

```
1. 新建 patch-<批次0拿到的字母>.MPQ
2. 塞一个改名的 mp3 到 Sound\Music\GlueScreenMusic\WotLK_main_title.mp3
3. 放进 Data\ ，删客户端 Cache 文件夹
4. 启动游戏，听登录界面音乐
```

| 结果 | 结论 |
|---|---|
| 听到你的歌 | **通了，客户端改造可以开工** |
| 没听到 | 换更靠后的字母重试；仍不行看 11 篇决策树 |

> `.wav` / `.ogg` **不能只改扩展名**，必须真转成 mp3。

## 批次 4 —— exe 补丁（可选，不是必需）

> **先读 `00` 篇的勘误**：原版 exe 本来就能加载 `patch-4.MPQ` 真文件。
> 这一批是**效率工具**，不是入场券。

### 什么时候才需要做这批

| 你的痛点 | 需要吗 |
|---|---|
| 每次改个贴图都要重打 MPQ，烦 | **需要**（文件夹补丁）|
| 自定义物品红问号 | 先试批次 3 的 WotLK Item Import |
| 想改登录界面 | 需要 |
| 只是想做内容 | **不需要** |

### 4.1 方案 A：现成的打好补丁的 exe

WotLK Modding Wiki 官方给的链接：
```
https://www.mediafire.com/file/kewam47gtdshhln/Wow.exe/file
```
教程页：https://wotlkdev.github.io/wiki/your_first_mod/your_first_client_edit

### 4.2 方案 B：anzz1 的 WoWPatcher335（功能更全）

```
https://github.com/anzz1/WoWPatcher335
下载在 wowmodding.net: WoW 3.3.5 Patcher (Custom Item Fix)
```

四个可选开关：

| 开关 | 作用 |
|---|---|
| 4GB RAM | 加 /LAA，32 位客户端能用 4G 内存 |
| Allow Interface Edits | 允许改登录界面 |
| Cast Bar Fix | 默认姓名板显示施法条 |
| **Disable Cache** | **不写 WDB 缓存 —— 改数据不用天天删 Cache** |

打完之后自定义物品**不用改 Item.dbc、不用打 MPQ**，
直接往 `item_template` 加数据。配套设 `DBC.EnforceItemAttributes = 0`。

### 4.3 【关键坑】

**这个 patcher 要求输入干净未改的 Wow.exe**，改过的会报
`invalid or corrupt wow.exe`。

**你的中文客户端 exe 已经被整合包作者动过，大概率喂不进去。**

解法：**别在作者那份上折腾**。找一份干净的 12340 原版 exe 单独打，
放在客户端目录里改个名（比如 `WoW-mod.exe`），两个 exe 并存。

> exe 是可替换件，不是不可逆的。

### 4.4 验收

`11` 篇的**测试 2**（文件夹型 patch）：
把 `patch-Y.MPQ` 改成**文件夹**，塞同一个 mp3，能听到就是成了。

## 三、和主线的关系（最后说清楚）

**你的主线是 `.emote` + `.say`，它不依赖上面任何一个工具。**

推荐节奏：

```
今天：批次 0（10 分钟）+ 批次 1（30 分钟）
      ↓
      回主线做 .emote + .say
      ↓
主线告一段落：批次 2 + 3（60 分钟），把客户端这条线的地基打好
      ↓
真要做新模型/新图标时：批次 4 / 5
      ↓
批次 6：可能永远用不上
```

**批次 1 的 WDE 对主线有直接帮助**：
`.emote` 要用的 emote ID、`.say` 可能要接的 SmartAI，
在 WDE 里都是下拉菜单而不是裸数字。

**其余批次和主线无关，不用等。**
