## 一、你问的两件事，答案不一样

### 1.1 增加 bot 数量上限 —— **现在就能做，不用编译**

实查结论：**这是纯 conf 配置，改完重启即可**。

```cpp
// botconfig.cpp:468
std::string max_npcbots_by_levels =
    sConfigMgr->GetStringDefault("NpcBot.MaxBots", "1,1,1,1,1,1,1,1,1");

// botconfig.cpp:470  【必须正好9个值，否则ASSERT崩服】
ASSERT(toks0.size() == BRACKETS_COUNT, "NpcBot.MaxBots must have exactly %u values", ...);
```

**9 个值 = 9 个等级段**（`BRACKETS_COUNT = DEFAULT_MAX_LEVEL/10+1 = 9`），
分别对应 1-9 / 10-19 / 20-29 / ... / 80+。

**硬上限 39**（botconfig.cpp:486）：

```cpp
if (uval >= MAX_RAID_SIZE)      // MAX_RAID_SIZE = 40
{
    BOT_LOG_ERROR("server.loading", "NpcBot.MaxBots value at offset {} is {} > 39, enforcing max value!");
    uval = uint8(MAX_RAID_SIZE - 1);   // 强制压到 39
}
```

**39 是团队上限 40 减去你自己**，这是客户端团队框架的限制，不是配置问题。

#### 直接抄这段配置

```ini
# worldserver.conf.d/npcbot_maxbots.conf
[worldserver]

# 9个值必须齐全，对应 1-9/10-19/.../80+ 九个等级段
# 建议：低级少给，高级给满，避免新号带一堆bot碾压
NpcBot.MaxBots = 2,3,4,5,10,15,20,25,39

# 每个职业最多几个（默认1，想要3个法师就改成3）
NpcBot.MaxBotsPerClass = 5

# 每个账号总上限（0=不限）
NpcBot.MaxBotsPerAccount = 0
```

> **注意 `NpcBot.MaxBots` 必须正好 9 个值**，
> 多一个少一个都会 `ASSERT` 直接崩服（botconfig.cpp:470）。
> 这条已经在待办总表的坑表里了。

**要我现在就出这个 conf 文件的话说一声**，5 分钟的事。

### 1.2 自主创建新 bot —— **要排期，不是小活**

这个和上面完全不是一个量级。需要做的：

```
1. 自动建账号（BOT_ 前缀，避免和真人冲突）
2. 自动建角色（随机种族/职业/外观/名字）
3. 名字池（中英文各一套，避免重名）
4. 装备生成（按等级发装备，否则光屁股）
5. 天赋分配（不点天赋等于废人）
6. 批量上线/下线管理
7. 崩溃恢复（服务端重启后自动重新上线）
```

**依赖前提**：PlayerBot 得先有**战斗 AI**，否则造 100 个站桩木头没意义。

**我的建议排期**：放在战斗 AI 之后。

## 四、关于「自动换装」（你本轮提的）

先说清楚它有两种，工作量差很多：

### 4.1 NPCBot 的自动换装 —— **上游已经有了**

```
botcommands.cpp  .npcbot 装等 (gs)
bot_ai.cpp       BOT_ROLE_AUTOLOOT 系列（botcommon.h:300-305 按品质分级）
```

NPCBot 本来就会自动捡装备、自动穿。
如果你觉得它穿得不好，那是**策略调优**（比如"优先穿高装等"），不是从零做。

### 4.2 PlayerBot 的自动换装 —— **要从零做**

PlayerBot 是真实 Player，有真背包，但**没有任何 AI 决定穿什么**。
需要做：

```
1. 评分函数（一件装备对这个职业值多少分）
2. 比较逻辑（新装备 vs 身上的）
3. 穿戴执行（EquipItem，要处理双手武器/戒指两格等特殊情况）
4. 触发时机（捡到装备时 / 升级时 / 定期检查）
```

**依赖**：得先有背包管理，而背包管理又依赖战斗 AI（不打怪哪来的装备）。

**建议**：和"自动学技能"打包做成「PlayerBot 自我维护」一个 step。
