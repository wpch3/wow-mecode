### `.pbot` 子命令

```
.pbot spawn <账号> <角色>    让角色以bot身份登录      [中文: 上线/召出]
.pbot list                   列出已登录的bot          [中文: 列表]
.pbot despawn <角色名>       让它下线                 [中文: 下线]
.pbot come <角色名>          把它传送到你身前         [中文: 过来]
.pbot goto <角色名>          你传送到它那里           [中文: 去找]
.pbot auto [角色名] [项目] [on|off]   自动接受开关   [中文: 自动]
     项目: group/guild/duel/res/summon/trade/release/all
.pbot auto master <on|off>   总开关（应急全停）
.pbot accept <角色名|all>    立刻处理挂起的邀请       [中文: 接受]
```

**默认开**：组队 / 公会 / 复活 / 召唤 / 释放 / **交易**
**默认关**：决斗

### `.botname` 子命令

```
.botname cn <中文名>          改中文名（zhCN客户端可见）  [中文: 中文]
.botname en <英文名>          改英文名（默认名）          [中文: 英文]
.botname entry <ID> cn <名>   按entry改，不用选中          [中文: 编号]
.botname show                 看当前中英文名               [中文: 查看]
.botname player <旧名> <新名> 改 PlayerBot 名字            [中文: 玩家]
```

> **已知限制**：重启后队伍窗口里的 bot 名字会变回英文
> （`Group.cpp:347` 只读 `ct->Name` 不读 locale）。
> 规避：中英文都改成同一个名字。

### `.pin` —— 已停用，原因

游荡bot的 `creature_template` 是**内存临时对象**
（`botdatamgr.cpp:63 _botsExtraCreatureTemplates`），
写进数据库会让 `ObjectMgr.cpp:10279` 断言失败 -> **崩服**。

**替代方案**：用官方 `.npcbot spawn` 创建真正的永久bot。

`.pin status` 仍可用（只读诊断，安全）。

## 八、注册自检（每次加指令后必跑）

```bash
cd /d/TrinityCore/src/server/scripts

# 1. 每个 AddSC_ 必须恰好出现 2 次（1声明 + 1调用）
grep -oP 'AddSC_\w+' Commands/cs_script_loader.cpp | sort | uniq -c | awk '$1!=2'

# 2. 每个注册的函数都要有实现（防 LNK2019）
for f in $(grep -oP 'AddSC_\w+' Commands/cs_script_loader.cpp | sort -u); do
  grep -rq "void $f()" . || echo "缺实现: $f"
done
```

**两条都无输出 = 正常。**

> 新增 `.cpp` 文件后**必须重跑 CMake**
> —— `cmake/macros/AutoCollect.cmake:26` 是 `file(GLOB)`，
> 不重跑工程里就没有这个文件。

## 九、和官方指令的关系

上面这些都是**自建指令**。官方原有指令（`.npc`、`.character`、`.reload`、
`.gm`、`.tele` 等）见 `指令清单/00-指令总清单-最终版.md`。

**有冲突风险的**：
- `.item` —— 官方也有 `.item`，我们的是子命令扩展
- `.set` —— 官方有 `.modify`，我们的 `.set` 是独立的
- `.spell` —— 官方有 `.learn`，不冲突
