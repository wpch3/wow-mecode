## 为什么 WDE 让你痛苦

我核实了源码，你卡住的地方是 `ItemTemplate.h:576` 的 `ItemEffect` 结构：

```cpp
struct ItemEffect {
    int32  SpellID;               // 技能ID          ← 你不知道填什么
    uint32 TriggerType;           // 触发方式        ← 填错=装备毫无反应，还不报错
    int32  Charges;               // 次数
    float  SpellPPMRate;          // 每分钟触发次数
    int32  CoolDownMSec;          // 冷却
    uint32 SpellCategoryID;       // 共享冷却组
    int32  CategoryCoolDownMSec;
};
```

**× 5 组 = 35 个格子**。WDE 让你手填，而且不告诉你哪个该填。

`TriggerType` 只有 7 个合法值，这是最大的坑：

| 值 | 含义 |
|---|---|
| 0 | 使用时触发（有装备冷却）—— 主动点击 |
| **1** | **装备时触发 —— 穿上就生效，被动光环用这个** |
| **2** | **命中时几率触发 —— 武器特效用这个，必须配 PPMRate** |
| 4 | 灵魂石专用，别用 |
| 5 | 使用时触发（无冷却）—— 消耗品 |
| 6 | 教学法术 |

**填 1 还是填 2 搞混，装备就是个废物，而且服务器不报错。**

## 第 0 层：效果词典（已完成）

### 解决什么

把「吸血/火球/闪电」这类**中文词**映射到实际 SpellID，你不用再记数字。

### 两级安全性（按你的要求）

| 级别 | 来源 | 风险 |
|---|---|---|
| **安全区** | `item_template` 里暴雪实际用过的 `spellid_1~5` | **零风险**，正式服跑了十几年 |
| 实验区 | 全量法术 | 可能是 BOSS 专用/未完成的，行为异常 |

### 怎么用

```bash
# 1. 看要执行什么 SQL
python3 tools/build_effect_dict.py --sql

# 2. 在你的 SQL 客户端跑这条（一条语句，符合你客户端的脾气）
SELECT entry, name, spellid_1, spelltrigger_1, spellppmRate_1, spellcooldown_1
FROM world.item_template
WHERE spellid_1 > 0
ORDER BY Quality DESC, ItemLevel DESC
LIMIT 5000;

# 3. 结果导出为 CSV，然后
python3 tools/build_effect_dict.py --parse 你的文件.csv --out 效果词典.md --tsv 效果词典.tsv
```

产出两份：
- `效果词典.md` —— 给你看的，按 26 个中文类别分好，带 TriggerType 速查
- `效果词典.tsv` —— 给程序读的，后面 `.item make` 直接查这张表

急速 暴击 力量 敏捷 智力 耐力 护甲 反伤 眩晕 减速
沉默 召唤 传送 变形 隐身 免疫

### 已做的验证

**回归测试 36/36 通过**（`tools/test_effect_dict.py`）

开发过程中真的抓到了 bug，都修了：

| 误判 | 原因 | 修法 |
|---|---|---|
| `Hand of Justice` → 冰霜 | Just**ice** 含 ice | 加词边界 `\bIce\b` |
| `Warp Slicer` → 冰霜 | Sl**ice**r 含 ice | 同上 |
| `Lightweight Boots` → 神圣 | **Light**weight | `\bLight\b` |
| `Manacles` → 奥术 | **Mana**cles | `\bMana\b` |
| `Warden's Blade` → 护盾 | **Ward**en | `\bWard\b` |
| `Mighty Boots` → 力量 | **Might**y | `\bMight\b` |
| 「霜之哀伤」漏判 | 词表只有"冰霜"没有单字"霜" | 补中文单字 |

改正则后**必须重跑** `python3 tools/test_effect_dict.py`，防止再引入误判。

## 第 1 层：`.item clone`（下一步）

### 设计

```
.item clone 49623                    抄霜之哀伤，自动分配新 entry
.item clone 49623 装等300            抄完把装等拉到 300，属性按比例放大
.item clone 49623 x10                所有属性 ×10
.item clone 49623 名字 真龙之牙       抄完改名
.item clone 49623 加 吸血             抄完再加一个吸血特效（查词典）
```

### 为什么风险最低

模型、图标、音效、特效全是暴雪做好的，**客户端认得**，不用发补丁。

### 技术要点（已核实）

- `ObjectMgr.h:996` `GetItemTemplateStore()` 拿到全部模板
- `ItemTemplate.h:769` `InitializeQueryData()` —— 改完必须调，否则客户端拿到旧数据
- 你已有的 `.reloaditem`（`step13`）已经处理过 QueryData 缓存这个坑
- **`LoadItemTemplates()` 不清空 `_itemTemplateStore`**，只覆盖写（删除的物品重载后仍在内存）

## 第 2 层：`.item make`（之后）

### 设计

```
.item make 武器 单手剑 装等300 力量 暴击 吸血
.item make 板甲 胸甲 装等300 坦克
.item make 法杖 装等300 法伤 急速 触发火球
```

后台自动：
- 按装等算属性总点数（参考暴雪的 ItemLevel 曲线）
- 按定位（坦克/DPS/治疗）分配属性权重
- 从词典查特效对应的 SpellID + 正确的 TriggerType + 合理 PPM
- 自动选一个同类型的模型
