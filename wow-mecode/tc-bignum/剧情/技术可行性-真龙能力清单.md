## 二、关键实现细节

### 2-1 锁血不死（核心机制）

**源码依据**：
```cpp
// Unit.h:1022 —— 全服唯一伤害入口，static 函数
static uint32 DealDamage(Unit* attacker, Unit* victim, uint32 damage,
                         CleanDamage const* cleanDamage, DamageEffectType damagetype,
                         SpellSchoolMask damageSchoolMask, SpellInfo const* spellProto,
                         bool durabilityLoss);
```

**为什么这个点最好**：
- 所有伤害来源（近战/法术/环境/掉落/GM指令）**全部经过这里**
- 是 `static`，不需要虚函数开销
- 在这里拦截，连 `.die` 指令都杀不死真龙

**实现伪码**：
```cpp
// 在 DealDamage 开头插入
if (victim->IsPlayer() && IsDragonsworn(victim->ToPlayer()))
{
    if (damage >= victim->GetHealth())
    {
        damage = victim->GetHealth() - 1;      // 锁血 1
        TriggerWorldSoulDrain(victim);         // 世界之魂损耗 +1
        ScheduleFullHeal(victim, 500ms);       // 0.5秒后回满
    }
}
```

**"债"系统联动**：
每次触发时递增计数器，存入自定义表 `custom_dragonsworn_debt`。
这个数字直接影响：
- 世界表现（天空颜色、植物生长、NPC 遗忘）
- 终章可选的结局分支

### 2-2 形态系统

**源码依据**：
```cpp
// Unit.h:1595/1598
virtual void SetDisplayId(uint32 modelId);
void SetNativeDisplayId(uint32 displayId);
// Unit.h:1185
Aura* AddAura(uint32 spellId, Unit* target);
```

**每个形态 = 三件套**：
```
DisplayID（外观） + 光环组（属性/特效） + 技能替换（能力）
```

**五色龙形态可以立刻做** —— 游戏内现成模型：
| 形态 | 可用 DisplayID 来源 |
|---|---|
| 红龙 | 阿莱克丝塔萨 / 红龙成体 |
| 蓝龙 | 玛里苟斯 / 蓝龙成体 |
| 绿龙 | 伊瑟拉 / 绿龙成体 |
| 青铜 | 诺兹多姆 / 青铜龙成体 |
| 黑龙 | 奈法利安 / 黑龙成体 |

**需要建模的**：泰坦形态（6）、噩梦形态（4）、真我形态（1）

### 2-3 自动施法（最大工作量）

**现成资源**：NPCBot 有 19 套职业 AI
```
标准职业(10)：warrior/paladin/hunter/rogue/priest/dk/shaman/mage/warlock/druid
魔兽3英雄(9)：archmage/bm/crypt_lord/dark_ranger/dreadlord/
              necromancer/sea_witch/spellbreaker/sphynx
```

**障碍**：`bot_ai : public CreatureAI` 绑定 Creature，不能直接用于 Player。

**三条路径**（详见《规划-游戏内难度菜单.md》附录C）：
- A. 影子Bot：隐形 bot 替你施法（40-60h）
- B. 提取优先级：抄逻辑成玩家版（80-120h）
- C. **Eluna 脚本**：推荐，迭代快、天然支持开关（40-60h）

**开关设计**：
```
/dragon auto warrior on     开战士技能
/dragon auto healer only    只开治疗系
/dragon auto all on         全开
/dragon auto off            全关（手动模式）
```

### 2-4 多结局判定

**需要记录的数据**：
```sql
CREATE TABLE custom_dragonsworn_story (
    guid          INT UNSIGNED,   -- 角色
    choice_id     INT UNSIGNED,   -- 选择点编号
    choice_value  TINYINT,        -- 选了 A/B/C
    PRIMARY KEY (guid, choice_id)
);

CREATE TABLE custom_worldsoul (

    integrity     INT UNSIGNED,   -- 世界之魂完整度 0~10000
    death_count   INT UNSIGNED    -- 触发不死的次数
);
```

**结局判定伪码**：
```cpp
if (integrity >= 8000 && never_relied_on_immortality)
    return ENDING_SEVENTH;        // 隐藏结局
if (integrity < 2000 && devour_choices >= 3)
    return ENDING_NEW_GOD;        // 新神
if (all_reunion_quests_done && dragon_rep == MAX)
    return ENDING_RETURN;         // 交还
// ... 其余按选择倾向判定
```

## 三、关于"要不要熊猫人"

我在设定集里给了替代方案，这里说清理由：

**建议：不要熊猫人，但要武僧**

武僧本土化为【断链武僧】：
- 起源于角斗士奴隶，没有武器（被剥夺）、没有魔法（被封印）
- 只能用身体和呼吸战斗，"断链"指打断自己的奴隶锁链
- **任何种族都能当武僧**，和艾泽拉斯历史严丝合缝
- 现成的故事土壤：角斗士竞技场、地下奴隶市场、战俘营

**如果以后改主意想要熊猫人**，有个自洽接法：
> 潘达利亚不是"被发现"的，是"浮上来"的。
> 迷雾散去是因为世界之魂受伤，伤口震荡把大陆推出水面。
> 熊猫人是被迫加入这个世界的，他们其实并不想来。

这样熊猫人就有了"不情愿的移民"这个身份，和其他种族的
"代价换生存"主题也能对上。

## 四、我补充的设定（你说黔驴技穷，这些可以拿去用）

### 4-1 让"无敌"不无聊的核心设计：债

这是我在设定里加的最重要的一笔。

**问题**：主角完全不死 = 没有紧张感 = 无聊。

**解法**：不死是有代价的，代价由世界承担。
- 每次不死，世界之魂消耗一分
- 消耗到一定程度，世界会**肉眼可见地衰败**
- 天空褪色 → 植物停止生长 → NPC 开始遗忘 → 时间紊乱

**效果**：玩家会主动避免依赖不死机制。
"我能不死"变成了一种**需要克制的力量**，而不是无脑护身符。

而且这直接联动隐藏结局——全程不依赖不死，才能解锁第七个选择。

### 4-2 反派的道理

你说"不要太极端，不能没有一点后路"，我按这个原则设计：

| 势力 | 他们的道理 |
|---|---|
| **泰坦** | 按几十万年前设定的预案办事，当时那个判断是对的 |
| **噩梦** | 是艾泽拉斯的免疫系统，过度反应了，但出发点是保护 |
| **部落精灵** | 吸邪能是为了让孩子活下去 |
| **联盟精灵** | 当年船位不够，是抽签，不是抛弃 |
| **五色巨龙** | 造真龙是为了救世界，但他们知道这对真龙不公平 |

**没有纯粹的反派**。连"格式化世界"的泰坦守护者，
在遇到真龙时也只是困惑地说"无法归档，请求上级指令"，
然后原地等一个永远不会来的回复。

### 4-3 沉浸式设计亮点

几个我觉得特别有力的场景设计：

**磐石豺狼人的无声营地**
玩家第一次进入时，所有 NPC 都不说话，只有手势。
需要先做任务学手语才能交流。
—— 用"听不见"让玩家亲身体验他们付出的代价。

**兽人的愤怒罐**
老萨满把切下来的血怒腺装在罐子里，摆满整个山洞。
"总得有人记得我们放弃了什么。"

**灰烬巨魔的七根手指**
"其中三根不是我的，是战场上死去的同伴的。我把他们带回家了。"

**被遗忘者的门前**
站在自己生前的家门口三年，不敢敲门。
玩家选"什么都不做，陪他站着"，会解锁他讲述生前一个平淡下午的独白。

### 4-4 贯穿全程的和解支线：桃林重植

第二幕里，光铸精灵问"这里以前有片桃林，是谁砍的"，
守塔者答"砍了当柴烧，不烧就得冻死"。

**这条线可以贯穿全程**：
- 玩家可以在两边阵营都接到"重植桃林"的任务
- 需要联盟精灵提供种子（他们保存了两百年）
- 需要部落精灵提供土地和照料（他们守着废墟）
- 完成后，两支精灵会在桃林下举行第一次联合仪式

**这是整个故事里唯一一条"双方都赢"的线**。
在一个到处是代价的世界里，需要有一个地方让人喘口气。

## 四、第二版新增机制的技术方案

> 这三条是剧情第二版新加的硬机制，它们撑起了「尘世线」（部落联盟和解），
> 全部是**纯服务端 + 数据库**改动，不需要客户端补丁，成本很低但叙事收益极大。
> 建议在阶段一之后、阶段二之前插入实现。

### 4-1 五个核心数值 —— 存储方案

新建一张表即可，全部数值挂在角色 GUID 上：

```sql
CREATE TABLE characters.custom_dragon_progress (
    guid          INT UNSIGNED NOT NULL PRIMARY KEY,
    reconcile     INT NOT NULL DEFAULT 0,    -- 和解度，越高越好
    compensation  INT NOT NULL DEFAULT 0,    -- 代偿值，真身出手次数，越低越好
    worldsoul     INT NOT NULL DEFAULT 100,  -- 世界之魂 0-100
    notebook      INT NOT NULL DEFAULT 0,    -- 记事册条目数
    ending_flags  BIGINT UNSIGNED NOT NULL DEFAULT 0  -- 结局判定位标记
);
```

> 注意用户 SQL 客户端的三个脾气：一次只执行光标所在语句、
> 会吞掉反引号里的点号、不执行 USE。
> 所以写成 `characters.custom_dragon_progress` 不加反引号，一个文件一条语句。

熟识度是玩家两两之间的关系，需要单独一张表：

```sql
CREATE TABLE characters.custom_familiarity (
    guid_a  INT UNSIGNED NOT NULL,
    guid_b  INT UNSIGNED NOT NULL,
    score   INT NOT NULL DEFAULT 0,
    PRIMARY KEY (guid_a, guid_b)
);
```

约定 `guid_a < guid_b`，避免存两份。

### 4-2 代偿值 —— 挂在锁血逻辑上

代偿值的触发点和锁血不死是**同一个位置**，实现几乎零额外成本：

```
Unit::DealDamage() 拦截到真龙致命伤
  → 锁血 1
  → worldsoul -= N        （世界之魂下降）
  → compensation += 1     （代偿值上升）
```

剧情上「真身主动出手解决剧情冲突」也要计代偿，这部分走任务脚本，
在对应任务的 `OnQuestComplete` 里手动 +N 即可。

**可行性：🟢 低难度。** 和锁血机制共用一个 Hook。

### 4-3 源血采集 —— 队伍血脉多样性判定

核心就是数队伍里有几种不同的 `race`：

```cpp
// 伪代码：统计队伍血脉多样性
std::set<uint8> races;
bool crossFaction = false;
uint32 firstTeam = 0;
for (GroupReference* itr = group->GetFirstMember(); itr; itr = itr->next())
{
    Player* member = itr->GetSource();
    if (!member || !member->IsInWorld()) continue;
    if (member->GetDistance(node) > 30.0f) continue;   // 只算泉眼附近的
    races.insert(member->getRace());
    if (firstTeam == 0) firstTeam = member->GetTeam();
    else if (member->GetTeam() != firstTeam) crossFaction = true;
}

uint32 yield = 0;
if (races.size() >= 2)
{
    yield = BASE_YIELD * races.size();
    if (!crossFaction)
        yield = yield * 30 / 100;      // 同阵营凑数只有三成
    yield += yield * GetFamiliarityBonus(group) / 100;   // 熟识度加成
}
```

需要的 API 全部现成：
- `Player::getRace()` —— 直接可用
- `Player::GetTeam()` —— 返回 ALLIANCE / HORDE
- `Group::GetFirstMember()` —— 遍历队伍
- `GetDistance()` —— 范围判定

**可行性：🟢 低难度。** 纯逻辑，可以用 Eluna 脚本先做原型验证，
跑通了再决定要不要下沉到 C++。

### 4-4 熟识度 —— 行为触发

设定里熟识度不是靠「组队次数」，是靠具体行为。
这些行为在 TrinityCore 里都有现成的 Hook：

| 行为 | Hook 位置 | 加分 |
|---|---|---|
| 互相治疗 | `PlayerScript::OnSpellCast` 判定治疗系法术且目标是队友 | +1 |
| 互相复活 | 复活法术同上 | +5 |
| 同场战斗都活下来 | 战斗结束时检查队伍存活 | +2 |
| 交易过物品 | `PlayerScript::OnTradeComplete`（如无则用 `OnCommand` 兜底） | +1 |
| 同副本通关 | `OnInstanceComplete` / Boss 击杀事件 | +10 |

> 注意：设定集里那位奥凝精灵统计员留了一句「不要公开这份报告，
> 一旦人们知道变熟能提高产量，他们就会开始表演变熟」。
> 这在玩法上是个真问题——如果加分规则完全公开，玩家会刷。
> **建议：加分规则不在 UI 里明示，只给一个模糊的「连接」等级显示。**

### 4-5 七位梦魇领主 —— 副本设计的技术要点

七个 Boss 里有几个机制比较特殊，这里标一下可行性：

| Boss | 特殊机制 | 可行性 | 说明 |
|---|---|---|---|
| 抽签者 | 随机把一名玩家移出战斗 | 🟢 | `Player::TeleportTo` 到旁观区 + 禁止回来 |
| 下雨前一天 | 全场强制停战 10 秒 | 🟢 | 全体上一个「缴械」光环，禁止攻击 |
| 两个版本 | 双血条，必须同时打空 | 🟢 | 两个 Boss 互相监听血量，任一 >0 就回满对方 |
| 罐子 | 打碎罐子同时增益自己和 Boss | 🟢 | 可破坏物件 + 双方各上一层叠加光环 |
| 没敲的门 | 完全免疫伤害，只能靠交互通关 | 🟢 | 设 `UNIT_FLAG_IMMUNE` + Gossip 交互 |
| 听不见 | 屏蔽所有语音和文字提示 | 🟡 | 服务端不发 `Yell/Say/Emote` 包即可，但真要做到
| | | | 「关掉音效」需要客户端配合，建议只屏蔽服务端提示 |
| 第一个孩子 | 问答式，答错惩罚队友 | 🟢 | Gossip 多选 + 对指定玩家上 debuff |

**结论：七个 Boss 里六个纯服务端就能做，一个（听不见）打个折扣也能做。**
这批副本的性价比非常高——机制新颖，但技术难度全在「设计」而不在「实现」。
