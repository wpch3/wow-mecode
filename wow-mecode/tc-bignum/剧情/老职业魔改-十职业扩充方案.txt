================================================================================
                    老职业魔改 · 十职业扩充方案
                    「新职业要有，老职业也要有」
================================================================================

【文档说明】

《技能设计集》第三部已经列了老职业每职业 6 个技能的创意，
但只有一句话描述，没法直接实装。

本文档是那部分的**落地版**，每个技能都补齐了：
    数值 / 冷却 / 等级 / 天赋树归属 / 实现难度 / 具体实现路径

【最重要的前提 —— 先看这个】

3.3.5 的技能分两种，成本差 100 倍：

  ┌────────────┬──────────────────────┬────────────────────────┐
  │ 类型       │ 要不要改客户端 DBC   │ 成本                   │
  ├────────────┼──────────────────────┼────────────────────────┤
  │ 改现有技能 │ **不用**             │ 一条 SQL / 几行 C++    │
  │ 加全新技能 │ **必须改，还要发补丁│ 每次改动全服重下客户端 │
  └────────────┴──────────────────────┴────────────────────────┘

  「服务端认为你会这个技能，客户端不显示」就是 DBC 不一致导致的。

  所以本文档按「零 DBC 成本」优先排序：
      A 级 —— 完全不碰客户端，改数值/挂脚本就行     ← 优先做
      B 级 —— 复用现有法术的图标和名字，改效果      ← 次优先
      C 级 —— 必须新建 DBC 条目                     ← 攒一批一起发补丁

【已核实的技术底牌】

  SpellMgr.h:671  SpellInfo* _GetSpellInfo(uint32 spellId)   ← 非 const！
      服务端启动时可以**运行时改写任何现有法术**的数值、冷却、效果。
      客户端只负责画图标和播动画，实际结算全在服务端。
      这意味着：**改数值、改冷却、改射程、改目标数，全部零 DBC 成本。**

  ScriptMgr.h:1144  RegisterSpellScript(spell_script)
      给现有法术挂自定义逻辑，实现原版没有的机制。

  spell_script_names 表
      纯 SQL 把脚本绑到法术上，不用改 DBC。

  ID 段（《技能设计集》6-4 已规划）
      920000 - 929999   原 10 职业的扩充技能


================================================================================
第一部 · 设计总原则
================================================================================

■ 1-1 三条铁律

  1. 【不做数值膨胀】
     老职业加技能不是为了让它更强，是为了补功能位、增加操作空间。
     单纯 +50% 伤害这种，用 conf 调倍率就行，不值得做成技能。

  2. 【每个职业补的是"它缺的"，不是"它已经强的"】
     战士缺远程手段 -> 给他投掷类
     法师缺生存 -> 给他位移和减伤
     不要给战士再加一个近战爆发。

  3. 【和新职业错位，不抢饭碗】
     新职业（断链武僧/血法师/符文铸造师…）有自己的定位。
     老职业的扩充要绕开那些，否则新职业没人玩。

■ 1-2 每职业给多少

  每职业 **8 个**，分三层：

  ┌──────────┬──────┬──────────────────────────────────────┐
  │ 层级     │ 个数 │ 定位                                 │
  ├──────────┼──────┼──────────────────────────────────────┤
  │ 通用层   │  3   │ 80 级前就能学，补基础功能位          │
  │ 精通层   │  3   │ 80 级后学，对应三系天赋各一个        │
  │ 觉醒层   │  2   │ 高等级/剧情解锁，有质变感            │
  └──────────┴──────┴──────────────────────────────────────┘

  10 职业 × 8 = **80 个新技能**

■ 1-3 等级规划

  你的 MaxPlayerLevel = 80。如果以后开到 255：

      1-80     原版内容
      81-100   通用层 + 精通层扩充技能
      101-150  觉醒层
      151-255  真龙线 / 新职业内容

  现在先按 80 级封顶设计，觉醒层用**任务解锁**而不是等级解锁，
  这样不改等级上限也能玩。

第三部 · 实装路线（按成本排序）
================================================================================

■ 3-1 统计

  ┌────────┬──────┬────────────────────────────────────────┐
  │ 等级   │ 数量 │ 说明                                   │
  ├────────┼──────┼────────────────────────────────────────┤
  │ A 级   │  42  │ 零 DBC 成本，改数值/复制现有法术       │
  │ B 级   │  24  │ 复用现有法术外观，改效果               │
  │ C 级   │  14  │ 必须新建 DBC 条目                      │
  └────────┴──────┴────────────────────────────────────────┘

  **先做 42 个 A 级的，一个客户端补丁都不用发。**

■ 3-2 第一批：纯数值强化（零代码）

  这批连 SpellScript 都不用写，服务端启动时用 _GetSpellInfo() 改数值。

  做法：写一个 CustomSpellTweak 模块，启动时批量改：

      SpellInfo* info = sSpellMgr->_GetSpellInfo(15237);   // 神圣新星
      const_cast<SpellInfo*>(info)->Effects[0].BasePoints *= 3;

  可以做的：
    · 神圣新星伤害/治疗 ×3          -> 2-5 神圣新星
    · 亡者大军数量 8->10             -> 2-6 亡者大军·强
    · 治疗链跳跃 +3                  -> 2-7 生命洪流
    · 星落持续时间 ×2                -> 2-10 星辰坠落·极
    · 法力护盾吸收率 ×2              -> 2-8 法力护盾·极
    · 投掷伤害 ×3、射程 +10          -> 2-1 投掷精通

  **优点：改完重启就生效，玩家客户端零感知，出问题改回来就行。**

■ 3-3 第二批：复制现有法术（一条 SQL）

  用你已有的 `.reloaditem` 思路，做一个 `.spell clone`：

      .spell clone 15237 920503 伤害x3 冷却25

  自动复制 Spell.dbc 条目到新 ID，改数值，写进服务端。
  客户端会显示"未知法术"但**能用** —— 适合自己测试。

  正式发给玩家前再统一做一次 DBC 补丁。

■ 3-4 第三批：SpellScript（要写代码）

  B 级里需要脚本的，集中写在一个文件：

      src/server/scripts/Custom/custom_class_spells.cpp

  每个技能一个 class，用 RegisterSpellScript 注册。
  参考已核实的宏：ScriptMgr.h:1144

■ 3-5 第四批：DBC 新建条目

  14 个 C 级技能攒一起，**只发一次客户端补丁**。
  和你之前规划的「读条显示同步 DBC 补丁」「新地图补丁」打包一起发。

第四部 · 平衡性建议
================================================================================

■ 4-1 数值锚点

  你的服务器 Solocraft 是 5/10/25/40 倍，装备上限 21 亿。
  在这个环境下，技能的**百分比加成**比固定数值有意义得多。

  建议：
    · 所有新技能一律用**百分比**，不写固定数值
    · 攻击强度加成不超过 +100%
    · 减伤不超过 50%
    · 治疗量加成不超过 +50%

■ 4-2 冷却时间分档

  ┌──────────────┬──────────────────────────────────┐
  │ 15-30 秒     │ 常用技能，循环的一部分           │
  │ 45-60 秒     │ 战术技能，关键时刻用             │
  │ 2-3 分钟     │ 爆发大招，一场战斗用 1-2 次      │
  │ 5-10 分钟    │ 保命/团队救场，一个副本用几次    │
  │ 15-30 分钟   │ 觉醒技，慎用                     │
  └──────────────┴──────────────────────────────────┘

  注意：你装了战斗节奏优化（speed.conf），CD 会被压缩到 85%/80%/90%。
  设计时按原始值写，实际生效会更短。

■ 4-3 别踩的坑

  1. 【不要做"无冷却"技能】
     巫妖王之影那个"所有技能无冷却"要格外小心，
     配合你的 CD 压缩可能出现无限连招。建议加"每个技能最多触发3次"限制。

  2. 【BOSS 免疫要提前设计】
     百分比斩杀、强制转化、单挑领域这类，
     必须对 BOSS 无效或大幅削弱，否则副本机制全废。

  3. 【和 NPCBot 的兼容】
     你装了 NPCBot，给玩家加的技能 bot 不会用。
     如果希望 bot 也能用，需要在 bot_ai 里加逻辑 —— 这是额外工作量。

  4. 【和 Solocraft 的叠加】
     Solocraft 已经给了 5-40 倍属性，再加百分比技能会指数级膨胀。
     建议新技能的加成用**加法**不用乘法。

■ 5-2 老职业的"不可替代性"

    战士     —— 最高的持续物理输出（百战之躯堆叠）
