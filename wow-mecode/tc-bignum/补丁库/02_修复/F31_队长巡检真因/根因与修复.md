## 二、三处关键差异 —— 这就是你装了还不生效的原因

| # | mod-playerbots 的做法 | 我上一版给你的 | 后果 |
|---|---|---|---|
| **1** | `isUseful()` **每个 AI tick 评估** | 只在 `TryAcceptGroup` 时做一次 | **上线走的是数据库恢复，不经过 TryAcceptGroup，所以永远不触发** |
| **2** | 改队长前先 `IsMember(newLeader)` | 没查 | 玩家还没进队就调 -> 静默失败 |
| **3** | `ChangeLeader` 后补 `SendUpdate()` | 没有 | 服务端改了，客户端 UI 不刷新 |

**差异1 是主因。** 你每次上线，队伍是从 `groups` 表恢复的，
根本不经过任何"接受邀请"的代码路径 —— 所以一次性钩子必然落空。

## 三、为什么"每 tick 巡检"是对的 —— 时序实证

这是本次最关键的一条，我实查了登录流程：

```
Player.cpp:17317    _LoadGroup(holder.GetPreparedResult(PLAYER_LOGIN_QUERY_LOAD_GROUP));
Player.cpp:18743    void Player::_LoadGroup(PreparedQueryResult result)
Player.cpp:18754        SetGroup(group, subgroup);
```

而 `ChangeLeader` 有一道**硬门槛**：

```cpp
// Group.cpp:925
void Group::ChangeLeader(ObjectGuid newLeaderGuid)
{
    member_witerator slot = _getMemberWSlot(newLeaderGuid);
    if (slot == m_memberSlots.end())
        return;                                    // 不在队里 -> 直接退出

    Player* newLeader = ObjectAccessor::FindConnectedPlayer(slot->guid);

    // Don't allow switching leader to offline players
    if (!newLeader)
        return;                                    // 【关键】不在线 -> 直接退出
}
```

**翻译成人话**：
你上线的**那一瞬间**，`_LoadGroup` 刚把你塞进队伍，
但此时 `FindConnectedPlayer` 不一定找得到你（会话还没完全就绪）。
这时候调 `ChangeLeader` 会**静默失败，不报任何错**。

**所以必须持续巡检，而不是在某个时间点赌一次。**
mod-playerbots 用 `isUseful()` 每 tick 评估，本质就是在等"条件成熟的那一刻"。

好消息：`ChangeLeader` 内部**自带写库和广播**，不用我们操心：

```
Group.cpp:970-977    CHAR_UPD_GROUP_LEADER  写库（持久化，下次上线不会变回去）
Group.cpp:983-985    SetFlag(PLAYER_FLAGS_GROUP_LEADER) + m_leaderGuid/m_leaderName
Group.cpp:988-990    WorldPacket data(SMSG_GROUP_SET_LEADER); BroadcastPacket(&data, true);
```

### 4.3 加巡检函数

搜索原文（`TryAcceptTrade` 的函数头，约 `:374`）：

```cpp

```

在这个函数**上面**，插入下面整段：

```cpp
// ------------------------------------------------------------------
//  F31: 队长巡检 —— bot 不该当队长
//
//  为什么要巡检而不是一次性钩子：
//    玩家上线时队伍是从 groups 表恢复的（Player.cpp:17317 _LoadGroup），
//    不经过任何"接受邀请"的代码路径，一次性钩子必然落空。
//  为什么要节流：
//    ChangeLeader 会写库（Group.cpp:970 CHAR_UPD_GROUP_LEADER），
//    每帧调用会把数据库打爆。
//
//  借鉴 mod-playerbots:
//    Ai/Base/Actions/PassLeadershipToMasterAction.cpp:36  isUseful()
//    Script/WorldThr/PlayerbotOperations.h:224            GroupSetLeaderOperation
// ------------------------------------------------------------------
static void TryPassLeadership(Player* bot)
{
    if (!bot || !bot->IsInWorld())
        return;

    Group* grp = bot->GetGroup();
    if (!grp)
        return;

    // 不是队长就没事干（Group.h:240 IsLeader public）
    if (!grp->IsLeader(bot->GetGUID()))
        return;

    // 节流：每 3 秒最多查一次
    // 用 find 而不是 operator[]，避免默认值 0 导致新 bot 首次就执行
    uint32 now = getMSTime();
    auto itr = _pbotLeaderTimer.find(bot->GetGUID());
    if (itr == _pbotLeaderTimer.end())
    {
        _pbotLeaderTimer[bot->GetGUID()] = now + 3000;
        return;
    }
    if (now < itr->second)
        return;
    itr->second = now + 3000;

    // 在队伍里找一个【真人】接手
    // Group.h:257 GetFirstMember public
    Player* newLeader = nullptr;
    for (GroupReference* ref = grp->GetFirstMember(); ref; ref = ref->next())
    {
        Player* member = ref->GetSource();
        if (!member || member == bot)
            continue;

        // 必须在线（Group.cpp:935 ChangeLeader 对离线玩家直接 return）
        if (!member->IsInWorld())
            continue;

        // 必须是真人：有 socket 的才是真玩家
        // WorldSession.h:503 PlayerDisconnected() { return !m_Socket; }
        if (!member->GetSession() || member->GetSession()->PlayerDisconnected())
            continue;

        newLeader = member;
        break;
    }

    // 全是 bot -> 不动，避免在 bot 之间反复乱转
    if (!newLeader)
        return;

    // 借鉴 PlayerbotOperations.h:239，改之前确认对方真在队里
    if (!grp->IsMember(newLeader->GetGUID()))
        return;

    grp->ChangeLeader(newLeader->GetGUID());   // Group.h:211 public
    grp->SendUpdate();                         // Group.h:289 public，补一发全队刷新

    ChatHandler(newLeader->GetSession()).PSendSysMessage(
        "|cff00ff00[%s]|r 把队长交给了你。", bot->GetName().c_str());
}
```

## 八、如果还不生效 —— 三个探针

**别猜，按顺序插日志。**

### 探针1：函数有没有被调用

在 `TryPassLeadership` 第一行加：

```cpp
    TC_LOG_ERROR("scripts", "F31-A: TryPassLeadership called for {}", bot ? bot->GetName() : "null");
```

看不到这条 → 说明 OnUpdate 循环没跑到，或者 bot 不在 `g_pbots` 里。

### 探针2：是不是队长

在 `if (!grp->IsLeader(bot->GetGUID())) return;` 上面加：

```cpp
    TC_LOG_ERROR("scripts", "F31-B: {} inGroup={} isLeader={}",
        bot->GetName(), grp != nullptr, grp && grp->IsLeader(bot->GetGUID()));
```

`isLeader=0` → bot 本来就不是队长，问题在别处。

### 探针3：找没找到接手的人

在 `if (!newLeader) return;` 上面加：

```cpp
    TC_LOG_ERROR("scripts", "F31-C: newLeader={}", newLeader ? newLeader->GetName() : "NONE");
```

`NONE` → 说明遍历没找到真人。可能是 `PlayerDisconnected()` 判断把你也过滤了
（如果你自己也是通过 pbot 方式登录的话）。

**不需要这一层**，直接调即可。这是我们和它的架构差异，不能照抄。
