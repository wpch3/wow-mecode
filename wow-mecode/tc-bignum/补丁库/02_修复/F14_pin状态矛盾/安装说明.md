# step60 安装说明 —— `.pin` 状态矛盾修复

---

## 一、你遇到的是什么

```
.pin      -> 这个bot已经有持久化数据了
.pin off  -> 这个bot本来就不是永久的
```

**两个指令都进不去，bot 卡死了。**

**这是我 step49 的设计缺陷**：`.pin` 和 `.pin off` 用了**两个不同的判断依据**。

| 指令 | 判断依据 | 查哪张表 |
|---|---|---|
| `.pin` | `BotDataMgr::SelectNpcBotData(entry)` | **characters_npcbot** |
| `.pin off` | `bot->GetSpawnId()` | **world.creature** |

你这个 bot 的真实状态是：**characters_npcbot 有记录，world.creature 没有**。

所以两句话**各自都"对"**，但对你来说就是自相矛盾。

### 怎么变成这样的

永久化必须**两张表同时写**（照抄官方 `botcommands.cpp:3859-3873` 的四步）。
但我 step49 **没做失败回滚** —— 第1步写完 `characters_npcbot`，
后面某步失败了，就留下这个"半永久"状态。

> **很可能就是 `UnsetWanderer` 编译报错（step59）之前那次**。
> 那时候 `.pin` 走的路径本来就不完整。

## 三、第一步：解开当前卡死的 bot（SQL）

### 3.1 先诊断（不改数据）

DBeaver 打开 `sql/诊断与修复.sql`，**`Alt+X` 执行全部**。

**第一部分是纯查询，不会改任何东西。**

它会列出三类：

```
损坏类型A：只有持久化数据，没有实体   <- 你的情况，安全但卡死
损坏类型B：只有实体，没有持久化数据   <- 危险，下次重启会崩服
正常的已固定bot                      <- 这些不用动
```

**先看清楚有哪些**，尤其确认一下有没有类型B（那个会崩服）。

### 3.2 再修复

在同一个文件里找到 **2.1 节**，把下面几行**去掉开头的 `--`**：

```sql
SET @entry := 70001;          -- <- 改成你那个bot的实际entry

DELETE FROM `characters`.`characters_npcbot`              WHERE `entry` = @entry;
DELETE FROM `characters`.`characters_npcbot_group_member` WHERE `entry` = @entry;
DELETE FROM `world`.`creature`                            WHERE `id`    = @entry;
```

**如果损坏的不止一个**，用 2.2 节的批量清理。

### 3.3 重启服务端（这步不能省）

`characters_npcbot` 在内存里有缓存（`BotDataMgr::_botsData`）。

**光删数据库不重启，`.pin` 还是会说"已经有持久化数据了"。**

重启后那个 bot 就变回普通游荡 bot 了。

### 4.2 改了什么

#### （1）判断依据统一

新增 `GetPinState()`，**三个指令都用它**：

```cpp
PIN_STATE_FREE               两张表都没有  -> 纯游荡bot，可以 .pin
PIN_STATE_PINNED             两张表都有    -> 已固定，可以 .pin off
PIN_STATE_BROKEN_DATA_ONLY   只有 characters_npcbot
PIN_STATE_BROKEN_SPAWN_ONLY  只有 world.creature（会崩服）
```

**再也不会出现"两个指令互相矛盾"** —— 因为它们看的是同一个东西。

#### （2）`.pin` 加失败回滚

```cpp
if (!db_guid)
{
    BotDataMgr::UpdateNpcBotData(entry, NPCBOT_UPDATE_ERASE, nullptr);
    handler->SendSysMessage("|cffff0000 固定失败：SaveToDB 没能生成 spawnId|r");
    handler->SendSysMessage("|cffffff00 已自动回滚，bot 保持游荡状态|r");
    return false;
}
```

`SaveToDB` 没成功就把第1步写的记录撤掉，**不再留下半永久状态**。

#### （3）新增 `.pin status` —— 看真实状态

```
.pin status
```

输出：

```
[鲤鱼] entry=70001
  characters_npcbot : 有
  world.creature    : 无
  spawnId(内存)     : 0
  IsWandererBot()   : 是
  判定: 损坏 只有持久化数据，没有实体
        用 .pin fix 清理
```

**一眼看出问题在哪一层。**

#### （4）新增 `.pin fix` —— 自助修复

选中 bot，`.pin fix`，它会自动清掉孤儿记录。
以后再遇到就不用跑 SQL 了。

**注意**：`.pin fix` 之后同样要**重启服务端**才能让内存缓存同步，
指令里会提示你。

### 4.3 新的帮助

```

.pin list            列出你固定的bot

.pin status          看这个bot的真实状态（两张表）      <- 新增

--- 中文别名 ---

```

## 七、我的错误记录

**教训：一个功能的"开"和"关"，必须用【同一个判断依据】。**

我 step49 写 `.pin` 时想的是"官方怎么判重复" -> 用了 `SelectNpcBotData`；
写 `.pin off` 时想的是"怎么拿到要删的 guid" -> 用了 `GetSpawnId()`。

**两个函数分开写、分开想，就用了两套标准，必然打架。**

正确做法：**先定义"什么叫已固定"，然后开关两边都用这一个定义。**
