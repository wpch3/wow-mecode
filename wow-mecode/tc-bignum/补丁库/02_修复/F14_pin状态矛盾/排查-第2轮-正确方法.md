## 一、先认错：`strings` 找不到中文，是工具限制，不是你 exe 旧

我让你跑的第3步：

```bash
strings worldserver.exe | grep -c "看这个bot的真实状态"
```

**这条命令永远返回 0，不管 exe 新旧。**

### 实测证据

我造了个小程序，里面**同时**有一个 ASCII 串和一个中文串，编译后：

```
strings + 中文  : 0     <- 我用错的方法
grep -a + 中文  : 1     <- 正确
strings + ASCII : 1     <- 也正确
```

**原因**：`strings` 默认只提取**可打印 ASCII**（0x20-0x7E）。
中文是 UTF-8 多字节（每字节都 >= 0x80），**被它当成"非文本"跳过了**。

**所以你的第3步返回 0 是我的锅，不能证明 exe 是旧的。**

你说得对 ——
step44 和 step49 你都做了，那两个错任一个没解决都编译不过，
`.pin` 肯定是存在的，不然你也报不出"指令错误"。**是我判断失误。**

## 二、正确的验证命令

```bash
echo "===== A. exe 里有没有新代码（中文串，用 grep -a）====="
grep -ac "看这个bot的真实状态" /d/TC-Build/bin/RelWithDebInfo/worldserver.exe
echo "  >=1 = exe 是新的"
echo
echo "===== B. 再验一个（ASCII，双保险）====="
grep -ac "botpersist_commandscript" /d/TC-Build/bin/RelWithDebInfo/worldserver.exe
echo "  >=1 = 脚本被编译进去了"
echo
echo "===== C. 你实际在跑的 exe 在哪 ====="
find /d -maxdepth 3 -name "worldserver.exe" -not -path "*/TC-Build/*" 2>/dev/null
echo "  (上面列出的是除build目录外的所有 worldserver.exe)"
echo
echo "===== D. 所有 worldserver.exe 的时间对比 ====="
find /d -maxdepth 3 -name "worldserver.exe" 2>/dev/null -exec ls -la --time-style=+%m-%d_%H:%M {} \;
```

## 三、我现在的判断：你跑的 exe 不是刚编译的那个

第4步显示：

```
/d/TC-Build/bin/RelWithDebInfo/worldserver.exe   2026-08-05 03:46:49
```

第5步我猜的路径 `/d/WOW-Server/` 不存在。

**所以关键问题是**：你的服务器实际是从哪个目录启动的？

TrinityCore 编译产物在 `TC-Build\bin\RelWithDebInfo\`，
但**大多数人不直接在那跑**，而是复制到另一个目录（带 conf、dbc、maps 那个）。

**如果你没把新 exe 复制过去，跑的就还是旧的。**

上面的命令 C 和 D 会把你硬盘上所有 `worldserver.exe` 列出来，
**一比时间就知道了**。

## 四、如果 A 返回 0（exe 真的没新代码）

那才是编译问题，按这个查：

```bash
echo "=== cs_botpersist.cpp 在不在工程里 ==="
grep -c "cs_botpersist" /d/TC-Build/src/server/scripts/scripts.vcxproj
echo "  >=1 = 在工程里；0 = CMake 没收录，要重跑 CMake"
```

`scripts.vcxproj` 是 CMake 生成的工程文件，
里面**必须**列出 `cs_botpersist.cpp`，否则 VS 根本不会编译它。

> 注意路径可能不同，如果找不到就：
> ```bash
> find /d/TC-Build -name "scripts.vcxproj" 2>/dev/null
> ```
