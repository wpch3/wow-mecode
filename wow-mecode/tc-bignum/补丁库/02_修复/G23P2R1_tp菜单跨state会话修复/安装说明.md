# G23-P2R1 `.tp`菜单跨Lua state假超时修复

更新时间：2026-08-22  
目标根：`D:\TC-Build\bin\RelWithDebInfo`  
前置：G23-P2已Apply；本批只替换`lua_scripts\custom_teleport.lua`

## 1. 修复什么

P2把`.tp`菜单上下文放在脚本局部`local sessions`表中。Eluna multistate下，聊天命令建立菜单与Player Gossip点击回调可能落在不同Lua state；每个state有独立局部表，因此点击“东部王国”等分类时，回调看不到命令state里刚建的session，立即误报：

```text
传送会话已超时，请重新输入 .tp
```

`.tp 暴风城`只有一个结果时直接传送，不依赖菜单session，所以仍然正常。这与用户现场现象及跨state回归模型完全吻合。

P2R1删除所有跨点击的内存session依赖：

- 分类、页码通过Gossip的`sender/intid`编码；
- 每页点击时按分类和页码重新只读查询；
- 目标点击按不可变`game_tele.id`重新查询，拒绝信任旧内存对象；
- 关键词多结果最多显示28项，过多时要求缩小关键词；
- 战斗、PVP、战场/竞技场、飞行/航线、坐骑、载具、死亡、副本、目标地图及GM权限安全门全部保留，并在菜单点击和最终传送前重检。

无会话即无会话过期或跨state清理问题；这不是放宽原安全门。

## 2. 唯一安装顺序

### 第一步：Check

双击：

```text
G23P2R1_Check.cmd
```

必须看到：

```text
G23P2R1_FILE=lua_scripts/custom_teleport.lua; state=PRE_P2
G23P2R1_STATE=READY_TO_APPLY
G23P2R1_SQL_REQUIRED=False
G23P2R1_COMPILE_REQUIRED=False
G23P2R1_RELOAD_ELUNA_ALLOWED=False
```

如果是`BLOCKED_UNKNOWN`，不要手工覆盖，回传窗口全文。

### 第二步：正常停服

从worldserver控制台正常关闭。Apply会阻止worldserver仍运行时写文件。

### 第三步：Apply

双击：

```text
G23P2R1_Apply.cmd
```

必须看到：

```text
G23P2R1_APPLY=PASS
G23P2R1_FINAL_STATE=POST_P2R1
```

### 第四步：正常启动

正常启动worldserver。

**本热修不需要SQL、不需要VS2022编译，也禁止执行`.reload eluna`。** P2已导入的每日奖励SQL不要重复执行。

## 3. 最小验收

只需一次简短验证：

1. 输入`.tp`；
2. 点击“东部王国”；
3. 确认出现地点列表，不再提示会话超时；
4. 点击一个普通地点，确认传送；
5. `.tp 暴风城`仍能正常使用。

不需要执行繁琐矩阵。

## 4. 回滚

只有热修出现新问题时，正常停服后双击：

```text
G23P2R1_Rollback.cmd
```

它只恢复P2版`custom_teleport.lua`，不会撤销其它P2 Lua、配置或数据库。正常安装时不要运行Rollback。
