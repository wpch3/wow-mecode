## 一、为什么 `.pin` 后会闪退

**游荡bot的"身份证"是临时的，写进数据库必然崩。**

### 实证链

`botdatamgr.cpp:63`：

```cpp
static CreatureTemplateContainer _botsExtraCreatureTemplates;
//     ^^^^^^ 文件级 static，纯内存，进程重启就没
```

`botdatamgr.cpp:344`（生成游荡bot时）：

```cpp
CreatureTemplate& bot_template = _botsExtraCreatureTemplates[next_bot_id];
bot_template.Entry = next_bot_id;
```

`ObjectMgr.cpp:10274-10279`（查模板时的硬断言）：

```cpp
if (entry >= BOT_ENTRY_CREATE_BEGIN)
{
    if (CreatureTemplate const* t = BotDataMgr::GetBotExtraCreatureTemplate(entry))
    {
        //custom creature template should only exist in custom container
        ASSERT_NODEBUGINFO(_creatureTemplateStore.find(entry) == _creatureTemplateStore.end());
```

**把游荡bot写进 `world.creature`，等于让"临时模板"的 entry
出现在持久化数据里 -> 踩断言 -> 崩服。**

### 我错在哪

`Creature.cpp:1429` 那道拦截**不是 bug，是保护**：

```cpp
//npcbot: disallow saving generated bots
if (IsNPCBot() && GetBotAI() && (GetBotAI()->IsWanderer() || IsSummon()))
    return;
```

注释写着 **"disallow saving generated bots"（禁止保存生成的bot）**。

我上一版（F16）为了让 `.pin` 成功，把 `UnsetWanderer()` 提前来绕过它——
**等于拆了安全气囊**。之前几版没崩，正是因为这道保护一直拦着。

## 三点五、上一版编译失败的原因（已修）

你收到的报错：

```

C2374  "extras": 重定义；多次初始化      cs_botpersist.cpp 475
```

**根因**：我把原 `DoPin` 实现改名成 `DoPinLegacy` 保留时，

保留它本来是想"将来做复制成真bot方案时参考"，
但那些落库四步的写法在 `根因-游荡bot根本无法被pin.md` 和

## 四、改了什么

### `.pin` 直接拒绝并说明原因

```
[.pin 已停用]
 游荡bot的模板是【内存临时对象】
 (botdatamgr.cpp:63 _botsExtraCreatureTemplates)
 写进数据库会让 ObjectMgr.cpp:10279 断言失败 -> 崩服
 想要永久bot请用官方指令: .npcbot spawn
 诊断用 .pin status 仍可用（只读，安全）
```

**关键**：拒绝发生在**任何落库操作之前**（自检确认：
`DoPin@327` → 停用return@404 → 不可达的 `SaveToDB@527`）。

### 原实现保留为 `DoPinLegacy`

不删掉，是为了将来做"复制成真bot"方案时参考落库四步的写法。
标了 `[[maybe_unused]]` 避免 C4505 告警。

### `.pin status` 保留

**只读操作，绝对安全**，可以继续用来诊断 bot 状态。

## 五、那"游荡bot永久化"还能做吗

**能，但要换一条路。**

### 不是"固定游荡bot"，是"用它的属性新建一个真bot"

```
1. 读游荡bot的：种族/职业/等级/外观/装备/名字
2. 在 creature_template 【新建】一条真实记录（专用entry段，如71001+）
3. 写 creature_template_npcbot_extras（职业种族）
4. 写 creature_template_npcbot_appearance（外观）
5. 在 creature 表 spawn 它
6. 让原来那个游荡bot消失
```

这样得到的是**真正的、可持久化的 NPCBot**，
和 `.npcbot spawn` 出来的一模一样。

**工作量比 `.pin` 大，但这是唯一正确的做法。** 需要单独排期。

### 或者：现在就有的简单办法

```
永久bot  -> 用官方 .npcbot spawn（已经能用）
游荡bot  -> 当背景板，数量调低
```
