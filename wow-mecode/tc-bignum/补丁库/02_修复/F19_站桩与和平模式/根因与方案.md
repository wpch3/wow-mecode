## 二、站桩不动 —— 根因锁定

### 真凶：`bot_ai.cpp:15689 UpdateImpossibleChase`

`bot_ai.cpp:5566`（攻击接近流程的开头）：

```cpp
if (UpdateImpossibleChase(newtarget))
    return;                    // <-- 返回 true 就【直接不走了】
```

而 `UpdateImpossibleChase`（`:15689`）：

```cpp
bool bot_ai::UpdateImpossibleChase(Unit const* target)
{
    if (_chaseTimer > lastdiff || me->isMoving() || !IAmFree())
        return false;

    if (JumpingOrFalling())
        return false;

    if (_jumpCount >= 3)
    {
        me->AttackStop();
        Evade();
        return true;
    }

    if (_unreachableCount < 5)
    {
        if ((IsRanged() ? me->GetDistance(target) > 40.0f : !me->IsWithinMeleeRange(target)) ||
            (target->IsCreature() && !me->IsWithinLOSInMap(target, LINEOFSIGHT_ALL_CHECKS, VMAP::ModelIgnoreFlags::M2)))
        {
            ++_unreachableCount;
            ResetChaseTimer(target);
            BotMovement(BOT_MOVE_POINT, target, nullptr, false);
            //                                          ^^^^^ generatePath = false
        }
        else
            _unreachableCount = 0;

        return true;               // <-- 【无论如何都返回 true，阻断后续接近逻辑】
    }
    ...
}
```

### 站桩是怎么发生的

```
1. bot 选中一个中立生物当目标
2. 目标不在近战距离 或 LOS被挡
3. -> _unreachableCount++ , BotMovement(BOT_MOVE_POINT, target, nullptr, false)
     注意最后一个参数 generatePath=false —— 【不生成寻路，直线冲】
4. -> return true  -> 阻断 GetInPosition 的正常接近逻辑
5. 直线路径被地形挡住 -> 走不到 -> 位置没变
6. ResetChaseTimer 把 _chaseTimer 设回 5000ms（wanderer）
7. 5秒后重来一遍，还是走不到
8. -> 循环 5 次后 _unreachableCount >= 5，才走 BotJump
9. 但 BotJump 也可能失败，_jumpCount >= 3 才 Evade
```

**在这 5+3 次循环期间（最长 5秒 x 8 = 40秒），bot 完全站着不动。**

**而你打死那个中立怪，目标消失 -> 流程重置 -> bot 恢复正常。** 完全对上。

### 为什么中立生物特别容易触发

`bot_ai.cpp:15707`：

```cpp
(target->IsCreature() && !me->IsWithinLOSInMap(target, LINEOFSIGHT_ALL_CHECKS, VMAP::ModelIgnoreFlags::M2))
```

**只对 Creature 做 LOS 检查**（对 Player 不做）。

中立生物常在树后、岩石后、室内 —— LOS 一挡就进入这个循环。

### 你日志里的旁证

```
Bot Llane id 82213 class 1 level 52 can't find full path to node 646 (res 4) ... falling back to default PF!
```

**12 条寻路失败** —— 同一个地形问题的另一面。

## 三、站桩修复方案

### 3.1 最小改动：让 wanderer 用真寻路

`bot_ai.cpp:15711` 那行：

```cpp
BotMovement(BOT_MOVE_POINT, target, nullptr, false);
//                                           ^^^^^ generatePath = false
```

**改成对 wanderer 启用寻路**：

```cpp
BotMovement(BOT_MOVE_POINT, target, nullptr, IsWanderer());
```

**理由**：
- 有主 bot 跟着玩家走，直线冲问题不大（玩家会带路）
- **游荡bot 没人带路**，遇到地形必须自己寻路
- `generatePath=true` 会走 `PathGenerator`，绕过障碍

### 3.2 配套：缩短卡死判定

`bot_ai.cpp:15732`：

```cpp
void bot_ai::ResetChaseTimer(Position const* /*pos*/)
{
    _chaseTimer = IsWanderer() ? 5000 : 20000;
}
```

wanderer 已经是 5000ms（比有主bot快4倍），**这个不用改**。

### 3.3 兜底：卡住就放弃目标

`_unreachableCount` 上限从 5 降到 3，让它更快放弃转而继续赶路。

**但这要改 `if (_unreachableCount < 5)` 这个硬编码**，
我倾向**先只做 3.1**，看效果再说。

**最小改动原则：一次只改一个变量。**

## 五、A36 在 A35 之后仍失败 —— 真因是 entry 范围对不上

### 我上一轮说"没跑A35"是错的，你确实跑了

**真因**：A35 和 A36 的默认 entry 范围**完全错开**。

**A35 的 2.1**：

```sql
WHERE cn.`entry` IS NULL AND e.`class` <> 0
ORDER BY e.`entry`        -- 【从最小的 entry 开始】
LIMIT 10;
```

你的 entry 分布（你自己的诊断结果）：

```
70001-70499   282 个    <- 最小的在这，A35 会挑这里的
71000-71499   500 个
```

-> **A35 实际写进 creature 表的是 70001~70010 附近**

**A36 的 2.1 默认**：

```sql
SET @from_entry := 71001;      -- 起始
SET @to_entry   := 71500;      -- 结束
```

-> `UPDATE ... WHERE id BETWEEN 71001 AND 71500` **匹配 0 行**

### 你说 70001/70002 也不行

**如果你手动改成 70001 还是 0 行**，说明 A35 那次实际没写成功。

**先跑这条确认**：

```sql
SELECT `guid`, `id`, `map`, `ScriptName`
FROM `world`.`creature`
WHERE `id` IN (SELECT `entry` FROM `world`.`creature_template_npcbot_extras`)
ORDER BY `id`;
```

- **有输出** -> 记下实际的 `id`，A36 用那些 id
- **无输出** -> A35 没成功，要重跑 A35
