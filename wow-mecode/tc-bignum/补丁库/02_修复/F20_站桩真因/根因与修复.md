# F20  站桩真因 —— F19 改错地方了

> 用户：「我已经装了F19，全部没出错，游荡bot还是对中立生物锁定目标而不会走向攻击范围」

**F19 改的 `UpdateImpossibleChase` 根本没被调用到。真因在更早的一步。**

---

## 一、真因：目标在「选中之后、移动之前」就被丢弃了

### `bot_ai.cpp:4319-4327`

```cpp
uint8 followdist = IAmFree() ? BotMgr::GetBotFollowDistMax() / 2 : master->GetBotMgr()->GetBotFollowDist();
//                             ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 100 / 2 = 50
...
bool dropTarget = followdist == 0 && master->IsAlive();
if (!dropTarget && (!u || IAmFree()) && master->IsAlive() && mytar && mytar == opponent)
{
    dropTarget = !me->CanSeeOrDetect(mytar) || (IAmFree() ?
        me->GetDistance(mytar) > (IsWanderer() ? float(followdist + 10) : foldist) :
        //                                             ^^^^^^^^^^^^^^^ 50 + 10 = 60码
        ...);
}
if (dropTarget)
{
    mytar = nullptr;              // <-- 【目标被丢弃】
}
```

### 三个关键点（全部实查）

| # | 事实 | 出处 |
|---|---|---|
| 1 | `GetBotFollowDistMax()` **恒定返回 100** | `botmgr.h:210` |
| 2 | wanderer 的 `master` 指向**自己**，`master->IsAlive()` 恒为 true | `bot_ai.cpp:459` |
| 3 | wanderer 的追击上限 = `100/2 + 10` = **60 码** | `bot_ai.cpp:4310` + `:4323` |

### 死循环

```
1. bot 视野内发现中立生物（比如 70 码外）
2. CanBotAttack 通过 -> 选它当 mytar
3. GetDistance(70) > 60  ->  dropTarget = true  ->  mytar = nullptr
4. 没有目标 -> 不调 GetInPosition -> 【不移动】
5. 下一帧重新扫描 -> 又发现 -> 又丢弃
6. 视觉上：锁定了但不走过去
```

**F19 改的 `UpdateImpossibleChase`（`:15689`）在第 4 步之后才会被调用，
目标在第 3 步就没了，根本走不到。所以 F19 无效。**

---

## 二、还有一处矛盾：两个 followdist 不一致

| 位置 | 值 | 用途 |
|---|---|---|
| `bot_ai.cpp:3657` | `GetBotFollowDistMax()` = **100** | `CanBotAttack` 判断"能不能打" |
| `bot_ai.cpp:4310` | `GetBotFollowDistMax() / 2` = **50** | `_getTargets` 判断"要不要保留目标" |
| `bot_ai.cpp:5330` | `GetBotFollowDistMax()` = **100** | `CalculateAttackPos` 算走位 |

**`CanBotAttack` 说 100 码内都能打，`_getTargets` 却在 60 码就丢目标。**

**60~100 码这个区间就是"锁定但不追"的死区。**

---

## 三、修复：给 wanderer 放开追击距离

### 改动（1 行）

`bot_ai.cpp:4310`：

```cpp
    uint8 followdist = IAmFree() ? BotMgr::GetBotFollowDistMax() / 2 : master->GetBotMgr()->GetBotFollowDist();
```

**改成**：

```cpp
    uint8 followdist = IAmFree() ? (IsWanderer() ? BotMgr::GetBotFollowDistMax() : BotMgr::GetBotFollowDistMax() / 2) : master->GetBotMgr()->GetBotFollowDist();
```

**效果**：
- wanderer 的追击上限从 **60 码 -> 110 码**
- 和 `CanBotAttack`（100码）、`CalculateAttackPos`（100码）**对齐**
- 其它 free bot（非wanderer）行为**不变**
- 有主 bot 完全不受影响

### 为什么不直接改成更大

`botcommon.h:45  BOT_MAX_CHASE_RANGE = 120` —— 上游的硬上限。

`bot_ai.cpp:4341` 还有一道：

```cpp
if (canAttack && (!IAmFree() || me->GetDistance(mytar) < float(BOT_MAX_CHASE_RANGE)) && ...)
```

**110 < 120，正好卡在上游允许的范围内，不会和别的逻辑打架。**

## 六、我的错误

**F19 我看到 `UpdateImpossibleChase` 里有 `BotMovement(..., false)`（不寻路），
就认定那是站桩原因，没有验证"这个函数会不会被调用到"。**

正确的排查顺序应该是：

```
1. 先确认 bot 有没有目标        <- 我跳过了这步
2. 有目标才看移动逻辑
3. 移动逻辑里再看寻路
```

**我直接从第 3 步开始查。**

**规则：排查"不动"类问题，必须从【状态链的最前端】开始验证：
有没有目标 -> 目标保不保得住 -> 有没有下移动指令 -> 移动指令能不能执行。
跳过任何一步都可能改错地方。**
