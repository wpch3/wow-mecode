# G23-P2 Lua稳定性与安全门：Windows安装、验收与回滚

更新时间：2026-08-22  
目标运行根：`D:\TC-Build\bin\RelWithDebInfo`  
性质：独立Lua/SQL/conf批次；不修改F45 C++，不编译，不重跑CMake，不执行`.reload eluna`

## 1. 回答“Lua是否已经全部做好”

交付前并没有做好：Windows上仍是P0R捕获的5个旧Lua和3个旧扩展，P2后像尚未安装。本包完成的是当前计划内的**Lua稳定性基线**：

- 新增`G23Core.ext`共享命令、错误保护、DB验证和日志冷却层；
- 公告只有世界state一个全服定时器；
- 每日奖励使用数据库唯一主键+UUID所有权令牌的原子领取闸，并处理发奖失败；
- 传送增加战斗/PVP/飞行/航线/坐骑/载具/死亡/副本/目标地图/权限安全门和5分钟会话清理；
- `.bigtest`删除恒真断言，区分必须API和可选标准库；
- 新增GM按需`.luadiag`，脚本顶层不查库；
- `.help2`改用共享命令表；
- 隔离会访问失效Creature userdata的旧`ObjectVariables.ext`。

这不等于“以后再也不增加Lua”。P3的`.server`统一助手、收藏/最近传送、每日/每周面板、个人便捷工具等属于下一功能批次，不冒充本P2已完成。

## 2. 包内原件与回滚边界

`original/`包含P0R实际部署的6个字节级旧文件：5个Lua和CRLF版`ObjectVariables.ext`。三个新文件原状态为不存在，分别带`.absent`记录。仓库旧`sql/13_daily_reward.sql`也在`original/repository/`保存。

安装器只接受两种完整状态：

```text
READY_TO_APPLY
ALREADY_APPLIED
```

任何缺文件、未知哈希或混装都会显示`BLOCKED_MIXED_OR_UNKNOWN`并拒绝覆盖。

## 3. 唯一安装顺序

### 第一步：Check

双击：

```text
G23P2_Check.cmd
```

必须看到：

```text
G23P2_STATE=READY_TO_APPLY
```

如果是`ALREADY_APPLIED`，不要重复Apply。如果是`BLOCKED...`，不要手工覆盖，回传窗口全文。

### 第二步：正常停服

从worldserver控制台正常关闭。Apply和Rollback都会阻止在`worldserver.exe`运行时写文件。

### 第三步：导入一份SQL

用HeidiSQL连接characters库并执行：

```text
sql\G23P2_daily_reward_atomic.sql
```

末尾结果应为：

```text
summary_table=1
claim_table=1
```

SQL可重复执行，不含过程、函数、游标或自定义分隔符。

### 第四步：Apply

双击：

```text
G23P2_Apply.cmd
```

必须看到：

```text
G23P2_APPLY=PASS
G23P2_FINAL_STATE=POST
G23P2_COMPILE_REQUIRED=False
G23P2_RELOAD_ELUNA_ALLOWED=False
```

### 第五步：正常启动

直接启动worldserver。**无需VS2022编译，也不要执行`.reload eluna`。** 新配置把`Eluna.ReloadSecurityLevel`有效覆盖为3，必须通过完整重启加载。

## 4. 最小正常使用验收

不做繁琐矩阵，只需平常使用时确认：

1. 登录欢迎正常，每日奖励不重复；
2. `.help2`能显示`.tp`、`.bigtest`和`.luadiag`；
3. `.tp`正常打开，战斗/PVP等状态会明确阻止；
4. 管理员可按需输入`.luadiag`；普通玩家应提示权限不足；
5. 服务端不再出现`ObjectVariables.ext ... GetGUIDLow on bad self`。

`.bigtest`是按需自检，不要求每次启动执行。`.luadiag`也只在需要诊断时执行。

## 5. 回滚

正常停服后双击：

```text
G23P2_Rollback.cmd
```

它会恢复6个字节级旧文件并删除3个P2新文件。SQL表和历史claim故意保留：旧版Lua仍兼容原`custom_daily_reward`汇总表，保留claim可防止因删除审计数据而重复发奖。

如确需检查长时间pending，仅运行只读文件：

```text
sql\G23P2_pending_claim_readonly.sql
```

不要直接删除pending；它可能代表奖励已经发出但最终DB确认中断。
