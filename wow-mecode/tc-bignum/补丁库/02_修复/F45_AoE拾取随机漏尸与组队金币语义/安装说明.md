## 1. 修复内容

1. **唯一物品触发点移动到合法打开尸体拾取窗**：`HandleLootOpcode -> SendLoot成功 -> LootAllAround`，删除物品槽后的旧入口。仅金币、roll物品或没有普通物品成功入包时也能触发。
2. **金币先聚合后统一分配**：在`SendLoot`响应前把周围合法金币搬到圆心`Loot::gold`，让客户端看到聚合总额；随后只执行一次原有NPCBot/真人/单人分金、金币成就和`OnLootMoney`。Custom代码中不再出现`ModifyMoney`。
3. **roll/master逐物品格保护**：删除`hasOverThresholdItem -> 整尸continue`。只保留`is_blocked`、超阈值、`rollWinnerGUID`或任务跟随分配规则的格；同尸体普通物品和金币继续处理。
4. **纯NPCBot队不伪装真人roll**：NPCBot在`GroupBotReference`链，真人计数使用`Group::GetMembersCount()>1`；纯NPCBot队不会因不存在真人竞争者而保护新鲜超阈值格。
5. **保持round-robin权限**：真人组队时低于阈值普通格仍检查`roundRobinPlayer`，不能因同尸体另有高品质物品而顺带拿走他人的低品质格。
6. **完整物品语义**：正常入包保持通知、任务入包检查、三类拾取成就、容器持久化删除和一次`OnLootItem`；事件源GUID使用真实邻近尸体。
7. **邮件边界收紧**：只有`EQUIP_ERR_INV_FULL`可进入邮件；唯一数量、携带上限和其它库存错误原样留尸。任务/FFA/条件格按原版结构结算，邮件每封最多12件。
8. **可诊断播报**：一次显示发现、合法、完成尸体、成功物品、邮件、成功金币尸体/金额，以及动态旗标、权限、剥皮、roll格、背包错误和上限原因。
9. **确定性顺序**：候选尸体按与玩家距离排序，优先处理最近尸体，不再依赖网格容器的非直观遍历顺序。

### 3.4 VS2022增量编译

使用与F44R1相同的既有方案，只编译worldserver：

```powershell
& {
    $ErrorActionPreference = "Stop"
    $Sln = "D:\TC-Build\TrinityCore.sln"
    $RunDir = "D:\TC-Build\bin\RelWithDebInfo"
    $Exe = Join-Path $RunDir "worldserver.exe"
    $Pdb = Join-Path $RunDir "worldserver.pdb"
    $VsWhere = Join-Path ${env:ProgramFiles(x86)} "Microsoft Visual Studio\Installer\vswhere.exe"

    if (Get-Process worldserver -ErrorAction SilentlyContinue) { throw "编译前必须停服" }
    $MSBuild = @(& $VsWhere -latest -products * -requires Microsoft.Component.MSBuild -find "MSBuild\**\Bin\MSBuild.exe" | Where-Object { $_ })[0]
    if (-not $MSBuild) { throw "找不到MSBuild.exe" }

    $BeforeExe = Get-Item -LiteralPath $Exe
    $BeforePdb = Get-Item -LiteralPath $Pdb
    $BeforeHash = (Get-FileHash -LiteralPath $Exe -Algorithm SHA256).Hash.ToLowerInvariant()

    & $MSBuild $Sln /m /t:worldserver /p:Configuration=RelWithDebInfo /p:Platform=x64 /verbosity:minimal
    if ($LASTEXITCODE -ne 0) { throw "MSBuild失败；回传第一条真实C/C++错误" }

    $AfterExe = Get-Item -LiteralPath $Exe
    $AfterPdb = Get-Item -LiteralPath $Pdb
    $AfterHash = (Get-FileHash -LiteralPath $Exe -Algorithm SHA256).Hash.ToLowerInvariant()
    if ($AfterExe.LastWriteTimeUtc -le $BeforeExe.LastWriteTimeUtc) { throw "worldserver.exe时间未前进" }
    if ($AfterPdb.LastWriteTimeUtc -le $BeforePdb.LastWriteTimeUtc) { throw "worldserver.pdb时间未前进" }
    if ($AfterHash -eq $BeforeHash) { throw "worldserver.exe哈希未变化" }

    Write-Host "[OK] exe size=$($AfterExe.Length) sha256=$AfterHash utc=$($AfterExe.LastWriteTimeUtc.ToString('o'))"
    Write-Host "[OK] pdb size=$($AfterPdb.Length) utc=$($AfterPdb.LastWriteTimeUtc.ToString('o'))"
    Write-Host "[OK] F45_WINDOWS_BUILD_PASS=True"
}
```

编译失败只回传**第一条真实C/C++错误、文件和行号**，不要只发后续链接错误。

## 4. 启动后不用做矩阵

只需留意新的单行播报，例如：

```text
群体拾取F45：发现9 合法8 完成尸体7，物品12 邮寄0，金币6具/834铜；保留[标志0 权限1 剥皮0 roll格1 背包错误0 上限0]。
```

- `roll格>0`表示只保留受保护物品格，不再整尸跳过；
- `权限>0`可能是合法的round-robin/归属保留；
- `背包错误>0`表示物品仍在尸体，只有明确空间不足且开启邮件时才邮寄；
- 若仍偶发剩一具，把当次这行播报原文发回即可，不需要重做测试矩阵。

任何重复物品、重复金币、roll物品被直接取走、异常邮件或崩服，立即停服并回滚。
