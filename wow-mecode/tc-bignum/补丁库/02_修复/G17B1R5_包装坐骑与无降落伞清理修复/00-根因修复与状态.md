## 精确根因

真实 `Spell.dbc` 与锁定服务端源码共同证明：爱情火箭 71342、无头骑士 48025 是“已学习外层 + C++ `spell_gen_mount` 选择内层”结构。外层 DBC 有 Mounted Aura metadata，但服务端 `SpellMgr` 为避免 NO_TARGET Aura 错误而把前两个运行时 Effect 清成 `SPELL_EFFECT_NONE`；真正 Mounted Aura 由未直接学习的内层法术提供。B1R4 的“当前 SpellInfo 必须 HasAura + 玩家必须学习同 ID + 活动 Aura 必须同 ID”三重同 ID 门因此排除了包装链。

完整链与字段见 `证据/g17b1r5_wrapper_spell_analysis_20260823.md`。

## 通用修复

1. 候选识别读取 effect 保留的 `ApplyAuraName == SPELL_AURA_MOUNTED`，同时覆盖直接坐骑和被 SpellMgr 清 Effect 的包装坐骑。
2. 所有权继续验证已学习的外层施放法术。
3. 延迟后以当前活动的任意 Mounted Aura 为真实内层来源，从其 `MiscValue` 取 creature entry，从玩家当前 mount display 取模型。
4. Runtime 源码不写死爱情火箭、无头骑士名称或 ID；普通法术仍需通过 Mounted metadata、成功 IsMounted 与活动 Mounted Aura 三重门。
5. `.dragon mount <spellId>` 同步支持直接/包装坐骑法术。
