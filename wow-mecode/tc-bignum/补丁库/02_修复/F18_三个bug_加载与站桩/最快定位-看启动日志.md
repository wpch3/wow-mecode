# 最快定位 160 —— 看启动日志那一行

> 我推断两轮都不准（候选池耗尽 / 500ms限速），都被你的数据打脸。
> **这次不猜，用服务端自己打印的数字。**

---

## 一、一行日志就能定案

`botdatamgr.cpp:1896`：

```cpp
BOT_LOG_INFO("server.loading", ">> Set up spawning of {} wandering bots in {} ms",
             spawned_count, GetMSTimeDiffToNow(oldMSTime));
```

**这行会打印实际"安排"了多少个。**

### 但你刚把日志关了

你现在 `Logger.npcbots=3` 或 `=4`。这行是 **INFO 级**（3），
所以：

- `Logger.npcbots=3` -> **能看到**
- `Logger.npcbots=4` -> 看不到

### 临时打开看一眼

把 conf 改成：

```ini
Logger.npcbots=3,NpcBots Server
```

重启，在启动日志里搜：

```
Set up spawning of
```

**看到的数字就是答案**：

| 日志显示 | 结论 |
|---|---|
| `Set up spawning of 500` | 500个确实安排了 -> 问题在【出场】或【你数的方式】 |
| `Set up spawning of 160` | 只安排了160 -> 问题在【候选池】 |

## 二、如果显示 500，那 160 是怎么来的

### 可能A：你只数了看得见的

游荡bot 分布在**整个大陆**（东部王国+卡利姆多+外域+诺森德）。

你在一个地方能看到的只是一小部分。

**验证方法**：

```
.npcbot wandering count      （如果有这个指令）
```

或者数据库直接查（但游荡bot不在数据库里，查不到）。

### 可能B：地图未加载的bot还没真正出现

`SpawnWandererBot` 里：

```cpp
Map* map = sMapMgr->CreateBaseMap(spawnLoc->GetMapId());
map->LoadGrid(spawnLoc->m_positionX, spawnLoc->m_positionY);
```

**每个bot都会强制加载它所在的网格**。500个bot分布在几百个网格上，
这些网格会一直保持加载 —— 理论上都该在。

### 可能C：bot 互相残杀

**你的日志里全是这个**：

```
Wandering bot Llane id 82355 class 1 level 29 WAS KILLED BY wandering bot Serena id 82539 class 8 level 39
Wandering bot Tuten'arak id 82303 KILLED wandering bot Llane id 82373
Wandering bot Prakar id 82504 KILLED wandering bot Llane id 82241
```

**大量 bot 在互相击杀。**

死掉的 bot 会 despawn（`botdatamgr.cpp:228 _botsExtraCreaturesToDespawn.insert(entry)`），
然后**重新生成一个新的**。

如果击杀速度 > 重生速度，**在线数量就会低于配置值并稳定在某个数**。

**160 很可能就是这个动态平衡点。**

## 三、这才是最可能的真相

```
配置 500 个
  -> 启动时安排 500 个
  -> 出场后开始互相打
  -> 死亡 -> despawn -> 重新生成（有延迟）
  -> 死亡速度和重生速度达到平衡
  -> 稳定在 160 个左右
```

### 支持这个判断的证据

1. **你的日志几乎全是击杀/死亡**（19条KILLED + 16条WAS KILLED BY，占一半以上）
2. **改快了出场速度还是160** —— 说明不是出场慢，是出场后消失了
3. **160 是个稳定值** —— 动态平衡的特征

### 怎么验证

**跑第一章的方法把日志打开**，然后：

```
观察 5 分钟，看 "Bots to despawn: N" 这行出现的频率
```

`botdatamgr.cpp:841`：

```cpp
BOT_LOG_DEBUG("npcbots", "Bots to despawn: {}", uint32(_botsExtraCreaturesToDespawn.size()));
```

**如果这行频繁出现，就坐实了。**（需要 `Logger.npcbots=2`，但那会很吵，看一分钟就改回去）

## 四、如果坐实是互相残杀，怎么解决

### 方案1：让游荡bot互不攻击（推荐）

`bot_ai.cpp:3623` 有现成的判断入口：

```cpp
if (IsWanderer() && target->IsCreature() && target->GetVictim() != me)
{
    if (BotCfg::EnableWanderingUntargetNpcQuestgiver() && target->IsQuestGiver())
        return false;
    ...
}
```

**在这里加一条：目标也是 wanderer 就不打。**

配一个 conf 开关，你可以随时切换"和平模式/大逃杀模式"。

### 方案2：加快重生

死亡后立刻补一个新的，维持总数。

### 方案3：保持现状

**如果你喜欢"世界很危险"的感觉**，160 个活跃 + 不断有新的出现，
其实挺有生命力的。
