## Bug 1：设 500 只出 160

### 根因：候选池耗尽时【静默退出】

`botdatamgr.cpp:665`：

```cpp
for (std::size_t i{}; i < brackets_shuffled.size() && !teamSpareBotIdsPerClass.empty();)
//                                                    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//                                                    池子空了就退出，不报错
{
    uint8 bracket = brackets_shuffled[i];
    int8 tries = 100;
    do {
        --tries;
        if (GenerateWanderingBotToSpawn(teamSpareBotIdsPerClass.back(), ...))
        {
            ++i; ++spawned;
            teamSpareBotIdsPerClass.pop_back();   // <- 每成功一个就消耗一个模板
            break;
        }
    } while (tries >= 0);
    if (tries < 0) return false;
}
```

**关键**：`GenerateWanderingBotToSpawn`（`botdatamgr.cpp:373`）
**全函数只有一个 `return true`（:478）**，我 grep 过没有任何 `return false`。

所以 `tries` 重试机制形同虚设，**不会因失败丢 bot**。

**唯一的出口是 `teamSpareBotIdsPerClass.empty()`。**

### 结论

```
spawned = min(你设置的数量, 可用模板数)
```

**你的可用模板只有 160 个。**

### 可用模板怎么算的

`botdatamgr.cpp:316-326`：

```cpp
for (auto const& [id, extras] : _botsExtras)          // 遍历 npcbot_extras
    if (c != BOT_CLASS_NONE && BotCfg::IsWanderingClassEnabled(c))
        if (!_botsData.contains(id))                   // 不在 characters_npcbot
            _spareBotIdsPerClassMap.at(c).insert(id);
```

三个条件缺一不可：
1. 在 `creature_template_npcbot_extras` 里
2. `class != 0` 且**该职业在 conf 里启用**
3. **不在** `characters_npcbot` 里

> 你之前查到「游荡池剩余 812」，但那是**没算职业启用过滤**的数字。
> 实际可用只有 160 -> 说明大部分模板的职业没在
> `NpcBot.WanderingBots.Continents.Classes` 里启用。

### 还有一层：等级分档

`botconfig.cpp:551` 默认：

```
NpcBot.WanderingBots.Continents.Levels = "20,15,15,10,10,15,15,0,0"
                                                              ^^^^
                                          70-79档 和 80+档 都是 0%
```

**我复现了分档算法（botdatamgr.cpp:635-647），数学上不丢**：
余数会补给最后一个非零档，500 -> `[100,75,75,50,50,75,75,0,0]` 合计正好 500。

**所以分档不是丢bot的原因**，但它决定了**生成出来的bot都是低等级的**。

### 修复方案（你选了"两个都要"）

**短期**：用 A30 的 SQL 批量造模板到 500+，并确认职业都启用
**长期**：改代码允许模板复用（一个模板生成多个实例）

## Bug 2：bot 站着不动，对中立目标原地索敌

### 根因：wanderer 的 `master` 指向自己

`bot_ai.cpp:459`：

```cpp
master = reinterpret_cast<Player*>(me);   // 无主bot的master指向Creature自己
```

而战斗走位逻辑 `bot_ai.cpp:18342-18364`：

```cpp
if ((IsWanderer() || ...) && !HasBotCommandState(BOT_COMMAND_STAY) && ...)
{
    Unit const* mover = me->GetVehicle() ? me->GetVehicleBase() : me;

    if (!master->IsAlive())          // <-- 【问题在这】
    {
        // 走"跟随主人尸体"的逻辑
        ...
    }
    else if (!IsCasting(mover) && ...)
    {
        Unit const* mmover = !IAmFree() ? master : nullptr;   // wanderer -> nullptr
        // 后面主要是【战场旗帜】逻辑，野外中立目标的接近逻辑很薄弱
    }
}
```

**两个问题**：

1. `master->IsAlive()` 对一个被强转成 `Player*` 的 `Creature` 调用——
   虽然 `IsAlive()` 不是虚函数（`Unit::IsAlive()`），不会崩，
   但语义是"bot自己活着吗"，恒为 true，所以永远走 else 分支

2. else 分支里 `mmover = nullptr`（因为 `IAmFree()`），
   然后大段代码是**战场专用**（BG旗帜），
   **野外遇到中立生物时缺少"走过去打"的分支**

### 为什么"打死中立怪它就走了"

因为它在 `AttackStart` 后进入战斗状态，但走位逻辑没让它靠近。
你帮它把目标清掉，它就恢复正常的路点移动。

### 修复方向

在 `bot_ai.cpp:18365` 的 else 分支里，
**给 wanderer 补一条"目标超出攻击距离就 MoveChase"的逻辑**。

**这个要改上游，风险中等，需要仔细做。**

## Bug 3：加载刷屏

### 根因：`Logger.root=4`（Debug级）兜底

你的 conf（`difficulty_adventure.conf:4006-4007`）：

```ini
Logger.root=4,Console Server        # 4 = Debug，所有没显式配置的logger都用它
Logger.server=3,Console Server      # 3 = Info
Logger.npcbots=2,NpcBots Server     # 2 = Warn
```

**`Logger.npcbots=2` 是对的**（Warn级，不输出 Debug）。

**但刷屏的那些日志用的是 `server.loading` 这个 logger**：

```cpp
// botdatamgr.cpp:1146
BOT_LOG_DEBUG("server.loading", ">> Spawned npcbot {} (id: {}, map: {}, grid: {}, cell: {})", ...);
```

`server.loading` 没有显式配置 -> **继承 `Logger.server=3`（Info）**
-> Debug 不该输出。

**但 `Logger.root=4` 会影响 appender 的过滤**，
而且 `Appender.Console=1,3,0,...` 是 Info 级。

### 实际要改的

```ini
# 加这一行，显式把加载日志压到 Info 以上
Logger.server.loading=3,Console Server
```

**或者更彻底**：把 `Logger.root` 从 4 改成 3。

> **我需要你确认**：刷屏的具体内容是什么？
> - 如果是 `>> Spawned npcbot XXX (id: ...)` 每bot一行 -> 上面的配置能解决
> - 如果是别的内容 -> 把刷屏的原文发我几行
