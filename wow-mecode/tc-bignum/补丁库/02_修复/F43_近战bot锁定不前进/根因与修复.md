# F43 · 近战游荡bot 锁定目标却站着不动

> 2026-08-09
> 用户：「游荡bot只要是近战攻击，低等级没有冲锋类和远程类技能
> 就只会锁定敌人，无论是不是中立，就算是敌方怪，
> 目标不是他他都只会在原地站着」

---

## 一、你描述的现象非常准确

关键词拆解：

| 你的描述 | 对应的技术含义 |
|---|---|
| 「只会锁定敌人」 | `me->Attack(target)` 成功了，有目标 |
| 「原地站着」 | 移动指令没下发，或下发了立刻被取消 |
| 「近战、低等级、没冲锋」 | 远程bot 不受影响（它们本来就站着打） |
| 「目标不是他」 | 目标没打 bot，所以 bot 不在"被攻击"状态 |

**这不是 F41 改的那个问题。** F41 修的是"拿不到移动目标"，
你这个是"拿到了目标但移动被拦下"。

---

## 二、真凶：三道拦截，近战全中

### 拦截1【主因】· `UpdateImpossibleChase` 提前返回

```cpp
// bot_ai.cpp:15689
bool bot_ai::UpdateImpossibleChase(Unit const* target)
{
    if (_chaseTimer > lastdiff || me->isMoving() || !IAmFree())
        return false;
    ...
    if (_unreachableCount < 5)
    {
        if ((IsRanged() ? me->GetDistance(target) > 40.0f : !me->IsWithinMeleeRange(target)) || ...)
        {
            ++_unreachableCount;
            ResetChaseTimer(target);
            BotMovement(BOT_MOVE_POINT, target, nullptr, false);   // :15711
        }
        else
            _unreachableCount = 0;

        return true;        // :15716  <<< 【关键】
    }
```

而它的调用方：

```cpp
// bot_ai.cpp:5566  在 GetInPosition 里
    if (UpdateImpossibleChase(newtarget))
        return;             // <<< 直接退出，后面的 MoveChase 永远走不到
```

**`:15716 return true` 让 `GetInPosition` 在 `:5567` 就退出了**，
`:5613` 那个真正的追击（`BOT_MOVE_CHASE`）**根本执行不到**。

#### `:15711` 那行为什么不管用

```cpp
BotMovement(BOT_MOVE_POINT, target, nullptr, false);
//                          ^^^^^^ Unit* 被隐式转成 Position*
```

能编译是因为 `WorldObject : public WorldLocation : public Position`。
但语义变成了「**走到目标此刻所在的那个点**」——

```
目标是活的会动     -> bot 走到旧位置，目标已经不在那了
generatePath=false -> 不寻路，遇到障碍就卡住
每次 tick 重算     -> 走走停停，看起来像"原地发呆"
```

**远程bot 为什么没事**：`IsRanged()` 分支判的是 `> 40.0f`，
40 码内直接进 else，`_unreachableCount = 0`，不触发这套逻辑。

**近战判的是 `!me->IsWithinMeleeRange(target)`** —— 只要不在近战距离内
就一直命中，一直走 `BOT_MOVE_POINT`，一直 `return true`。

### 拦截2 · `_chaseTimer` 对游荡bot 只有 5 秒

```cpp
// bot_ai.cpp:15732
_chaseTimer = IsWanderer() ? 5000 : 20000;
```

配合 `:15691 if (_chaseTimer > lastdiff ... ) return false;`，
游荡bot 每 5 秒才允许重新评估一次追击 —— 中间这 5 秒站着不动。

### 拦截3 · `:5560` 目标未进战斗就返回

```cpp
// bot_ai.cpp:5560
if ((!newtarget->IsInCombat() || (mover->isMoving())) && !force && !(_atHome && _evadeMode))
    return;
```

**F41 传的 `force=true` 能过这道**，所以这条不是主因，
但如果你没装 F41，这里也会拦。

## 三、修复（一处，最小改动）

**文件**：`D:\TrinityCore\src\server\game\AI\NpcBots\bot_ai.cpp`

搜索原文（`:5566-5567`，在 `GetInPosition` 里）：

```cpp
    if (UpdateImpossibleChase(newtarget))
        return;
```

替换为：

```cpp
    // F43: 近战游荡bot 锁定目标却站着不动的主因。
    //   UpdateImpossibleChase 在 :15716 无条件 return true，
    //   导致 GetInPosition 提前退出，:5613 的 BOT_MOVE_CHASE 永远走不到。
    //   而它内部用的 BotMovement(BOT_MOVE_POINT, target, nullptr, false)
    //   是"走到目标此刻的坐标"且不寻路，对会动的目标等于原地打转。
    //   这里让游荡近战bot 跳过它，直接走下面的正常追击逻辑。
    if (!(IsWanderer() && !IsRanged()))
    {
        if (UpdateImpossibleChase(newtarget))
            return;
    }
```

### 为什么这样改是安全的

| 谁受影响 | 行为变化 |
|---|---|
| 游荡近战bot | **跳过卡死逻辑，走正常 MoveChase** ← 目标群体 |
| 游荡远程bot | 不变（`IsRanged()` 为真，条件不成立） |
| 有主人的bot | 不变（`IsWanderer()` 为假） |

**`UpdateImpossibleChase` 的本意是"防止bot卡在够不到的目标上"**
（比如目标在悬崖上）。跳过它之后，游荡近战bot 改用
`:5613 BOT_MOVE_CHASE` —— 那是 MotionMaster 的标准追击，
自带寻路，本来就能处理够不到的情况。

## 四、可选增强：缩短评估间隔

如果改完还觉得反应慢，把追击计时器调短。

搜索原文（`:15732`）：

```cpp
    _chaseTimer = IsWanderer() ? 5000 : 20000;
```

替换为：

```cpp
    // F43: 游荡bot 5秒才重新评估一次追击，中间站着不动很明显。
    //   缩短到 1.5 秒，反应更自然。
    _chaseTimer = IsWanderer() ? 1500 : 20000;
```

> **建议先只装第三章那一处，测试后再决定要不要加这个。**
> 一次只改一个变量，出问题好定位。
