# step43 装完闪退：`Duplicate blank sub-command` —— 修复

> 报错原文：
> ```
> ChatCommand.cpp:39 in ...LoadFromBuilder ASSERTION FAILED:
>   !_invoker
> Duplicate blank sub-command.
> ```

---

## 一、先说结论：多半是我的安装说明写坑了你

**这个 ASSERT 的意思是：同一个命令名被注册了两次处理函数。**

```cpp
// ChatCommand.cpp:37-39
if (std::holds_alternative<ChatCommandBuilder::InvokerEntry>(builder._data))
{
    ASSERT(!_invoker, "Duplicate blank sub-command.");
    //     ^^^^^^^^^ 这个位置已经有处理函数了，又来一个 -> 崩
```

而 `step43/安装说明.md` 我是这么写的：

```
第 105 行： 在它下面加一行：
              AddSC_botrename_commandscript();

第 113 行： 改完长这样：
              AddSC_titles_commandscript();
              AddSC_wp_commandscript();
              AddSC_pbot_autoaccept();
              AddSC_botrename_commandscript();     <- 又出现一次
```

**如果你把「加一行」和「改完长这样」两处都照抄了，就会写成两遍。**

这是我文档的问题 —— 「改完长这样」本意是给你对照，不是让你再贴一次。
以后我会把对照块标成"仅供核对，不要复制"。

## 二、一条命令定位

在 **Git Bash** 里跑（把路径换成你的）：

```bash
grep -n "AddSC_botrename_commandscript\|AddSC_pbot_autoaccept" \
  /d/TrinityCore/src/server/scripts/Commands/cs_script_loader.cpp
```

### 正常应该是这样（每个函数各 2 行）

```
59:void AddSC_pbot_autoaccept();                    <- 声明
60:void AddSC_botrename_commandscript();            <- 声明
106:    AddSC_pbot_autoaccept();                     <- 调用
107:    AddSC_botrename_commandscript();             <- 调用
```

### 出问题是这样（调用出现两次）

```
59:void AddSC_botrename_commandscript();
106:    AddSC_botrename_commandscript();

```

**每个 `AddSC_xxx` 全文件应该正好出现 2 次**（1 声明 + 1 调用）。
出现 3 次或更多 = 重复注册 = 闪退。

也可以用我写的诊断脚本，一次性全查：


## 三、修复：删掉多余那行

打开 `cs_script_loader.cpp`，确保**整个文件**里：

```cpp
// ===== 声明区（59行附近）每个只能有一行 =====
void AddSC_wp_commandscript();
void AddSC_pbot_autoaccept();              // step42
void AddSC_botrename_commandscript();      // step43


// ===== 调用区（AddCommandsScripts 函数体内）每个也只能有一行 =====
void AddCommandsScripts()
{
    ...
    AddSC_wp_commandscript();
    AddSC_pbot_autoaccept();               // step42
    AddSC_botrename_commandscript();       // step43
}
```

**删掉任何重复的行**，然后重新编译（不用重跑 CMake）。

## 四、如果查完发现【没有】重复，那是另外三种原因

按可能性排序：

### 4.1 文件被复制了两份

比如 `cs_botrename.cpp` 同时存在于
`scripts/Custom/` 和 `scripts/Commands/` 两个目录。

CMake 会把两份都编进去 -> `new botrename_commandscript()` 执行两次。

**查法**：

```bash
find /d/TrinityCore/src -name "cs_botrename.cpp"
find /d/TrinityCore/src -name "cs_playerbot.cpp"
find /d/TrinityCore/src -name "pbot_autoaccept.cpp"
```

**每个文件应该只有 1 个结果。** 多的删掉。

> **为什么会崩**：`ScriptMgr.cpp:942 AddScript()` 只检查
> **指针**是否重复，**不检查名字**。两次 new 出来是两个不同指针，
> 都会被加进注册表，于是命令被注册两遍。

### 4.2 命令名和别的脚本撞了

`botname` 这个名字我查过上游没有占用：

```bash
grep -rn '"botname"' /d/TrinityCore/src/
```

**应该只有 `cs_botrename.cpp` 一处**。如果有两处，改掉其中一个名字。

### 4.3 旧的 .obj 没清干净

改动结构后 VS 有时会留着旧的目标文件。

**解决**：VS2022 里 `生成` -> `清理解决方案`，然后重新生成。

## 五、为什么 `.pbot` 装的时候没崩，这次崩了

因为 step42/43 是**一次装了三个文件**（`pbot_autoaccept.h/.cpp` +
`cs_botrename.cpp`），要往 `cs_script_loader.cpp` 加 **4 行**。

行数一多，就容易在「加一行」和「改完长这样」之间贴重复。

step40 那次只加 2 行，所以没踩到。

## 七、我这边的改进

这次的教训我记进坑表了：

> **安装说明里「改完长这样」的对照块，必须明确标注
> 「仅供核对，不要复制」**，否则用户会把「加一行」和
> 「完整样子」都贴进去，导致重复。

以后所有涉及"往已有列表里插入"的说明，我都会：

1. 只给**一处**可复制的代码块
2. 对照块加上 `<!-- 仅供核对，不要复制 -->` 标记
3. 附一条 `grep` 自检命令，让你贴完能立刻验证
