## 一、先说清楚：这次是我改错了，要撤回来

**step53 我判断反了。** 我让你注释掉的 `TryAcceptTrade`，
**正是唯一能让交易窗口弹出来的那行代码。**

你的现象「窗口完全没有 + 再点说已在交易中」，就是我删掉它的直接后果。

### 一句话根因

`TradeHandler.cpp:729`：

```cpp
    info.Status = TRADE_STATUS_BEGIN_TRADE;
    info.TraderGuid = _player->GetGUID();
    pOther->GetSession()->SendTradeStatus(info);
//  ^^^^^^ 收包的是 pOther = 【bot】，不是你
```

我 step53 看到 `HandleInitiateTradeOpcode` 里有 `BEGIN_TRADE`，
就以为是发给发起人的，**没看清收包对象是 `pOther`**。

真人交易是**两段式**的：

```
1) 你发起  -> 核心给【bot】发 BEGIN_TRADE  -> bot 客户端弹"是否交易"
2) bot 点接受 -> 发 CMSG_BEGIN_TRADE
            -> HandleBeginTradeOpcode 给【双方】各发 OPEN_WINDOW
            -> 两边窗口这才打开
```

bot 没客户端，第 1 步的包在 `WorldSession.cpp:211` 被丢弃，
它永远走不到第 2 步 -> **你的窗口也永远打不开**。

而你的 `m_trade` 已经建立了（`TradeHandler.cpp:724`），
所以再点交易被 `TradeHandler.cpp:611` 拦下 -> 「你已经在交易了」。

**`TryAcceptTrade` 干的事，就是替 bot 点那个"接受"按钮。**

> **附带说明**：step53 之前你说窗口不显示，其实是因为
> `PBOT_AUTO_TRADE` **默认是关的**，`TryAcceptTrade` 压根没被调用过。
> 我却把「开关没开」误判成「实现有错」，然后把对的代码删了。
> 这次一并把交易加进默认开关，省得你还要手动开。

## 三、这次改了什么

### 3.1 恢复 TryAcceptTrade 调用（2处）

OnUpdate 和 PBotForceAcceptAll 里各一处，都恢复了。

### 3.2 交易改为默认开启

`pbot_autoaccept.h`：

```cpp
PBOT_AUTO_DEFAULT   = PBOT_AUTO_GROUP | PBOT_AUTO_GUILD |
                      PBOT_AUTO_RESURRECT | PBOT_AUTO_SUMMON |
                      PBOT_AUTO_RELEASE | PBOT_AUTO_TRADE;   // <- 加了 TRADE
```

**为什么现在敢默认开**：`TryAcceptTrade` 只调 `HandleBeginTradeOpcode`
（=点"接受交易"），**从不调 `HandleAcceptTradeOpcode`**（=点"确认交易"）。

所以**最终确认那一下永远由你自己点**，它不会让你丢任何东西。
我在自检里专门加了一条断言确认这点。

> **重要**：默认开关只对**新 spawn 的 bot** 生效。
> 已经在线的 bot 是旧开关。**改完编译后请 `.pbot despawn 鲤鱼` 再 spawn 一次**，
> 或者手动 `.pbot auto 鲤鱼 trade on`。

### 3.3 新增：距离自愈（防卡死）

```cpp
if (!bot->IsWithinDistInMap(trader, TRADE_DISTANCE, false))
{
    bot->TradeCancel(true);
    _pbotTradeOpened.erase(bot->GetGUID());
    return;
}
```

**为什么需要**：官方只在**发起交易时**查距离（`TradeHandler.cpp:704`），
建立之后不再查，靠客户端主动发 `CMSG_CANCEL_TRADE`。

bot 没客户端不会发 -> 你走远了交易还挂着 -> `m_trade` 不释放
-> 再点交易被拦 -> **就是你现在遇到的卡死**。

现在 bot 会替你检查，超过 11.11 码自动取消。

API 已核实：
```

Object.h:420         IsWithinDistInMap(...)        public(356段)
Player.h:1191        TradeCancel(bool, TradeStatus) public(904段)
```

## 五、party1 刷屏 —— 根因找到了，但需要你确认来源

### 5.1 那句话是谁发的

「party1不在你的队伍中」= `ERR_TARGET_NOT_IN_GROUP_S`。

全服**只有两处**会发它（实查确认）：

```
GroupHandler.cpp:335   HandleGroupUninviteGuidOpcode 结尾
GroupHandler.cpp:381   HandleGroupUninviteOpcode 结尾
```

**两个都是"踢人"函数。** 也就是说：**有东西在不停地尝试踢队友。**

### 5.2 为什么找不到人

`party1` 不是名字，是魔兽客户端的**单位ID**（UnitID），
意思是"队伍里第1个成员"。

服务端拿这个字符串**按名字**去队伍里找（`Group.cpp:2854`）：

```cpp
ObjectGuid Group::GetMemberGUID(const std::string& name)
{
    for (...)
        if (itr->name == name)    // 拿 "party1" 和 "鲤鱼" 比
            return itr->guid;
    return ObjectGuid::Empty;      // 永远找不到
}
```

找不到 -> 回你一句「party1不在你的队伍中」。

**每个ID刷两次**：客户端有两个 uninvite opcode
（按名字的 / 按GUID的），某些插件两个都发。

**连着刷 party1~party4**：说明有东西在**遍历整个队伍**批量踢人。

### 5.3 我已排除的可能

**服务端 npcbot 模块不是凶手** —— 我 grep 了全仓库，
`SendPartyResult` 只在 `GroupHandler.cpp` 里被调用，
npcbot 模块（`src/server/game/AI/NpcBots/`）**一次都没调过**。
