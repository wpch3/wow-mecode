## 问题一：无法把 pbot 移出小队 —— 根因确定

### 根因（一行源码）

`Player.cpp:24268-24269`，在 `CanUninviteFromGroup()` 里：

```cpp
if (grp->IsLeader(guidMember))
    return ERR_NOT_LEADER;
```

**队长不能被踢出队伍。** 这是上游硬规则。

`.pbot spawn` 出来的 bot，如果队伍是它先建的、或者你邀请它时它成了队长，
右键菜单的「移出小队」就会被这行拦掉，**而且客户端不会给明显提示**，
看起来就像"点了没反应"。

### 完整拦截链（`Player.cpp:24225-24273`，已实查）

```text
24228  !GetGroup()                        -> ERR_NOT_IN_GROUP
24262  你不是队长也不是助理              -> ERR_NOT_LEADER
24265  在战场里                          -> ERR_INVITE_RESTRICTED
24268  【目标是队长】                    -> ERR_NOT_LEADER   <- 就是这个
```

### 立即可用的绕过办法（不用改代码）

**先把队长转给自己，再踢：**

```text
右键 bot 头像 -> 「设为队长」不行的话（bot 是队长时你没这个选项）
改用：右键【你自己】的头像 -> 提升为队长
      （只有队长能操作，所以如果 bot 是队长，你得让它先给你）
```

如果卡死了，最直接的是**你自己退队**：

```text
右键自己头像 -> 退出小队
```

队伍解散，bot 自然脱离。

### 根治：给 `.pbot` 加踢人指令

`.pbot` 现在只有 7 个子命令（已实查 `cs_playerbot.cpp`）：

```text
326  spawn   / 上线 / 召出
339  list    / 列表
373  despawn / 下线
406  come    / 过来 / 召唤
593  goto    / 去找 / 前往
655  auto    / 自动
794  accept  / 接受
```

**确实没有踢出队伍的指令。** 需要新增，见下文「改动一」。

## 问题二：交易被自动拒绝

### 先说清楚一件事

`TryAcceptTrade`（`pbot_autoaccept.cpp:365`）**只负责打开交易窗口，
不负责最终确认** —— 这是当初就这么设计的，代码注释和游戏内提示都写了：

```cpp
ChatHandler(trader->GetSession()).PSendSysMessage(
    "|cff00ff00[%s]|r 打开了交易窗口。|cffffff00（最终确认需要你自己点）|r",
    bot->GetName().c_str());
```

**所以如果你看到的是"窗口开了但成交不了"，那是预期行为，不是 bug。**

### 如果是"窗口根本弹不出来"，按这个顺序排查

上游 `TradeHandler.cpp:606-730 HandleInitiateTradeOpcode` 的**完整拒绝链**
（已逐行实查，按检查顺序）：

| 行号 | 条件 | 客户端提示 |
|---|---|---|
| 611 | 你已经在交易中（`m_trade` 非空） | **静默 return，什么都不显示** |
| 615 | 你死了 | YOU_DEAD |
| 622 | 你被击晕 | YOU_STUNNED |
| 629 | 你在登出 | YOU_LOGOUT |
| 636 | 你在飞行中 | TARGET_TO_FAR |
| 643 | 你等级低于 `CONFIG_TRADE_LEVEL_REQ` | 「需要等级 N」 |
| 653 | 找不到对方 | NO_TARGET |
| **660** | **对方 `m_trade` 非空（对方正在交易）** | **BUSY** |
| 667 | 对方死了 | TARGET_DEAD |
| 674 | 对方在飞行 | TARGET_TO_FAR |
| 681 | 对方被击晕 | TARGET_STUNNED |
| 688 | 对方在登出 | TARGET_LOGOUT |
| 695 | **阵营不同** 且 `CONFIG_ALLOW_TWO_SIDE_TRADE` 关 | WRONG_FACTION |
| **704** | **距离 > `TRADE_DISTANCE` = 11.11 码** | TARGET_TO_FAR |
| **711** | **Eluna `OnTradeInit` 返回 false** | **BUSY** |

### 我最怀疑的三个（按可能性排序）

**1. `:660` 对方 `m_trade` 残留 —— 最可能**

`_pbotTradeOpened` 这个 set 记录"已开过窗口"，但如果上次交易**异常中断**
（你直接关窗口 / bot 被 despawn / 你换地图），
bot 的 `m_trade` 可能没被清干净 -> 下次再交易就报 BUSY。

**验证方法**：`.pbot despawn` 再 `.pbot spawn`，重新召一次，然后立刻试交易。
如果这样就好了，那就是残留问题，见「改动二」。

**2. `:704` 距离超过 11.11 码**

比想象中近很多。**站到 bot 身上再试**。

**3. `:711` Eluna 钩子**

你这是 Eluna 版仓库。我查过 `lua_scripts/` 目录下 6 个脚本
（`bignum_selftest` / `custom_announce` / `custom_daily_reward` /
`custom_diag` / `custom_teleport` / `custom_welcome`），
**没有任何一个注册了交易事件**，所以这条大概率排除。

但如果你从别处装过 lua 脚本，检查一下有没有 `PLAYER_EVENT_ON_TRADE_INIT`。

## 改动一：给 `.pbot` 加踢人指令

文件：`D:\TrinityCore\src\server\scripts\Custom\cs_playerbot.cpp`
（或你实际放置的位置）

### 在 `accept` 分支后面加一个新分支

搜索原文（约 794 行）：

```cpp
        if (s0 == "accept" || tok[0] == "接受")
```

在这个 `if` **整个代码块结束之后**（找到它对应的闭合 `}`），插入：

```cpp
        if (s0 == "kick" || tok[0] == "踢出" || tok[0] == "移出")
        {
            Group* grp = player->GetGroup();
            if (!grp)
            {
                handler->SendSysMessage("|cffff0000 你不在队伍里|r");
                handler->SetSentErrorMessage(true);
                return false;
            }

            std::vector<ObjectGuid> toKick;
            for (PBotEntry const& e : g_pbots)
            {
                if (!grp->IsMember(e.CharGuid))
                    continue;
                if (tok.size() >= 2 && Lower(e.CharName) != Lower(tok[1]))
                    continue;
                toKick.push_back(e.CharGuid);
            }

            if (toKick.empty())
            {
                handler->SendSysMessage("|cffff0000 队伍里没有匹配的 pbot|r");
                handler->SetSentErrorMessage(true);
                return false;
            }

            uint32 kicked = 0;
            for (ObjectGuid guid : toKick)
            {
                if (grp->IsLeader(guid))
                {
                    grp->ChangeLeader(player->GetGUID());
                    handler->SendSysMessage("|cffffff00 bot 是队长，已把队长转给你|r");
                }
                Player::RemoveFromGroup(grp, guid, GROUP_REMOVEMETHOD_KICK, player->GetGUID(), "pbot kick");
                ++kicked;
            }

            char kbuf[128];
            snprintf(kbuf, sizeof(kbuf), "|cff00ff00 已把 %u 个 pbot 移出队伍|r", kicked);
            handler->SendSysMessage(kbuf);
            return true;
        }
```

**用法**：

```text
.pbot kick           踢出队伍里【所有】pbot
.pbot kick 角色名    只踢指定的那个
.pbot 踢出           中文同义词
```

### 关键点

```text
Group.h:211  void ChangeLeader(ObjectGuid guid)        public(185段)
Group.h:240  bool IsLeader(ObjectGuid guid) const      public(185段)
Player.h:1593 static void RemoveFromGroup(Group*, ObjectGuid, RemoveMethod, ObjectGuid, char const*)  public
```

**先 `ChangeLeader` 再踢**，这就绕过了 `Player.cpp:24268` 那道
「队长不能被踢」的检查 —— 因为踢的时候它已经不是队长了。

> 代码里用的 `g_pbots` / `PBotEntry` / `Lower()` / `player` 变量
> **都是你 `cs_playerbot.cpp` 里现成的**（照抄 `come` 分支 406-415 行的写法），
> 不需要新增任何辅助函数。
>
> 实查依据：
> ```text
> cs_playerbot.cpp:106   std::vector<PBotEntry> g_pbots;
> cs_playerbot.cpp:415   for (PBotEntry const& e : g_pbots)
> cs_playerbot.cpp:417   if (Lower(e.CharName) != Lower(tok[1]))
> ```

## 改动二：交易残留清理（如果确认是残留问题）

文件：`pbot_autoaccept.cpp`

### 在 `TryAcceptTrade` 开头加超时清理

搜索原文：

```cpp
static void TryAcceptTrade(Player* bot)
{
    TradeData* trade = bot->GetTradeData();     // Player.h:1190 public(904段)
```

替换为：

```cpp
static std::unordered_map<ObjectGuid, uint32> _pbotTradeOpenTime;

static void TryAcceptTrade(Player* bot)
{
    TradeData* trade = bot->GetTradeData();     // Player.h:1190 public(904段)

    // 交易窗口开了超过 60 秒还没结束 -> 强制取消，防止 m_trade 残留
    if (trade)
    {
        uint32 now = GameTime::GetGameTimeMS();
        auto oitr = _pbotTradeOpenTime.find(bot->GetGUID());
        if (oitr == _pbotTradeOpenTime.end())
            _pbotTradeOpenTime[bot->GetGUID()] = now;
        else if (now - oitr->second > 60000)
        {
            bot->TradeCancel(true);
            _pbotTradeOpened.erase(bot->GetGUID());
            _pbotTradeOpenTime.erase(oitr);
            return;
        }
    }
    else
        _pbotTradeOpenTime.erase(bot->GetGUID());
```

需要的 include（如果还没有）：

```cpp
#include "GameTime.h"
```

**先别急着装这个** —— 先按上面「验证方法」确认是不是残留问题。
如果 despawn/spawn 后交易正常，才需要这个补丁。

## 顺带查出的其它 pbot 隐患

### 1. `.pbot` 缺少的常用指令

现有 7 个：`spawn` `list` `despawn` `come` `goto` `auto` `accept`

**建议补充**（按实用度排序）：

| 指令 | 作用 | 难度 |
|---|---|---|
| `kick` / 踢出 | 移出队伍 | 本文档改动一 |
| `invite` / 邀请 | 主动拉进队伍（现在只能你邀请它自动接受） | 低 |
| `follow` / 跟随 | 跟着你走 | 中（G5 已有规划） |
| `stay` / 待命 | 停在原地 | 低 |
| `all` 批量后缀 | 对所有 pbot 生效 | 低 |

### 2. 队长归属问题（本次 bug 的根源）

`.pbot spawn` 后如果 bot 变成队长，很多操作都会失效，不只是踢人：
- 无法踢任何人（`:24262` 你不是队长）
- 无法设置副本难度
- 无法转换团队

**建议**：在 `TryAcceptGroup` 里加一句，接受邀请后主动把队长让给邀请人。
这个我可以下一步做。

### 3. 距离检查只在发起时做一次

`TradeHandler.cpp:704` 只在 `HandleInitiateTradeOpcode` 查距离，
交易过程中跑远了不会自动取消（F10 文档里已记录过这点）。
不影响功能，属于上游行为。
