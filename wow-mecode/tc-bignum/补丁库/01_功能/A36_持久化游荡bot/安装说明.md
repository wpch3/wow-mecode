# A36  持久化游荡bot —— 让有 spawnId 的 bot 也能游荡

> **【2026-08-05 重要：前置依赖，不做这步 SQL 会生效0个】**
>
> 用户实测「A36 的 SQL 不管 2.1 还是 2.2 都生效 0 个，70001/70002 都不行」。
>
> **根因**：A36 的 SQL 是
> `UPDATE world.creature SET ScriptName='wanderer' WHERE id BETWEEN ...`
> —— 它只能改**已存在于 `creature` 表**的行。
>
> 而游荡bot是**纯内存对象**（`botdatamgr.cpp:210` spawnId=0，
> `:460` 官方注释 `//We do not create CreatureData for generated bots`），
> **`creature` 表里根本没有它们** -> UPDATE 匹配 0 行。
>
> **必须先跑 A35**（把 bot 写进 `characters_npcbot` + `creature`），
> A36 才有东西可改。
>
> ```
> A35（进creature表变永久）-> A36（打wanderer标记让它游荡）-> 重启
> ```
>
> 这是我的文档错误：依赖原本写在第七章末尾，你按顺序执行走不到那里。


> 用户要求：「路线三也要实现，有spawnId的也能游荡，
> 但是指令召唤的不能受到影响，只影响我们创造的这些新bot」

**改动只有 1 处，10 行代码。所有 API 已实查确认。**

## 一、原理

### 现状：`bot_ai.cpp:246-250`

```cpp
void bot_ai::InitializeAI()
{
    if (!me->GetSpawnId() && !IsTempBot() && !me->IsSummon())
        SetWanderer();
    Reset();
}
```

**`spawnId == 0` 是成为游荡bot的唯一条件。**
写进 `creature` 表就有了 spawnId -> 永久失去游荡能力。

### 改法：加一条「显式标记」通道

```
creature.ScriptName = "wanderer"   -> 这个固定bot【也要游荡】
ScriptName = 空 / 其它             -> 完全不变（官方 spawn 的bot不受影响）
```

**为什么用 ScriptName**：
- NPCBot 走 `bot_ai` 不走 ScriptName，**这字段对bot无副作用**
- 纯数据驱动，不用新建表
- step49 验证过这个做法

### 改成

```cpp
void bot_ai::InitializeAI()
{
    // A36: 原判断只有 !me->GetSpawnId() —— spawnId==0 才是游荡bot。
    //   这导致「写进creature表变永久」和「会游荡」互斥：
    //   一旦落库就有了 spawnId，bot 永远站桩不动。
    //
    //   现在增加一条通道：creature.ScriptName == "wanderer" 的固定bot
    //   也进入游荡状态。这样持久化和游荡不再冲突。
    //
    //   【只影响显式标记的bot】官方 .npcbot spawn 出来的 ScriptName 是空，
    //   scriptId==0，走不进下面那个分支，行为完全不变。
    //
    //   SpawnData.h:101      uint32 scriptId
    //   Creature.h:202       GetCreatureData()          public(78段)
    //   ObjectMgr.h:1508     GetScriptId(std::string const&)  public(947段)
    bool wantWander = !me->GetSpawnId();

    if (!wantWander)
    {
        if (CreatureData const* cdata = me->GetCreatureData())
        {
            static uint32 const wandererScriptId = sObjectMgr->GetScriptId("wanderer");
            if (cdata->scriptId != 0 && cdata->scriptId == wandererScriptId)
                wantWander = true;
        }
    }

    if (wantWander && !IsTempBot() && !me->IsSummon())
        SetWanderer();

    Reset();
}
```

`bot_ai.cpp` 已经 include 了 `ObjectMgr.h` 和 `CreatureData.h`（通过 Creature.h）。
**不用加 include**，但编译时如果报错告诉我。

## 三、五项风险实查结果

| # | 风险 | 实查结论 |
|---|---|---|
| 1 | 路点初始化会不会空指针 | **安全**。`bot_ai.cpp:14897` `if (IsWanderer()) { _travel_node_cur = ASSERT_NOTNULL(GetClosestWanderNode()); }` —— 设成 wanderer 后自动分配最近路点 |
| 2 | `scriptId` 存的是什么类型 | `SpawnData.h:101 uint32 scriptId`，用 `GetScriptId("wanderer")` 比对 |
| 3 | `GetScriptId` 能不能用 | `ObjectMgr.h:1508` **public(947段)**，签名 `uint32 GetScriptId(std::string const& name)` |
| 4 | **死亡respawn会回原点** | **会**。`Creature.cpp:2807` `if (m_creatureData) m_creatureData->spawnPoint.GetPosition(...)` —— 有 creature 记录就用表里的坐标 |
| 5 | pool 系统干扰 | `Creature.cpp:2271` 只在 `sPoolMgr->IsPartOfAPool()` 时生效，我们不用 pool，无影响 |

### 关于第 4 条（唯一的行为差异）

**bot 死了复活会回到 creature 表记录的坐标，而不是死亡地点。**

- 对**游荡bot**（spawnId=0）：`m_creatureData` 是 null，走 `GetHomePosition()`
- 对**A36的bot**（有spawnId）：走 creature 表的 `spawnPoint`

**这其实不算坏事** —— 相当于每个持久化游荡bot有个"家"，
死了回家，然后从家开始重新游荡。

**如果你不想要这个行为**，可以把 `spawntimesecs` 设大一点，
或者后续我们再改 `GetRespawnPosition`。

## 四、SQL：给bot打上 wanderer 标记

见同目录 `sql/给固定bot开启游荡.sql`。

核心就一句：

```sql
UPDATE `world`.`creature`
SET `ScriptName` = 'wanderer'
WHERE `id` BETWEEN <起始entry> AND <结束entry>;
```

**注意**：`ScriptName` 要写进 `creature` 表（每个 spawn 单独设），
不是 `creature_template`。
