## 一、这是我的错：改错函数了

系统里有**两个独立的挑台词函数**，我只改了其中一个。

| 函数 | 读哪张表 | 什么时候用 | A42第2步改了吗 |

| `PickGiftText` | `npcbot_gift_text` | **你给它东西时** | **没改** ← 问题在这 |

**你给 bot 东西 -> 走 `PickGiftText` -> 那个函数只认 `botClass`，
根本不看 `bot_race`。** 所以种族台词永远选不中。

而我在 A42 第2步给 `npcbot_gift_text` 表**加了 `bot_race` 字段、也插了种族台词**，

## 二、"谢谢太多"是另一个问题：三层回退把台词池缩小了

`PickGiftText` 的三层回退（`:230-246`）：

```cpp
// 第1层：职业专属
if (... && t.BotClass == botClass) pool.push_back(&t);

// 第2层：职业通用
if (pool.empty())
    for (...) if (... && t.BotClass == 0) pool.push_back(&t);

// 第3层：万能兜底 —— 【问题在这】
if (pool.empty())
    for (CompanionGiftText const& t : _giftTexts)
        if (t.ItemKind == 7 && t.ReactType == reactType && t.BotClass == 0)
            pool.push_back(&t);
```

**第3层只按 `item_kind == 7`（通用）筛**，
如果你给的东西（比如食物 kind=1）在前两层没匹配到，
就会落到第3层那一小撮"通用感谢"里反复抽 —— 所以你觉得"谢谢太多"。

**不是羁绊不够。** 羁绊只影响 `bondTier`，而 `bondTier == 0` 的台词对所有档位都匹配。

### 改动4 · `bot_companion.cpp` 换成评分匹配

搜索原文（`PickGiftText` 的整个函数，约 `:223`）：

```cpp
CompanionGiftText const* BotCompanionMgr::PickGiftText(uint8 itemKind, uint8 needState,
                                                       uint8 bondTier, uint8 reactType, uint8 botClass) const
```

**把整个函数替换为**：

```cpp
// A42第2步修复：加种族维度 + 改评分匹配
//   原来是三层 if 回退，第3层只认 item_kind==7，
//   导致大部分情况都落到那一小撮"通用感谢"里 -> 用户反馈"谢谢太多"。
//   改成评分制后，item_kind 匹配的台词优先级最高，池子大得多。
//
//   评分：物品种类+40 / 反应类型+30 / 职业+20 / 种族+10 / 需求状态+5 / 羁绊档+5
CompanionGiftText const* BotCompanionMgr::PickGiftText(uint8 itemKind, uint8 needState,
                                                       uint8 bondTier, uint8 reactType, uint8 botClass,
                                                       uint8 botRace/* = 0*/) const
{
    int bestScore = -1;
    std::vector<CompanionGiftText const*> pool;

    for (CompanionGiftText const& t : _giftTexts)
    {
        // ---- 硬性条件：反应类型必须一致（收下/当场用/拒绝）----
        if (t.ReactType != reactType)
            continue;

        // ---- 物品种类：要么精确匹配，要么是通用(7)----
        if (t.ItemKind != itemKind && t.ItemKind != 7)
            continue;

        // ---- 指定了就必须对上，没指定(0)则不限 ----
        if (t.BotClass  != 0 && t.BotClass  != botClass)  continue;
        if (t.BotRace   != 0 && t.BotRace   != botRace)   continue;
        if (t.NeedState != 0 && t.NeedState != needState) continue;
        if (t.BondTier  != 0 && t.BondTier  != bondTier)  continue;

        // ---- 打分 ----
        int score = 0;
        if (t.ItemKind  == itemKind)  score += 40;   // 精确种类 > 通用
        if (t.BotClass  != 0)         score += 20;
        if (t.BotRace   != 0)         score += 10;
        if (t.NeedState != 0)         score += 5;
        if (t.BondTier  != 0)         score += 5;

        if (score > bestScore)
        {
            bestScore = score;
            pool.clear();
            pool.push_back(&t);
        }
        else if (score == bestScore)
            pool.push_back(&t);
    }

    if (pool.empty())
        return nullptr;

    uint32 total = 0;
    for (CompanionGiftText const* t : pool)
        total += t->Weight;

    if (!total)
        return pool[0];

    uint32 roll = urand(0, total - 1);
    for (CompanionGiftText const* t : pool)
    {
        if (roll < t->Weight)
            return t;
        roll -= t->Weight;
    }

    return pool.back();
}
```

## 六、关于"羁绊不够熟悉"

**不是这个原因。** 解释一下机制：

```
bondTier:  1=生疏(0-1)  2=熟悉(2-3)  3=深交(4-5)
```

台词的 `bond_tier = 0` 表示**任意档位都匹配**。
我 A42 插的种族台词全部是 `bond_tier=0`，所以生疏时也该出现。

真正的原因就是上面说的：**`PickGiftText` 根本没读 `bot_race`**。

如果你想看羁绊分档的效果，可以查一下当前羁绊值：

```sql
SELECT `bot_id`, `owner_guid`, `bond_level`, `time_together`, `gifts_to_bot`
FROM `characters`.`npcbot_bond`
ORDER BY `bond_level` DESC
LIMIT 10;
```
