## 一、真凶：上游【故意】对客户端隐藏了 GOSSIP 标记

`Unit.cpp:14534-14537`，注释写得明明白白：

```cpp
//npcbot: make wandering bots non-interactive for non-GM players
if ((appendValue & UNIT_NPC_FLAG_GOSSIP) && !target->IsGameMaster() && IsNPCBotOrPet() && creature->IsWandererBot())
    appendValue &= ~UNIT_NPC_FLAG_GOSSIP;
//end npcbot
```

### 这段代码在做什么

它在 `BuildValuesUpdate` 里 —— **服务端往客户端发送字段更新的地方**。

```
服务端内部：  bot 确实有 UNIT_NPC_FLAG_GOSSIP     <- 所以 .bd 显示"有标记"
发给客户端：  这一位被抹掉                        <- 所以客户端不认为它可交互
客户端表现：  鼠标不变手，右键无反应
```

**鼠标光标由客户端根据 `UNIT_NPC_FLAGS` 决定。
客户端收到 0，就当它是路人 NPC。**

```cpp

                // step39: 开了 NpcBot.WanderingBot.AllowHire 时不再隐藏，

                    appendValue &= ~UNIT_NPC_FLAG_GOSSIP;
                //end npcbot
```

**只是在条件末尾加了 `&& !BotCfg::IsWanderingBotHireEnabled()`。**

## 六、这次的教训（重要）

### 用户的一句话解决了我五轮没解决的问题

> 「甚至鼠标都没有转换可交互的提示」

**鼠标光标是纯客户端行为**。这句话直接说明：
问题在"服务端发给客户端的数据"，不在"服务端的处理逻辑"。

我前面五轮全在查处理逻辑（`OnGossipHello` 里的各种拦截），
**方向从一开始就错了。**

### 提炼

**区分"服务端内部状态"和"客户端收到的状态"。**

- `.bd` 报告的是前者
- 玩家看到的是后者
- 中间隔着 `BuildValuesUpdate` 的过滤层

**以后遇到"服务端看着正常，客户端没反应"，
第一个要查的就是 `BuildValuesUpdate` 里有没有针对性过滤。**
