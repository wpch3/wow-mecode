## 问题2：`_pbotTradeOpened` 未声明（386 行）

### 报错

```text
C2065 "_pbotTradeOpened": 未声明的标识符   pbot_autoaccept.cpp 386
```

386 行还残留着对它的引用。**F11 已经删了这个变量**，
所以任何用到它的代码都要清掉。

### 修法

打开 `pbot_autoaccept.cpp`，跳到 **386 行**附近，
找到含 `_pbotTradeOpened` 的那一行（或那几行），**整行删掉**。

常见的残留形态有两种：

```cpp
        _pbotTradeOpened.erase(bot->GetGUID());     // 删掉这行
```

```cpp
    if (_pbotTradeOpened.count(bot->GetGUID()))      // 这两行一起删
        return;
```

### 删完自检

`Ctrl+F` 搜 `_pbotTradeOpened`，**应该是 0 个结果**。

## 问题3：`C1069 无法读取编译器命令行`

### 这不是代码错误

```text
C1069 无法读取编译器命令行   pbot_autoaccept.cpp 740
C1069 无法读取编译器命令行   cs_playerbot.cpp 1162
```

这是 MSVC 的**构建系统错误**，通常由前面的真错误（C2065）连带引起 ——
编译器在处理错误时中断了。

**先修好问题1和问题2，这个大概率自动消失。**

如果修完还报 C1069：

```text
1. 关掉 VS，删除 D:\TC-Build 下的 .vs 隐藏文件夹
2. 重新打开解决方案 -> 生成 -> 重新生成解决方案
```

`MapDefines.h:48 E0065 应输入";"` 那条也是同类 ——
**E0065 是 IntelliSense 报的（不是编译器）**，前面有错时经常误报，
修好真错误后会消失。

## 教训

`.cpp` 里定义的枚举/常量/静态函数**只有该文件可见**。
只要有第二个文件要用，就必须放头文件。

**规则**：设计跨模块共用的类型时，第一反应就该放 `.h`，
不能等到第二个文件要用时才发现。
