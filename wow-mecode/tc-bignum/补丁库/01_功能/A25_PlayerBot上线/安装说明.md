## 一、改动 1：给 WorldSession 加一个 public 方法（门2）

### 为什么需要

```cpp
// WorldSession.h:1285
bool IsLegitCharacterForAccount(ObjectGuid lowGUID)
{
    return _legitCharacters.find(lowGUID) != _legitCharacters.end();
}
```

`_legitCharacters` **只在客户端请求角色列表时填充**。
bot 没有客户端 -> 集合为空 -> 登录时被 `CharacterHandler.cpp:700` 拒绝。

### 改法【已修正】

> **上一版我说"加在 IsLegitCharacterForAccount 下面"是错的。**
> 那个函数在 `WorldSession.h:1274` 起的 **private 段**里，
> 加在那儿会报 `C2248 无法访问 private 成员`。
> 我犯了自己记在坑表里的错：**grep 到行号就当 public**。

**必须加在 public 段。Ctrl+F 搜**（`WorldSession.h:577`）：

```cpp
        void QueuePacket(WorldPacket* new_packet);
        bool Update(uint32 diff, PacketFilter& updater);
```

**在 `QueuePacket` 这一行上面加**：

```cpp
        // step40: PlayerBot 需要手动把角色加进白名单。
        // 正常玩家在请求角色列表时填充，bot 没有客户端所以要手动加。
        // 【必须放 public 段】—— IsLegitCharacterForAccount(1285行) 在 private 段，
        // 加在它旁边会导致 C2248。
        void AddLegitCharacter(ObjectGuid guid) { _legitCharacters.insert(guid); }
```

改完应该长这样：

```cpp
        bool DisallowHyperlinksAndMaybeKick(std::string const& str);

        // step40: PlayerBot 需要手动把角色加进白名单。
        void AddLegitCharacter(ObjectGuid guid) { _legitCharacters.insert(guid); }

        void QueuePacket(WorldPacket* new_packet);
        bool Update(uint32 diff, PacketFilter& updater);
```

**为什么这样可以**：`_legitCharacters` 是 private 成员，
但这个方法本身是**类的成员函数**，访问自己的私有成员完全合法。
关键是**方法本身要是 public**，外部才能调。

# 【本轮追加】come 落地修复 + goto 新指令

> 2026-08-04
> 你的反馈：「能传送不过是传送到tp的传送点，只是加一个可以传送到我身前的」

## 一、这不是缺功能，是一个必现 BUG

我先说清楚**你看到的现象为什么会发生**，因为病根和表面症状不是一回事。

### 真人玩家的传送是【两步】

```
第1步  服务端 TeleportTo()  ->  只是【发个包】给客户端，坐标【没变】
第2步  客户端收到后回 ACK   ->  服务端在 ACK 里【才真正改坐标】
```

实证（Player.cpp:1660，同地图分支）：

```cpp
// code for finish transfer called in WorldSession::HandleMovementOpcodes()
// at client packet MSG_MOVE_TELEPORT_ACK
SetSemaphoreTeleportNear(IsMovedByClient());
```

实证（Player.cpp:1793，跨地图分支）：

```cpp
// move packet sent by client always after far teleport
// code for finish transfer to new map called in WorldSession::HandleMoveWorldportAckOpcode at client packet
SetSemaphoreTeleportFar(true);
```

**两条分支的结尾都是"挂起，等客户端回话"。**

### bot 没有客户端

所以 ACK **永远不会来**，传送**永远停在第1步**，
bot 的坐标**压根没被改过** —— 它还在原地。

你看到它"在传送点"，是因为它**从登录那一刻起就没动过**。

### 为什么 bot 也会被判定成"要等客户端"

我一开始以为 bot 的 `IsMovedByClient()` 应该是 false，实查发现**不是**：

```
WorldSession.cpp:157   _gameClient(new GameClient(this))   <- 每个会话都 new，bot 也有
Player.cpp:22776       GetGameClient()->SetMovedUnit(this, true);   <- 登录时挂上
Unit.h:1312            bool IsMovedByClient() const { return _gameClientMovingMe != nullptr; }
```

**bot 会话也有 GameClient 对象**，所以 `IsMovedByClient()` 返回 **true**，
信号量被置上，然后永远没人来清 —— 死锁。

## 四、改了什么

### 1. 落点：从"脚底下"改成"身前2码，且面朝你"

旧版：

```cpp
float x, y, z;
player->GetClosePoint(x, y, z, p->GetCombatReach());
p->TeleportTo(player->GetMapId(), x, y, z, player->GetOrientation());
```

`GetClosePoint` 的 relAngle 默认 0、distance2d 默认 0，
距离只有 `size`(战斗触及范围)，**几乎和你重叠**，而且朝向和你一样（背对你）。

新版：

```cpp
Position dest = player->GetFirstCollisionPosition(PBOT_COME_DIST, 0.0f);
float o = dest.GetAbsoluteAngle(player->GetPositionX(), player->GetPositionY());
```

- `GetFirstCollisionPosition`（Object.h:370）会做 **raycast**，
  保证不会卡进墙里或掉到地板下（内部走 `MovePositionToFirstCollision`，Object.cpp:3574）
- 距离 `PBOT_COME_DIST = 2.0f` 码 —— 一个身位，正好面对面
- `GetAbsoluteAngle` 让它**转过来看着你**，而不是背对你

### 2. 补 ACK：让传送真正落地【核心】

```cpp
if (p->IsBeingTeleportedFar())
{
    uint8 guard = 0;
    while (p->IsBeingTeleportedFar() && guard++ < 5)
        p->GetSession()->HandleMoveWorldportAck();
}
else if (p->IsBeingTeleportedNear())
{
    p->SetSemaphoreTeleportNear(false);
    ... 照抄 MovementHandler.cpp:356 的完整收尾 ...
}
```

`guard < 5` 是**死循环保护**：万一 `HandleMoveWorldportAck` 内部
传送失败又跳 homebind，不至于卡死主线程。官方没加这个保护，我加了。

### 3. 新增 `.pbot goto` —— 你过去找它

```
.pbot goto <角色名>      /  .pbot 去找 <角色名>
```

**这条比 come 安全得多**，因为移动的是**你自己**（真人有客户端会回 ACK），
走完全原生的路径，不需要任何补 ACK。

> 【教训来源】step35 那个坑：`.bf come` 移动被观察者，
> 制造了原本不存在的 bug，花了 4 轮排查自己造的问题。
> **移动观察者比移动被观察者安全。**
