## 一、你说对了我之前没讲清的事

游荡bot 和 `.npcbot spawn` 出来的永久bot，**用的是同一批模板**。

区别只有一个：**这个 entry 有没有进 `characters_npcbot` 表**。

### 实证（`botdatamgr.cpp:316-326`，服务器启动时）

```cpp
for (auto const& [id, extras] : _botsExtras)          // 遍历 npcbot_extras
{
    uint8 c = extras.bclass;
    if (c != BOT_CLASS_NONE && BotCfg::IsWanderingClassEnabled(c))
    {
        ++enabledBotsCount;
        if (!_botsData.contains(id))                  // <-- 【关键】
        {
            _spareBotIdsPerClassMap.at(c).insert(id); // 才进游荡池
        }
    }
}
```

`_botsData` = `characters_npcbot` 表的内存镜像。

**所以规则就是**：

```
extras有 + characters_npcbot【没有】  ->  进游荡池，每次重启洗牌
extras有 + characters_npcbot【有】    ->  不进游荡池，永久bot
```

**往 `characters_npcbot` 写一条，它就自动退出游荡池。**
这正是 `.npcbot spawn` 做的事（`botcommands.cpp:3860`）。

## 二、澄清：我之前说"必须复制到新entry"是错的一半

**要分清两种 entry**：

| | entry 是什么 | 能持久化吗 |
|---|---|---|
| **你库里的bot模板**（70001-70500等） | `creature_template` 里的**真实记录** | **能** |
| **运行时生成的游荡实例**（80770等） | `_botsExtraCreatureTemplates` **内存临时对象** | **不能** |

`botdatamgr.cpp:379-386`：

```cpp
while (all_templates.contains(++next_bot_id));      // 找个没用过的id，如 80770
const auto [bot_class, orig_entry] = spareBotPair;  // orig_entry = 你库里的真实模板
CreatureTemplate& bot_template = _botsExtraCreatureTemplates[next_bot_id];
bot_template = *orig_template;                       // 复制
bot_template.KillCredit[0] = orig_entry;             // 记住本体
```

**你在游戏里看到的 `Llane (80770)` 是临时副本**，
它的本体是你库里某个真实 entry。

**`.pin` 错在试图固定临时副本 80770。
正确做法是固定它的本体。** 而固定本体只需要一条 INSERT。

## 三、批量能力

**能，纯 SQL，上千条没问题。**

核心就两句：

```sql
-- 1. 让它退出游荡池
INSERT INTO characters.characters_npcbot (entry, owner, roles, spec, faction) SELECT ...

-- 2. 给它一个站立位置
INSERT INTO world.creature (guid, id, map, position_x, ...) SELECT ...
```

### 硬约束：两张表必须同时写

`botdatamgr.cpp:1170-1176` 启动交叉校验：

```cpp
if (creature表有bot but characters_npcbot没有)
    report_inavlid_ids("Invalid NPCBot spawns found in `creature` table having no data in `characters_npcbot` table!");
    // -> ABORT_MSG 崩服
```

**反过来（characters_npcbot有、creature没有）不崩**，只是 bot 不出现。

**所以顺序应该是：先写 characters_npcbot，再写 creature。**
中途出错也不会崩服。

**但你这一问帮我抓到了真 bug** —— 见下。

### 你的提问抓出的问题

我去验证那两段被注释的 SQL 时发现，**旧版 2.3（现 2.2）有 4 个逻辑缺陷**：

```sql
-- 旧版用用户变量生成行号
SELECT ..., (@i := IFNULL(@i, 0) + 1) AS rowno FROM ... ORDER BY ...
```

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | `@i` / `@j` 跑完不重置 | 第二次执行行号接着累加 -> JOIN 不上 -> **插入 0 条** |
| 2 | MySQL 8.0 起 SELECT 里的变量赋值已弃用，**不保证求值顺序** | 行号和 ORDER BY 顺序可能对不上 |
| 3 | 派生表里的 `ORDER BY` **会被优化器忽略**（8.0.21+ 明确行为） | 位置分配变成随机 |
| 4 | 两个子查询 LIMIT 不对称（t 没有、w 有 10） | 多出来的行**静默丢失** |

**已改用 `ROW_NUMBER() OVER (ORDER BY ...)`** —— MySQL 8.0+ 原生窗口函数，
无副作用、顺序有保证、跑几次结果都一样。

**这个 bug 如果不是你问，会在你取消注释执行时才炸。**

### 工具已升级

`tools/check_sql.py` 新增第 6 项检查：
**把被注释的 SQL 块还原后同样做真解析**。

以前的 5 项只检查未注释的部分 —— 注释掉的代码是检查盲区，
而用户取消注释就会执行它。

## 八、注意事项

### 8.1 固定后的 bot 不会游荡

SQL 里 `MovementType=0`（IDLE）+ `wander_distance=0`，
**它们会站在原地不动**。

想让它们小范围溜达：把 `wander_distance` 改成 5-10。

### 8.2 会减少游荡池

你固定多少个，游荡池就少多少个。

如果配置里 `Npcbot.WanderingBots.Continents.Count` 设的数量
超过剩余池子大小，**启动会 ASSERT 崩服**（`botdatamgr.cpp:1887`）。

**所以固定之后要把那个配置调低。** SQL 第一部分的查询3会告诉你池子还剩多少。

### 8.3 不要碰 `owner > 0` 的记录

那些是玩家真正招募的 bot，动了会出问题。
SQL 里所有操作都带了 `owner = 0` 的条件。
