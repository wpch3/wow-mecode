# step25 血量参数扩容 —— 安装说明

## 一、承接 step24，修剩下的一半

step24 修好了 `ModifyHealth` 的**内部计算**，你实测确认：

- 治疗不会死了 是
- 致死伤害仍能杀死 是
- 血量超上限正确钳制 是

但你发现**还有一层**：

> 耐力提升到四亿后，就会变成一个血量缓慢上升的状况，
> 恢复到21亿和使用了治疗就死了，变不成40亿血，根本测试不了40亿血量的情况

**根因：step24 只改了函数内部，参数还是 `int32`。**

```cpp
int32 ModifyHealth(int32 val);     // ← 参数 int32，治疗量本身被截断
                  ^^^^^
```

血量上限 40 亿没问题，但**每次能回多少被卡在 int32**：

- 回血量 / 治疗量超过 21.47 亿 → 强转成负数 → `val <= 0` → 暴毙
- 所以只能靠**自然回血一点点涨**（每次几百点），涨到 21 亿附近就出事

## 二、这次改了什么（11 处）

| 文件 | 改动 |
|---|---|
| `Unit.h:929-930` | `ModifyHealth` / `GetHealthGain` 参数+返回值 → `int64` |
| `Unit.cpp` | 两个函数定义签名同步 → `int64`，去掉内部 `(int32)` 回转 |
| `Unit.cpp` DealHeal | `gain` → `int64`；**`OnHeal` 的 `(uint32&)gain` 改用临时变量转接** |
| `Unit.cpp:967` | `ModifyHealth(-(int32)damage)` → `-(int64)damage` |
| `Player.cpp:2109` | `ModifyHealth(int32(addValue))` → `int64(addValue)` |
| `Unit.cpp` 顶部 | 加 `#include <limits>` |

### 为什么 OnHeal 那行必须特殊处理

原代码：

```cpp
sScriptMgr->OnHeal(healer, victim, (uint32&)gain);
```

`gain` 改成 `int64` 后，`(uint32&)` 强转引用会**按小端只读低 4 字节**，
大数值下读出完全错误的值。实测验证：

```
int64 gain = 0x0000000100000005;
uint32 wrong = *(uint32*)&gain;    // 读出 5，高位丢失
```

改成临时变量转接：

```cpp
uint32 gainForHook = (gain > 0)
    ? uint32(std::min<int64>(gain, std::numeric_limits<uint32>::max()))
    : 0u;
sScriptMgr->OnHeal(healer, victim, gainForHook);
gain = int64(gainForHook);
```

## 四、编译可能遇到的情况

改了 `Unit.h` 的公开签名，如果有第三方模块/脚本直接引用了
`int32 ModifyHealth(int32)`，可能报类型不匹配。

**已验证的 28 个官方调用点全部兼容**（int32 隐式提升到 int64），
测试覆盖了所有真实调用形态：

```
me->ModifyHealth(-5)                            字面量
ModifyHealth(int32(CountPctFromMaxHealth(3)))   int32 强转
ModifyHealth(-(int32)damage)                    负 int32
ModifyHealth(-std::min<int32>(a, b))            模板推导
ModifyHealth(missingHealth)                     int32 变量
std::max<int32>(1 - GetHealth(), amt)           混合表达式
uint32(-GetHealthGain(-damage) * mult)          生命偷取
```

如果编译报错，把**第一条 error** 发我。
