# step23 `.dummy` 打木桩 —— 安装说明

## 一、这个指令解决什么问题

普通服打木桩就是看个 DPS 数字，可有可无。**但本服不一样**——`stat_value` 扩到 21 亿后，
会撞上一批**静默溢出**：不报错、不崩服、不写日志，数字直接变负或归零。

你已经实测撞到两个：

| 现象 | 根因 | 源码 |
|---|---|---|
| 耐力堆高 → 血量变 0 | 耐力 ×10 进血量，`SetMaxHealth((uint32)v)` 上限 42.9 亿 | `StatSystem.cpp GetHealthBonusFromStamina()` |
| 力量堆高 → 攻强变负数 | `SetAttackPower(int32(v))`，x86-64 溢出返回 **INT_MIN** | `StatSystem.cpp UpdateAttackPowerAndDamage()` |

第二个尤其阴：客户端面板显示 `-2147483648`，同时服务端 `Unit.cpp:9754` 有
`if (ap < 0) return 0.0f`，**伤害直接掉回白板**。两件事同时发生。

`.dummy` 就是用来**提前发现**这类问题的——按你说的：

> 最重要的不是服务端给的数据更改，而是客户端里的实际情况

所以诊断面板**不做理论推算**，而是把 `UNIT_FIELD_*` 的**实际存储值**读回来对比。

## 二、指令

| 命令 | 作用 |
|---|---|
| `.dummy` | 召唤木桩并开始统计 |
| `.dummy stop` | 结束并出报告 |
| `.dummy clear` | 清掉木桩（不出报告） |
| `.dummy armor <值>` | 设木桩护甲，模拟不同目标 |
| `.dummy check` | **只看属性溢出诊断，不用打** |

中文别名：`结束` / `清除` / `护甲` / `检查`

| 属性 | 倍率 | 卡在 | 安全上限 | 你现在 |

### 精神为什么"恐怖"

```
StatSystem.cpp:960  power_regen = std::sqrt(Intellect) * OCTRegenMPPerSpirit();
Player.cpp          OCTRegenMPPerSpirit(){ return spirit * moreRatio->Data; }
```

**它和智力相乘**，不是独立的。你智力1.2亿 -> sqrt≈10954 x 精神122 = 22444，
反推系数 0.0168，与实测完全吻合。**精神只要 1 万，回复就到 184 万/5秒**。

诊断分四档：`安全 < 60% <= 注意 < 85% <= 危险 < 100% <= 已溢出`

## 六、实现里两个关键决定

### 1. 统计钩子挂在单一汇聚点，零侵入

```
ScriptMgr.h:397   virtual void OnDamage(Unit* attacker, Unit* victim, uint32& damage)
Unit.cpp:756      sScriptMgr->OnDamage(attacker, victim, damage);   <- 在 DealDamage 内
```

近战 / 法术 / DOT **全部经过这一行**，所以不用改任何现有代码。

`UnitScript` 是 **code-only script**（`ScriptMgr.cpp:941` 注释
"Adds a non database bound script"），`new` 一下就生效，不需要在 DB 里配 ScriptName。

> 顺带一提：这个仓库里**没有任何 UnitScript 子类**，我们是第一个用的，
> 所以注册路径是我逐行核实的，没有先例可抄。

### 2. 累计伤害必须 `uint64`

`DealDamage` 单次是 `uint32`（上限 42.9 亿），但你每击约 1.88 亿——
**打 23 下总量就超 42.9 亿**。用 `uint32` 累计会回绕成小数字，报告直接失真。

## 六点三、v6：不再依赖 SQL（还是会死 / 还是矮人）

你第四次反馈「还是会死，还是矮人」。两个根因都找到了，
而且都是**依赖 SQL 生效**导致的 —— 这次改成**代码兜底，SQL 可有可无**。

### 为什么还是会死：ScriptName 没绑上

```
ObjectMgr.cpp:9834  GetScriptId(name) 在 _scriptNamesStore 里二分查找
                    查不到 -> return 0（= 无脚本）
ObjectMgr.cpp:9765  LoadScriptNames() 启动时【一次性】收集所有表的 ScriptName
```

`LoadScriptNames` 只在启动时跑一次。只要顺序不对
（先重启后跑 SQL、或者只 `.reload` 没重启），木桩就绑不上 AI，
**就是个普通怪，一下被打死**。

**修法**：运行时直接注入 AI，绕开整条 ScriptName 链路：

```cpp
// Creature.h:166  bool AIM_Initialize(CreatureAI* ai = nullptr);
dummy->AIM_Initialize(new npc_bignum_dummy(dummy));
```

**SQL 跑没跑、ScriptName 有没有绑，都不影响了。**

### 为什么还是矮人：探测全部失败

上一版只探 `creature_template` 里官方假人的 entry（32546 等），
但**你库里很可能根本没有这些 entry**（TDB 数据包不全 / NPCBot 精简库），
探不到就回退成模板里的 3053 —— 矮人。

**修法**：加写死兜底 + 双字段设置

```cpp
if (!s_dummyModel)
    s_dummyModel = 25225;                  // 客户端 MPQ 自带的稻草人模型

dummy->SetDisplayId(s_dummyModel);         // Unit.h:1595
dummy->SetNativeDisplayId(s_dummyModel);   // Unit.h:1598  两个都设，防回退
```

`25225` 是客户端自带的训练假人模型，**不依赖你的 world 库**。

### 你观察到的"血量固定只出伤害数字"

这正是 `damage = 0` 的效果 —— 伤害数字照常飘（客户端自己算的），
但服务端血量一点没掉。现在我们的木桩就是这个行为。

## 六点四、v5：借鉴官方木桩（你的建议）

你说「可以借鉴一下主城里的木桩，因为不会死，而且数据也在」—— 这是对的，
官方 `npc_training_dummy`（`npcs_special.cpp:1379`）的关键就一行：

```cpp
void DamageTaken(Unit* attacker, uint32& damage, DamageEffectType damageType,
                 SpellInfo const* /*spellInfo*/) override
{
    damage = 0;              // <- 伤害在【扣血之前】被抹成 0
    if (!attacker || damageType == DOT) return;
    _combatTimer[attacker->GetGUID()] = 5s;
}
```

**不是靠血厚，是伤害根本没进扣血流程**。所以永远不死。

### 但照抄会踩一个致命坑

```
Unit.cpp:730   victimAI->DamageTaken(attacker, damage, ...);    <- 这里抹成 0
Unit.cpp:756   sScriptMgr->OnDamage(attacker, victim, damage);  <- 读到的已经是 0
```

`DamageTaken` 在 `OnDamage` **之前**执行。原来的统计挂在 `OnDamage` 上，
照抄官方后 **DPS 会永远是 0**。

**解法**：把统计移进自己的 AI，**先记账、再抹零**：

```cpp
struct npc_bignum_dummy : public NullCreatureAI
{
    void DamageTaken(Unit* attacker, uint32& damage, ...) override
    {
        // 1. 先记账（damage 还是真实值）
        s->total += damage;  ++s->hits;  s->bySpell[spellId] += damage;
        // 2. 再抹零（官方做法）
        damage = 0;
    }
};
```

这样就是你要的「**不会死，而且数据也在**」。

### 顺带解决了一个原有限制

`DamageTaken` 直接给了 `SpellInfo const* spellInfo` 参数，
比原来在 `OnDamage` 里靠 `GetCurrentSpell()` 猜准得多 ——
**分技能明细的偏差问题一并修好了**。

### 模型改为运行时自动探测

我连着三次让你看矮人，因为只敢用 step21 验证过的 3053。这次改成去库里
**找官方训练假人真正在用的模型**（`ObjectMgr.h:983 GetCreatureTemplates()`）：

```cpp
static uint32 const officialDummies[] =
    { 32546, 32541, 31144, 32666, 2673, 30527, 31146 };
// 按顺序找第一个存在且 Modelid1 有效的，取其模型
```

探不到就保持模板原值（3053），**不会变隐形**。

## 七、SQL 里避开的一个坑

木桩的 `unit_flags` 是 **32832**，不是服务 NPC 那个 **33088**：

```
33088 = 0x40 + 0x100(IMMUNE_TO_PC) + 0x8000(CAN_SWIM)
32832 = 0x40                       + 0x8000(CAN_SWIM)
```

`UNIT_FLAG_IMMUNE_TO_PC`（`UnitDefines.h:143`，注释
"disables combat with PlayerCharacters"）会让**玩家根本打不动木桩**，DPS 永远是 0。

不还手是靠代码里的 `SetReactState(REACT_PASSIVE)` + `SetImmuneToNPC(true)` 实现的，
不靠这个 flag。

另外 `modelid1` 用的是 **3053**（step21 实测确认可见的模型）。
官方训练假人的 displayid 我**没验证过，不敢填**——step21 踩过
"随手填 15294 → 无效 ID → 客户端静默失败看不到 NPC"的坑。
你要是知道真正的假人模型 ID，改 `modelid1` 一个字段就行。

## 九、已知限制

1. **分技能统计靠 `GetCurrentSpell(CURRENT_GENERIC_SPELL)` 推断**
   （`Unit.h:1488`）。瞬发技能和 DOT 可能归到"普通攻击"里，
   总量准确，但构成明细会有偏差。这是 `OnDamage` 钩子只传 `damage`
   拿不到 `spellProto` 导致的——要精确得改 `ScriptMgr` 签名，那是侵入式改动，
   先不动。

2. **暴击率没做**。`OnDamage` 拿不到 `cleanDamage->hitOutCome`
   （`Unit.h:415` 有这个字段，但钩子没往下传）。同样要改签名才能拿到，
   等你确认需要再说。
