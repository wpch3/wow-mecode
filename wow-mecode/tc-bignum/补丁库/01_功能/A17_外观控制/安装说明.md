## 二、`.disguise` 隐藏装备外观

### 核心特性：**属性完全保留**

| 项 | 状态 |
|---|---|
| 别人看到的外观 | **空手裸装** |
| 属性加成 | **照常生效** |
| 战斗力 | **完全不受影响** |
| 背包/装备栏 | 东西还在 |

**原理**（查了 `Player.cpp:12170` 实现）：
`SetVisibleItemSlot` 只写 `PLAYER_VISIBLE_ITEM_*` 这组**外观广播字段**，
**完全不碰 `m_items`**。真正动装备的是 `VisualizeItem`（12185 行）。

属性走 `m_items` 和光环，所以隐藏外观对属性零影响。

### 用法

| 指令 | 效果 |
|---|---|
| `.disguise on` | 隐藏全身19个槽位 |
| `.disguise off` | 恢复 |
| `.disguise weapon` | 只隐藏武器（主手/副手/远程）|
| `.disguise armor` | 只隐藏护甲（其余16槽）|
| `.disguise toggle` | 切换 |
| `.disguise status` | 看当前状态 |

`weapon` / `armor` 后面还能跟 `on`/`off`：

```
.disguise weapon on     只隐藏武器
.disguise armor off     只恢复护甲
```

## 三、`.model` 换模型

### 对玩家 / NPC / BOSS / NPCBot 全部有效

`SetDisplayId` 是 `Unit` 的方法，它们都是 Unit 子类。

| 指令 | 效果 |
|---|---|
| `.model <ID或别名>` | 对选中目标 |
| `.model r <半径> <模型>` | 对周围所有NPC |
| `.model entry <ID> <模型>` | 对指定entry |
| `.model me <模型>` | 自己换 |
| `.model reset` | 复位到原生模型 |
| `.model reset r <半径>` | 批量复位 |
| `.model save` | 写库持久化（仅NPC）|
| `.model npc <entry>` | 用该生物的模型（推荐）|
| `.model copy` | 复制选中目标的模型 |
| `.model id <displayid>` | 直接指定 |

### 【v2 重要变更】别名表已删除

**v1 的模型别名表全部作废。** 用户实测：巫妖王变死亡战马、
伊利丹直接消失、小兔子变洞穴人 —— 表里的 displayid **是我凭印象编的，
一个都没查证过**。

而且还有个更根本的问题：**你装了 HD 补丁之后，
displayid 到实际模型的对应关系本来就变了**，任何硬编码表都靠不住。

### 模型来源三选一

| 写法 | 说明 | 可靠性 |
|---|---|---|
| **`npc <entry>`** | 服务端查 `creature_template` 拿真实 modelid | **100%准确，推荐** |
| **`copy`** | 复制当前选中目标的模型 | **所见即所得** |
| `id <displayid>` | 直接给数字 | 老手用，自负 |

### 推荐流程

```
1. .lookup creature 巫妖王      -> 查出 entry（比如 36597）
2. .model npc 36597             -> 套用它的模型
```

**或者更直接**：

```
选中那个 NPC -> .model copy -> 换到别的目标身上
```

### 为什么 entry 比 displayid 可靠

```
ObjectMgr.h:982      GetCreatureTemplate(entry)
CreatureData.h:358   GetFirstValidModelId()
Creature.cpp:133     依次返回 Modelid1..4 中第一个非0
```

entry 是**服务端数据库主键**，查出来的 modelid 就是这个生物
在**你这个客户端**上真正显示的模型。不存在猜的成分。

### `reset` 用的是官方 API

```
Unit.h:1191    void DeMorph()
Unit.cpp:3461  { SetDisplayId(GetNativeDisplayId()); }
```

不用自己存原始 ID，调 `DeMorph()` 就回去了。

## 四、验收清单

### `.disguise`（10条）

```
1. 穿好装备，.disguise status    -> 显示"显示中"和实际穿戴件数
2. .disguise on                  -> 变裸装，提示"属性完全保留"
3. 看角色面板                     -> 属性数值【应该完全没变】 <- 核心
4. 打个怪                        -> 伤害正常，说明装备属性还在
5. .disguise status              -> 显示"已隐藏"
6. .disguise off                 -> 装备外观回来
7. .disguise weapon              -> 只有武器消失，护甲还在
8. .disguise armor               -> 只有护甲消失，武器还在
9. .disguise toggle              -> 切换
10. 裸身状态下 .disguise on      -> 不崩，正常返回
```

**第 3 步是重点** —— 属性面板数值必须一个字都不变。

### `.model`（10条）

```
11. .lookup creature 巫妖王       -> 查出 entry
12. 选中NPC，.model npc <entry>   -> 变成该生物的模型
13. 选中A，.model copy，再选B      -> B 变成 A 的模型
14. .model reset                 -> 变回原样
15. .model me 隐形               -> 自己消失（模型11686）
16. .model me reset              -> 自己回来
17. .model r 30 骷髅             -> 周围NPC全变骷髅
18. .model reset r 30            -> 批量复位
19. .model entry 1234 狼          -> 只有entry=1234的变狼
20. .model npc <entry> 然后 .model save -> 提示已写库，.respawn 后仍生效
```

### 错误处理（5条）

```
21. 不选目标 .model npc 448       -> 提示没选中，给替代用法
22. .model r 999 狼              -> 提示半径需0-500
23. .model npc 99999999          -> 提示 entry 不存在
24. .model 999999                -> 提示displayid超范围
25. .model save（不选NPC）        -> 提示先选中NPC
```

## 五、和已有工具的配合

```
.model r 40 骷髅          周围NPC全变骷髅
.nst r 40 剧情            设为剧情态（无敌）
.emote r 40 跪下          全体跪下
.say r 40 主人，我们回来了。  说话
.scene save 亡灵大军       整个场景存快照
```

**`.scene` 本来就存 display**，所以模型改动能一起存进快照。

## 六、已知限制

| 限制 | 说明 |
|---|---|
| **`.disguise` 换装后会恢复显示** | 换装备时 `VisualizeItem` 会重设外观字段。<br>重新敲一次 `.disguise on` 即可 |
| `.disguise` 重登后失效 | 外观字段不持久化。这是**有意的**——<br>避免玩家忘了自己开着隐藏 |
| `.model save` 只能存NPC | 玩家模型无法持久化（没有对应的库表）|
| `.model save` 写 `modelid1` | 对**新生成**的NPC生效，已存在的要 `.respawn` |
| NPCBot/宠物被排除 | 沿用 `.nst`/`.emote`/`.say` 的保护 |
| 玩家换模型后装备外观 | 可能错位。配合 `.disguise on` 可解决 |

## 七、本文件遵守的三条铁律（前面踩过的坑）

| 铁律 | 说明 |
|---|---|
| **SQL 用 `{}` 不用 `%u`** | `DatabaseWorkerPool.h:99` 走 fmt 库。<br>step29 写 `%u` 崩过服 |
| **不在运行时调 `LoadXxx()`** | 会让容器 rehash，指针失效 -> 崩溃。<br>step29 踩过。持久化只写库 |
| **注册改两处** | 声明 + `AddCommandsScripts()` 调用。<br>step29/30 都踩过 |

> `snprintf` 里的 `%u` 是对的，那是标准 C 函数，不要混淆。
