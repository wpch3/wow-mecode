## 一、装什么

**一个文件，两步操作。**

### 第 1 步：放文件

把 `源文件/cs_emote.cpp` 复制到：

```
D:\TrinityCore\src\server\scripts\Commands\cs_emote.cpp
```

### 第 2 步：注册（两处都要改，缺一不可）

> **【勘误 2026-08-01】本节初版写"只加声明就够了、不用改 ScriptLoader.cpp"，**
> **是错的。** 结果是编译全过、但游戏里报
> `Command 'emote 跳舞' does not exist`。
>
> **错误根源**：我看到 CMake 用 `CollectSourceFiles` 自动扫描源文件，
> 就推断注册也是自动的。这两件事是**分开的** ——
> 源文件自动进编译（这条对），但 `AddSC_xxx()` 的调用**必须手动加**。

#### 2a. 加声明

```
D:\TrinityCore\src\server\scripts\ScriptLoader.h
```

在其它 `AddSC_xxx_commandscript();` 旁边加：

```cpp
void AddSC_emote_commandscript();
```

#### 2b. 【关键】加调用

CMake 生成的 `ScriptLoader.cpp` 里，调的是**目录级汇总函数**，
不是逐个 `AddSC_xxx`：

```
src/server/scripts/CMakeLists.txt:118
    set(LOADER_FUNCTION "Add${LOCALE_SCRIPT_MODULE}Scripts()")
                         -> 生成 AddCommandsScripts()
```

所以**必须把你的函数加进 `AddCommandsScripts()` 里面**，
否则它永远不会被执行 —— 类没注册，命令表里就没有这条命令。

定位它：

```bash
grep -rn "AddCommandsScripts" /d/TrinityCore/src/server/scripts/Commands/
```

打开找到的文件，在里面加一行（照抄 `.nst` 那行的位置）：

```cpp
void AddCommandsScripts()
{
    AddSC_account_commandscript();
    ...
    AddSC_npcstate_commandscript();     // .nst
    AddSC_emote_commandscript();        // <- 加这行
}
```

**症状对照**：

| 现象 | 缺了哪步 |
|---|---|
| 编译报 `无法解析的外部符号` | 缺 2a 声明 |
| **编译全过，但游戏里 `Command does not exist`** | **缺 2b 调用** |
| CMake 报找不到 cs_emote.cpp | 没重跑 CMake |

### 第 3 步：重跑 CMake + 编译

**必须重跑 CMake**（新增文件要被扫描到）：

```
CMake GUI -> Configure -> Generate
VS2022 -> 生成 -> 重新生成解决方案
```

## 二、怎么用

### 最常用的三条

```
.emote 跳舞              选中的 NPC 开始跳舞（一直跳）
.emote r 30 跪下         周围 30 码所有 NPC 跪下
.emote list              174 个表情记不住？查这个
```

### 完整语法

| 指令 | 作用 |
|---|---|
| `.emote <表情>` | 对选中目标 |
| `.emote r <半径> <表情>` | 对周围所有 NPC（半径 0-500）|
| `.emote entry <ID> <表情>` | 对指定 entry 的所有 NPC |
| `.emote once <表情> [目标]` | 强制一次性播放 |
| `.emote state <表情> [目标]` | 强制持续状态 |
| `.emote clear [目标]` | 清除表情（= STATE_NONE）|
| `.emote save` | 选中目标的当前表情写库 |
| `.emote list [关键词]` | 查表情表 |
| `.emote me <表情>` | 自己做表情 |

### 表情参数三种写法都行

```
.emote 跳舞      中文别名
.emote dance     英文别名
.emote 10        原始数字（表外的数字也能用）
```

### 末尾可跟 save

```
.emote r 30 跪下 save      周围30码NPC跪下，并写库持久化
```

## 三、【重点】两种表情的区别

这是本指令最核心的设计，用之前必须懂。

| | 持续状态 | 一次性动作 |
|---|---|---|
| 底层 | `SetEmoteState`（Unit.h:968）| `HandleEmoteCommand`（Unit.h:1037）|
| 原理 | 写 `UNIT_NPC_EMOTESTATE` 字段 | 只发一个网络包 |
| 效果 | **一直保持** | **播完就没** |
| 新玩家进视野 | **看得到** | 看不到 |
| 能否 save | **能** | 不能 |
| 典型 | 跳舞、坐下、睡觉、干活 | 挥手、鞠躬、大笑 |

**指令会自动判断用哪种**，不用管。想强制就用 `once` / `state`。

> 实现依据（查了 `Unit.cpp:1712`，不是猜的）：
> `HandleEmoteCommand` 全部实现只有 5 行，就是组个包 `SendMessageToSet`，
> **不碰任何字段**，所以必然不持久。

## 四、验收清单（照着做一遍）

### 基础功能

```
1. .emote list              -> 应列出 STATE 28 条 + ONESHOT 22 条
2. .emote list 跪           -> 应只列出含"跪"的条目
3. 选中一个 NPC
   .emote 跳舞              -> NPC 开始跳舞，且【一直跳】
4. .emote clear             -> 停下
5. .emote 挥手              -> 挥一次手就停（这是 ONESHOT，正常）
6. .emote me 跳舞           -> 自己跳舞
```

### 批量

```
7. 站在人多的地方
   .emote r 30 跪下         -> 周围30码NPC全跪下，提示"半径30: N 个目标"
8. .emote r 30 clear        -> 全部恢复
9. .emote entry 1234 坐下   -> 只有entry=1234的NPC坐下
```

### 强制模式

```
10. .emote once 跳舞        -> 跳一下就停（强制ONESHOT）
11. .emote state 挥手       -> 保持挥手姿势（强制STATE）
```

### 持久化

```
12. 选中NPC，.emote 跪下
13. .emote save             -> 提示"已写库: guid=xxx emote=68"
14. .server restart 或重启服务端
15. 回去看那个NPC           -> 应该还在跪着
```

### 错误处理

```
16. 不选目标直接 .emote 跳舞    -> 应提示"没有选中NPC"，并给出替代用法
17. .emote r                   -> 应提示"用法: .emote r <半径> <表情>"
18. .emote r 999 跳舞          -> 应提示"半径需在0-500之间"
19. .emote entry abc 跳舞      -> 应提示用法错误
20. .emote 不存在的表情        -> 应提示"认不出表情"并让你查 list
21. .emote r 30 挥手 save      -> 应提示"一次性表情无法持久化，save已忽略"
```

## 五、和已有工具的配合

### 和 `.scene`（step28）

`.scene` 已经在存 `emote` 字段。所以：

```
1. .emote r 40 跪下          摆好表情
2. .scene save 献祭仪式      连表情一起存进快照
3. 随便怎么改
4. .scene load 献祭仪式      表情也一起还原
```

**两个工具天然打通，不用做额外适配。**

### 和 `.nst`（step26）

```
.nst r 40 剧情      周围NPC设为剧情态（无敌、不可攻击）
.emote r 40 跪下    同一批NPC跪下
.scene save 仪式    一起存
```

**这三条组合，一个剧情场景就成型了。**

## 六、已知限制

| 限制 | 说明 |
|---|---|
| 临时召唤物存不了 | 没有 `spawnId`，`save` 会跳过 |
| NPCBot 被排除 | 沿用 `.nst` 的保护（`IsNPCBotOrPet()`）|
| 玩家宠物被排除 | 同上 |
| `entry` 搜索半径固定 200 码 | 超出范围的同 entry NPC 不受影响 |
| 表外数字默认判 ONESHOT | 想要持续效果用 `.emote state <数字>` |

## 七、写库说明

`save` 写的是 `creature_addon` 表的 `emote` 字段：

```sql
INSERT INTO `creature_addon` (`guid`, `emote`) VALUES (?, ?)
ON DUPLICATE KEY UPDATE `emote` = ?
```

用 `ON DUPLICATE KEY UPDATE` 是因为那个 NPC 可能还没有 `creature_addon` 行。

**不需要执行任何 SQL 建表**，`creature_addon` 是 TrinityCore 自带的表。
