> 制定：2026-08-02
> 用户需求原话：「会在你饿了给你面包，渴了给你水，穷了给你钱，
> 就像是一个伙伴，一个值得信赖的伙伴，
> 是会自己拿出背包里的东西给予伙伴的一个战友！」

---

## 零、这个系统做了什么

**把 bot 从"听指令的工具"变成"会主动关心你的同伴"。**

| 场景 | bot 的反应 |
|---|---|
| 你血量 < 50% 且脱战 | 从自己包里掏食物给你 + 说句话 |
| 你法力 < 40% | 给你水 |
| 你身上钱 < 10金 | 塞给你 5 金 |
| 你升级了 | 祝贺一句 |
| 你死后复活 | 关心一句（还带点自责）|
| 长时间没事 | 讲讲见闻 |

### 三条设计底线

1. **主动** —— 不用你点菜单，它自己观察自己给
2. **有来源** —— 从 bot 的**虚拟背包**里扣，不是凭空变出来。包空了就给不出
3. **不烦人** —— 多重冷却 + 战斗中闭嘴 + 距离判断

## 二、执行 SQL

**两个文件，都是直接 `Alt+X` 执行全部，不用选库、不用管当前连的是哪个库。**

```
sql/01_world_台词与物品.sql      建 world.npcbot_care_text + world.npcbot_care_item
sql/02_characters_背包.sql       建 characters.npcbot_inventory
```

### 为什么不用选库

两个文件里**所有表名都写成了完全限定名**（`world.xxx` / `characters.xxx`），
所以不管 DBeaver 当前连着哪个库都能跑。

> **这是修正过的版本。** 上一版把三张表写在一个文件里、让你手动分库执行，
> 结果报了 `No database selected`。
> 档案里第 1980 行本来就记着「客户端不执行 USE，用完全限定名更稳」，
> 是我没遵守自己记的教训。

### 物品插入是"自动跳过不存在的"

`01` 文件里的物品用的是 `INSERT ... SELECT ... JOIN item_template` 写法：

```sql
INSERT INTO `world`.`npcbot_care_item` (...)
SELECT 1, t.entry, v.minlvl, v.maxlvl, v.src
FROM ( ... 候选列表 ... ) AS v
JOIN `world`.`item_template` AS t ON t.entry = v.id;
```

**只有你库里真实存在的物品才会被插入。** 所以就算你的 `item_template`
和标准 3.3.5 不一样，也不会插进无效数据。

### 执行完会自动显示结果

两个文件末尾都带了自查语句，执行完直接看输出：

```
类型   条数        <- 食物/水各插了几条
台词总数           <- 应该是 24
表名 行数 说明     <- characters 那张表建好没
```

**如果"食物"或"水"的条数是 0**，说明你库里那几个 itemid 都不存在，
需要换成你库里有的（见第十章）。

> 已跑过 `check_sql_range.py`（数值范围）和 `sqlglot` 语法解析（14 + 3 条语句全部通过），
> 并确认所有表引用都已限定库名。

> **本章原来写得太含糊（"找一个加载点挂进去"），导致用户插错位置，


### 6-B：在 `LoadNpcBots` 的【末尾】调用

**Ctrl+F 搜这一行**（`botdatamgr.cpp:1187`，全文件唯一）：

```cpp
    allBotsLoaded = true;
```

它下面紧跟着一个 `}` 就是函数结尾。**改成**：

```cpp
    allBotsLoaded = true;

    // step34 伙伴关怀：台词、物品池、bot虚拟背包
    // 必须放在这里（函数末尾）—— LoadCareItems 要校验 item_template，
    // 放函数开头的话物品表还没加载完，会误判所有物品都不存在。
    sBotCompanionMgr->ReloadAll();
}
```

### 【重要】不能放函数开头

```cpp
botdatamgr.cpp:910   void BotDataMgr::LoadNpcBots(bool spawn)
botdatamgr.cpp:911   {
botdatamgr.cpp:912       if (allBotsLoaded)      <- 插这里会报 C2447
```

两个原因：
1. 插在 910 和 911 之间会把函数头和 `{` 隔开 -> **编译错误 C2447**
2. 就算插对了位置，`item_template` 此时还没加载完 -> **所有物品都会被误判为不存在**

## 九、验证清单

### 准备

```
1. 招募一个 bot
2. 服务端日志里应该看到：
   >> Loaded N npcbot care texts in X ms
   >> Loaded N npcbot care items in X ms
   >> Loaded N npcbot inventory entries in X ms
```

**如果 care items 那行显示 "Skipped N invalid..."**，
说明 SQL 里某些 itemid 在你的库里不存在 —— 看日志里具体是哪个，
从 `npcbot_care_item` 表里删掉或换成你库里有的。

### 逐项测

```
[ ] 让自己掉血到 50% 以下，脱战等 -> bot 应该递食物 + 说话
[ ] 检查背包，食物真的到手了
[ ] 再掉血一次 -> 2分钟内不该重复给（冷却）
[ ] 法系职业耗蓝到 40% 以下 -> 给水
[ ] 把钱花到 10 金以下 -> 给钱
[ ] 升一级 -> 祝贺
[ ] 死一次再复活 -> 关心
[ ] 挂机 10 分钟 -> 讲见闻
[ ] 战斗中掉血 -> 不该说话（打架时闭嘴）
[ ] 跑远 40 码 -> 不该说话
```

### 核心保证验证（最重要）

```
[ ] 连续让 bot 给你食物，直到它说不出话
    -> 说明它包里的东西真的用完了，不是无限供应
```

**这一条验证的是「真的从背包拿」这个设计底线。**

## 十、怎么加内容（不用重编译）

### 加台词

```sql
INSERT INTO `world`.`npcbot_care_text` (care_type, bot_class, text, weight) VALUES
(4, 0, '你有没有听说过瓦里安国王的事？', 10);
```

`care_type`：1食物 2水 3钱 4闲聊 5升级 6复活
`bot_class`：0 = 所有职业通用，其他值 = 职业专属（优先级高于通用）
占位符：`{item}` 物品名、`{gold}` 金额、`{from}` 来源

### 加可给予物品

```sql
INSERT INTO `world`.`npcbot_care_item` (care_type, item_id, min_level, max_level, source_text) VALUES
(1, 你的物品ID, 60, 80, '你编的来源描述');
```

**先确认物品存在**（不存在的话服务端启动时会跳过并打日志）：

```sql
SELECT entry, name FROM `world`.`item_template` WHERE entry = 你的物品ID;
```

**想找你库里有哪些食物/水可以用**：

```sql
SELECT entry, name, RequiredLevel
FROM `world`.`item_template`
WHERE class = 0 AND subclass = 5      -- 0=消耗品 5=食物/饮料
  AND RequiredLevel BETWEEN 55 AND 80
ORDER BY RequiredLevel;
```

**改完重启服务端即可，不用重新编译。**

## 十三、验收标准（用户视角，不是测试视角）

> 反思过的一点：以前只验"指令能不能跑通"，从没验"玩起来什么感觉"。

**这次的验收标准是**：

```
带一个 bot 打半小时，
它至少主动关心你 3 次，
且你不觉得烦。
```

**如果觉得烦** -> 调大 `Cooldown`
**如果觉得太安静** -> 调小 `Cooldown`，或往台词表里加内容
