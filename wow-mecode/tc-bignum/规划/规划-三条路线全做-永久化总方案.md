## 二、路线3 详细方案（可行性已实证）

### 2.1 改动点只有一处

实查：`bot_ai.cpp` 里 `GetSpawnId()` **只出现 1 次**：

```cpp

void bot_ai::InitializeAI()
{

        SetWanderer();
    Reset();
}
```

**改动面极小**，这是好消息。

### 2.2 怎么区分「我们创造的bot」和「指令召唤的bot」

你的要求：**指令召唤的不受影响，只影响我们新造的**。

**方案：用 `creature.ScriptName` 打标记**

```
ScriptName = "wanderer"   -> 这个固定bot【也要游荡】
ScriptName = 空/其它      -> 保持原样（站桩）
```

**为什么用 ScriptName**：
- NPCBot 走 `bot_ai` 不走 ScriptName，**这个字段对bot无副作用**
- step49 已经验证过这个做法（当时用 `pin:<guid>` 格式）
- 纯数据驱动，不用新建表

### 2.3 改后的代码

```cpp
void bot_ai::InitializeAI()
{
    // step65: 原判断是 if (!me->GetSpawnId() && ...)
    //   spawnId==0 才是游荡bot -> 写进 creature 表就永久失去游荡能力
    //
    // 现在增加一条：creature.ScriptName == "wanderer" 的固定bot
    // 也进入游荡状态。这样「持久化」和「会游荡」不再互斥。
    //
    // 【只影响显式标记的bot】—— 官方 .npcbot spawn 出来的
    // ScriptName 是空的，行为完全不变。
    bool wantWander = !me->GetSpawnId();

    if (!wantWander && me->GetSpawnId())
    {
        if (CreatureData const* cdata = sObjectMgr->GetCreatureData(me->GetSpawnId()))
            wantWander = (cdata->scriptId == sObjectMgr->GetScriptId("wanderer"));
    }

    if (wantWander && !IsTempBot() && !me->IsSummon())
        SetWanderer();

    Reset();
}
```

> **待实查**：`CreatureData` 里存的是 `scriptId`（uint32）还是字符串。
> 如果是 id，要用 `sObjectMgr->GetScriptId("wanderer")` 比对。
> **写代码前我会先查清楚，不猜。**

### 2.4 已知风险（要验证）

| # | 风险 | 怎么验 |
|---|---|---|
| 1 | bot 死亡后 respawn 会回到 creature 表记录的原点 | 实测：让它走远后杀死，看复活在哪 |
| 2 | `Creature.cpp:2271` 的 pool 系统会不会干扰 | 我们不用 pool，应该无影响，但要确认 |

| 4 | 保存位置：游荡中的bot如果 SaveToDB 会覆盖原点 | 确保不触发 SaveToDB |

**第3条是关键** —— 要查 `SetWanderer()` 之后路点怎么初始化。
