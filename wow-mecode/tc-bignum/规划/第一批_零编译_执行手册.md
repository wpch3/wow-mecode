## 第 1 步 · 拍卖行（最先做，因为要留时间铺货）

**为什么排第一**：铺满 12 万条挂单需要 25 分钟以上，先启动它，
你在等待期间可以做第 2、3 步。

### 1.1 放文件

把这个文件复制过去：

```
从： 工作区  conf/worldserver.conf.d/ahbot.conf
到： D:\TC-Build\bin\RelWithDebInfo\worldserver.conf.d\ahbot.conf
```

> 如果 `worldserver.conf.d` 目录不存在，就新建一个，
> **名字必须一模一样**（`Main.cpp:70` 里写死的 `#define _TRINITY_CORE_CONFIG_DIR "worldserver.conf.d"`）。

**你的 `worldserver.conf` 不用改，一个字都不用动。**

### 1.2 【注意】附带修复：`切换档位.bat` 会把 ahbot.conf 关掉

这个坑我这次一并修了，**你需要把修好的 bat 也复制过去**：

```
从： 工作区  conf/切换档位.bat
到： D:\TC-Build\bin\RelWithDebInfo\切换档位.bat
```

**原来的问题**（旧 bat 第 55 行）：

```bat
for %%f in ("%DIR%\*.conf") do ren "%%f" "%%~nxf.off" 2>nul
```

`*.conf` 是通配符，**会把目录里所有 conf 都改名成 `.off`** ——
包括刚放进去的 `ahbot.conf`。你下次切档位，拍卖行配置就静默失效了，
而且不报任何错，极难发现。

**改成了只处理 5 个档位文件**：

```bat
for %%t in (casual adventure epic hardcore legend) do (
    if exist "%DIR%\%%t.conf" ren "%DIR%\%%t.conf" "%%t.conf.off" 2>nul
)
```

### 1.3 生效（二选一）

**方式 A（推荐，最稳）**：重启 worldserver。

启动时看这一行，确认加载成功：

```
Loaded additional config file ...worldserver.conf.d/ahbot.conf
```

**方式 B（不重启）**：控制台依次执行**两条**命令，顺序不能反：

```
.reload config
.ahbot reload
```

> **为什么必须先 `.reload config`**：
> `AuctionHouseBot.h:240` 是 `void Reload() { GetConfigFromFile(); }` ——
> 它只从内存里的 ConfigMgr 取值，**不会自己去读磁盘文件**。
> 不先 `.reload config` 的话，`.ahbot reload` 读到的还是旧值。

### 1.4 铺货

```
.ahbot rebuild all
```

> 这条命令**不会立刻填满**。实查 `AuctionHouseBot.cpp:490 Rebuild()`，
> 它做的是把现有挂单的 `expire_time` 设为当前时间（标记过期）。
> 真正填充靠周期性补货，配置里我把 `Update.Interval` 设成了 **60 秒**加速。

等约 25 分钟，然后看进度：

```
.ahbot status
```

### 1.5 铺满后必须做（别忘了）

把 `ahbot.conf` 里这一行改回去：

```ini
AuctionHouseBot.Update.Interval = 60      ->   3600
```

然后再 `.reload config`。
不改回来的话服务器会一直每 60 秒跑一次补货循环，白耗 CPU。

### 1.7 关于「杂乱」，有一件事必须说清楚

我这次实查发现了一个**上一版没说明的限制**：

`AuctionHouseBotSeller.cpp:235-236`，等级过滤这段代码在：

```cpp
case ITEM_CLASS_ARMOR:
case ITEM_CLASS_WEAPON:
{
    if (uint32 value = ...CONFIG_AHBOT_ITEM_MIN_ITEM_LEVEL)
        if (prototype->GetBaseItemLevel() < value) continue;
```

**这组 ItemLevel 过滤只作用于「武器」和「护甲」两类。**

好处是：设 `ItemLevel.Min = 15` **不会**把亚麻布、铜矿这些材料过滤掉
（它们是 TRADE_GOODS 类，走的是 `:320` 的 `CONFIG_AHBOT_CLASS_TRADEGOOD_*`）。

所以这次配置能**精准去掉低级垃圾装备**，同时**保住所有材料**。
如果你之后觉得材料也杂，那要调的是另一组参数，告诉我我再给。

  COMMENT '限定种族 0=通用';

### 2.5 说明白一件事：这一步还做不到「对应场景说对应话」

你要求过「**之后一定要在对应的场景说对应的话，不要太杂乱和繁忙**」。

**这 141 条只解决了「话不够多、来回就那两句」，还没解决「看场合说话」。**

现在的机制是：从 `care_type=4` 池子里按权重随机抽。
bot 在副本里也可能说「风景不错」——这就是你说的「杂乱」。

**真正解决它的是 G19 第3步（场景感知）**，需要编译，在第二批里。

## 第 3 步 · 时间线试点（G20）

### 3.1 这一步是什么

你的原话：

> 「有些时间线部落没有来入侵，但是拥有渴魔症的精灵吸取生物的魔力或者自主吸取邪能」

这是**银月城渴魔症时间线**的最小可玩试点，用 `phaseMask` 实现，
**零客户端改动**（不用碰 MPQ/DBC）。

| 相位 | 内容 |
|---|---|
| phase 1 | 正常时间线（默认，所有人看到的） |
| phase 2 | 渴魔症时间线：没有兽人入侵，精灵们慢慢全疯了 |

### 3.2 【注意】这个文件我这次修过，别用旧的

**旧版有 8 处 `` `id1` ``，跑下去会直接报错**：

```
Unknown column 'id1' in 'field list'
```

根因：`creature` 表的列名是 `` `id` ``，不是 `` `id1` ``。
（`creature_template` 表才是 `entry`；`modelid1` 那个 1 是对的，别混淆）

实查依据：
```
ObjectMgr.cpp:2170   SELECT creature.guid, id, map, position_x, ...  FROM creature
sql/updates/ 官方脚本  INSERT INTO `creature` (`guid`,`id`,`map`,...)
```

工作区里的文件**已经改好了**，直接用：

```
规划/G20_世界重塑与时间线/02-时间线试点_零客户端.sql
```

### 3.3 执行

DBeaver 里用「执行脚本」(Alt+X) 跑整个文件。同样是幂等的。

跑完重载：

```
.reload creature_template
```

NPC 的摆放（`creature` 表）需要重启才生效。

### 3.4 进游戏测试

```
.go xyz 9738 -7454 13.5 530     传送到银月城「时间线守望者」旁边
.modify phase 2                 切到渴魔症时间线
.modify phase 1                 切回正常
```

**应该看到**：

```
phase 1 时： 只有「时间线守望者」这一个 NPC
phase 2 时： 守望者消失，出现「清醒的法师」+ 2 只「魔瘾狂乱者」+ 1 只「魔力吸取者」
```

### 3.5 说明白：这一步是试点，不是完整玩法

现在只有 **4 个 NPC + 2 段对话**，切相位还得靠 GM 命令。

**缺的是「让玩家自己切换时间线」**——那需要给守望者写一个 gossip 脚本
（玩家点「让我看看那条时间线」→ 自动 `SetPhaseMask(2)`）。
Gossip 菜单的数据我已经在 SQL 里建好了（`MenuID 98001/98002`），
差的是 C++ 或 Eluna 脚本把点击事件接上。

这个可以用 **Eluna 纯 Lua 实现，零编译**。如果第一批跑通了，
下次我直接给你 Lua 脚本，那样玩家就能自己切了。
