## 一、G19 第3步到底为后面什么做准备

G19 第3步不是孤立的「多几句台词」，它做了四块基础能力：

1. 把 bot 所处环境归类为副本、团本、主城、小镇、野外、战场、圣所；
2. 把 `scene / zone_id / map_id` 传进台词选择器；
3. 用地图、区域、种族、场景、职业综合评分选择最合适的台词；
4. 按 bot 与台词 ID 记录冷却，避免一直重复同一句。

这为两条后续路线提供了共同地基：

```text
G19：bot 知道“自己在哪里”
  -> G11 第2步：bot 知道“附近有谁、对方正在做什么”
  -> G11 第3步：决定要不要打招呼、接近或帮忙
  -> G11 第4步：偶遇后组成队伍并一起冒险
```

所以之前做 G19 第3步，主要就是在为 **G11「自主冒险 + 偶遇玩家自动组队」的感知层**做准备。

## 二、编译通过后现在先做什么

正确顺序不是马上再改一批 C++，而是先把这次编译变成一个可运行、可验收的基线：


## 三、部署前数据库检查

### 3.1 先检查四个字段，不要直接重复 ALTER

在 DBeaver 执行：

```sql
SELECT `COLUMN_NAME`, `COLUMN_TYPE`, `COLUMN_DEFAULT`
FROM `information_schema`.`COLUMNS`
WHERE `TABLE_SCHEMA` = 'world'
  AND `TABLE_NAME` = 'npcbot_care_text'
  AND `COLUMN_NAME` IN ('scene', 'zone_id', 'map_id', 'cooldown')
ORDER BY FIELD(`COLUMN_NAME`, 'scene', 'zone_id', 'map_id', 'cooldown');
```

预期必须返回 4 行。

- 返回 4 行：不要重复加字段，继续 3.2。
- 少于 4 行：执行 `06-第3步_精确补丁_基于你的真实源码.md` 的「步骤1 SQL 加字段」，然后重跑本查询。

### 3.2 检查场景数据

```sql
SELECT
    COUNT(*) AS total_texts,
    SUM(`scene` <> 0) AS scene_tagged,
    SUM(`zone_id` <> 0) AS zone_specific,
    SUM(`map_id` <> 0) AS map_specific,
    SUM(`id` BETWEEN 1100 AND 1199) AS g19_scene_texts,
    MIN(`cooldown`) AS min_cooldown,
    MAX(`cooldown`) AS max_cooldown
FROM `world`.`npcbot_care_text`;
```

G19 第3步的最低要求：

- `g19_scene_texts = 14`；
- `scene_tagged > 0`；
- `cooldown` 可正常读取。

如果 `g19_scene_texts` 不是 14，执行 06 号文档「步骤7 给台词打场景标签」的 `UPDATE + DELETE + INSERT` 整段，再重跑查询。

### 3.3 检查 14 条场景台词分布

```sql
SELECT `scene`, COUNT(*) AS rows_in_scene,
       GROUP_CONCAT(`id` ORDER BY `id`) AS ids
FROM `world`.`npcbot_care_text`
WHERE `id` BETWEEN 1100 AND 1199
GROUP BY `scene`
ORDER BY `scene`;
```

预期：

| scene | 场景 | 条数 |
|---:|---|---:|
| 1 | 副本 | 3 |
| 2 | 团本 | 2 |
| 3 | 主城 | 4 |
| 4 | 小镇 | 2 |
| 6 | 战场 | 2 |
| 7 | 圣所 | 1 |
| | **合计** | **14** |

## 四、部署新编译结果

1. 停止当前 worldserver；
2. 备份运行目录现有 `worldserver.exe`；
3. 从本次成功编译使用的配置目录复制新的运行文件到实际运行目录；
4. 确认文件修改时间是本次编译时间，避免又启动旧 exe；
5. 不要只复制 `.pdb`，必须确认真正的 `worldserver.exe` 已覆盖；
6. 启动时保存完整控制台输出或 `Server.log`。

推荐在替换前后记录哈希：

```powershell
Get-FileHash D:\TC-Build\bin\RelWithDebInfo\worldserver.exe -Algorithm SHA256
Get-FileHash <你的实际运行目录>\worldserver.exe -Algorithm SHA256
```

两个 SHA256 应一致。

## 五、启动日志验收

worldserver 启动后，日志中不得出现以下关键词：

```text
npcbot_care_text
Unknown column 'scene'
Unknown column 'zone_id'
Unknown column 'map_id'
Unknown column 'cooldown'
Column count doesn't match
QueryResult
SQL error
```

重点不是全日志中永远不能有任何历史 SQL 警告，而是不能有 `npcbot_care_text` 的字段/查询错误。

如果启动成功但 bot 完全不说话，先检查：

```ini
NpcBot.Companion.ChatCooldown
```

G19 文档中的默认行为是约 10 分钟一次。为了验收可临时设：

```ini
NpcBot.Companion.ChatCooldown = 60000
```

即 60 秒。验收结束后建议恢复到 `300000` 或 `600000`，避免刷屏。

配置修改后按项目现有方式重载；如果无法确认该项是否支持热重载，直接重启最稳。
