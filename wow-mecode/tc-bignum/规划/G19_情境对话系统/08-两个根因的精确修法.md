## 我的两条教训（已入坑表）

### 教训1：说"在某行下面加"，用户可能理解成"替换那一行"

**这次 `_giftTexts` 被顶掉就是这么来的。**

**以后的正确写法**：凡是"新增成员/新增行"，一律给**替换前/替换后的完整对照块**，
把相邻的 2-3 行一起写出来，让用户看到"旧的那行还在"。

反面教材（我这次写的）：
```
搜索原文：  std::vector<CompanionGiftText> _giftTexts;
在它下面加：std::unordered_map<...> _textCooldowns;
```

正确写法：
```
搜索原文：
    std::vector<CompanionGiftText> _giftTexts;

替换为：
    std::vector<CompanionGiftText> _giftTexts;
    std::unordered_map<...> _textCooldowns;
```
**把原文原样抄在替换后的第一行，用户就不会删掉它。**

### 教训2：说"整函数替换"，必须明确告诉用户"旧函数体也要删"

**这次 775 行的孤立 `{` 就是这么来的。**

我写的是「搜索 `std::string BotCompanionMgr::PickText(...)`，
**从这一行开始，到它对应的收尾 `}` 为止，整段替换**」——
但用户很自然会只选中**签名那一行**做替换。

**以后的正确写法**：给一条能算出删除范围的命令（像本文第二节那个 Python 配对脚本），
让用户先看到"要删第 X 行到第 Y 行"，再动手。
