## 二、「主动邀请」怎么做（设计已定）

### 两个方向，都要做

**方向 A：bot 邀请你**（它想去哪，问你去不去）

```
触发：游荡bot，玩家靠近 20 码，双方等级差 <= 5，冷却已过
行为：
    BotWhisper("我正要去{地名}，路上不太平。一起？")
    同时给玩家一个 Gossip 选项："好，一起走"
玩家点了 -> 走 step33 的招募流程（但不收钱，因为是它主动邀的）
```

**方向 B：你邀请它**（看它顺眼，问它愿不愿意）

```
右键游荡bot -> 菜单里除了"雇佣"，多一个"要一起冒险吗？"
bot 根据条件回应：
    等级差太大   -> "你这身板，跟着我怕是要吃亏。"（拒绝）
    队伍满了     -> "你人手够了，不缺我一个。"（拒绝）
    条件合适     -> "好啊，正好我一个人也闷。"（同意，免费加入）
```

**方向 B 更重要** —— 因为它给了 bot「拒绝」的能力，
而**会拒绝的伙伴才像个人**。

### 数据层扩展（复用 step34 的表）

```sql
-- 在 npcbot_care_text 里加两个新类型，不用建新表
care_type 7 = bot主动邀请
care_type 8 = bot同意加入
care_type 9 = bot拒绝加入（附原因）
```

**这就是 step34 把台词做成数据表的价值** —— 加功能不用改表结构。

## 三、更多社交与互动 —— 完整清单

按「已有 / 能做 / 有难度」分三档，每条标注依赖。

### 第 1 档：step34 基础上直接加（每条 1-2 天）

| 功能 | 说明 | 依赖 |
|---|---|---|
| **主动邀请同行** | 见第二章 | care_type 7-9 |
| **告别** | 解雇时说一句，不是默默消失 | care_type 10 |
| **重逢** | 之前的同伴再遇到会认出你 | 需要"见过面"记录表 |
| **道谢** | 你给它装备/复活它，它会谢 | 钩子 + care_type |
| **提醒** | 你背包满了/耐久低了/没吃的了 | 读 Player 状态 |
| **警告** | 前面有精英怪、你等级不够 | 读周围 Creature |
| **附和** | 你在世界频道说话，它偶尔搭腔 | 聊天钩子 |
| **称呼变化** | 从"你"变成叫你名字，再变成外号 | 好感度字段 |

### 第 2 档：要新数据表（每条 3-5 天）

| 功能 | 说明 | 需要什么 |
|---|---|---|
| **好感度系统** | 一起打的时间/救过它/给过东西 -> 好感涨 | `npcbot_affinity` 表 |
| **记忆系统** | 记住一起打过的BOSS、去过的地方 | `npcbot_memory` 表 |
| **基于记忆的对话** | "上次在这我们差点全灭" | 记忆表 + 台词模板 |
| **成长故事** | 台词随等级/共同经历变化 | 好感度 + 等级分档 |
| **它也会请求** | "能给我把好点的剑吗" | 装备评估逻辑 |
| **礼物** | 好感高了会送你东西 | 复用虚拟背包 |
| **心情** | 连败沮丧/连胜兴奋，影响台词 | 状态机 |

### 第 3 档：多 bot 互动（每条 1 周+）

| 功能 | 说明 | 难点 |
|---|---|---|
| **bot 之间对话** | 队伍里两个 bot 互相拌嘴 | 要调度谁先说谁后说 |
| **bot 之间关系** | 有的合得来，有的互相看不顺眼 | 关系矩阵 |
| **阵营/种族反应** | 兽人和人类同队会有摩擦 | 需要设定支撑 |
| **职业互动** | 法师给术士递水时的调侃 | 职业组合表 |
| **集体反应** | 打完硬仗全队一起感慨 | 同步机制 |

### 第 4 档：和剧情深度绑定（长期）

| 功能 | 依赖 |
|---|---|
| 剧情 bot 按六卷推进说不同的话 | 真龙剧情落地 |
| 七位凡人主角做成可同行 bot | 身份体系 |
| bot 有自己的支线 | 伪任务系统 |
| 分歧与选择（bot 反对你的决定）| 剧情分支 |

## 四、我的推荐顺序（按"像人"的收益排）

**不是按技术难度排，是按「让 bot 更像个人」的效果排：**

```
1. 主动邀请 + 拒绝        <- 会拒绝才像人           step36
2. 告别 + 重逢            <- 有始有终才像关系       step36
3. 道谢 + 提醒            <- 有来有往才像伙伴       step37
4. 好感度                 <- 关系会变化才真实       step38
5. 记忆 + 基于记忆的对话  <- 有共同经历才是战友     step39
6. bot 之间对话           <- 世界有生命感           step40
7. 心情 + 成长            <- 立体的人               step41
```

### 为什么「拒绝」排第一

一个永远说"好"的 NPC 是工具。
**一个会说"不"的 NPC 才是人。**

这条实现成本极低（就是个条件判断 + 一句台词），
但对体验的提升是质变的。

### 为什么「记忆」这么靠后但很重要

记忆是所有"深度社交"的基础：
- 没有记忆，就没有"上次"
- 没有"上次"，就没有关系的积累
- 没有积累，好感度就只是个数字

**但它需要前面几步先跑通**，否则记了也没地方用。

## 五、一个提醒：别做成骚扰

功能越多，**bot 越可能变成话痨**。

step34 已经有的防护：
```
全局冷却        NpcBot.Companion.Cooldown       默认 2 分钟
闲聊单独冷却    NpcBot.Companion.ChatCooldown   默认 10 分钟
战斗中闭嘴
30 码距离判断
```

**后续每加一类互动，都要问三个问题**：

1. 这条会不会和已有的抢冷却？
2. 玩家能不能单独关掉这一类？
3. 一小时内最多会触发几次？

**建议**：等 step36 做完，加一个总的"话痨程度"配置：

```ini
NpcBot.Companion.Verbosity = 2
# 0 = 只在关键时刻说话（给东西、告别）
# 1 = 适中（默认）
# 2 = 话多（开发/测试用）
```

## 附：step34 给后续省了多少事

写这份清单时才意识到，step34 的几个设计决定，
让后面所有社交功能都变简单了：

| step34 的决定 | 后续收益 |
|---|---|
| 台词进数据库 | 加新互动类型不用改表结构，加行就行 |
| care_type 用数字枚举 | 直接往后排 7、8、9... |
| 权重随机 | 同一场景多种说法，不重复 |
| 职业专属台词字段 | 天然支持"不同职业不同性格" |
| 虚拟背包 | 送礼物直接复用 |
| 冷却机制 | 新功能挂上去就有防刷屏 |

**这就是"当总集成来做"的价值** —— 不是又一个孤立功能。
