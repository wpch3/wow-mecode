# 游戏内难度/趣味菜单 —— 可行性与方案

> 你的需求：不想每次改 conf 重启，想在游戏里通过 NPC 或菜单
> 动态切换难度、开关"1级学全技能"这类选项。

---

## 一、结论：可行，而且能纯 Lua 实现

我核对了源码，两个关键点都通过：

### 1. 配置在运行时是**可写**的

```cpp
// World.h:686-724，全部是 public
void setRate(Rates rate, float value)              { rate_values[rate] = value; }
void setBoolConfig(WorldBoolConfigs index, bool)   { ... }
void setIntConfig(WorldIntConfigs index, uint32)   { ... }
```

不是只读的，**可以在游戏运行中直接改**。

### 2. Eluna 有完整的 Gossip 菜单 API

```
GossipMenuAddItem / GossipSendMenu / GossipClearMenu / GossipComplete
```

**做 NPC 对话菜单不需要改 C++**，纯 Lua 就行，改完 `reload eluna` 即生效。

---

## 二、⚠️ 但必须先理解一个关键区别

你现在开的这些配置，**分两类，行为完全不同**：

### A 类：「一次性」配置 —— 只在角色创建时生效

```ini
PlayerStart.AllSpells    = 1      <- 你开的这个
PlayerStart.AllReputation = 1
PlayerStart.MapsExplored  = 1
StartPlayerLevel          = 1
```

这些只在 **`Player::Create()` 建角色那一刻**读取一次。

**含义**：
- 运行时改成 0 → **已有角色不受影响**，之后新建的角色才不送技能
- 想让现有角色"忘掉"技能 → 得手动 `.unlearn`，配置改了没用

### B 类：「持续生效」配置 —— 每次判断都读

```ini
AlwaysMaxSkillForLevel = 1        <- 武器熟练度自动满级
Instance.IgnoreLevel   = 1        <- 无视副本等级限制
Instance.IgnoreRaid    = 1        <- 单人进团本
Quests.IgnoreRaid      = 1
AllFlightPaths         = 1
InstantFlightPaths     = 1
Rate.XP.Kill / Rate.Drop.*        <- 各种倍率
Death.SicknessLevel    = 120      <- 复活虚弱
```

这些**每次触发时都会读配置**，所以运行时改**立刻生效**，无需重启。

---

**所以**：你说的"想有挑战时关掉学全技能"——
`PlayerStart.AllSpells` 属于 A 类，改了只影响**新建角色**。
真想让现有角色变难，得从 B 类里选（降倍率、开复活惩罚、关无视等级等）。

---

## 三、推荐方案：三层设计

### 第 1 层：全局难度预设（服务器级，GM 用）

一条指令切换整套参数：

```
.difficulty easy      休闲：经验x5 掉落x5 怪物血量x0.5 无复活惩罚
.difficulty normal    标准：全部 x1，原版体验
.difficulty hard      挑战：经验x0.5 掉落x0.5 怪物血量x2 伤害x1.5
.difficulty hell      地狱：怪物血量x5 伤害x3 关闭无视副本等级
.difficulty custom    进入细项菜单
.difficulty show      查看当前所有设置
```

**实现**：C++ 或 Lua 都行，批量调用 `setRate()` / `setBoolConfig()`。

### 第 2 层：个人难度（玩家级，各玩各的）

这个更有意思 —— **不改全局，只影响自己**：

```
.mydiff hard          我自己承受2倍伤害、造成0.5倍伤害
.mydiff hardcore      开启硬核模式：死亡即删角色（可选）
.mydiff off           恢复正常
```

**实现**：用 Eluna 的伤害钩子，按玩家挂"难度光环"。
存在自定义表 `custom_player_difficulty`，登录时恢复。

> 这个比全局难度实用得多 —— 你想挑战时自己开，不影响 bot 和其他角色。

### 第 3 层：NPC 菜单（可视化，最方便）

在主城放一个「时空调律者」NPC，点开就是菜单：

```
[时空调律者]
  > 调整世界难度        -> 子菜单：休闲/标准/挑战/地狱
  > 调整我的难度        -> 子菜单：个人倍率
  > 经验倍率            -> x1 / x2 / x5 / x10
  > 掉落倍率            -> x1 / x2 / x5 / x10
  > 切换开关            -> 子菜单
      - [开] 无视副本等级
      - [开] 单人进团本
      - [开] 全飞行点
      - [关] 复活虚弱
  > 传送服务            -> 主城/副本门口
  > 查看当前设置
```

**纯 Lua 实现**，用 `GossipMenuAddItem` 动态生成，
菜单项文字能实时显示当前状态（`[开]`/`[关]`）。

# 附录 A：猎人/术士驯服任何生物 —— 已核实可行

> 状态：**已完成源码核实，方案确定，暂不执行**。等第 7 步之后再排期。

## 核心结论：改动只有一个函数

限制全部集中在这一处：

```cpp
// src/server/game/Entities/Creature/CreatureData.h:395
bool IsTameable(bool canTameExotic) const
{
    if (type != CREATURE_TYPE_BEAST              // 关卡1：必须是野兽
        || family == CREATURE_FAMILY_NONE        // 关卡2：必须有宠物家族
        || (type_flags & CREATURE_TYPE_FLAG_TAMEABLE) == 0)  // 关卡3：必须标记可驯服
        return false;
    return canTameExotic || !IsExotic();
}
```

**关键发现**：真正执行驯服的 `EffectTameCreature()`（SpellEffects.cpp:3010）里
**完全没有生物类型检查**，只有一句：

```cpp
if (unitCaster->GetClass() != CLASS_HUNTER)
    return;
```

也就是说，**放开 `IsTameable()` 就能捕捉任何生物**，不需要改别的地方。

## 三个必须处理的现实问题

### 1. `family == CREATURE_FAMILY_NONE` 这关不能简单拆掉

宠物的技能、模型、成长曲线都来自 `CreatureFamily.dbc`。
没有 family 的生物变宠物后会：无宠物技能、宠物栏异常、**可能崩客户端**。

**解法**：
- 方案一：动态给目标指定一个通用 family（如野猪）
- 方案二：新建自定义 family 供所有非野兽使用

### 2. BOSS 必须拉黑

不加限制能把死亡之翼抓成宠物。建议按 `rank` 过滤：

```cpp
if (rank == CREATURE_ELITE_WORLDBOSS || rank == CREATURE_ELITE_RAREELITE)
    return false;
```

### 3. 宠物属性继承原生物

抓 80 级精英 = 得到 80 级精英属性的宠物。
配合大数值改造可能强到离谱，需要加缩放系数。

# 附录 B：无限制施法 + AI 智能辅助 —— 已核实

> 状态：**已完成源码核实，暂不执行**。

## 一、重要区分：「施法间隔」其实是三个不同的东西

很多人混为一谈，但源码里是三套独立机制：

| 机制 | 含义 | 例子 |
|---|---|---|
| **施法时间 (CastTime)** | 读条时长 | 火球术读条 3 秒 |
| **法术冷却 (Cooldown)** | 单个技能的CD | 冲锋 15 秒 CD |
| **全局冷却 (GCD)** | 用任何技能后的 1~1.5 秒硬直 | 所有职业通用 |

**你说的「不间断施法」主要指第 3 个 GCD**，但可能三个都想去掉。

## 二、好消息：功能已经存在，且天然只对玩家生效

源码 `Spell.cpp:8626` —— GCD 触发处：

```cpp
void Spell::TriggerGlobalCooldown()
{
    if (!CanHaveGlobalCooldown(m_caster))
        return;
    if (!m_spellInfo->StartRecoveryCategory)
        return;

    // ★ 关键：只有玩家能通过这个开关跳过 GCD
    if (m_caster->GetTypeId() == TYPEID_PLAYER)
        if (m_caster->ToPlayer()->GetCommandStatus(CHEAT_COOLDOWN))
            return;
    ...
}
```

`TYPEID_PLAYER` 判断意味着 **怪物和 BOSS 永远不受影响**，
完全符合你「怪物不要有这个功能」的要求。

现成的三个开关（`Player.h:810`）：

```cpp
enum PlayerCommandStates
{
    CHEAT_GOD       = 0x01,
    CHEAT_CASTTIME  = 0x02,   // 瞬发（去掉读条）
    CHEAT_COOLDOWN  = 0x04,   // 无CD + 无GCD
    CHEAT_POWER     = 0x08,   // 无蓝耗
    CHEAT_WATERWALK = 0x10
};
```

对应游戏内指令（**现在就能用**）：

```
.cheat casttime    瞬发
.cheat cooldown    无CD + 无GCD ← 你要的核心功能
.cheat power       无消耗
```

生效点已核实：
- `Spell.cpp:3308`  CHEAT_CASTTIME → 跳过读条
- `Spell.cpp:3735`  CHEAT_COOLDOWN → 跳过法术冷却
- `Spell.cpp:8635`  CHEAT_COOLDOWN → 跳过 GCD
- `Spell.cpp:4948`  CHEAT_POWER → 跳过法力消耗

## 四、AI 智能辅助 —— 可行但要分层看

你想要「自动放伤害技能 + 自动保命」，这在技术上分三个层次：

### 层次 1：服务端自动施法（可行，但体验差）

**技术**：Eluna 的 `PLAYER_EVENT_ON_ENTER_COMBAT` + 定时器，
每 N 毫秒判断一次，自动调 `player:CastSpell()`。

**问题**：
- 服务端不知道你的**意图**（想集火哪个目标？想省蓝？）
- 技能选择只能靠硬编码优先级，不够聪明
- 每个职业每个天赋都要单独写逻辑（11职业 × 3天赋 = 33套）

### 层次 2：智能提示（推荐先做）

不自动放，而是**提示你该放什么**：

```
- 血量低于30% -> 屏幕提示「建议使用：治疗石」
- BOSS读条中  -> 提示「建议打断」
- 增益快过期  -> 提示「刷新BUFF」
```

**优点**：保留操作感，不会「代打」到无聊。

### 层次 3：完整战斗 AI（大工程）

真要做成「像有个AI辅助我」，需要：
- 技能优先级表（每职业每天赋一套）
- 资源管理（能量/怒气/法力预判）
- 目标选择（AOE还是单体？）
- 打断/保命时机判断

**工时估算：每个职业 20~40 小时**，11 个职业就是 200~400 小时。

### ⚠️ 一个现实提醒

**NPCBot 已经有完整的战斗 AI 了**（`bot_ai.cpp` 有 15000+ 行）。
如果目标是「不想手动操作」，更快的路径是：

```
让 NPCBot 控制你的角色（或者说，你只需下指令，bot 负责输出）
```

而不是从零写一套玩家 AI。

# 附录 C：真龙自动战斗 —— 复用 NPCBot AI 的可行性（已核实）

> 补充说明：真龙设定里「可操控所有生物和力量」，
> 因此自动施法不是可选项，而是**设定的一部分**。

## 一、关键技术障碍

```cpp
// bot_ai.h:51
class bot_ai : public CreatureAI
```

**NPCBot 的 AI 继承自 `CreatureAI`，绑定的是 Creature 而非 Player。**

这意味着**不能直接把 bot_ai 挂到玩家身上**。玩家用的是
`PlayerAI`（如果有）或者根本没有 AI 层。

## 二、但有三条可行路径

### 路径 A：影子 Bot（推荐，最省事）

思路：**不改玩家，而是让一个隐形 bot 替你施法**。

```
玩家开启「自动战斗」
  -> 后台生成一个隐形的 NPCBot（跟随玩家、不可见、不占队伍位）
  -> bot 复制玩家的技能列表和目标
  -> bot 施法，视觉效果作用在玩家身上
```

**优点**：
- 完全复用 bot_ai 的 15000 行成熟逻辑
- 19 个职业 AI 现成可用
- 不用改玩家的战斗代码

**难点**：施法视觉来源是 bot 不是玩家，需要处理表现层。

### 路径 B：提取技能优先级表（工作量中等）

不复用整个 AI，只**提取每个职业的技能优先级逻辑**：

```cpp
// bot_ai.h 里的可复用接口
uint32 GetSpell(uint32 basespell) const;
bool doCast(Unit* victim, uint32 spellId, bool triggered);
virtual void CheckAttackState();
void CheckUsableItems(uint32 diff);
```

把 `bot_XXX_ai.cpp` 里的判断逻辑抄成玩家版本。

**现成可参考的 19 个职业 AI**：

```
标准职业(9)：warrior / paladin / hunter / rogue / priest
              death_knight / shaman / mage / warlock / druid
魔兽3英雄(9)：archmage(大法师) / bm(剑圣) / crypt_lord(地穴领主)
              dark_ranger(黑暗游侠) / dreadlord(恐惧魔王)
              necromancer(亡灵法师) / sea_witch(娜迦海巫)
              spellbreaker(血法师) / sphynx(斯芬克斯)
```

> ⭐ 那 9 个魔兽3英雄 AI 对「真龙可操控所有力量」的设定
> 简直是现成素材 —— 真龙可以切换不同「形态」，
> 每个形态套用一套英雄 AI。

### 路径 C：Eluna 脚本层（最灵活，但要自己写逻辑）

用 `PLAYER_EVENT_ON_ENTER_COMBAT` + 定时器，Lua 里写技能循环。

**优点**：改完 reload 即生效，迭代快，容易做开关
**缺点**：技能优先级要自己写，但**只需为真龙一个职业写**

## 三、针对真龙的具体建议

既然真龙是**唯一**需要自动战斗的职业，那就**不用做全职业 AI**：
