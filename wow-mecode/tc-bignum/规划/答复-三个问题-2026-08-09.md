## 问题3（最急）· 闪退和拍卖行【无关】

详见 `补丁库/02_修复/F36_游荡bot数量ASSERT崩服/根因与修复.md`

**一句话**：

```ini
NpcBot.WanderingBots.Continents.Count = 802    ->   改成 750
```

原因：可用 bot 模板只剩 801 个，你要 802 个，
`botdatamgr.cpp:1885 ASSERT(false)` 直接中止启动。

**每固定/招募一个 bot，空闲池就少一个**，所以要留余量。

> 你上传的旧 conf 里这项是 `0`，说明是后来改的。
> 不确定配多少就先改回 `0` 确认能启动，再往上加。

## 问题1 · 拍卖行：conf 只是第1步，后面还有 4 步

**conf 能做到的**：货架满、种类全、每小时补货、不上架灵魂绑定装备。

**conf 做不到的**（需要写代码）：

| 步骤 | 内容 | 为什么 conf 做不到 |
|---|---|---|
| **第2步** | Buyer 价格调优 | 你的 Buyer 已开着，有刷钱风险，要算数值 |
| **第3步** | 经济钩子与账本 | 要挂 `OnAuctionAdd`，记录 bot 赚了多少 |
| **第4步** | **pbot 真的去拍卖行挂单** | 要构造包、走 `HandleAuctionSellItem` |
| **第5步** | 打工层（卖垃圾/修装备/采集） | 全是新代码 |

### 现在的状态 vs 目标状态

```
现在（conf 改完后）
  AHBot 凭空造货 -> 挂在影子账号名下 -> 玩家买
  【本质是个自动商店，不是"经济"】

第4步之后
  pbot 打怪捡到装备 -> 自己跑去拍卖行 -> 挂单 -> 玩家买 -> pbot 收到金币
  【货物有来源，金币有去向，这才是经济】
```

**第4步是质变点。** 我上次查过 mod-playerbots，
它的 `LootAction.cpp:280 AuctionItem()` 实现了这个，
但**整段被 `/* */` 注释掉了**（`:259` 到 `:353`），并未启用。

所以这块**没有现成的可抄，得我们自己做**。技术路径已探明：

```cpp
WorldSession.h:937            HandleAuctionSellItem(WorldPacket&)   public(706段)
AuctionHouseHandler.cpp:189   GetNPCIfCanInteractWith(auctioneer, UNIT_NPC_FLAG_AUCTIONEER)
                              ^^^ 这道门要求 pbot 站在拍卖师旁边（5码内）
ObjectDefines.h:24            #define INTERACTION_DISTANCE 5.0f
```

**pbot 是真 Player 有真 session，所以能走正规下单路径** ——
这是它比 NPCBot 强的地方（NPCBot 的 guid 类型对不上，
`QueryHandler.cpp:81` 那条 CharacterCache 路径查不到它）。

### 我的建议

**先把 conf 跑通看效果，再决定要不要做第4步。**

因为第4步的收益取决于你玩法：
- 如果你只是想"拍卖行有东西买" -> conf 就够了
- 如果你想"看到鲤鱼把打到的装备挂上去卖" -> 才需要第4步

## 问题2 · 问号武器：exe 补丁解决不了，必须改 DBC

**先纠正我之前的说法**：我说过"补丁 exe 能解决自定义物品红问号"，
这个说法**不准确**，让你白折腾了。

### 为什么 exe 补丁不管用

红问号的成因是**客户端找不到物品的显示数据**：

```
服务端  item_template 表有这个物品      -> 服务端知道它是什么
客户端  Item.dbc / ItemDisplayInfo.dbc  -> 客户端【不知道】
        -> 图标画不出来 -> 红问号
```

**补丁 exe 改的是"允许加载哪些文件"**（文件夹当MPQ、Interface Edits、4GB内存），
**它不会凭空给客户端补上物品数据**。

工作区里 `工具库/19-补丁exe到底给了你什么.md` 列了 exe 的五项价值，
"自定义物品修复"那一项**指的是让客户端不因为找不到数据而崩溃**，
不是"让物品正常显示"。这是我表述不清。

### 正确解法：给客户端补 DBC

**必须改两个 DBC**（服务端和客户端都要，坑表铁律：两边必须一致）：

| DBC | 作用 | 缺了会怎样 |
|---|---|---|
| `Item.dbc` | 物品ID -> 显示ID/品质/背包类型 | **红问号** |
| `ItemDisplayInfo.dbc` | 显示ID -> 模型/图标文件名 | 有名字但没图标 |

### 好消息：有自动化工具

`待办总表.md:248` 记过：

> **WDBX Editor 自带 `WotLK Item Import`** —— 解自定义物品红问号

**用法**：
```
1. WDBX Editor 打开客户端的 Item.dbc
2. 菜单找 WotLK Item Import
3. 连你的 world 数据库，指定 item_template
4. 它会自动把缺失的物品补进 Item.dbc
5. 存盘 -> 打包成 MPQ 补丁 -> 放进 Data 目录
6. 服务端 dbc 目录也放一份同样的
```

**关键**：`Item.dbc` 里的 `DisplayInfoID` 必须指向一个**已存在的**
`ItemDisplayInfo.dbc` 条目。最省事的做法是**复用现有物品的显示ID**
（比如你的自定义战刃，就用某把官方战刃的 DisplayInfoID）。

### 最省事的替代方案

如果你的自定义物品不多，**直接用官方物品的 DisplayInfoID**：

```sql
-- 查一把官方战刃的显示ID，抄给你的自定义物品
SELECT `entry`, `name`, `displayid`
FROM `world`.`item_template`
WHERE `name` LIKE '%战刃%' AND `entry` < 60000
LIMIT 10;

-- 把自定义物品的 displayid 改成官方的
UPDATE `world`.`item_template`
SET `displayid` = 【抄来的显示ID】
WHERE `entry` = 【你的自定义物品ID】;
```

**这样连 DBC 都不用改** —— 因为那个 DisplayInfoID 客户端本来就有。
代价是外观和官方物品一样。

> **但这只解决图标**。如果客户端 `Item.dbc` 里完全没有这个 entry，
> 还是会红问号。3.3.5 的规则是：
> **entry 必须在客户端 Item.dbc 里存在**，否则背包里显示不出来。

### 需要你确认

这三条决定用哪个方案：

```
1. 你的自定义物品 entry 是多少？（800000+ ？）
2. 数量大概多少个？（10个 还是 1000个）
3. 你的客户端 Data 目录里，有没有自己打的 patch-X.MPQ？
```

数量少（<50）用"抄官方 DisplayInfoID"最快；
数量多就得上 WDBX Editor 批量导入。
