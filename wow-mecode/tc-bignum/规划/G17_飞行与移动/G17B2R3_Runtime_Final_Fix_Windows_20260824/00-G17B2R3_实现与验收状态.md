## 技能4 根因（本次证据链完整闭环）

解析项目真实客户端 `Spell.dbc`（`g17r5_lifecycle/create/DBFilesClient/Spell.dbc`，49839 条记录、234 字段，按 fork `src/DBCStructure.h` SpellEntry 布局）：

| 字段 | 值 | 说明 |
|---|---|---|
| Attributes | 256 = SPELL_ATTR0_CASTABLE_WHILE_MOUNTED | 客户端按钮可在骑乘时按（OK） |
| RequiresSpellFocus | **1553** | 需要“飞行器”法术焦点 → `SPELL_FAILED_REQUIRES_SPELL_FOCUS` |
| CasterAuraSpell | **52255** | 需要施法者光环 52255 → `SPELL_FAILED_CASTER_AURASTATE` |
| Stances/StancesNot | 0 | 姿态无限制 |
| EquippedItemClass | -1 | 无装备限制 |
| Reagent/Totem | 全 0 | 无试剂/图腾 |
| Effect1 | 3 (SPELL_EFFECT_DUMMY) | 保留原生 Dummy |

核心 `Spell::CheckCast` 顺序（fork `src/Spell.cpp`）：死亡/冷却 → 形状/姿态 → 施法者光环(**CasterAuraSpell**) → 数据库条件 → 目标/朝向/LOS → 地图/坐骑 → **法术焦点(RequiresSpellFocus)** → 物品/试剂 → 射程/能量 → `CallScriptCheckCastHandlers()`（=我们的 OnCheckCast）。**焦点和光环检查都在脚本钩子之前**，所以 B2R1/R2 的 OnCheckCast/AfterCast 永远没机会执行——这就是“完全无法使用”的原因。

关键事实：fork 的 `spell_dbc` 覆盖表（见 fork `world_database.sql`）**没有 `RequiresSpellFocus` / `CasterAuraSpell` 列**，SQL 覆盖永远清不掉这两个限制 → 必须 C++ 运行时净化。

## B2R3 修复

### 修复1：技能4（权威）
新增 `G17Dragonriding::EnsureLandingCommandCastable()`（同文件）：
- 启动时（AddSC + 乘客上马的 PassengerBoarded 双保险）把 52226 的 SpellInfo 运行时清零：`RequiresSpellFocus`、`CasterAuraSpell/TargetAuraSpell/Exclude*`、`CasterAuraState/TargetAuraState/Exclude*`、`TargetCreatureType`、`Stances/StancesNot`、`EquippedItemClass=-1/SubClass/InvTypes`、Reagent/ReagentCount、Totem/TotemCategory。
- 只动服务端运行副本，**客户端 Spell.dbc / 按钮名称 / 图标完全不动**。
- 保留 OnCheckCast 放行 + OnEffectHit 抑制原生 Dummy + AfterCast 幂等兜底。
- 启动日志证明行：`>> G17-B2R3 landing command 52226 cast-gates cleared (focus/aura/item/stance); ...`

### 修复2：技能3 防倒车
`StartForwardClimb()` 重排：
- 旧：先 `BuildClimbPath`（取坐标）→ 后 `RestoreClientFlightControl(true)`（Clear 旧运动）。
- 新：先 `RestoreClientFlightControl(true)` + `me->StopMoving()`（StopMoving 会先 `UpdateSplinePosition` 把旧 spline 结算到真实端点）→ 锁定朝向 → **再从结算后的真实位置** `BuildClimbPath` 取样 → 启动。
- 效果：冲刺从静止状态开始，客户端不再看到“旧后退 spline 收尾 + 新路径起点”的错位倒车。
