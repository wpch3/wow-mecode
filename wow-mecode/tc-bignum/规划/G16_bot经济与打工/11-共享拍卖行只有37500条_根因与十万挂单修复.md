## 一、你给出的结果没有算错

你给出的 13 个物品类别数量为：

| 类别 | 数量 |
|---|---:|

| 武器 | 5,950 |

| 配方（class 9） | 4,553 |

`37,500` 不是某个类别的上限，也不是「每类应该有一万但没有补完」。AHBot 的 `Items.Amount.*` 是按品质给出的总预算，再按 `Class.*` 权重分配到各类别；它从来不会让每个类别都达到一万。

## 二、已经由源码证明的真正原因

你的主配置使用：

```ini
AllowTwoSide.Interaction.Auction = 1
```

上游配置说明已经明确写明：开启后，所有拍卖都按中立拍卖行处理，并且 AHBot 只应配置中立行。

源码链如下：

1. `AuctionHouseMgr.cpp:58-61`

```cpp
if (sWorld->getBoolConfig(CONFIG_ALLOW_TWO_SIDE_INTERACTION_AUCTION))
    return &mNeutralAuctions;
```

联盟、部落、中立三种查询全部返回同一个 `mNeutralAuctions`。

2. `AuctionHouseMgr.cpp:75-78`

按数据库 `houseid` 载入拍卖时，跨阵营开启后也全部装进同一个中立内存池。

3. `AuctionHouseBot.cpp:58-67`

上游会直接警告：跨阵营拍卖开启时，AHBot 应只启用 Neutral；联盟和部落的独立设置可能不按预期工作。

4. `AuctionHouseBot.cpp:484-509`

`.ahbot status` 对 Alliance/Horde/Neutral 分别调用 `GetAuctionsMap(ahType)`。但跨阵营开启时三次拿到的是同一个指针，于是同一批约 39,500 条会显示三遍，最后又相加成约 118,500。

### 结论

旧配置：

```ini
Alliance Ratio = 100
Horde Ratio    = 100
Neutral Ratio  = 100
```

并不等于三个独立拍卖池各 39,700 条。三个卖家配置轮流检查的是同一个共享池，并且每一个都以约 39,700 为自己的目标。因此数据库中真正的唯一挂单总数仍然只会在约 39,700 附近，而不是 119,100。

你现在查到 `37,500`，就是单个共享池接近原 `39,700` 目标的结果：

```text
37500 / 39700 = 94.46%
```

剩余约 2,200 条差异可以来自正常过期、刚执行 rebuild 后仍在回补、部分品质/类别物品池为空以及分配取整；它不可能解释「为什么没有十万条」。十万条缺口的根因就是三行被合并，而不是补货速度。

## 三、真正约 10 万条的正确配置

保留跨阵营共享拍卖行，并只启用 Neutral：

```ini
AuctionHouseBot.Alliance.Items.Amount.Ratio = 0
AuctionHouseBot.Horde.Items.Amount.Ratio = 0
AuctionHouseBot.Neutral.Items.Amount.Ratio = 250
```

你当前七个品质预算合计：

```text
2000 + 12000 + 12000 + 8000 + 5000 + 500 + 200 = 39700
```

Neutral 设为 `250` 表示 250%：

```text
39700 × 250% = 99,250 条 AHBot 目标挂单
```

这才是数据库里接近十万条**唯一挂单**的配置。`250` 在源码允许的 `0..10000` 范围内。

仓库中的权威配置已同步改成：

```text
tc-bignum/conf/worldserver.conf.d/ahbot.conf
```

并按你最后的选择把 `AuctionHouseBot.Class.Misc` 保持为 `2`；它只改变类别配额分布，不改变七个品质总预算约 99,250 的结论。

## 四、一次生效的执行顺序

1. 把更新后的 `ahbot.conf` 覆盖到运行服的：

```text
worldserver.conf.d\ahbot.conf
```

2. 游戏或 worldserver 控制台执行：

```text
.reload config
.ahbot reload
.ahbot rebuild all
```

顺序不能反：`.reload config` 先把磁盘配置载入 `ConfigMgr`，`.ahbot reload` 才会从新的内存配置重建 AHBot 配置和物品池。

3. 执行 `.ahbot status all`，只用它确认 Ratio 已变成：

```text
Alliance = 0
Horde = 0
Neutral = 250
```

**不要再把 status 的三列 ItemsCount 相加。** 在 `AllowTwoSide.Interaction.Auction=1` 时三列仍可能重复显示同一个共享池，这是上面已经证明的实现行为。

4. 用同目录的只读 SQL 验证数据库唯一行数：

```text
12-共享拍卖行_只读诊断.sql
```

主要看结果 1 的 `unique_auctions` 和结果 2 的 `ahbot_rows`。目标是 AHBot 有效挂单接近 `99,250`；玩家自己的挂单应单独计算，不计入 AHBot 目标。

5. 新配置从约 37,500 增至约 99,250，缺口约 61,750。Boost 为每轮最多 5,000，60 秒一轮，理论上需要约 13 个补货轮次；最终几千条可能进入 Normal 分支。这里给等待时间只是执行后的预期，不是诊断结论——根因和配置修复已经确定。

6. 稳定后建议把：

```ini
AuctionHouseBot.Update.Interval = 60
```

改回：

```ini
AuctionHouseBot.Update.Interval = 3600
```

然后再次执行：

```text
.reload config
.ahbot reload
```

## 五、如何判定修复成功

同时满足以下条件才算完成：

- [ ] `AllowTwoSide.Interaction.Auction = 1`；
- [ ] Ratio 为 `0 / 0 / 250`；
- [ ] SQL 中 `ahbot_rows` 接近 `99,250`，而不是拿 `.ahbot status` 三列相加；
- [ ] rebuild 后旧 `houseid=2/6` 的 AHBot 挂单逐步过期，新挂单主要为 `houseid=7`；
- [ ] 联盟、部落和中立拍卖师都能看到同一套共享商品；
- [ ] 数据库总行数与 `COUNT(DISTINCT itemguid)` 一致；
- [ ] 玩家挂单和 AHBot 挂单已分开统计。

如果将来希望联盟、部落、中立真的是三个独立市场，就必须把 `AllowTwoSide.Interaction.Auction` 改为 `0`，届时才使用三个 Ratio 各 `100`。这会改变玩家访问已有拍卖的方式，上游配置说明也警告生产服切换时旧阵营挂单会暂时不可见，因此本次不采用这条路线。
