## 二、为什么我放弃自己推荐的修法A

08 号文档我推荐"把 `Bind.Pickup` 改回 1 + 黑名单排除金色战刃"。
**现在我要收回这个建议**，理由是它有个我当时没算清的副作用：

```
Bind.Pickup = 1  会放行【所有】拾取绑定物品
                 = 295 种坐骑  [是] 想要
                 + 全服所有 BoP 装备（副本紫装 / 任务奖励 / PvP 装 / 稀有掉落）  [否] 不想要
```

而你上一批刚刚说过：**「其他的物品都丰富了」**——说明你对当前的物品构成是满意的。

修法A 会把一大批 BoP 装备重新灌进拍卖行，**等于把上一批好不容易调好的"不杂乱"又推翻**。
为了 295 种坐骑，赔上整个拍卖行的清爽度，不划算。

**所以改用修法B：白名单精确放行，只放坐骑，一件装备都不多放。**

## 三、修法B：把 295 种坐骑塞进白名单

### 原理（实查依据）

```
AuctionHouseBotSeller.cpp:123-129
        if (includeItems.count(itemId))
        {
            _itemPool[prototype->GetQuality()][prototype->GetClass()].push_back(itemId);
            ++itemsAdded;
            continue;          <- 直接入池，【跳过下面所有过滤】
        }
AuctionHouseBotSeller.cpp:131-156   绑定过滤（白名单根本走不到这）
```

白名单在绑定过滤**之前**，所以进了白名单的坐骑，
**不管 `Bind.Pickup` 是 0 还是 1 都能上架**。

`Bind.Pickup` 继续保持 0 → BoP 装备继续被挡在外面 → 拍卖行保持清爽。

### 容量确认（不用担心 ID 太多）

```
AuctionHouseBot.h:220   std::string const& GetAHBotIncludes() const { return _AHBotIncludes; }
AuctionHouseBotSeller.cpp:50-54
        std::stringstream includeStream(sAuctionBotConfig->GetAHBotIncludes());
        while (std::getline(includeStream, temp, ','))
            includeItems.insert(atoi(temp.c_str()));
```

存储是 `std::string`，解析成 `std::unordered_set<uint32>`，**没有任何长度上限**。
你现在 359 项，加到 600 多项完全没问题。

## 四、执行步骤

### 第1步：生成坐骑 ID 列表

在 DBeaver 执行，**结果是一长串数字**：

```sql
SELECT GROUP_CONCAT(`entry` ORDER BY `entry` SEPARATOR ',') AS `坐骑entry列表`
FROM `world`.`item_template`
WHERE `class` = 15
  AND `subclass` = 5
  AND `Quality` < 7
  AND `bonding` = 1;
```

> 只取 `bonding = 1` 那 295 种——因为 bonding 0 和 3 本来就能上架，
> 重复加进白名单没意义（虽然也无害）。

**DBeaver 注意**：结果可能显示不全被截断。
右键那个单元格 → **Copy** 或 **View Value**，确保拿到完整字符串。

如果你想稳妥一点，也可以用这条**分段输出**，避免超长截断：

```sql
SELECT COUNT(*) AS `应该有295个`
FROM `world`.`item_template`
WHERE `class` = 15 AND `subclass` = 5 AND `Quality` < 7 AND `bonding` = 1;
```

先确认数量对得上，再复制上面那条的结果。

### 第2步：追加进主 conf

打开 `D:\TC-Build\bin\RelWithDebInfo\worldserver.conf`，
搜索 `AuctionHouseBot.forceIncludeItems`，找到那一行（很长）。

**在现有内容的末尾**，先加一个英文逗号 `,`，再粘贴第1步的结果。

```ini
AuctionHouseBot.forceIncludeItems = "……你现有的359项……,<粘贴295个坐骑ID>"
```

**三个注意点**：
```
[ ] 不要删掉现有的 359 项，是【追加】不是替换
[ ] 现有内容和新内容之间必须有一个英文逗号，且【不要有空格】
[ ] 如果原值有引号，保持引号包裹；整串必须在【同一行】，不能换行
```

> **为什么改主 conf 而不是 ahbot.conf**：
> `forceIncludeItems` 你已经在主 conf 里配了 359 项。
> 如果在 ahbot.conf 里再写一个同名项，会**整个覆盖**掉主 conf 那 359 项
> （`Config.cpp:166 put_child` 是覆盖语义，不是追加）。
> **所以必须在主 conf 原地追加。**

### 第3步：生效

```
.reload config
.ahbot reload
.ahbot rebuild all
```

### 第4步：验证

等铺货后（`Update.Interval` 若还是 60 秒，约 25 分钟），跑：

```sql
SELECT
    COUNT(DISTINCT ii.`itemEntry`) AS `坐骑种类数`,
    COUNT(*)                       AS `坐骑挂单数`
FROM `characters`.`auctionhouse` a
JOIN `characters`.`item_instance` ii ON ii.`guid` = a.`itemguid`
JOIN `world`.`item_template` it      ON it.`entry` = ii.`itemEntry`
WHERE it.`class` = 15 AND it.`subclass` = 5;
```

**预期**：种类数从 3 涨到几十甚至上百（取决于配额抽样）。

## 五、如果嫌 295 个太多，可以只放常用的

不想让稀有坐骑（如陨落的宝藏、大脚野人）也满天飞的话，用这条替代第1步：

```sql
-- 只放 普通/优秀/精良 品质，且需求等级 <= 80 的坐骑
SELECT GROUP_CONCAT(`entry` ORDER BY `entry` SEPARATOR ',') AS `坐骑entry列表`
FROM `world`.`item_template`
WHERE `class` = 15
  AND `subclass` = 5
  AND `bonding` = 1
  AND `Quality` <= 3
  AND `RequiredLevel` <= 80;
```

先跑这条看看数量：

```sql
SELECT `Quality`, COUNT(*) AS `种类数`
FROM `world`.`item_template`
WHERE `class` = 15 AND `subclass` = 5 AND `Quality` < 7 AND `bonding` = 1
GROUP BY `Quality` ORDER BY `Quality`;
```
