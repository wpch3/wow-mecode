## 一、羁绊系统（陪伴越久，话越多）

### 核心设计：好感度不是数字，是"共同经历"

很多游戏的好感度就是个进度条，刷满了给奖励。**那样没意思。**

我们做的是：**bot 记住和你一起做过什么，然后在合适的时候提起。**

### 数据表

```sql
-- characters 库
CREATE TABLE `npcbot_bond` (
  `bot_guid`        INT UNSIGNED NOT NULL,
  `owner_guid`      INT UNSIGNED NOT NULL,
  `bond_level`      TINYINT UNSIGNED DEFAULT 0,   -- 羁绊等级 0-5
  `bond_points`     INT UNSIGNED DEFAULT 0,       -- 累计点数
  `time_together`   INT UNSIGNED DEFAULT 0,       -- 一起在线的秒数
  `battles_won`     INT UNSIGNED DEFAULT 0,       -- 一起打赢的战斗
  `times_saved_me`  INT UNSIGNED DEFAULT 0,       -- bot救过你几次
  `times_i_saved`   INT UNSIGNED DEFAULT 0,       -- 你救过bot几次
  `deaths_together` INT UNSIGNED DEFAULT 0,       -- 一起团灭过几次
  `first_met`       INT UNSIGNED DEFAULT 0,       -- 初遇时间戳
  PRIMARY KEY (`bot_guid`, `owner_guid`)
);
```

### 羁绊等级与解锁内容

| 等级 | 称呼 | 解锁 |
|---|---|---|
| 0 | 雇佣关系 | 只说必要的话（现在的 step34）|
| 1 | 认识了 | 开始闲聊见闻 |
| 2 | 熟人 | 会问你的想法、提议去哪 |
| 3 | 朋友 | **主动送东西**、记得共同经历 |
| 4 | 战友 | 危险时会挡在你前面、说重话 |
| 5 | 生死之交 | **专属台词**、会说很私人的事 |

### 台词表扩展（复用 step34 的表结构）

```sql
ALTER TABLE `world`.`npcbot_care_text`
  ADD COLUMN `min_bond` TINYINT UNSIGNED DEFAULT 0 COMMENT '需要的羁绊等级';
```

**只加一列，不动现有结构。** 挑台词时多一个过滤条件。

### 温馨话语示例（按羁绊等级）

```
等级1  「这一路还算顺利。」
等级2  「你有没有想过，等这些事都完了要做什么？」
等级3  「上次那个洞里，要不是你拉我一把，我就交代在那了。」
等级4  「你先走，这里我来。」
等级5  「说实话，我以前是一个人惯了。现在……有点习惯不了一个人。」
```

**关键**：等级5的台词要**少而重**，一天说一次就够，说多了廉价。

### 羁绊点数怎么涨

| 事件 | 点数 | 钩子 |
|---|---|---|
| 一起在线 1 分钟 | +1 | 现有的 UpdateCompanionCare |
| 一起击杀精英/BOSS | +10 | `OnCreatureKill` |
| bot 救了你（你血<20%时它治疗/拉仇恨）| +20 | 自定义判定 |
| 你复活了 bot | +20 | 自定义判定 |
| 一起团灭 | +5 | **共患难也算感情** |
| 给 bot 好装备 | +15 | 装备变更时 |

## 二、对手系统（这个更有意思）

### 核心：世界上有几个"认识你"的敌人

不是随机怪，是**特定的、会记住你的对手**。

### 设计

```sql
CREATE TABLE `npcbot_rival` (
  `bot_guid`      INT UNSIGNED NOT NULL,
  `player_guid`   INT UNSIGNED NOT NULL,
  `rival_level`   TINYINT UNSIGNED DEFAULT 0,  -- 敌意等级 0-5
  `my_wins`       INT UNSIGNED DEFAULT 0,      -- bot赢了几次
  `your_wins`     INT UNSIGNED DEFAULT 0,      -- 玩家赢了几次
  `corpse_camped` INT UNSIGNED DEFAULT 0,      -- 被守尸次数
  `last_encounter` INT UNSIGNED DEFAULT 0,
  PRIMARY KEY (`bot_guid`, `player_guid`)
);
```

### 已确认可用的钩子（实查 ScriptMgr.h）

```cpp
ScriptMgr.h:664   virtual void OnDuelRequest(Player* target, Player* challenger);
ScriptMgr.h:667   virtual void OnDuelStart(Player* player1, Player* player2);
ScriptMgr.h:670   virtual void OnDuelEnd(Player* winner, Player* loser, DuelCompleteType type);
ScriptMgr.h:634   virtual void OnPVPKill(Player* killer, Player* killed);
ScriptMgr.h:637   virtual void OnCreatureKill(Player* killer, Creature* killed);
ScriptMgr.h:640   virtual void OnPlayerKilledByCreature(Creature* killer, Player* killed);
ScriptMgr.h:731   virtual void OnPlayerRepop(Player* player);
ScriptMgr.h:643   virtual void OnLevelChanged(Player* player, uint8 oldLevel);
```

**用户要的四个场景，钩子全都有。**

### 场景 1：主动挑衅

```
触发：对手bot看到你（视野内）+ 冷却已过
行为：Yell 或 TextEmote

  敌意0  「……」（只是盯着你）
  敌意1  「又是你。」
  敌意2  「上次让你跑了。」
  敌意3  「这次别想走。」  + 拔武器动作
  敌意5  「我找你很久了。」  + 全屏红字（step30 的 BOSS 提示）
```

**动作挑衅**：接 step29 的 `.emote` 系统
```
EMOTE_ONESHOT_RUDE       （鄙视）
EMOTE_ONESHOT_ROAR       （咆哮）
EMOTE_ONESHOT_POINT      （指着你）
EMOTE_STATE_READY2H      （举武器）
```

### 场景 2：决斗时的棋逢对手

```cpp
OnDuelRequest  ->  「有点意思。」/「你确定？」
OnDuelStart    ->  「让我看看你有多少长进。」
OnDuelEnd(赢)  ->  「还是差一点。」
OnDuelEnd(输)  ->  「……你变强了。」   <- 敌意高时会变成认可
```

**彩蛋**：连续决斗 10 次以上，**敌意会转化成尊重**：
```
「说起来，我们打了这么多次，还不知道你叫什么。」
-> 羁绊系统解锁：对手可以变成盟友
```

**这是我最想做的一个设计** —— 宿敌变战友。

### 场景 3：被守尸会气急败坏

```
判定：同一个对手在 60 秒内被同一玩家杀 2 次以上
行为：
  第2次  「卑鄙……」
  第3次  「你就只会这套吗！」  + EMOTE_ONESHOT_RUDE
  第4次  「够了！」  + 召唤增援 / 逃跑 / 变强（buff）
```

**「气急败坏」不只是说话，要有实际反应** —— 这样才有分量。

### 场景 4：战场互动

| 情境 | 反应 |
|---|---|
| 你血量低于 20% | 「结束了。」（追击）|
| 它血量低于 20% | 「不……还没完！」（狂暴或逃跑）|
| 你被别人杀了 | 「本来该由我来的。」|
| 它救了你（阵营变化时）| 「别误会，我只是不想欠你的。」|
| 长时间没见 | 「好久不见。你没死，我很意外。」|

## 三、我额外想到的功能（用户问"还有什么"）

### A. 传承系统（bot 会"死"，但留下东西）

如果开启硬核模式，bot 永久死亡时：
```
- 留下它的装备和遗言
- 遗言内容取决于羁绊等级
- 羁绊5的会说：「帮我把这个……交给……」（引出剧情）
```

**这能让"带 bot"这件事有真正的分量。**

### B. bot 的过去（每个bot有随机身世）

```sql
CREATE TABLE `npcbot_backstory` (
  `id` INT, `race_mask` INT, `class_mask` INT,
  `origin` VARCHAR(200),      -- 「我以前在藏宝海湾当过码头工。」
  `motivation` VARCHAR(200),  -- 「我在找我弟弟。」
  `secret` VARCHAR(200)       -- 羁绊5才会说的秘密
);
```

**随机组合，每个bot都不一样。** 纯数据，零风险。

### C. bot 之间的关系网

```
两个bot同队时：
  同种族   -> 互相照应
  世仇种族 -> 拌嘴（兽人vs人类）
  同职业   -> 攀比装备
  互补职业 -> 配合台词（法师给术士递水时的调侃）
```

### D. 节日与时间感知

```
现实时间深夜   -> 「你该睡了。」
游戏内下雨     -> 「这鬼天气。」
万圣节等节日   -> 专属台词
你连续在线4小时 -> 「歇会儿吧，我等你。」
```

**「你该睡了」这种话，是最能建立情感连接的。**

### E. 战斗中的实时呼喊

```
你被围攻      -> 「撑住！我来了！」
它交大招      -> 「都让开！」
残血反杀      -> 「漂亮！」
你操作失误    -> 「……下次小心点。」
```

**接 step30 的 `.say` 系统，全屏提示已经做好了。**

### F. bot 会向你提要求（不只是给予）

```
「这把剑该换了。」          （装备落后时）
「能给我留点钱吗？我想买匹马。」
「下次能不能别把我一个人丢在后面。」
```

**会提要求的伙伴才像人**，只会给予的是工具。

## 四、PlayerBot 的自动生成（用户特别强调）

> 「playerbot做好后还可以给playerbot装自动生成游荡机器人和
> 自动不用小号就可以自动生成机器人等各种功能吗？一定要实现！」

**答案：能做，而且这正是 mod-playerbots 的 `RandomPlayerbotMgr` 在干的事。**

### 不用小号 = 自动建号建角色

```
1. 服务端启动时检查："BOT_" 前缀的账号有几个
2. 不够就自动创建：
   - CreateAccount("BOT_0001", 随机密码)
   - 随机种族/职业/外观，建角色
   - 直接设定等级和装备（不用真练级）
3. 按需登录这些角色当 playerbot
```

**mod-playerbots 的做法（已查证）**：
```
AiPlayerbot.RandomBotAccountPrefix     账号前缀
AiPlayerbot.MinRandomBots / MaxRandomBots   数量区间
RandomPlayerbotFactory                  自动建号建角色
```

**我们可以照这个思路做，但用 TrinityCore 的 API。**

### 游荡 playerbot（在世界里自己活动）

因为它是真 `Player`，**能做 NPCBot 做不到的事**：
```
- 真的去接任务、交任务
- 真的去打怪升级
- 真的去银行、拍卖行
- 真的组队打副本
```

**这是"活着的世界"的关键。**

### 但要面对的现实

| 项 | 说明 |
|---|---|
| 性能 | 每个 = 完整 Player + Session。**50 个 ≈ 50 个真人在线** |
| 内存 | 每个约几 MB，100 个就是几百 MB |
| 数据库 | 每个都要写 characters 表 |
| **建议数量** | 单机自己玩：**10-30 个**足够有"世界感" |

**分层方案**：
```
游荡 NPCBot   50-100个   填充远处的世界（轻量）
游荡 PlayerBot 10-20个    在你附近活动（真实）
队友 NPCBot    3-4个      日常跟随
队友 PlayerBot 1-2个      需要做任务时
```

**两种混用，各取所长。**

## 五、执行顺序建议

```
现在      step40 PlayerBot 第1步（能站着不崩）    <- 阻塞项
接着      羁绊系统（step34 的直接扩展，最快见效）
再接着    对手系统（钩子都现成，纯数据+台词）
之后      PlayerBot 自动生成
长期      身世/关系网/传承
```

**为什么羁绊排在对手前面**：
羁绊是 step34 的直接扩展（同一张台词表加一列），**1-2轮就能出效果**。
对手系统要新建表和新的脚本类，工作量大一些。

## 六、一个原则

**所有这些系统，台词和数值都进数据库。**

你应该能够：
- 自己加台词，不用等我
- 自己调数值，不用重编译
- 自己写身世，让每个bot都不一样

**我做框架，你填内容。** 这样这个服才真正是你的。
