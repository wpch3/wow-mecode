## 一、为什么"光是游荡npc做不到"（用户判断正确）

现有游荡 bot 的行为（实查 `bot_ai.cpp:18717`）：

```cpp
WanderNode const* nextNode = GetNextTravelNode(&pos, false);
```

**纯粹是在路点图里随机挑下一个点走过去**，
没有任何"目标"、"注意到旁边有人"、"想不想搭话"的概念。

### 缺的三样东西

| 缺什么 | 现状 | 证据 |
|---|---|---|
| 感知 | 只在 HideBotSpawns 时搜过一次玩家 | `bot_ai.cpp:17692` 是唯一一处 |
| 决策 | 只有"打不打它"，没有"理不理他" | `bot_ai.cpp:3623` 和平模式判断 |
| 社交 | `Group::AddMember` 从没被 bot 主动调用过 | `Group.h:197/209` |

## 第1步：索要机制重做（含你现在的 bug）

### 现在的三个硬伤

| 问题 | 现状 | 改成 |
|---|---|---|
| **必须组队** | 没队 = 永远不说话 | 附近有玩家就可能开口 |
| **只跟队长说** | 队长是别人就不理你 | 跟"羁绊最高的在场玩家"说 |
| **说了没下文** | `answered` 永远 0 | 检测你给的东西是否对口 |
| **满足了没奖励** | 给了也不加分 | 满足索要额外 +15 羁绊分 |

### 新的索要对象选择逻辑

```text
1. 找附近 40 码内所有活着的玩家
2. 每人查一次 npcbot_bond 的 bond_level
3. 选羁绊最高的那个
4. 都是 0 分（陌生人）-> 只有 30% 概率搭话，且用"生疏"台词
```

**这样即使不组队，路过的玩家也可能被搭话** ——
这正好是 G11 第3步"搭话"的雏形。

### 满足检测

你给 bot 东西时（第2步赠予 / PlayerBot 交易），
查最近 10 分钟有没有未满足的索要，物品对口就标记满足：

```text
索要食物(1)  <- 你给了 BOT_GIFT_KIND_FOOD    -> 满足
索要水(2)    <- 你给了 BOT_GIFT_KIND_DRINK   -> 满足
索要绷带(3)  <- 你给了绷带类物品              -> 满足
索要修装备(4) <- 暂不支持（需要修理逻辑）
```

满足后：
```sql
UPDATE npcbot_request_log SET answered = 1, answer_time = ? WHERE id = ?
UPDATE npcbot_bond SET requests_met = requests_met + 1, gift_points = gift_points + 15
```

**bot 会说一句特别的感谢**（新增 react_type = 3 的台词）。

## 第2步：感知层

### bot 每隔一段时间扫一次附近

```cpp
// 复用 bot_ai.cpp:17692 的模板
std::list<Player*> plist;
Bcore::AnyPlayerInPositionRangeCheck pcheck(me, 40.0f, true);
Bcore::PlayerListSearcher<decltype(pcheck)> searcher(me, plist, pcheck);
Cell::VisitWorldObjects(me, searcher, 45.0f);
```

### 记录"注意到了什么"

| 观察项 | 用途 |
|---|---|
| 玩家血量 < 30% | 要不要过去帮忙 |
| 玩家在战斗中 | 要不要加入战斗 |
| 玩家等级差 | 等级差太多不搭话 |
| 玩家是否已有队伍 | 满员就不邀请 |
| 之前遇到过吗 | 查 npcbot_bond |

**性能考虑**：扫描间隔 5-10 秒，且只在 bot 脱战、
非传送中、在大陆地图时才扫。

## 第3步：搭话层

### 决策树

```text
附近有玩家
   |
   +-- 认识（bond_level > 0）
   |      +-- 直接打招呼："又见面了，{player}。"
   |
   +-- 陌生人
          +-- 玩家血量低 -> "你还好吗？需要帮忙吗？"
          +-- 玩家在打怪 -> 直接过去帮忙（不说话）
          +-- 都正常     -> 30% 概率点头/挥手（emote），10% 概率搭话
```

### 新增台词表

```sql
CREATE TABLE `world`.`npcbot_greet_text` (
  `id`          INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `greet_type`  TINYINT UNSIGNED NOT NULL COMMENT '1=初见 2=重逢 3=关心 4=告别',
  `bond_tier`   TINYINT UNSIGNED NOT NULL DEFAULT 0,
  `personality` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '0=通用 见第5步',
  `bot_class`   TINYINT UNSIGNED NOT NULL DEFAULT 0,
  `text`        TEXT NOT NULL,
  `emote`       INT UNSIGNED NOT NULL DEFAULT 0,
  `weight`      TINYINT UNSIGNED NOT NULL DEFAULT 10,
  PRIMARY KEY (`id`)
);
```

**防骚扰**：同一个玩家 10 分钟内只搭话一次。

## 第4步：组队层

### 什么情况下 bot 会想组队

```text
1. 一起打过怪（bot 帮你打了，或你帮它打了）
2. 羁绊 >= 1 级
3. 玩家队伍没满
4. 同地图、40码内
5. 距离上次邀请 > 30 分钟（防骚扰）
```

### 两个方向

**bot 主动邀请你**：

```cpp
// NPCBot 版
if (!player->GetGroup())
{
    Group* grp = new Group();
    grp->Create(player);          // 玩家当队长
    sGroupMgr->AddGroup(grp);
    grp->AddMember(me);           // Group.h:197 Creature重载
}
else if (!player->GetGroup()->IsFull())
    player->GetGroup()->AddMember(me);
```

**bot 接受你的邀请**：
PlayerBot 已经有 A27 的自动接受，NPCBot 走招募流程，
这部分基本现成。

### 组队后的行为

```text
自动跟随（复用 A39 的 follow）
一起打怪
玩家死了会来救（A20 已有复活逻辑）
分开时说告别台词
```

## 第5步：记忆与性格

### 性格系统（让 bot 不一样）

```sql
ALTER TABLE `characters`.`npcbot_bond` ADD COLUMN `personality` TINYINT UNSIGNED DEFAULT 0;
-- 或者放 world 库按 bot entry 固定
```

| 性格 | 搭话概率 | 索要频率 | 台词风格 |
|---|---|---|---|
| 0 内向 | 5% | 低 | 客气、简短 |
| 1 普通 | 15% | 中 | 自然 |
| 2 外向 | 35% | 高 | 主动、话多 |
| 3 高冷 | 3% | 极低 | 简短、偶尔毒舌 |

**性格由 bot entry 决定**（哈希一下固定下来），
这样同一个 bot 永远是同一个性格。

### 记忆的用法

```text
"上次在{zone}遇到你的时候，你还是个{level}级的新手。"
"你上次给我的那把{item}，我还留着。"
"我们一起打过{n}场仗了。"
```

**这些数据 A37 的 npcbot_bond 表已经全都在存了。**

## 六、风险点

| 风险 | 应对 |
|---|---|
| **性能**：500个bot每秒扫描 | 5-10秒扫一次 + 只在脱战时扫 + 分批 |
| **骚扰**：bot 疯狂搭话 | 每玩家10分钟一次 + 性格系统 |
| **刷屏**：满屏 bot 说话 | 只对最近的1-2个玩家说 |
| **组队爆炸**：一堆bot挤进队 | 每队最多2个自主加入的bot |
| **和现有系统冲突** | 游荡bot的路点移动优先级更高，搭话不打断 |
