## 真正的三个可能

### 可能1：VS 陈旧缓存（最可能，和上次 C2011 一模一样）

上次 C2011 就是这个 —— 你代码明明改对了，编译器读的是旧版本。

**先做这个，不用改任何代码**：

```text
1. 生成 -> 清理解决方案
2. 等它完全跑完
3. 生成 -> 重新生成解决方案
```

**注意看输出窗口**（不是错误列表），应该出现：

```text
1>正在编译... bot_companion.cpp
```

**如果没有这行，说明 VS 又跳过了这个文件。**

---

### 可能2：`bot_companion.cpp` 没被加进编译

这个最隐蔽。`bot_companion.cpp` 是 A20 新增的文件，
如果当初 CMake 没扫到它，**整个文件都不会被编译**。

#### 怎么确认

在 VS 的**解决方案资源管理器**里：

```text
展开 game 项目 -> 找 bot_companion.cpp
```

| 结果 | 说明 |
|---|---|
| **找得到** | 文件在编译列表里，看可能1或3 |
| **找不到** | **就是它** —— 需要重跑 CMake |

#### 如果找不到

```text
1. 关闭 VS
2. 打开 CMake GUI
3. Configure -> Generate
4. 重新打开 sln，完整编译
```

> `cmake/macros/AutoCollect.cmake:26` 用 `file(GLOB)` 扫描目录，
> **新增 .cpp 必须重跑 CMake 才会被收进去**（我们坑表里记过这条）。
>
> 但你之前 A37 第3-5步改过 `bot_companion.cpp` 且编译成功，
> 说明它应该是在的。除非那几步你其实只改了 `.h`。

---

### 可能3：实现被加到了错误的位置

比如加到了：
- 某个 `#if 0` / `#ifdef` 块里
- 另一个命名空间里
- 文件末尾 `#endif` 之后

#### 怎么确认

在 `bot_companion.cpp` 里，把光标放到
`uint8 BotCompanionMgr::GetPendingRequest` 这一行，
**看 VS 编辑器顶部的导航栏**：

```text
应该显示：BotCompanionMgr  ->  GetPendingRequest(uint32, uint8, uint32)
```

如果显示"全局范围"或空白，位置就不对。

## 顺带：怎么快速判断"装了几份"

VS 里 `Ctrl+F` 搜 `BotCompanionMgr::GetPendingRequest`，
**查找框右边会显示 "1/N"** —— 那个 N 就是份数。

```text
N = 1  正确
N = 0  没装
N = 2  装重了，删掉一份
```
