## 一、它在最终目标中的位置

用户最终目标：

```text
bot 自主冒险
  -> 偶遇附近玩家
  -> 判断玩家是否需要帮助
  -> 主动打招呼或接近
  -> 相处后发起/接受组队
  -> 一起冒险并形成记忆
```

G11 分层执行：

| 层 | 内容 | 当前状态 |
|---|---|---|
| 第1步 | 索要/互动基础 | 已有交付与测试记录 |
| **第2步** | **感知附近玩家并生成事实快照** | **本次下一步** |
| 第3步 | 决策：忽略、观察、打招呼、帮助 | 未开始 |
| 第4步 | 行为：接近、说话、治疗/协助 | 未开始 |
| 第5步 | 组队与长期记忆 | 未开始 |

G19 已让 bot 理解「自己在哪里」；G11 第2步让它理解「附近有谁」。两者组合后，下一层才能形成「我在副本入口遇到一个残血、未组队的玩家」这种可用于决策的完整事实。

## 二、本批严格边界

### 必须实现

只对满足条件的自主游荡 NPCBot 周期性扫描附近玩家：

- bot 在世界中且存活；
- `IsWanderer()`；
- `IAmFree()`；
- 不在传送过程中；
- 配置总开关开启；
- 扫描计时器到期。

每个候选玩家生成只读快照：

```text
player guid
player name
real player / disconnected PlayerBot
map / zone
3D distance
player level
level delta (player - bot)
health percent
alive
in combat
has group
same phase
first seen / seen again
help candidate（只记录事实，不执行帮助）
```

第一版只挑最近的合法玩家写日志，避免一轮输出几十行。

### 明确禁止

本批不得执行以下任何行为：

- 不 `MoveFollow`、不 `MovePoint`；
- 不改变当前战斗目标；
- 不施法、不治疗；
- 不 `Say`、不 `Whisper`；
- 不调用 `Group::AddMember` / `AddInvite`；
- 不修改 `npcbot_bond`；
- 不写数据库；
- 不改变原来的 wander 路点；
- 不把「需要帮助」直接等同于「一定去帮助」。

这样即使感知判断有误，也只会出现一行调试日志，不会破坏现有 AI。

## 四、建议配置

新增独立配置文件：

```text
worldserver.conf.d\g11_perception.conf
```

建议项：

```ini
[worldserver]

# G11 第2步总开关；首版默认关闭，装好后手工开启测试
NpcBot.Autonomy.Perception.Enable = 0

# 扫描半径（码）
NpcBot.Autonomy.Perception.Range = 60

# 随机扫描间隔（毫秒），每只bot错峰，防止同一tick一起扫描
NpcBot.Autonomy.Perception.IntervalMin = 4000
NpcBot.Autonomy.Perception.IntervalMax = 8000

# 同一bot对同一玩家最短日志间隔，避免刷屏
NpcBot.Autonomy.Perception.LogCooldown = 15000

# 只输出日志，不允许行为层动作；第2步必须保持1
NpcBot.Autonomy.Perception.ReadOnly = 1
```

必须对配置做范围钳制：

- Range：10..120；
- IntervalMin：1000..60000；
- IntervalMax 不得小于 Min；
- LogCooldown：1000..300000；
- 首版 `ReadOnly=0` 也不能自动解锁行为，因为行为层尚未实现；它只是预留并打印警告。

## 五、建议内部结构

### 5.1 快照结构

```cpp
struct BotPerceivedPlayer
{
    ObjectGuid Guid;
    std::string Name;
    float Distance;
    int16 LevelDelta;
    float HealthPct;
    uint32 MapId;
    uint32 ZoneId;
    uint8 Scene;
    bool IsAlive;
    bool IsInCombat;
    bool HasGroup;
    bool IsDisconnectedBot;
    bool IsHelpCandidate;
};
```

说明：这是内存临时事实，不落库。熟识度与长期记忆留到后续记忆层。

### 5.2 bot_ai 新状态

每只 bot 至少需要：

```text
_perceptionTimer
_lastPerceivedPlayerGuid
_lastPerceptionLogTime
```

计时器必须在构造/重置时随机初始化，不能用 map `operator[]` 默认 0；项目坑表已有「默认0导致新对象第一帧执行完整逻辑」的事故记录。

### 5.3 更新入口

建议在 `GlobalUpdate(uint32 diff)` 已通过以下检查后调用：

```text
FindMaster 已完成
不是传送中
bot 存活
bot 在世界中
```

不要把函数插进某个 `if ... else` 中间。最终补丁必须依据 07 号探针返回的真实源码给出完整替换块和自动脚本，不再让用户凭肉眼找「某个大括号下面」。

## 六、候选过滤规则

候选必须全部满足：

1. 非空；
2. 在世界中；
3. 活着（首版只看活玩家）；
4. 与 bot 同地图、同相位；
5. 距离不超过配置 Range；
6. 不是 bot 的主人/当前 master（首版只对自由 wanderer 运行，仍保留防护）；
7. 不是正在传送的玩家；
8. 如果是 GM 也保留，用于用户自己测试，不静默过滤。

### 最近玩家选择

对全部合法候选按 3D 距离选最小值。距离相同不需要稳定排序；下一层决策尚未启用。

### 帮助候选事实

首版可以生成一个简单布尔值，但只能用于日志：

```text
IsHelpCandidate =
    player is alive
    AND player is in combat
    AND player health < 50%
    AND abs(level delta) <= 10
```

这里不是最终 AI 规则，只是验证所有输入事实能否组合。以后决策层会加入阵营、关系、性格、敌人数量、bot 职责、冷却和风险评估。

## 七、日志格式

统一使用单行、可 grep 的格式：

```text
[G11-PERCEPTION] bot=70231 name=xxx scene=5 map=0 zone=12 player=3 playerName=xxx kind=human dist=18.4 levelDelta=2 hp=43.0 combat=1 group=0 seen=first helpCandidate=1 readonly=1
```

要求：

- 固定前缀 `[G11-PERCEPTION]`；
- 一条事实一行；
- bool 统一输出 0/1；
- 距离与血量保留一位小数；
- 不打印账号名、IP、邮箱等敏感信息；
- 没有候选时默认不写日志，避免每只 bot 都刷 `none`；
- 最近玩家发生变化，或同一玩家超过 LogCooldown，才重复输出。

## 八、性能护栏

首版只运行在 `IsWanderer() && IAmFree()` 的活跃 bot 上，并使用空间网格搜索，不遍历全服玩家。

仍要记录以下数据：

```text
每分钟 perception 扫描次数
每次候选数量
平均扫描耗时
最大扫描耗时
```

不要求第一版立刻做完整指标系统，但测试时至少用日志和 world update diff 观察：

- 100 只 wanderer；
- 500 只 wanderer；
- 玩家密集主城；
- 玩家为空的野外。

如果 500 只下出现明显卡顿，先增大 Interval，不要删功能。上万 bot 的最终方案必须与已有「休眠/分片机制」计划结合。

## 十、为什么现在不直接给可粘贴 C++ 补丁

GitHub 工作仓库保存的是规划、补丁和上传证据，不是用户当前 `D:\TrinityCore` 的完整已修改源码。G19 过程中已经发生过多次「文档锚点与用户真实源码相差数百行」以及插进错误作用域的问题。

因此本次按正确流程：

1. 先运行 `07-第2步_装机前探针.md` / `probe_g11_step2.py`；
2. 取得用户当前四个真实文件的上下文与符号计数；
3. 再生成完整文件替换块、自动备份脚本和 Ctrl+F 计数自检；
4. 用户编译；
5. 按本实施规格验收。

这不是拖延，而是为了不再让用户用一次完整编译去验证我猜的行号。
