## 八、第五步：启用只读日志验收

编译并部署新 `worldserver.exe` 后，把配置改成：

```ini
NpcBot.Autonomy.Perception.Enable = 1
```

重启 worldserver。第一版只对：

```text
IsWanderer() && IAmFree() && alive && in world && not teleporting
```

的 NPCBot 生效。

将真人角色站到自由游荡 NPCBot 的 60 码内，日志预期出现：

```text
[G11-PERCEPTION] bot=... name=... scene=... map=... zone=... player=... playerName=... kind=human dist=... levelDelta=... hp=... combat=... group=... candidates=... seen=first helpCandidate=... readonly=1
```

当前最小验收只要求真人：v2报告至少一条完整 `kind=human`，缺失字段数为0，并给出 `G11_HUMAN_MINIMUM_PASS=True`。

无客户端PlayerBot不是最小验收前置，只用于后续可选T7。观察者仍必须是自由NPCBot，PlayerBot只是60码内的被感知对象，预期：

```text
kind=playerbot
```

若真人更近，代码会选择真人；所以T7需单独布置，不能用PBot替代观察者NPCBot。

### 验收矩阵

| 测试 | 操作 | 预期 |
|---|---|---|
| T1 | 60码外 | 不记录该玩家 |
| T2 | 进入60码 | `seen=first` |
| T3 | 原地等待 | 至少间隔 LogCooldown 才有 `seen=again` |
| T4 | 两名玩家靠近 | 记录最近者，`candidates` 显示合法候选数 |
| T5 | 玩家进入战斗且生命低于50% | `helpCandidate=1`，但 bot 不采取行动 |
| T6 | 已组队玩家 | `group=1` |
| T7 | 无客户端 PlayerBot | `kind=playerbot` |
| T8 | bot 传送/死亡/不在世界 | 不扫描、不崩服 |
| T9 | 普通固定或随行 bot | 第2步不运行 |
| T10 | 观察移动和聊天 | bot 原行为不应被 G11 改变 |

## 十一、本阶段的硬边界

即使日志显示 `helpCandidate=1`，本阶段仍然：

- 不移动；
- 不说话；
- 不攻击；
- 不治疗；
- 不邀请组队；
- 不调用 `Group::AddMember`；
- 不改变羁绊；
- 不写数据库。

只有第2步感知准确且性能通过后，才进入第3步决策层。
