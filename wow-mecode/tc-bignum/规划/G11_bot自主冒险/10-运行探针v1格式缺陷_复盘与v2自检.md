# G11 运行探针 v1 格式缺陷：复盘与 v2 自检

> 日期：2026-08-20
> 结论：v1 PowerShell探针已停用；唯一运行探针改为 `probe_g11_runtime_v2.py`。
> 总体执行入口：`tc-bignum/00-当前整体安装步骤_单文件入口.md`

## 一、问题是什么

旧 `probe_g11_runtime.ps1` 把多种PowerShell对象放进同一个延迟格式化管线，最后统一 `Out-String`。PowerShell格式系统复用了表格视图，导致：

- 六项配置对象只剩空白行；
- 进程、exe、logger只显示Path，隐藏其他字段；
- G11日志命中只显示 `Server.log` 路径，隐藏LineNumber和Line正文。

用户回传报告中出现20行 `Server.log` 路径，实际上证明探针找到了**至少20条** `[G11-PERCEPTION]` 命中；不能把“正文列没显示”误判为“没有日志”。

## 二、为什么这是不可接受的

探针的目的就是消除歧义。一个会隐藏字段的探针，即使读取逻辑正确，也不能用于验收结论。旧版只做了静态括号/写入范围检查，没有在真实PowerShell环境执行，也没有用正/负fixture验证最终报告文本；测试门槛不完整。

## 三、修复

### 3.1 v1 fail-closed

旧 `probe_g11_runtime.ps1` 现在只会明确报错并退出，不再生成可能误导的报告。

### 3.2 v2改用Python纯文本协议

`probe_g11_runtime_v2.py`：

- 每个结果直接输出稳定的 `KEY=VALUE` 文本；
- 不依赖PowerShell表格格式化；
- 精确列出最多50条G11日志正文；
- 统计human/playerbot命中；
- 校验每条日志必需字段；
- 计算明确的 `G11_HUMAN_MINIMUM_PASS`；
- 对源码、配置、数据库写入为0，只写指定报告。

### 3.3 已执行的自检

本地已通过：


正fixture同时包含human与playerbot完整日志，并把最终报告真正写盘后校验UTF-8 BOM、CRLF及关键正文，直接覆盖v1的最终渲染回归风险。负fixture既测试Enable=0/logger=4/exe无标记/日志为空，也测试残缺字段、`readonly=10`、`kind=humanity`等容易被子字符串误判的行，均不得假阳性。日志字段现在按独立 `key=value` token精确解析；只有一个活动worldserver且路径准确才通过。大文件路径采用流式exe哈希/marker搜索和逐行日志扫描，避免整文件装入内存。缺路径另测为受控退出码2、单行错误、且不产生报告。

## 四、Windows首次self-test发现并修复的第二个问题

用户在Windows PowerShell 5.1 / Python 3.12.10运行self-test时，正fixture的 `process_path_match` 为False。根因是 `analyze()` 会对运行目录执行 `resolve()`，而fixture进程记录此前使用未规范化的TEMP路径；Windows的TEMP可能通过8.3短路径或目录联接暴露，两个字符串因此不一致。这是测试夹具路径构造缺陷，不应绕过。

修复与复验：

- fixture进程路径改为 `str(exe.resolve())`，与被测逻辑使用同一种规范化口径；
- 所有Python `assert` 改为不会被 `python -O` 删除的显式检查，并输出具体失败字段；
- 普通模式和 `python -O` 模式各运行一次完整self-test，全部通过；
- PowerShell预检命令改为单个 `& { ... }` 原子脚本块，内部失败后不会再错误打印“第一步完成”。

旧文件SHA256 `6bb8e1...` 已作废。replacement SHA256 `5f7a200640d4f2af1571108a11cc4cfb00d861a7874a94f8c77b14e4256b3d98` 随后已由用户在Windows PowerShell 5.1 / Python 3.12.10完整通过三组self-test，第一步正式完成。

## 五、以后强制门槛

1. 新探针必须有可运行的self-test，不只做语法/括号检查；
2. 必须同时有正fixture和负fixture；
3. 报告必须使用稳定纯文本字段，禁止依赖终端表格宽度；
4. 验收结论必须读取summary计数和原始正文，不能凭显示空白猜测；
5. 发现探针自身缺陷时，旧版必须fail-closed，不能让用户继续使用；
6. 每次状态更新同步总体单文件入口、专项文档、交接、Git状态和manifest。
