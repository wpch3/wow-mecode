# 新想法 · 计划外还能做什么

> 2026-08-09
> 用户：「如果可以再想想我们除了计划里的还有什么可以做」

**筛选标准**：钩子现成、成本低、能立刻感受到。
不写"很酷但要三个月"的东西。

---

## 一、【最推荐】五个被浪费的现成钩子

我扫了 `ScriptMgr.h`，发现这几个钩子**一个都没用过**，但每个都能出好效果。

### 1. `OnTextEmote` —— bot 会回应你的动作 ★★★★★

```cpp
ScriptMgr.h:686   virtual void OnTextEmote(Player* player, uint32 textEmote, uint32 emoteNum, ObjectGuid guid);
```

**效果**：你对 bot `/hug`，它抱回来；你 `/dance`，它跟着跳；
你 `/rude`，它生气（羁绊-1）。

```text
玩家 /hug 鲤鱼   ->  鲤鱼也 /hug 你 + "……突然干嘛。" （羁绊低）
                  ->  鲤鱼 /hug 你 + "嘿嘿。" （羁绊高）
玩家 /dance      ->  队伍里所有 bot 跟着跳
玩家 /cheer      ->  bot 也欢呼
玩家 /rude       ->  bot 不高兴，说一句，羁绊 -1
```

**为什么效果好**：这是**你主动做，它立刻回应**——反馈最直接的一类互动。
而且 `guid` 参数直接告诉你"对谁做的"，不用自己找目标。

**成本**：一个钩子 + 一张映射表（emote -> 回应emote + 台词类型）。
台词直接复用 A42 的表，加个 `care_type`。

---

### 2. `OnPVPKill` / `OnCreatureKill` —— 战斗后的反应 ★★★★

```cpp
ScriptMgr.h:634   virtual void OnPVPKill(Player* killer, Player* killed);
ScriptMgr.h:637   virtual void OnCreatureKill(Player* killer, Creature* killed);
ScriptMgr.h:640   virtual void OnPlayerKilledByCreature(Creature* killer, Player* killed);
```

**效果**：
```text
你杀了精英怪      -> bot："这家伙挺硬的，干得漂亮。"
你被怪杀了        -> bot："我没能保护好你……"（羁绊高时）
你 PVP 杀了人     -> bot："干净利落。"
连杀 10 个        -> bot："你今天状态不错啊。"
```

**已有基础**：`bot_ai.cpp:15914 ++_killsCount` 已经在数了，
只是没人用这个数字说话。

---

### 3. `OnLevelChanged` —— 升级不只是祝贺 ★★★

```cpp
ScriptMgr.h:643   virtual void OnLevelChanged(Player* player, uint8 oldLevel);
```

A20 已经做了升级祝贺，但可以更有层次：

```text
每级           -> 简单祝贺（已有）
10的整数倍     -> 更隆重 + 送东西
到 60/70/80    -> 专属台词（"我们走到这一步了"）
```

**加分项**：种族/职业专属的里程碑台词，直接复用 A42 评分制。

---

### 4. `OnDuelEnd` —— 对手系统的入口 ★★★★

```cpp
ScriptMgr.h:664   virtual void OnDuelRequest(Player* target, Player* challenger);
ScriptMgr.h:667   virtual void OnDuelStart(Player* player1, Player* player2);
ScriptMgr.h:670   virtual void OnDuelEnd(Player* winner, Player* loser, DuelCompleteType type);
```

**这是 A2「对手系统」的现成入口**，规划早就写了但一直没动。

最小可用版：
```text
决斗次数存表 -> 达到阈值改变称呼和态度
1-3 次    "又是你？"
4-9 次    "我记得你的剑路。"
10+ 次    "……我们打了这么多次，也算老朋友了。"（宿敌变战友）
```

**用户原话**：「连续决斗10次以上 -> 敌意转化为尊重 -> 宿敌变战友」
——这条在 `未完成想法-总清单.md` A2 里躺了很久。

---

### 5. `OnChat` —— G14 对话式索要的正规入口 ★★★

```cpp
ScriptMgr.h:673   virtual void OnChat(Player* player, uint32 type, uint32 lang, std::string& msg);
ScriptMgr.h:675   virtual void OnChat(..., Player* receiver);      <- 私聊，最有用
ScriptMgr.h:677   virtual void OnChat(..., Group* group);          <- 队伍频道
```

**G14 一直卡在"NPCBot 没有 session 收不到私聊"**，
但 `:677` 的**队伍频道版**能解决：

```text
你在队伍频道说 "有吃的吗"
  -> OnChat(group) 捕获
  -> 队伍里的 bot 关键词匹配
  -> 按羁绊决定给不给
```

**不用私聊，用队伍频道** —— 绕开了 NPCBot 没 session 的架构墙。

## 二、纯 SQL 就能做的（零编译）

### 6. 更多情境台词 ★★★★★

你说「可以根据这个多加台词和场景应用了」——**这是性价比最高的**。

已有的 `care_type` 只用了 6 个：
```
1食物 2水 3钱 4闲聊 5升级 6复活
```

**可以加的**（不用改代码，加 care_type 值 + 台词即可）：
```
7  你背包满了      -> "你东西太多了，要不要卖点？"
8  你装备耐久低    -> "你的护甲快碎了。"
9  你没吃的了      -> "储备见底了，进城补点吧。"
10 天黑了/天亮了   -> 时间感
11 下雨/下雪       -> 天气感
12 进入危险区域    -> "这里不太平，小心点。"
13 长时间没战斗    -> "……有点无聊。"
14 刚打完硬仗      -> "呼，总算完了。"
```

**注意**：7-9 需要读玩家状态，要一点代码。10-14 更简单。

### 7. 台词里的占位符扩展 ★★★

现在支持 `{item}` `{player}` `{gold}`，可以加：
```
{zone}    当前区域名（G19 已实证 AreaTableEntry.AreaName[16] 含中文）
{time}    早上/中午/晚上/深夜
{weather} 晴/雨/雪
{level}   你的等级
{botname} bot 自己的名字
```

**`{zone}` 最有用** —— 一条台词自动适配全世界所有地名。

## 三、中等成本但效果显著

### 8. bot 之间互相说话 ★★★★

**现在所有台词都是 bot 对你说，没有 bot 之间的交流。**

```text
队伍里有矮人和暗夜精灵：
  矮人："你们精灵是不是从来不喝酒？"
  暗夜："我们喝月光。"

亡灵和圣骑士：
  圣骑："……我还是不习惯和你并肩作战。"
  亡灵："彼此彼此。"
```

**技术上不难**：`bot_ai` 里能拿到队伍其他 bot，
台词表加 `partner_race` / `partner_class` 字段，
两个 bot 都在场时触发对话。

**效果极好** —— 这是"世界活着"最直观的体现。

**成本**：一张对话表 + 调度逻辑（谁先说谁后说、间隔多久）。

---

### 9. bot 记住"第一次" ★★★

```text
第一次一起进副本      -> "第一次和你下本，别拖后腿啊。"
第一次一起打死精英    -> "配合得不错。"
第一次你救了它        -> "……谢了。我记住了。"
第一次它救了你        -> "小心点，下次我不一定赶得及。"
```

**数据层已有** —— `npcbot_bond` 表加几个 bool 字段即可。

**为什么值得做**：「第一次」是最有记忆点的时刻，
而且**每个只触发一次**，不会腻。

## 四、我最推荐的三个（如果只做三件事）

| 优先级 | 项目 | 理由 |
|---|---|---|
| 第1 | **`OnTextEmote` 动作回应** | 反馈最直接，你做它就回，钩子现成 |
| 第2 | **更多 care_type 台词** | 纯SQL零编译，立刻见效，你已经认可这套风格 |
| 第3 | **bot 之间对话** | 从"bot陪你"升级到"世界活着"，质变 |

**理由**：这三个都建立在 A42 已验证的台词系统上，
不用新建架构，是**复利型投入**。

---

## 五、明确不建议现在做的

| 项目 | 为什么先别做 |
|---|---|
| 接外部 AI 生成对话 | Eluna HTTP 能力未验证，有踩空风险；模板法已经够用 |
| bot 自己接任务 | NPCBot 架构墙（`规划-Bot自主行为.md` 第五章已论证） |
| 语音/TTS | 3.3.5 客户端不支持，要改客户端 |
| 完整情绪状态机 | 收益不明显，先用羁绊分档代替 |
